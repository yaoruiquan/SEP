# SEP 前端设计草图

这些 SVG 按 `docs/architecture/前端设计文档-v1.md` 重做，是前端开发前的高保真方向稿，重点确认页面结构、用户任务和视觉系统。文档定义的是“能给老板演示的完整闭环”：管理员上架员工，用户登录后进入仪表盘，浏览员工广场，订阅员工，再进入对话中心使用。

## 视觉系统

- **品牌橙**：严格使用文档指定的 `#eb3f00`，取自 `/Users/yao/Pictures/favicon.ico`，用于主按钮、选中项、链接、关键数字和审核动作。
- **白底商务风**：页面背景 `#ffffff`，侧边栏 `#f7f7f6`，卡片保持白色，主要靠 `#e5e5e3` 边框分层。
- **炭黑文字**：主文字 `#171717`，次要文字 `#6b6b6b`，占位文字 `#9a9a9a`。
- **克制用橙**：橙色只承担“最想让用户点击的一个动作”，不做整片背景，保证后台和工作台专业、耐看。

建议落地为 CSS 变量：`--brand: #eb3f00`、`--background: #ffffff`、`--sidebar: #f7f7f6`、`--border: #e5e5e3`、`--fg: #171717`、`--fg-muted: #6b6b6b`。

## 页面说明

### `overview.svg`：产品总览

给产品、设计和开发统一对齐用。它把五个板块放在一张图里，适合第一次评审时快速判断导航关系、内容密度和颜色分工。它不是用户实际页面，而是整个平台的信息架构地图。

### `login.svg`：登录 / 注册入口

面向所有角色的统一入口。左侧负责传达品牌和产品价值，右侧承载邮箱、密码、注册和找回密码等认证动作。后续可以在这里补充企业登录、邀请码注册和登录后角色跳转。

### `user-dashboard.svg`：用户仪表盘

这是登录后的默认落地页，对应文档中的用户端首页。页面回答三个问题：我订了谁、我聊了多少、接下来点哪。包含 4 个指标卡、我的员工横向卡片、最近会话和平台动态，适合演示闭环时作为第一张用户端页面。

### `employee-market.svg`：员工广场

这是普通用户的核心首页，负责浏览、搜索、筛选和订阅“碳基员工”。卡片中展示员工擅长的工作方向、绑定的硅基能力数量、价格和详情入口。后续可增加收藏、对比、试用会话、行业筛选和订阅套餐。

### `chat-workbench.svg`：数字员工对话工作台

这是订阅后的主要使用场景。左侧是员工与历史会话，中间是 ChatGPT 风格对话区，右侧是“能力调用”过程。右侧非常重要，它让用户知道员工正在调用哪个硅基能力、当前进度是什么，并为失败重试、结果展开和调用日志预留位置。

### `admin-dashboard.svg`：管理端数据看板

这是运营后台首页，展示活跃用户、活跃员工、本月调用、待审核能力、调用趋势和热门员工。它对应文档中的 `(admin)/dashboard`，目的是让运营先看全局，再进入员工管理、能力审核和用户管理。

### `contributor.svg`：旧版贡献者概念稿

这张图保留为后续版本参考。根据前端设计文档 v1，贡献者端本期跳过，后续再挂到用户端一个板块，因此它不属于本期老板演示闭环。

### `admin-review.svg`：运营审核后台

面向平台运营和审核人员。重点是待审核队列、能力详情、贡献者信息、类型、版本、风险提示和审核动作。后续可以增加审核意见模板、批量审核、操作日志、用户管理、订阅管理和平台数据看板。

## 市场应该怎么拆

是的，平台应该有“市场”，但建议分成两个层级：

1. **碳基员工市场**：用户购买的是“结果导向的数字员工”，例如电商运营专员、内容策划师、数据分析师。它是普通用户默认看到的市场，也是产品的主入口。
2. **硅基能力库 / 能力市场**：贡献者和运营人员管理可复用的 Agent、RPA、Skill、AI App。普通用户不一定直接购买能力，而是通过订阅某个碳基员工间接使用它们。

因此导航建议是：用户端突出“员工市场”和“我的员工”；贡献者端突出“我的能力”和“上传能力”；运营端突出“能力审核”和“员工编排”。不要把两种市场混成同一组卡片，否则用户会分不清自己买的是一个完整岗位，还是一个底层工具。
