# 国内电商员工市场可用性与下架核查

核查日期：2026-10-14。目标：用户订阅员工后能直接完成明确的国内电商任务，而不是只获得岗位介绍或泛泛建议。

本文保留修复前的市场核查和岗位取舍建议。后续已修复中文名称兼容性，在本机暂停新增贡献奖励并正常补齐 9 个旧技能版本；本机 107 个已上架员工均通过技术就绪检查，未部署线上，也未执行改名、下架或岗位合并。详见 [修复与补版进度](../progress/2026-10-14-Skill兼容性与员工可安装性修复.md)。下文的安装阻塞数量对应修复前基线；岗位建议尚需真实任务验收，不是已批准的下架清单。

## 一、结论

本地实际数据库与公开市场接口有 107 位上架员工，另有 47 位已下架。当前岗位名称大部分已经围绕国内电商；主要问题不是简单清退非电商名称，而是安装阻塞、交付能力不足与重复岗位过多。

**不能把当前 107 位员工整体标为“订阅即可使用”。按当前平台制品服务和客户端代码，新订阅采用平台默认版本时，106 位有确定的安装阻塞。剩余 1 位只是静态制品校验通过，不等于真实业务交付验收通过。**

| 当前技术状态 | 员工数 | 证据 |
| --- | ---: | --- |
| 中文 Skill 名称被当前自定义校验阻塞 | 100 | 86 个批准版本的中文 `name` 被 ASCII-only 规则拒绝，平台实际返回 `BLOCKED / INVALID_ENTRY` |
| 缺少批准版本 | 6 | 9 个绑定能力没有任何版本；运行时跳过这些能力，技能目录返回空当前版本与客户端契约冲突 |
| 静态制品校验通过 | 1 | 抖音运营策略师的 Douyin Strategist；尚未实机、模型和交付验收 |
| 合计 | 107 | 全量逐员工关联核查，无遗漏 |

上表针对新订阅使用平台默认版本。企业启用版本、订阅历史选版、客户端本地工作副本等可能改变特定存量订阅的实际表现，本轮没有逐订阅验收，不把结果扩展为“所有已订阅用户完全无法对话”。

**产品目标建议收敛为 20 位国内电商员工：23 位暂时下架等待能力补齐，64 位下架独立入口并把有用任务合并到主员工。** 20 位只是值得投入的保留候选，必须修复和验收后才能作为“可直接使用”上架。短期不能以“建议保留”为由继续宣传已可用。

## 二、确定阻塞与能力边界

### 1. 新增 Skill 的中文安装名被过严校验拒绝

96 个独立绑定能力全部为 SKILL；210 条绑定全部启用。87 个平台批准版本中，86 个正文带类似以下头部：

```yaml
---
name: 商品卖点结构化
description: ...
---
```

`backend/src/shared/client-skill-artifact.dto.ts` 的安装名要求 `/^[a-z0-9]+(?:-[a-z0-9]+)*$/`。`ClientSkillArtifactService.describe()` 对已有头部执行该自定义 ASCII 校验，不会自动换名。本轮直接调用该真实服务校验数据库批准正文，86 个版本全部得到 `INVALID_ENTRY`，映射到 100 位员工。这证明当前实现存在安装阻塞，不证明中文 Skill 名称违反规范。

客户端 `sep-client/electron/common/platform/platform-api.ts` 协商 `skillArtifactProtocolVersion=1`；`pi-skill-packages.ts` 对 BLOCKED 制品拒绝准备。旧正文安装路径也要求合法安装名，因此不能把切回旧协议视为已证明的修复。

修复建议（2026-10-14 纠正）：支持中文 Skill 名称，统一平台、客户端安装、运行快照和 Pi 加载器警告策略，不强迫用户改成英文 slug。任何导入规范化须与批准/制品哈希策略一致，不静默篡改已批准正文。详见同日《Skill校验兼容性核查》；本轮未执行业务修复。

### 2. 六位老员工缺少正式版本

| 员工 | 缺少版本的能力 | 产品处理 |
| --- | --- | --- |
| 国内电商运营专家 | China E-Commerce Operator | 保留候选，补版本并验收 |
| 商品内容与详情页策划 | Content Creator / Visual Storyteller | 保留候选，限定文案交付，补版本 |
| 电商售后与退货专员 | Retail Customer Returns / Customer Service | 保留候选，补国内场景与正式版本 |
| 私域复购运营师 | Private Domain Operator | 合并到电商社群运营师 |
| 直播电商增长教练 | Livestream Commerce Coach | 合并到直播脚本总编 / 电商活动复盘官 |
| 电商投放优化师 | PPC Campaign Strategist / Tracking & Measurement Specialist | 暂时下架，国内化重建 |

`SkillVersionService.resolveEffectiveVersion()` 不会用 `skillConfig.template` 兜底。`ClientService.getRuntime()` 跳过没有有效批准版本的技能；客户端技能目录 schema 要求 `currentVersion` 非空，空版本可能使整个员工准备失败。

旧电商投放优化师的核心 PPC 模板针对 Google Ads、Microsoft、Amazon，不应以此直接出售国内平台投放优化能力。

### 3. SKILL 能辅助工作，不等于已接入店铺系统

96 个能力没有 `agentConfig`，因此后端 `CapabilityService.execute()` 这条工具执行路径会触发 `No agent config`。但近期架构是平台发布、客户端执行，不能仅因没有 agentConfig 就断言所有文字型员工都不可用。

实际应按承诺区分：

- 标题、客服回复、直播脚本、供应商沟通稿：合法 Skill 加模型可以作为辅助交付，仍需真实样例验收。
- 图片、成品详情页：当前媒体运行时 `executionAvailable: false`，图片网关为受限 mock，不能当成真实生图证据。
- 视频脚本、切片方案：不等于视频生成、剪辑或发布。
- 用户上传报表分析：不等于自动采集、持续监控、真实归因或自动投放。
- 退款、发券、改价、采购、客服发送：必须证明授权执行、结果回读和人工确认，不能只凭提示词宣称已经实现。

86 个能力模板不足 1000 字符，且大量复用通用工作规则。长度本身不是不可用的证明，但结合缺少业务样例、固定输出和实机证据，不足以支持“成熟数字员工”承诺。

市场可见的商品内容员工 7 次执行记录为通用 `{ok: true, summary: "已完成"}`，未关联 skillVersionId，形状与 seed 演示记录一致。它们不足以证明真实交付，不把执行计数作为验收结果。

## 五、下架独立入口并合并的 64 位

逐位合并目标见 `outputs/market-audit-2026-10-14/逐员工核查.md`，以下是收敛规则：

- 全链路运营、总监、老板决策、目标拆解、SOP、项目任务等，收敛到国内电商运营专家。
- 驾驶舱、周会、汇报、会议秘书、多店分析等，收敛到经营日报 / 活动复盘。
- 会员、生命周期、客户分层、转介绍、复购增长等，收敛到电商社群运营师。
- 直播编排、增长教练、直播诊断等，收敛到直播脚本 / 活动复盘。
- 视频导演、切片策划、抖音运营策略等，收敛到抖音短视频策划师。
- 商品资料、卖点、视觉需求等，收敛到商品内容与详情页策划。
- 履约异常、客诉、退款风险、退货再售等，收敛到售后与退货专员的辅助子任务。
- 客服合规、交接总结等，收敛到客服会话质检师。
- 优惠券、分销佣金等，收敛到促销机制设计师。

这里的“合并”是建议，不代表已迁移技能。不得因下架入口就删除员工、能力、历史记录或订阅。

## 六、上架验收门槛与执行顺序

1. 当前已确定有阻塞的 106 位，不再作为“开箱即用”推荐；产品选定的 20 位保留为待修复候选，其余 87 位退出首期独立售卖目标。唯一制品可用的抖音运营策略师也应先交付验收，随后迁入统一短视频入口。
2. 修复版本缺口、中文名称兼容性和过严校验；必要的正文迁移通过明确的发布流程，不静默修改历史批准版本。下架前验证存量授权、订阅和数据影响。
3. 首期 8 位逐员工走完整路径：新订阅 → 授权 → 客户端启动 → 正确批准版本安装 → 模型执行 → 输出检查 → 重启后重复执行。用户不应手工改 YAML、选历史版本或复制 Skill。
4. 每位至少 3 个真实电商样例：标准输入、缺字段、边界/错误输入。固定输入表与输出格式；不足资料应追问或明确缺口，不编造库存、订单、平台规则与成交数据。
5. 数值产物必须可复算；文案事实有输入出处；投诉、退款和投放动作须明确人工确认。没有授权接口的员工只能卖辅助产物，不能宣称已执行外部操作。
6. 员工详情页明确输入、交付物、适用平台和边界。只有实机与交付双验收通过，才恢复“直接使用”推荐。

## 七、本轮证据与限制

- 只读检查本地实际数据库，事务显式 `SET TRANSACTION READ ONLY`；公开市场接口 HTTP 200，107 位员工与数据库逐项交叉核验。不是生产环境可用性声明。
- 直接复用平台 `ClientSkillArtifactService.describe()` 和共享 frontmatter schema，不用自行近似规则判定格式；没有模型费用或对外店铺动作。
- 可复跑脚本：`node outputs/market-audit-2026-10-14/audit.mjs`。脚本仅写审计产物，不写业务数据库；其姓名映射针对本次 107 位快照，市场变化会显式报缺失。
- 已执行后端 capability execution/download、client service、artifact HTTP/service 5 套相关测试，共 96 项通过。测试说明现有机制行为一致，不证明 107 位员工真实业务验收完成。
- 未做真实客户端登录订阅、模型调用、图片/视频生成、店铺平台授权与真实订单动作；本轮没有更改业务代码、上架状态或订阅。
- 外部搜索及官方页面获取未得到可引用结果。因此本报告不是最新平台规则、平台 API 开放范围或商业需求调研的完成声明；选型以代码与实际发布数据为证据，未来接入应另查官方接口和权限。
