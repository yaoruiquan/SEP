# Skill 校验兼容性核查

核查日期：2026-10-14。范围：SEP 发布/审核/制品服务与 sep-client 安装、运行快照、实际 Pi 加载器。目标：先查清同类过严校验，再修中文名称、旧技能版本缺口、员工上架可安装性三个问题。

本文记录修复前的核查基线，原始探针结果保留用于追溯。后续已完成兼容性、客户端安装和上架检查的代码修复及回归验证，见 [修复与补版进度](../progress/2026-10-14-Skill兼容性与员工可安装性修复.md)。截至最新进度，已按用户要求在本机关闭新增贡献奖励并正常发布 9 个旧模板版本，新增入账为 ¥0，107 个已上架员工全部通过技术就绪检查；未部署线上、改名或下架员工。下文中的“当前问题”和代码行号均对应修复前基线，不代表最新状态。

## 一、结论

**存在同类问题，而且不止名称正则。** 当前最主要的风险是多层各自校验，平台 AVAILABLE 不保证客户端能安装，安装成功也不保证运行加载成功。

建议采用“内容与名称兼容从宽、安全与授权从严”的原则：非空正文与描述保留最低要求；短正文、普通元数据、风格提示尽量降为警告；真正损坏、权限错误、缺必要执行资源、哈希不符、真实凭据泄漏仍阻止发布或运行。

## 二、应放宽或统一的校验

| 类别 | 实际复现/代码证据 | 建议 |
| --- | --- | --- |
| 中文和 Unicode 名称 | 中文 `商品文案整理`、`café` 在平台和旧客户端安装被拒绝；中文运行快照也失败 | 支持 Unicode 名称，不要求用户改英文；安全目录规则和名称规则分开 |
| 所有 Pi diagnostics 均当失败 | 实际 Pi 0.83.0 加载中文名并发 warning，但员工加载器拒绝任何 diagnostics | 只允许明确的非安全、非完整性兼容提示降级；不得忽略全部 diagnostics |
| BOM 与头部空行 | BOM 平台拒绝，旧客户端接受；头部空行平台拒绝，旧客户端虽通过但未识别原 YAML | 在导入/发布阶段统一规范化；不要批准后偷偷改字节，运行 Pi 自身也不识别 BOM |
| 外链中包含 `assets/` | `https://example.com/assets/product.jpg` 平台误判 PACKAGE_REQUIRED，客户端接受 | 按链接语义区分远程 URL、输入依赖和输出路径，避免全正文关键词匹配 |
| 输出文件示例 | “保存为 `result.json` / `result.md`”平台 AVAILABLE，客户端误判缺资源；输出目录 `assets/output.png` 两端拒绝 | 输出声明和文件名示例不能单凭文本当成必须预装的依赖 |
| 自链接与 URL | `./SKILL.md#步骤` 平台拒绝、客户端接受；`//example.com/info` 平台接受、客户端拒绝 | 统一引用规则；外部 scheme 是否允许另做明确策略，不等于允许客户端执行任意协议 |
| 禁止自动发现标志 | `disable-model-invocation: true` 平台 AVAILABLE，客户端安装失败；Pi 原生支持 | 接受字段并保留语义；它影响自动发现，不代表安全隔离；要定义员工使用时的显式调用路径 |
| YAML 元数据类型 | `metadata.date: 2026-10-14`、`metadata.revision: 1` 被平台拒绝，旧客户端接受 | 非执行元数据类型差异不应阻塞整份技能；统一 YAML 解析与必要字段验证 |
| YAML merge | 用 `<<` 提供 description 时平台 AVAILABLE，客户端 CORE_SCHEMA 解析后缺 description | 与实际 Pi 使用相同的解析语义；如不支持，发布时给准确提示，不留到安装时失败 |
| 中文大小限制 | 18 万个“中”正文为 540061 字节：更新 DTO 接受，制品拒绝 | 统一实际字节预算及提示；可评估提高预算，但不能无上限 |
| 短正文 | “将输入商品名翻译成英文。”被正文至少 20 字符硬规则拒绝 | 非空保留；最少 20 字符改质量提示，质量靠任务验收而不是凑字数 |
| 凭据占位符 | `token: YOUR_TOKEN`、`password: example`、`api_key: ${API_KEY}` 都触发敏感凭据错误 | 明确排除常见占位符和参数示例；不确定情况提示复核，真实凭据仍阻断 |

补充：CRLF 探针两端通过，不属于待修问题。一般未知 frontmatter 字段探针也通过，不应误报为全部禁止扩展字段。角色/输入/输出/步骤标题缺失目前只是 warning，不是硬性阻塞。

### 发布与表单的额外差异

以下由实际 schema 内存探针确认，未做浏览器/HTTP 端到端；应一并纳入校验整理，但不扩大为所有流程都已失败：

- 员工创建页默认提交 `avatar: ''`，运营接口 `.url().optional()` 拒绝空串；页面提示的站内 `/assets/...` 路径也被拒绝，共享头像 schema 却接受。定位：`web/src/app/(platform)/admin/employees/new/page.tsx:40`、`backend/src/modules/admin/admin.controller.ts:50`、`backend/src/shared/index.ts:1077`。建议允许省略/空值，站内资源与外部 URL 使用同一规则。
- Coze 两类创建表单要求描述至少 10 字符，实际运营接口只要求非空；“自动回复”后端接受、前端拒绝。定位：`web/src/app/(platform)/admin/capabilities/new/page.tsx:172`、`backend/src/modules/admin/admin.controller.ts:77`。建议把 10 字门槛降为提示。
- Skill 创建与贡献创建表单缺少后端名称 100、描述 2000 字符上限；超过后前端通过、服务端失败。定位：`web/src/app/(platform)/admin/capabilities/new/skill-form.tsx:21`、`web/src/features/contribution/contribution-create-dialog.tsx:50`、`backend/src/shared/index.ts:846`、955。应复用契约或同步预算，不是简单取消所有上限。
- 员工共享创建/编辑 DTO 的描述为 10–2000 字符，运营接口描述任意字符串且可省略。运营页面短描述本身不会被共享规则拦截，但两套契约应统一。定位：`backend/src/shared/index.ts:1092`、1118、`backend/src/modules/admin/admin.controller.ts:47`、63。
- 贡献版本正文最低 20 字符、变更说明上限 1000；通用编辑/客户端个人提交最低 1、说明上限 2000。定位：`backend/src/shared/index.ts:1044`、1058、`backend/src/shared/skill-version.dto.ts:22`、`sep-client/src/shared/platform-supplement-contracts.ts:99`。放宽短正文时必须同时处理 DTO 和 service，不能只改一层。
- 客户端审核 schema 尚不接受后端已有的 `expectedUpdatedAt` 字段。定位：`backend/src/shared/skill-version.dto.ts:54`、`sep-client/src/shared/platform-supplement-contracts.ts:124`。需要同步契约，不要通过删除并发保护解决；尚未确认现有 UI 会发送该字段。

业务员工/能力显示名没有 ASCII 限制，单字中文名可通过。员工版本 `x.y.z` 规则与个人提交 `.strict()` 本身不定性为错误，不纳入盲目放宽。

## 三、不能靠放宽规则解决的问题

1. **ZIP 安装能力尚未实现。** 合法包在平台上传解析和安装制品校验都通过，但客户端明确拒绝 ZIP，禁止正文降级。这需要实现安装支持或在发布前明确目标客户端不支持，不能把它称为包格式不合法。
2. **上传规则与安装规则不同。** 1200 字描述、多入口包都能通过上传解析，安装制品校验再失败。应前置检查或区分“上传供查看”和“可发布给员工安装”；多入口的选择必须无歧义，不宜直接取消限制。
3. **批准版本缺口是数据生命周期问题。** 旧能力只有 `skillConfig.template`、没有可解析的 SkillVersion；不是正文无效或名字不对，也不是必须另找外部机构认证。需要明确旧技能迁移/发布政策。
4. **上架可用性验证是工作流缺口。** 需要把目标客户端实际安装与加载能力纳入发布/上架检查，不应只判断平台制品 AVAILABLE。

## 四、必须保留的边界

- 相对路径安全、路径穿越/绝对路径/危险控制字符限制、符号链接限制。
- SHA256、版本身份、批准来源、正文与制品一致性、下载授权和不可变字节。
- ZIP CRC、结构校验、条目数和解压体积预算；不能为兼容包取消防炸弹限制。
- 真正执行依赖缺失仍需阻止；有附件时应提供完整包，不能把检测全部删除。
- 数据库 ID、哈希、Idempotency-Key、模型 function/tool 标识等机器字段保留协议约束；中文展示名称不应与这些字段混用。
- `allowed-tools` 在当前 Pi 中未形成工具授权逻辑；接受其元数据不等于授权工具执行。`disable-model-invocation` 也不是访问控制。
