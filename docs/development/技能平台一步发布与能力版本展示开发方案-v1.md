# 技能平台一步发布与能力版本展示开发方案 v1

## 1. 目标与边界

本次合并运营端“收录到平台审核”和“审核通过”两个动作，并在能力管理展示当前平台版本。企业审核继续保留，客户端仍是修改技能正文的唯一入口。运营管理员预览来源后点击“发布为平台版本”，确认即完成平台发布，不再创建需要再次人工审核的中间流程。

本次不改变认证、企业启用、客户端提交、非技能能力审核，不修改数据库结构，不批量改写历史记录，不自动提交或部署。

## 2. 现状与问题

- 技能监控当前通过 `adopt` 创建 `PENDING_PLATFORM_REVIEW`，再通过 `review` 才发布；同一管理员需要操作两次。
- 私有技能已支持复制为独立平台能力，公开来源在原平台能力下生成版本；此隔离逻辑必须保留。
- 能力管理只显示能力审核状态，无法直接看出平台版本从 v1.0.0 变为 v1.0.1。
- 通用能力审核接口可能绕过技能精确选版，必须禁止对 SKILL 使用，其他能力保留原流程。

## 3. 新业务流程

1. 管理员在技能监控选择个人、企业或历史平台待发布版本。
2. 详情只读展示来源、正文、安全检查、当前平台版本与差异。首次发布明确显示无平台基线。
3. 点击“发布为平台版本”，确认弹窗显示来源、当前平台版本和影响范围。
4. 服务端检查管理员权限、来源更新时间、平台最新版本、安全和包一致性。
5. 在一个事务中冻结必要的历史工作副本、建立私有来源的平台映射、创建/发布精确平台版本、更新能力公开状态与执行正文、平台模板绑定、审计和去重奖励。
6. 返回已发布平台版本；详情跳转到该版本，能力管理和监控缓存同步刷新。

企业审核待审、拒绝、历史来源均可由平台管理员独立选择；这不伪造企业审核通过，也不改变企业默认版本。已归档的平台记录不可直接发布。已经发布的来源重复请求返回原发布结果，不重复奖励、不将当前版本回退。

## 4. 版本与隔离规则

- 平台版本序列只统计 `scope=PLATFORM`，首次为 1.0.0，后续递增 patch；企业序列独立。历史草稿、待审或拒绝记录发布时按其他平台版本重新计算版本号与父版本，不覆盖正文、不删除历史审核。
- `sourceVersionId` 指向选中的精确来源；`parentVersionId` 指向发布时当前平台版本。
- 个人/企业来源保留原文和审核状态。可变历史个人工作副本先生成不可变来源快照，再发布。
- 非公开来源创建或复用独立的平台能力，不公开企业原能力，不复制企业私有 metadata。
- 平台发布只推进员工模板中原本钉在平台版本上的默认绑定；企业默认版本、企业订阅选版不改动。
- 来源版本号不是平台版本号。例如企业 v1.0.0 发布后可产生平台 v1.0.1，详情同时展示二者，避免将“平台换成企业版”误解成平台版本范围改变。

## 5. API 契约

新增 `POST /admin/skill-versions/:id/publish`，沿用平台管理员 Guard。

```ts
{
  expectedUpdatedAt: string; // 必填 ISO 时间，锁内检查所选来源未变化
  expectedPlatformVersionId: string | null; // 必填，null 表示预览时尚无已发布平台版本
  changeSummary?: string; // 最多 2000 字，只影响发布说明，不修改正文
}
```

使用共享严格 Zod DTO。成功返回平台版本摘要及正文；校验失败 400，无权限 403，不存在 404，来源或平台基线变化 409。确认失败保留页面操作错误，刷新预览后再试。

详情新增 `currentPlatformVersion: { id, capabilityId, version, content, updatedAt } | null`，私有来源查询映射平台能力的已发布版本。发布和预览使用同样的映射与排序规则。

新增入口不接受请求正文覆盖、人工状态跳转或忽略安全验证。旧 `adopt`/`submit-review`/`review` 接口仅保留历史兼容，不再作为正常界面入口。通用能力审核接口对 SKILL 返回明确错误，指引到技能监控精确发布。

## 6. 原子性、并发与幂等

- 锁顺序为来源能力、来源版本、映射平台能力；精确版本在锁内重新读取。
- 来源 `updatedAt` 和当前平台 head 都与预览值比对；不一致时整体回滚，禁止静默发布过期内容。
- 同一不可变来源已有发布记录时返回原记录，不重复执行能力、绑定或奖励更新；历史待审/拒绝记录允许在重新校验后直接发布。
- 旧来源已经发布后不能以重试名义覆盖后续新版本；需要新的来源提交。
- 奖励继续沿用原能力 dedupeKey，私有映射不会产生第二次奖励。
- 校验、版本创建和发布的数据库写入必须在同一事务；失败不能留下新待审记录或半公开能力。

## 7. 能力管理

新增“当前平台版本”表头，SKILL 展示最新 `PLATFORM_APPROVED` 的 `v{version}`，无已发布版本展示“未发布”；非 SKILL 展示 `-`。

版本号链接到带 `capabilityId` 和 `scope=PLATFORM` 的技能监控版本列表，可以查看父版本、来源与发布时间。查询采用每能力最多一条的受限关系查询，不逐行请求，不读取全文。平台当前版本按 `platformReviewedAt desc nulls last, createdAt desc, id desc` 判断，运行时、下载、监控与能力管理同步采用此规则；历史创建早不影响新发布生效，旧缺发布时间的版本按创建时间回退。普通历史时间线仍按创建时间排列。

SKILL 不再显示旧通用通过/拒绝或投稿审核跳转，使用技能监控入口；其他能力和状态筛选保留原行为。待审核/已拒绝仍对非技能能力及历史记录有意义，不为本次发布重新制造待审核状态。

## 8. 监控与历史兼容

- 主动作统一为“发布为平台版本”；已发布显示当前/历史平台版本状态，不再提供二次审核动作。
- 平台处理筛选改为“未发布、已发布、历史待审、历史拒绝”，枚举不变以兼容旧数据。
- 能力列表跳入监控时保留能力过滤和平台范围，分页、刷新保持上下文；可明确清除上下文返回全量。
- 内容差异复用现有 `diffLines`，不新增依赖。
- 缺少结构段落仍是提示；凭据、空正文、包不一致等硬错误继续阻止发布。
- 历史审核记录不删除，发布写入一次 PLATFORM/APPROVE 审计；对旧拒绝重发布保留先前记录。

## 9. 实施顺序

1. 写本文并补发布行为回归测试。
2. 新增 DTO、发布事务和详情平台基线，复用已有安全、映射和奖励逻辑。
3. 更新能力管理接口、版本列及 Skill 精确选版入口。
4. 更新监控动作、确认、差异、筛选文案、能力上下文。
5. 执行定向测试、类型检查、lint、构建，使用模拟 API 的真实浏览器验证桌面和移动布局，避免写业务数据库。

## 10. 验收标准

- 个人/企业来源一次确认后产生已发布平台版本，无第二次审核，企业状态与默认不变。
- 首次私有发布产生独立平台能力；再次发布复用映射并递增平台版本，正确关联来源与父版本。
- 过期来源/平台预览拒绝发布，校验失败不留下任何新版本。
- 重复发布幂等，不重复奖励、不回退当前平台绑定。
- 历史草稿、待审、拒绝平台记录可直接发布；归档不可直接发布。
- 能力管理展示已发布平台版本，不误显示企业版、个人版或待审版；点击可查看该技能的平台历史。
- 通用 Skill 审核快捷路径被阻止，非 Skill 审核不回归。
- 正文、安全提示、发布错误、确认弹窗和差异在桌面/移动端可见且不溢出。

## 11. 交付与风险

无 schema 变更，无需迁移。旧接口暂留供历史调用兼容，后续移除须独立统计调用方。首次私有发布会新增一条平台能力，这是安全隔离，不是重复公开企业能力。新发布的内容与包一致性仍可能因真实对象存储环境失败，应显示原始可操作原因，不自动绕过检查。

## 12. 实际交付

本方案已实现，核心文件如下：

| 模块 | 文件 | 交付内容 |
| --- | --- | --- |
| 共享契约 | `backend/src/shared/skill-version.dto.ts` | 严格发布 DTO，必填来源时间和平台基线 |
| 发布接口 | `backend/src/modules/skill-version/skill-version.controller.ts` | 管理员发布接口、Guard、Swagger |
| 发布事务 | `backend/src/modules/skill-version/skill-version.service.ts` | 一步发布、来源冻结、安全重验、映射隔离、并发和幂等、审计和奖励 |
| 能力列表 | `backend/src/modules/admin/admin.service.ts` | 当前平台版本摘要、禁止 Skill 通用审核绕过 |
| 执行与下载 | `backend/src/modules/capability/capability.service.ts`、`backend/src/modules/digital-employee/digital-employee.service.ts`、`backend/src/modules/capability-contribution/capability-contribution.service.ts` | 同步按发布时间选择当前平台版本 |
| 发布详情 | `web/src/app/(platform)/admin/skills/[versionId]/page.tsx` | 当前平台基线、正文差异、一次确认、失败保留错误、发布成功跳转 |
| 技能监控 | `web/src/app/(platform)/admin/skills/page.tsx`、`monitor.ts`、`use-skill-monitor.ts` | 发布状态文案、能力上下文、发布资格、查询缓存刷新 |
| 能力管理 | `web/src/app/(platform)/admin/capabilities/page.tsx`、`web/src/features/admin/admin-api.ts`、`use-admin.ts` | 当前平台版本列、未发布/非技能占位、平台历史链接 |

历史工作副本资格额外处理：旧 revision 已发布不阻止新 revision 发布；只将更新时间匹配的快照视为当前内容的已发布记录。缺少 revision 的旧已发布关系无法可靠区分，保守阻止误重复发布。
