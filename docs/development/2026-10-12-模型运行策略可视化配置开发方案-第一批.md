# 模型运行策略可视化配置开发方案：第一批

日期：2026-10-12。状态：待实施。本文件是开发与验收要求，不代表功能已实现或已上线。

## 1. 目标与边界

在平台运营后台现有「设置中心」增加「模型运行策略」，使管理员能够配置模型超时、调用频率、并发及输出与周期预算，并确保保存结果真正被执行链路读取。

本批包含：

- 客户端网关、Web 对话、任务规划的模型请求超时。
- 企业成员及企业聚合的模型业务请求频率、并发限制。
- 单次模型输出上限、默认输出数量、企业每分钟保守资源预留预算。
- 已有无消费配置的兼容处理；配置校验、版本、审计、恢复及页面状态。

本批不包含：

- 上传、知识库、工具循环步数、可配置重试策略，均留在第二批。
- 实际 Token 的日/月额度、人民币资金预占、钱包扣费重构。保守预留预算不能替代这些功能。
- 每企业单独配置套餐、按模型定制超时、多级配置继承。第一版为平台统一策略，按成员/企业分别计数。
- 代理、数据库、Redis、失败认证及通用 REST 安全参数的运营修改入口。
- 模型或工具任务的自动重放，不修改监控接口 403 的权限规则，不更改客户端模型完成标志协议。

所有调用仍经 sub2api，不新建独立 Gateway，不接模型厂商直连。

## 3. 配置契约

### 3.1 通用约定

- 数据库存储沿用字符串值；共享 Zod schema 负责转换为有类型的策略对象，前后端复用校验。
- 已存在的环境变量名称和毫秒单位保留，后台显示秒或分钟；界面以整数秒输入，保存时精确乘 1000。
- 新增默认值必须写入 `defaultValue`，不得只写 `placeholder`。
- 优先级：数据库覆盖 > 环境变量 > 代码默认。空值表示取消数据库覆盖，不表示无限制。
- 除企业周期预留预算允许 0 关闭外，超时、频率、并发、输出参数都必须是正整数。
- 下表的“现有”是代码默认，不是线上实际值；“建议新增”是实现目标，不自动覆盖既有环境或数据库值。
- 不合法环境值不得静默变为无限制；生成策略失败时阻止新调用并记录配置错误，后台展示具体字段，不自动回退忽略坏配置。

### 3.2 超时

| 配置键 | 后台名称 | 默认 | 校验范围 | 计时口径 |
| --- | --- | --- | --- | --- |
| `GATEWAY_STREAM_HEADER_TIMEOUT_MS` | 客户端：等待响应头 | 120 秒，现有 | 1–120 秒 | 开始上游调用至响应头返回，不是等到第一个文字 Token |
| `GATEWAY_STREAM_IDLE_TIMEOUT_MS` | 客户端：流连续空闲 | 120 秒，现有 | 1–120 秒 | 等待上游 read 时无非空字节的持续时长；背压暂停不计 idle |
| `GATEWAY_STREAM_TOTAL_TIMEOUT_MS` | 客户端：流总时长 | 600 秒，现有 | 1–600 秒 | 从调用开始至响应读取完成；背压不暂停总预算 |
| `GATEWAY_NON_STREAM_TIMEOUT_MS` | 客户端：非流式总时长 | 120 秒，并行实现 | 1–120 秒 | 包括等待响应头及完整响应体读取 |
| `SUB2API_STREAM_IDLE_TIMEOUT_MS` | Web：每轮模型流空闲 | 45 秒，现有 | 1–120 秒 | 每轮 AI SDK 流等待；有效事件按现有协议重置，不按浏览器心跳重置 |
| `WEB_MODEL_TOTAL_TIMEOUT_MS` | Web：本次模型处理总时长 | 600 秒，建议新增 | 1–600 秒 | 通过准入并取得会话锁后，至本轮对话模型和工具循环完成，包含 RAG/附件准备及循环内等待 |
| `PLANNER_REQUEST_TIMEOUT_MS` | 任务规划：模型请求总时长 | 120 秒，建议新增 | 1–120 秒 | 规划上游 fetch 至完整 body 读取，包括错误 body |

跨字段校验：客户端 total 不小于 header、idle；Web total 不小于 Web idle。计时器必须支持客户端取消，完成、取消和异常路径都清理 timer/reader/监听器。

120 秒分段、600 秒总时长作为第一版运营硬边界，沿用用户此前确认的保护水平；提高边界需要工程修改、容量与代理验证，不在后台开放无限输入。若现有部署配置已超过边界，先报告冲突并人工调整，不静默截断或覆盖。

Web 总预算是新增保护，不能错误地每个工具步骤重新获得 10 分钟。预算耗尽后取消模型、不再派发工具、不再写成功结束；不支持取消的工具可能仍运行，其实际执行结果必须保留，不能声称已撤销。

### 3.3 频率与并发

| 配置键 | 默认 | 范围 | 适用范围 |
| --- | --- | --- | --- |
| `GATEWAY_MODEL_RATE_LIMIT` | 60，现有 | 1–10000 次 | 保留客户端企业+成员+订阅组合频率 |
| `GATEWAY_MODEL_RATE_WINDOW_MS` | 60 秒，现有 | 1–60 秒 | 上项的固定时间窗口 |
| `GATEWAY_MEMBER_RPM` | 120，并行实现 | 1–10000 次/分钟 | 成员的客户端、Web、规划业务请求合计 |
| `GATEWAY_ENTERPRISE_RPM` | 600，并行实现 | 1–100000 次/分钟 | 企业的客户端、Web、规划业务请求合计 |
| `GATEWAY_MEMBER_CONCURRENCY` | 4，并行实现 | 1–32 个 | 同一成员活跃业务请求合计 |
| `GATEWAY_ENTERPRISE_CONCURRENCY` | 32，并行实现 | 1–256 个 | 同一企业活跃业务请求合计 |

以上数值范围为第一版建议边界，正式启用前需用现有部署资源验证；不是容量保证。部署允许上限低于表格时，以部署边界为准，并返回明确校验错误。

语义要求：

1. 成员键包含 enterpriseId 和 memberId，身份只能来自服务端已校验上下文；不信任请求体传入的企业、成员或订阅。
2. 聚合 RPM 一次业务请求消耗一次：一次客户端 completion、一次 Web 发消息、一次规划 preview。Web 多轮模型调用及现有 SDK 内部重试不重复计算业务 RPM；页面标为“业务请求次数”，不宣称等于上游 HTTP 请求次数。
3. 聚合并发占位覆盖完整业务执行，Web 工具循环不能每步释放重取。终止、异常、客户端断开均释放；拒绝不调用上游、不占永久租约。
4. 同一 Web 会话互斥仍由会话锁保证；企业并发 32 不代表同一会话能同时处理 32 条消息。
5. 企业并发不得小于成员并发，企业 RPM 不得小于成员 RPM。订阅组合限流与聚合限流是同时成立的多层防护，不按数值大小推测哪个必先命中。
6. 已有客户端组合 RPM 保持独立，禁止再叠加重复的成员/企业实现。新聚合计数客户端、Web、规划使用相同 Redis key 空间，而非各链路各有一份额度。

### 3.4 输出与周期预算

| 配置键 | 默认 | 范围 | 语义 |
| --- | --- | --- | --- |
| `GATEWAY_DEFAULT_MAX_TOKENS` | 4096，并行实现 | 1–1048576 | 客户端未传 max_tokens 时的默认输出数量 |
| `WEB_DEFAULT_MAX_OUTPUT_TOKENS` | 4096，建议新增 | 1–1048576 | Web 每轮模型调用的默认输出数量 |
| `PLANNER_MAX_OUTPUT_TOKENS` | 4000，沿用硬编码 | 1–1048576 | 规划请求最大输出数量 |
| `MODEL_MAX_OUTPUT_TOKENS` | 32768，建议新增、启用前评估兼容 | 1–1048576 | 平台统一单次输出上限，与具体模型能力上限取更小值 |
| `GATEWAY_ENTERPRISE_TOKEN_BUDGET` | 0，并行实现 | 0–1000000000 | 企业每分钟保守资源预留预算；0 关闭，不是实耗或计费 Token |

输出规则：

- 有效输出上限 = min(平台上限, 已知的模型 maxOutputTokens)。模型未提供能力上限时仍受平台上限限制；平台模型能力数据为非法值时拒绝调用。
- 客户端显式 max_tokens 超限返回 400，不静默修改；缺省时取默认与有效上限的较小值。Web 和规划作为平台内部调用使用校验后的数量。
- 默认输出、Web 默认、规划输出都不得大于平台上限。每轮输出上限不是整场对话累计 Token 限制。
- 32768 是新增限制，不能直接套用给已有大输出业务；启用前评估现有模型和请求，必要时在允许范围内调整首次值。
- `contextLength` 是上下文能力，不等于 maxOutputTokens。没有适配模型 tokenizer 的情况下，不提供“精确上下文 Token 上限”输入框；现有请求字节硬上限继续有效。

周期预算规则：

- 后台名称使用“企业每分钟资源预留预算（保守估算）”，不得显示为实际 Token 额度、人民币余额或日/月配额。
- 每次真正发起模型调用前按规范化完整请求的 UTF-8 字节数加最大输出数量预留，包含系统提示、工具 schema 和历史；这是一种资源保护估算，不保证覆盖所有多模态 Token，也不用于计费。
- 客户端通常一次预留；Web 每轮模型请求分别预留；规划一次预留。预留拒绝时不发送该轮上游请求，并保留之前已执行步骤结果。
- 同一业务请求的 RPM/并发与每轮资源预留拆成两个入口，禁止每轮都重复 acquire 整体并发；现有 SDK 隐式重试不额外重复预留，本指标不表示逐次网络尝试的累计成本。
- 估算预留在窗口到期前不按实际 usage 退还；失败请求也不返还已获准预留，防止反复失败绕过保护。计费仍使用原有实际 usage 链路。
- 所有链路共用企业一分钟桶。关闭预算时不声称仍在完整统计；从 0 启用时从已有可用桶或新窗口开始保护，不回算之前未记录的调用。

## 4. 生效、一致性及存储

### 4.1 请求快照

新增薄层 `ModelRuntimePolicyService`，放在现有 `setting` 模块，负责批量读取和验证，不另建配置平台。

每个新业务请求在身份和权限校验后、业务准入前，使用一次数据库查询读取本批全部设置及策略版本；空值回退固定部署环境和默认值，生成不可变 `ModelRuntimePolicySnapshot`。所有步骤复用快照，禁止循环中逐项重新读配置。

快照至少包含 version、各链路 timeouts、rates、concurrency、output、budget。多实例第一版不做长期本地缓存，也不依赖 Redis pub/sub 保证正确性；新请求从同一主数据库读取，不能走有延迟的只读副本。数据库读取失败返回 503，不绕过保护。

各实例环境回退值必须一致；部署预检比较本批非敏感策略的环境指纹，发现不同则禁止开放写入口。数据库版本相同不代表不同部署环境会生成相同策略，不能用版本号掩盖环境差异。

保存提交后开始读取快照的请求使用新版本；已读取快照的请求继续旧版本。页面不得承诺所有在途请求同时切换。正常 SDK 重试仍沿用本次快照与剩余总预算。

### 4.2 版本与原子保存

策略字段值继续存 `SystemSetting`，不新增一份平行 JSON 配置。增加内部保留键 `MODEL_RUNTIME_POLICY_REVISION`，不出现在通用可编辑列表，初始为 0，首次初始化需幂等。

一次保存事务执行：

1. 用 expectedVersion 对 revision 行做条件更新；不匹配返回 409，禁止覆盖其他管理员更新。
2. 读取当前字段及未覆盖的环境值，把本次更新合并后做全部字段和跨字段校验。
3. 所有字段一次性 upsert/delete，空值只删除数据库覆盖；任何失败整批回滚。
4. 写入同事务的 `AuditLog`，记录本批全部字段的 before/after 覆盖快照及有效值、来源、版本、actorId、reason 和专用 action `MODEL_RUNTIME_POLICY_UPDATED`。只含白名单非敏感策略，不复制其他系统设置。
5. 提交后返回新版本及有效策略；验证失败、审计写入失败都不能留下部分配置。

使用 Prisma 事务和条件更新，不手写历史 migration。本方案复用现有 SystemSetting/AuditLog，不必增加业务表；如果实现发现必须变更 schema，使用项目迁移工具生成并独立说明。

通用 `PUT /settings` 禁止直接修改本批策略键和内部 revision，返回明确 400 并引导新接口；旧页面需随发布切换，不能留下绕过版本和关系校验的写入通道。

### 4.3 Redis 窗口和租约

- 修改限额不清 Redis 桶，不把配置版本拼入桶键，防止每次保存都获得新额度。
- 频率窗口已开始时维持其原始到期时间和窗口元数据；新窗口才采用新窗口长度。限额使用新请求快照中的值，响应 resetAt/retryAfter 必须来自实际 TTL。
- 当前桶由老版本创建且缺窗口元数据时，保留原 TTL 到期，不提前清桶；兼容转换不得延长拒绝请求的封锁时间。
- 并发降低不终止在途请求；直到占用数低于新阈值才准入新请求。
- 租约使用固定部署硬边界而非可降低的运营值：至少覆盖本批所有请求最大总时长 600 秒及 120 秒清理余量；租约崩溃过期不是正常释放的替代品。
- Redis 失败返回结构化 503；不退化为每进程计数或直接放行。计数、比较和过期处理沿用原子 Lua。

## 5. 后端接口

在现有 `SettingController` 增加专用子路由，继续使用 JwtAuthGuard、RolesGuard、ADMIN。路径省略项目统一 `/api` 前缀。

| 接口 | 用途 | 关键契约 |
| --- | --- | --- |
| `GET /settings/model-runtime-policy` | 获取当前策略和字段元数据 | version、fields、effectivePolicy、warnings；字段含 value/effectiveValue/source/unit/min/max/editable/applyMode |
| `PUT /settings/model-runtime-policy` | 保存本次修改 | `{ expectedVersion, updates: Record<PolicyKey, string>, reason }`；返回新策略；空字符串表示恢复环境/默认 |
| `GET /settings/model-runtime-policy/history` | 查看本策略变更 | cursor 分页，默认 20，最大 100；仅返回专用 action 的脱敏审计，不暴露无关日志 |
| `POST /settings/model-runtime-policy/restore` | 恢复某次变更前或后的覆盖状态 | `{ expectedVersion, historyId, side: 'before' | 'after', reason }`；重新校验并产生新版本，不倒退版本号 |

`reason` 去除两端空白后 1–500 字符。共享 Zod DTO 限制允许的 key、记录数量及字符串长度，禁止 unknown key、secret key 和内部 revision。controller 仅处理 HTTP、DTO、鉴权与 Swagger，业务进入 service。

400：字段或跨字段非法；401/403：无身份或非平台管理员；409：版本冲突；503：配置/准入依赖不可用。成功响应按项目既有响应封装，不改变其他设置接口返回结构。

恢复保存当时的数据库覆盖状态：原先未覆盖的字段恢复为未覆盖，届时采用当前部署环境；返回完整差异并说明这不保证复现历史环境的有效值。当前硬边界不再允许的历史配置不可强行恢复。

模型业务拒绝使用稳定 code/source/rule/dimension/limit/count/resetAt/policyVersion；429 附 Retry-After，不能伪装成上游 429。超时单独标识 header、idle、total、non-stream、planner 阶段；请求已开始 SSE 后沿现有错误事件或异常断流机制通知，不伪造成功结束帧。

## 6. 执行链路改造

### 6.1 客户端网关

认证成功后，由现有组合限流 guard 获取一次快照并放入类型化请求上下文，后续 service 复用。该限流保持在原有授权与余额业务逻辑前的位置；聚合准入和资源预留仍在权限、模型策略与余额校验之后，避免为了动态配置改变原防护顺序。禁止 guard 和 service 分别读出不同版本。

规范化输出参数后，在 sub2api 前完成聚合准入及资源预留。生命周期接收已校验 timeout 数值，不再自行读取环境变量。finally 统一释放；流缺完成标志、客户端取消和结算失败沿网关加固约定处理，不改计费结论。

### 6.2 Web 对话

从服务端 enterpriseContext 获取企业和成员，不能从浏览器任意指定。对话权限/余额通过后取得策略快照；取得会话锁后、用户消息持久化前进行聚合准入，拒绝不留下待回复的用户消息。

取锁成功而准入失败时必须释放会话锁；会话锁等待不占业务并发。准入完成后启动 Web 总预算；每轮模型按快照设置输出上限、idle 和剩余总时长，并在发起上游前做资源预留。

会话锁增加基于 owner value 的 CAS 续租与释放，续租间隔由工程常量控制，不放入运营表单。续租失败立即停止后续模型/工具派发并取消可取消调用，不能等旧锁过期后仍继续写会话。以 finally 清理续租任务；本项是开放长请求的正确性前置，不是第二批运营功能。

### 6.3 任务规划及其他调用入口

规划使用相同企业/成员维度获得业务准入和预算；fetch 和 body 读取共用同一 AbortController 总预算，并传递客户端取消。不新增自动重试，默认输出仍为 4000。

实施时搜索所有实际生产模型调用，至少核对 `digital-employee.runner.ts` 的调用方。会执行上游请求的入口不得绕过统一输出上限和准入；未使用的 runner 不得仅因文件存在宣称已接入。模型列表/健康探测不纳入业务 RPM，本批不重做它们的超时。

## 7. 运营页面

入口：现有设置中心，新增「模型运行策略」分类，按以下顺序使用无嵌套卡片的分组表单：

1. 客户端超时。
2. Web 与任务规划超时。
3. 调用频率与并发。
4. 输出数量与企业预留预算。

页面要求：

- 数字输入显示单位及范围；0 关闭预算使用独立开关，关闭时保留尚未提交的输入但保存为 0，不把所有数字 0 都解释成不限。
- 展示当前有效值、来源、版本；来源为环境/默认时允许添加数据库覆盖。恢复环境/默认与历史恢复是不同操作。
- 保存前显示本次变更的前后值、取消覆盖项及影响链路，管理员填写原因；版本冲突保留草稿并重新加载，禁止静默覆盖。
- 成功提示仅说“已保存，新请求使用版本 N；运行中请求保持原策略”。窗口变更补充“当前计数窗口到期后采用新窗口”，不能笼统宣称所有调用即时切换。
- 若部署代理上限未知，只显示“需部署核验”，不能凭后端值宣称代理支持。代理配置只读，不提供数据库保存入口。
- 普通企业管理员和用户看不到写入口，直接请求也返回 403。第一版复用 ADMIN，不扩大现有角色体系。
- 复用 TanStack Query hooks、共享 DTO、现有输入与图标；处理 loading/error/dirty/saving/conflict/history-empty 状态；不做独立配置平台和营销页面。

## 8. 旧配置与上线兼容

停用以下旧编辑项，历史数据库值保留可审查，不删除、不自动扩散映射：

| 旧键 | 处理 |
| --- | --- |
| `MODEL_RESPONSE_TIMEOUT` | 隐藏旧编辑器或显示只读“未接入”；不能自动套给所有 header/idle/total |
| `MAX_CONCURRENT_SESSIONS` | 不自动映射到新企业模型并发，因为旧会话语义与活跃业务请求不同 |
| `MAX_TOKENS_PER_CONVERSATION` | 不自动映射成单轮输出上限或周期预留预算 |

管理员读取旧值后，通过新策略显式保存；历史审计不能把它们标为之前已生效。`BasicSettings.tsx` 与当前 SettingsCenter 的所有入口都要检查，旧通用写接口不能继续写这些停用键。

部署前进行一次只读预检：当前有效环境、三个旧覆盖是否存在、模型输出能力、新增默认兼容性、入口代理超时语义、发布排空和容器停止宽限。不得在报告或日志输出密钥。

前端/后端新能力上线期间先禁用新策略写入口；所有后端实例切换并确认消费快照后才开放。混用旧实例和新实例时不能承诺配置全局生效，不靠新前端隐藏按钮替代服务端发布开关。

代理 timeout 是 idle 还是整请求截止必须实测：若是总截止，它需要覆盖后端相应总预算加余量；若是 idle，则核对分段等待及缓冲。现有 Next 默认 180 秒不能直接证明 600 秒模型流已端到端可用。

配置回滚使用历史恢复产生新版本；代码回滚到不支持动态策略的版本时，先禁用写入，恢复兼容部署参数并说明数据库覆盖将不再被旧代码消费。不得删除原用量日志或待结算数据。

## 10. 测试与验收

| 类别 | 必须覆盖的场景 |
| --- | --- |
| 配置优先级 | DB/env/default、空值取消覆盖、placeholder 不是默认、不合法环境值拒绝 |
| 原子保存 | 一项非法整批不写；两管理员同版本仅一个成功；审计失败回滚；通用 PUT/未知 key 无法绕过 |
| 恢复 | before/after 均可恢复覆盖状态；恢复产生新版本；环境已变明确提示；当前硬边界不允许时拒绝 |
| 动态生效 | 两实例读取同一版本；保存后新请求用新值；老流/工具循环保持原快照；数据库故障不放行 |
| 超时 | header、idle、total、非流式 body、planner body 分别触发；有数据重置 idle；背压不误触 idle；总预算不重置 |
| Web 生命周期 | RAG/附件/工具循环计入总预算；工具不支持取消时不标撤销；客户端断开；重复结束不重复释放 |
| 会话锁 | 模型执行超 60 秒仍互斥；失去 owner/Redis 故障停止派发；续租和 finally 清理；异常不删别人锁 |
| 限流 | 订阅组合限制保留；成员/企业跨客户端、Web、规划共桶；拒绝不延长 TTL；变更窗口不清桶；429 规则与 Retry-After 正确 |
| 并发 | 多实例竞争不超额；企业/成员双阈值原子检查；降低阈值不杀在途；取消/失败释放；崩溃租约过期；Redis 故障返回 503 |
| 输出预算 | 缺省、显式超限、模型能力更小、能力为空/非法；Web 每轮/规划应用上限；不把请求字节当精确上下文 Token |
| 周期预算 | 默认关闭、开启、关闭后再启用；跨链路累计；Web 第二轮被拒绝保留第一轮；失败不退预留；SDK 重试口径明确；不改实际 usage 计费 |
| UI/权限 | 未登录/普通用户/企业管理员拒绝；保存中防重复；409 保草稿；来源与单位正确；恢复确认；桌面和移动截图无重叠 |
| 协议回归 | OpenAI-compatible completion/SSE 完成标志保留；监控上报失败不因本功能中止模型；已有结算和取消测试不回归 |

建议验证命令，以实际新增 spec 路径补全：

## 11. 完成与风险

交付时必须能回答：某个请求使用哪个策略版本、哪项规则拒绝、何时可重试、保存后哪些请求受影响。日志关联 requestId/executionId、链路和 policyVersion，不写原始提示词、完整附件或凭证。

满足以下条件才算第一批完成：所有开放字段有执行读取；旧死配置不再可编辑；三条链路策略与权限正确；配置事务、审计、恢复通过；跨实例及在途请求验证通过；线上启用前完成代理与发布排空预检。

剩余边界必须明确：保守预留预算不是准确 Token/金额额度；业务 RPM 不等于上游 RPM；不支持取消的工具不能保证物理停止；本批不解决上游租户自身限流，也不据此归因历史 429 或监控 403。
