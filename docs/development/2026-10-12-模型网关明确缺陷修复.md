# 模型网关明确缺陷修复

日期：2026-10-12

## 范围

针对客户端检查报告和本地复现修复明确缺陷，不调整 RPM、并发、输出 token 和超时默认值，不修改其他正在开发的媒体模块，不调用生产模型。

## 修改与契约

1. HTTP JSON 解析：模型执行接口独立使用 `GATEWAY_HTTP_JSON_LIMIT`，默认 `4mb`；其他 REST 保持 `REQUEST_JSON_LIMIT` 默认 `2mb`。仅识别 POST 模型路由，兼容大小写、末尾斜线和 query。已知 Express `entity.too.large` 映射为 413 / `REQUEST_BODY_TOO_LARGE`，保留 requestId，不暴露原请求或堆栈。
2. 协议字段：请求及嵌套消息、工具、工具调用、选项改为严格校验。未声明字段明确返回 400 / `INVALID_PARAMETER`，错误路径指向具体字段。JSON Schema 参数仍允许已有扩展关键字。当前不支持的 `response_format`、`max_completion_tokens`、`top_p`、`stop` 不再静默忽略，本轮不新增未经上游验证的支持。
3. 业务错误：保持既有状态码和可读消息，补齐订阅、授权、余额、模型策略、输出预算及序列化上限的稳定 code、platform source 和 param。
4. 流诊断：补齐响应头、首数据块、最后数据时间和转发字节指标，成功和异常均保留请求关联。不记录消息内容，不改变 SSE 原始字节、usage checkpoint、取消或结算流程。

HTTP 上限计原始 JSON，`GATEWAY_MAX_REQUEST_BYTES` 计默认字段注入后的规范化请求，均默认 4 MiB。两者字节数可能不同，超限分别返回 `REQUEST_BODY_TOO_LARGE` 和 `MODEL_REQUEST_TOO_LARGE`；不静默裁剪或删除历史。部署模板透传新 HTTP 配置，更新环境需重建容器。

### 错误码

以下错误使用 `error.source: platform`，保留关联的 `requestId`。客户端应依据 `code` 分流，而不是匹配中文消息或将所有失败作为 429 重试。

| HTTP | code | 含义 / param |
| --- | --- | --- |
| 400 | `INVALID_PARAMETER` | 未声明字段或参数校验失败；具体字段路径 |
| 413 | `REQUEST_BODY_TOO_LARGE` | HTTP 解析阶段超限；null |
| 413 | `MODEL_REQUEST_TOO_LARGE` | 规范化模型请求序列化超限；null |
| 403 | `SUBSCRIPTION_INACTIVE` | 订阅不存在、停用或不属于企业；null |
| 403 | `SUBSCRIPTION_ACCESS_DENIED` | 订阅不属于企业或缺少有效授权；null |
| 403 | `MEMBER_ACCESS_DENIED` | 成员与当前用户、企业不匹配；null |
| 403 | `INSUFFICIENT_BALANCE` | 算力余额检查拒绝；null |
| 403 | `MODEL_NOT_ALLOWED` | 模型不在成员允许范围；model |
| 400 | `MODEL_UNAVAILABLE` | 模型未启用或已下架；model |
| 400 | `MODEL_POLICY_DEFAULT_INVALID` | 强制默认模型不在有效允许范围；model |
| 400 | `MODEL_FEATURE_UNSUPPORTED` | 已明确不支持的能力；stream / tools / tool_choice / messages |
| 400 | `MODEL_OUTPUT_LIMIT_INVALID` | 模型输出上限元数据无效；model |
| 400 | `OUTPUT_BUDGET_EXCEEDED` | 输出预算无效或超过上限；max_tokens |
| 400 | `REQUEST_SERIALIZATION_FAILED` | 无法序列化请求；null |
| 400 / 500 | `GATEWAY_CONFIG_INVALID` | API Key 缺失保持既有 400；数值策略配置无效保持 500；null |

未知数据库或配置读取异常继续向外抛出，由全局过滤器返回安全错误，不伪装成业务拒绝。本轮未覆盖所有认证、网络和上游非 429 错误的 source，不能宣称整个网关已完成统一错误分类。

### 流指标

| 字段 | 定义 |
| --- | --- |
| `headerLatencyMs` | 发起上游转发到收到响应头的毫秒数，采样在执行日志写入之前 |
| `firstByteLatencyMs` | 发起上游转发到读取首个非空数据块的毫秒数；没有数据为 null |
| `lastDataAt` | 最后读取非空上游数据块的 Unix 毫秒时间戳；没有数据为 null |
| `bytesForwarded` | usage checkpoint 成功后交给下游管道的原始字节数，不是客户端确认收到的字节数 |

响应头事件、正常结束及异常中断日志携带这些指标。首数据块时间包含平台读取前的等待，不能当作模型服务内部生成耗时；本轮也未增加转发尚未建立时的完整阶段追踪。日志不包含消息、工具参数或认证信息。

### 兼容性与发布

- 既有客户端若传入从前被静默丢弃的字段，现在会收到明确的 400，需要删除字段或后续完成经验证的能力支持；不得自动删参数后重发。
- 仅扩大模型 POST 接口的 HTTP JSON 默认上限，普通 REST 上限仍为 2 MiB。RPM、并发、输出 token、响应头/空闲/总时长默认值不变。
- 单容器、蓝绿和开发部署模板均透传 `GATEWAY_HTTP_JSON_LIMIT`。配置变更需重建容器，并单独核对实际入口代理限制。
- 无数据库迁移、新增依赖或上游自动重试。本次 Git 提交仅包含网关修复，不包含并行媒体改动；未推送或部署，回滚可恢复本次代码和部署配置。

## 验收

- 真实 Nest/Express 隔离 HTTP 测试：2 MiB 以上的模型 body 可解析，普通 REST 上限不变；HTTP 字节边界明确；超限 413 且无敏感输入。
- DTO 和网关 HTTP 测试：未知顶层/嵌套字段拒绝并准确定位；不进入计费执行或上游；现有工具 JSON Schema 原样保留。
- service/policy 测试：常见业务失败保留状态、message，并提供不同的稳定错误码。
- controller 测试：多块流、成功、异常和无数据场景的阶段指标正确，原始输出不变。
- 运行相关网关测试、后端/共享类型检查和构建、Compose 合同检查及 diff 检查。

## 不包含

真实模型的 `tools + stream_options` 支持需要针对当前 sub2api 版本验证，本轮不猜测兼容策略、不自动重试。上下文 tokenizer、多模态支持、共享上游全局容量、资金预占和业务执行幂等不在本轮。公网回归和生产发布仍需单独执行，不能把本地测试等同于线上验收。
