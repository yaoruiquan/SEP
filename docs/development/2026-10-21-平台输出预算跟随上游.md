# 平台输出预算跟随上游

## 目标与范围

客户端省略输出预算时，SEP 网关不再补入 4096。Web 对话、员工执行、任务规划、交付汇总和能力分析采用相同语义。所有请求仍经 sub2api。

## 配置约定

- `GATEWAY_DEFAULT_MAX_TOKENS=0`：客户端未指定时跟随上游。
- `WEB_DEFAULT_MAX_OUTPUT_TOKENS=0`：Web 对话和员工执行跟随上游。
- `PLANNER_MAX_OUTPUT_TOKENS=0`：规划、交付汇总和能力分析跟随上游，移除局部 3000/4000 截断。
- `MODEL_MAX_OUTPUT_TOKENS=0`：不设置 SEP 平台输出硬上限。
- 四个配置的代码默认值和部署模板回退值均为 0；正整数继续表示显式预算或硬上限。
- 请求参数 `max_tokens` 仍必须为正整数，不能把配置哨兵值 0 发给模型。省略参数时不发送 `max_tokens` 或 `max_completion_tokens`，AI SDK 的 `maxOutputTokens` 选项也省略。
- 平台硬上限为正整数时，省略预算的请求使用该上限（与已登记模型能力取较小值），保证显式配置的上限有效。
- 平台硬上限为 0、默认预算为 0 时，即使登记了模型能力，省略参数仍跟随上游；显式预算仍校验已知模型能力。未知能力不伪装为无限能力。

## 资源预留

RPM、并发、超时、余额校验和现有用量计费保留。企业每分钟保守资源预算关闭时，允许未知输出预算；开启时，必须有确定的输出预算，否则调用上游前返回 `MODEL_RESERVATION_OUTPUT_UNKNOWN`，不能用 0 预留或绕过限制。管理员可配置有限输出预算/平台上限后使用资源预留。

## 验证

回归覆盖：省略字段、显式大预算透传、已知模型能力、正整数策略回退、0 的配置校验与保存、未知预算的预留错误，以及各业务入口的实际请求构造。使用本地确定性响应验证 SDK 发出的请求，不发起付费调用。

本次本地验证结果：

- 后端网关及关联业务回归：23 个测试套件通过、656 项通过；依赖专用 Redis/数据库的 3 个套件、43 项跳过。
- 管理端表单与设置组件回归：2 个文件、27 项通过。
- 后端、Web TypeScript 检查通过；后端生产构建通过。
- 真实 AI SDK 本地 smoke：流式、非流式均不自动补入预算，显式 65536 保持原值。
- 部署模板回归与 `git diff --check` 通过。

以上不包含生产供应商实测、生产配置变更或部署，也未进行浏览器视觉验证。

## 发布与边界

本次只改 SEP。sub2api 和真实供应商可能有自己的默认输出长度；SEP 省略参数不能证明最终输出超过 4096，不能把既有仅思考问题宣称为根因已解决。

取消 SEP 默认预算后，单次输出量、耗时及费用可能增加。既有超时和余额校验继续生效；省略预算也不保证供应商一定使用最大输出能力。

数据库覆盖优先于环境变量。升级时先发布后端支持 0，再更新管理端；在管理端将四项输出配置显式设为 0，或移除数据库覆盖并将部署环境四项设为 0。已有 `.env` 中的 4096/32768 不会因模板默认值变化自动消失。策略写入环境指纹需按现有发布流程重新核对。不要在旧后端仍服务时保存 0。

回滚前恢复旧版本接受的正整数配置，再回滚应用。无需改数据库 schema 或清理历史审计。
