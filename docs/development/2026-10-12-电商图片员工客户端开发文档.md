## 1. 客户端要交付什么

用户选择已订阅的商品视觉员工，提供商品图和制作要求；员工依据电商 Skill 创作，通过受控图片工具生成；客户端持续跟踪，把图片可靠保存到本地，支持预览、导出和有授权的重做。

**客户端负责执行到底。** SEP 上架员工/Skill、提供配置/授权/请求回执和模型通道，不替客户端运行任务。关闭面板或切换任务不停止主进程跟踪；彻底退出、关机或休眠停止跟踪，上游可能继续收费。重启后查原任务，不自动再次生成。

首期交付：

- 批准 runtime 消费、员工提示词注入、合法 Skill 安装与任务版本快照。
- 图片能力读取、参考素材导入、生成/编辑工具和费用审批。
- 本地持久任务、有限退避查询、提交不明保护、断线/重启恢复。
- 成品安全下载、图片预览、导出、部分成功与文件缺失提示。
- 与现有任务、认证、监控和工具策略兼容。

首期不交付视频生成/播放入口、多镜头剪辑、云端素材库、自动上架或像素级商品保真承诺。不因类型里预留 video 就在 UI 或工具集中启用视频。

## 4. runtime 与 Skill 准备

### 4.1 入队前准备，不阻塞全局调度

1. 获取有效会话和订阅目录，读取该订阅 runtime；只在入队准备阶段做网络 IO。
2. 校验订阅、支持的 manifest/媒体协议、企业/成员 scope 和允许的会话模型。
3. 校验宿主受控工具及实际可用 profile/操作；不新增平台批准的媒体依赖清单。图片模型不加入聊天 modelId 选择，不把 upstreamModelId 当聊天模型。
4. 准备批准 Skill，冻结提示词、实际 SkillVersion/hash、profile/configVersion 和工具协议。
5. 将快照与队列条目关联；调度器读取已准备结果，不在 pump/resolve 中再拉取 runtime。

授权不通过或必要资源缺失时明确失败；不能用旧账户缓存或静默回退到缺 Skill 的员工。网络结果返回时再次核对 scope/会话代次，登出后的结果不得写进新账户。

当前清单的 `templateVersion` 不意味着全部提示词已不可变；客户端保存实际快照，而不是只存一个版本号。新运行可以使用新配置，旧媒体 job 保留原回执与版本；订阅/token 权限仍由 SEP 逐次校验，快照不是永久授权。

### 4.2 批准 Skill 下载合同（SEP 第二批已实现）

客户端请求 runtime 时可独立协商：`GET /client/subscriptions/:subscriptionId/runtime?skillArtifactProtocolVersion=1`，不依赖 `mediaProtocolVersion`。成功时读取每个 Skill 的 `artifact` descriptor；未传或不支持时不得猜测下载路径。接口使用普通 access token，下载地址是 descriptor 的 `downloadPath`，由 HTTP port 加部署前缀，不要拼接上游或 storage 地址。

下载：`GET /client/subscriptions/:subscriptionId/skills/:capabilityId/versions/:versionId/artifact`。200 是原始 `SKILL.md` 或 ZIP 字节，不是 JSON；校验 `X-SHA256`、`Content-Length`、`artifactSha256`、`byteLength`，并校验 `approvedContentSha256` 对应 runtime 的批准正文。客户端版本缓存必须绑定企业/成员 scope、subscription、capability、versionId 与 hash，不能跨账户复用。

字段和 BLOCKED reason 以 `backend/src/shared/client-skill-artifact.dto.ts` 与 `backend/src/shared/fixtures/skill-artifact-v1.json` 为准。`AVAILABLE` 仅表示产物可安装；`BLOCKED` 必须停止本次准备。下载每次服务端重新验权，因此 descriptor/本地快照不是永久授权。

正文提交不继承 `parentVersionId` 对应的 ZIP 附件；批准后，自包含正文可生成单文件，仍引用本地资源时会得到 `BLOCKED/PACKAGE_REQUIRED`。审核通过及企业默认切换不保证可安装，历史包正文不一致时会得到 `PACKAGE_CONTENT_MISMATCH`；客户端停止准备并提示管理员修正，不回退旧包。

单文件安装为 `installationDirectory/SKILL.md`。ZIP 安全解包到 staging 后原子移动到不可变版本目录，保留所有附件和嵌套入口，不改写、不覆盖正在运行版本。客户端必须复核 hash、UTF-8/frontmatter、入口路径/目录名、条目数及解压预算；包内 scripts 不自动执行，`allowed-tools` 不是宿主授权。根入口 ZIP 放入 `installationDirectory`，嵌套入口保留整包布局，SDK 使用入口父目录。

安全解包须拒绝本地文件头与中央目录名字节/flags/method 不一致，并按目标文件系统拒绝大小写/Unicode 等价路径碰撞、文件与目录冲突及 staging 文件覆盖。SEP 的 `AVAILABLE` 不替代客户端复核；这部分仍需客户端实际验收。

错误处理：401 刷新认证后重新取 runtime；403/404 停止本次准备；409 `SKILL_ARTIFACT_BLOCKED` 不降级旧包；503 仅有限退避重试。快照保存实际 `content`、`versionId`、`approvedContentSha256`、产物 hash、协议版本与安装目录。新的任务重新取得授权。

### 4.3 单文件闭环优先，完整包按需要实现

首期 Skill 可整理为自包含 `SKILL.md`，保留有效 `name` / `description` frontmatter，不引用缺失的 references/scripts。现有预览正文可能被 SEP 剥掉 frontmatter，不能原样写回后宣称符合规范；用批准元数据恢复并验证，或使用批准原包。

需要完整包时：按 SEP 正式批准下载接口获取，校验 hash、ZIP 路径、软链接、体积和条目数，原子安装到不可变版本目录；运行期间不覆盖。包内脚本/扩展不自动执行，不由模型提供下载 URL。

系统提示词注入必须沿当前 SDK 实际接口与测试验证，不猜 API。Pi 的实际 Skill 路径和 task 快照一致；资源缺失要显式报错。任务历史记录可追溯来源/许可与实际版本。

## 5. 图片工具和审批

| 工具 | 输入/行为 | 安全边界 |
| --- | --- | --- |
| `media_get_capabilities` | 返回 runtime 与当前授权交集 | 不提供 key/上游 URL，不触发生成 |
| `media_generate_image` | profile、operation、localAssetId 列表、创作要求、允许规格 | 宿主创建 requestId，审批后提交；返回本地 jobId，不代表图片已完成 |
| `media_get_job` | 查询当前任务内本地 job，可触发一次受调度的查原回执 | 不新建上游任务，不接受其他 scope 的 ID |
| `media_cancel_job` | 按能力取消上游，或仅停止本地跟踪 | 分开表达，不把本地停止伪装成上游取消/退款 |

工具注册经现有 runtime/SDK 扩展入口完成，service 用端口而不是 SDK 对象。工具集合由 runtime、平台依赖、员工允许范围及本地策略共同决定；planner `disableTools` 模式不得暴露媒体工具，缺能力不回退 bash/curl。

`generate` 与 `edit` 明确区分；编辑不支持时不能悄悄忽略商品图改成纯文生图。四个候选模型由 SEP profile 映射，客户端不硬编码四套请求，不假设名称后缀代表速度、质量或价格。

审批至少展示参考图片、传输提示、profile/规格/张数、报价状态与次数。报价和许可绑定当前输入/规格/hash/有效期；修改后重新审批。Key、计费金额、subscription scope、Skill 版本和 requestId 不由模型输入。

拒绝或审批超时不提交；`full-local + auto-approve` 不能绕过网关预算与报价校验。真实价格未知时显示不可报价，不伪装免费；收费政策由 SEP 决定，客户端不自定单价、汇率或退费规则。

## 6. 本地任务与素材

新增记录遵循现有文件持久化风格，以下是职责划分，不要求照字段清单一次重构整个 Task 类型。

| 记录 | 最少保存 |
| --- | --- |
| 运行快照 | task/run、scope、订阅、实际提示词、Skill 版本/hash、媒体配置版本、协议 |
| LocalMediaJob | jobId、taskId、初始 runId、稳定 clientRequestId、语义请求 hash、receiptId、输入/规格/授权引用、生成状态、跟踪状态、退避时间、错误和时间戳 |
| LocalMediaAsset | localAssetId、父 job/outputId、来源、相对安全路径、MIME、大小、尺寸、hash、版本关联、保存/缺失状态 |

媒体文件位于企业/成员/任务授权目录，scope 来自当前会话，不相信 renderer 提供的企业 ID。模型和 renderer 只用 ID；data 层解析实际路径，不把绝对路径写进跨端合同。

**同一 job 跨 run 恢复时保留原 clientRequestId/receiptId。** 网络重试不是创意重做；修改创意、输入或规格才创建新 job/requestId 并审批。新增运行可以记恢复关联，不覆盖原始审计记录。

按 outputId 去重保存；单张重试不能把成功项全部重生成。文件 manifest 和写入状态必须能在进程重启后恢复，不只存在内存 map 或 React state。

## 7. 提交、等待与恢复

### 7.1 正常流程

```text
批准输入 -> 校验能力/参考图 -> 获取报价并审批
    -> 持久化本地 job 与稳定 requestId
    -> 提交网关 -> 立即保存 receiptId
    -> 按协议查询或接收同步结果
    -> 流式下载 .part -> 校验 -> 原子改名 -> manifest 持久化
    -> 图片预览可用 -> 最终交付
```

收到 `accepted` 不是成品成功。依赖成品的步骤必须等待保存完成；等待期间不维持无意义的 Pi 推理，也不要求模型循环查进度。主进程调度与 task UI 生命周期独立。

### 7.2 必须覆盖的中断窗口

| 中断位置 | 恢复动作 |
| --- | --- |
| 本地已写，尚未发送 | 由持久状态确认未发送后按原 ID 提交；权限/报价失效先重新授权 |
| 已开始发送，未获得响应 | 标记 SUBMISSION_UNKNOWN；按原 requestId 查回执，不自动换 ID 重发 |
| 收到 503 MEDIA_STORAGE_UNAVAILABLE | 数据库读取/插入/最终回写可能失败或结果不明；保留原 ID，仅有限退避查询，不重发生成 |
| receipt 已返回，未成功落盘 | 重启用持久 requestId 找回原回执 |
| SEP 重启后原回执仍为 SUBMITTING | 继续读取原 ID；自占用起两分钟超时在读取时持久转 SUBMISSION_UNKNOWN，不自动补提 |
| 异步任务仍运行 | 重新鉴权后查原任务，遵守退避 |
| 同步无查询，响应丢失 | 明确不可自动恢复；不能伪造轮询或承诺必能找回 |
| 上游完成，下载失败/磁盘满 | SAVE_FAILED，仅重试取得/保存原 output，不再生成 |
| 文件改名后 manifest 未写完 | 校验既有文件并修复记录，不能自动新增生成 |
| 原结果过期 | 仅在网关/上游支持刷新时尝试；否则 RESULT_EXPIRED |

提交前在本地持久化“将发送/可能发送”状态，不能依赖崩溃后内存标志判断未发送；无法证明安全的窗口统一保守处理。查不到回执也不证明上游没有接单。

生成状态、本地保存状态和跟踪状态分离，按共用合同映射。切换页面继续；任务暂停/取消要区分停止创作、停止本地跟踪、上游取消三种含义，不直接复用会话 abort 来宣称上游已取消。

应用退出、断网、休眠只保存/恢复跟踪状态，不承诺上游停止收费。启动后按原 scope 显示可恢复任务；认证恢复后才恢复查询/保存。登出/换企业取消旧网络活动并使异步回调失效，禁止旧响应污染新用户。

删除任务含未完成媒体 job 时，不静默丢弃唯一回执和账务关联；沿现有删除语义确认保留/归档策略，不擅自递归删除仍在使用的资源。该策略需两端实施评审，不把“删除 UI 行”当“上游已取消”。

## 8. 下载、预览和导出

参考图由系统文件选择操作导入，检查 MIME/文件头/体积；复制或安全引用到授权资源后才分配 ID。上传只把必要图像交给 SEP，不让 renderer 传任意路径要求主进程读取。

下载从已鉴权 receipt/output 的 content 接口进行；限定大小、类型、超时和取消，写 `.part` 后校验并原子改名。若适配器允许受控短期 URL，仍按可信域名、重定向和内网约束验证，不接受模型自由网址。

预览经受限 IPC 或 custom protocol 暴露素材句柄，范围限定当前 scope/task；不暴露磁盘根目录、任意 `file://` 或 Node API。解码错误、文件被移动/删除、下载未完成有明确状态；object URL 用完释放。

导出通过系统保存对话框选择目标，由主进程校验并复制，覆盖已有文件遵守系统确认；不能由模型任意指定外部写路径。已经保存/合法导出的本地文件属于本地交付，不承诺通过 SEP 订阅撤销能够远程收回 OS 文件。

## 9. 客户端界面范围

复用现有对话任务详情和成果面板，不另建营销首页或第二套制作应用。

- 输入：商品参考缩略图、用途、不可改变特征、授权 profile 和规格。
- 审批：本次传输与收费信息、生成数量、确认/拒绝、报价失效状态。
- 进度：受理、等待、生成、保存、失败/提交不明/认证待恢复/过期，不只一个转圈。
- 成果：图片网格、大图预览、规格和来源、保存状态、导出、重新保存、重做。
- 批量：成功项立即可查看，失败项单独操作；重做提醒新生成可能收费。
- 未配置：图片不可用有明确提示，普通聊天继续可用；视频入口不显示为可操作。

准确包装文字、Logo、外形和颜色需人工确认；模型调用成功不能替代商品质量验收。UI 不写“保证与原图完全一致”。

### 11.1 图片网关 mock 联调（第三批闭环、第四批持久化）

SEP 在显式 `NODE_ENV=development/test` 加 `MEDIA_GATEWAY_MOCK_ENABLED=true` 时开放 `/gateway/v1/media/*`，详见共用合同 3.1。客户端使用原有 employment token；mock 必须走独立、显式的测试端口，不通过修改正式 runtime 绕过 `executionAvailable: false`。先 `GET profiles` 取得测试场景及固定 PNG，上传该 PNG，再报价、提交、查询并下载保存。禁止用真实商品图联调该入口。

第四批 `profiles.persistence: "database"`：参考/报价元数据、回执和冻结配置通过 Prisma 存入数据库，重启恢复依赖同一已迁移数据库，不是单进程缓存。服务端保存参考 ID/内容 hash、语义 hash 和 mock 配置/价格快照，不保存创作要求原文、真实素材或输出字节；客户端仍须自己持久化本地 job、输入与保存状态。

复用 `backend/src/shared/media-gateway.dto.ts` 和 `backend/src/shared/fixtures/media-gateway-v1.json`：严格请求字段、`parameters: { size: "1x1", count: 1..4 }`、六位小数模拟人民币报价、`MOCK_NOT_CHARGED`、outputs hash 与恢复标记。JSON 成功响应是裸 DTO，没有 `{ data: ... }` 包装；内容接口是裸 PNG；错误遵循现有网关 `{ error: ... }`，不能把错误 JSON 保存成图片。

场景包括同步、异步、部分失败、失败、提交不明、过期、无报价、预算不足和不支持取消。by-client-id 只查原回执，不推进模拟异步适配器；receipt GET 才推进 QUEUED/RUNNING。两种读取都可能将超时 SUBMITTING 持久转 UNKNOWN。客户端验证断线查原 ID、不重生成、本地保存/部分成功及跨 scope 拒绝；mock 不提供后台 worker。

恢复与去重按以下规则处理：

- 唯一键为 `(enterpriseId, clientRequestId)`；scope 另绑定企业、订阅、成员和用户，每次恢复/下载重新验权，知道 ID 不等于有权访问。同企业不同 scope 不能抢占已有 key。
- 只有确认数据库插入本次 SUBMITTING 回执成功才调用 submit；唯一冲突返回原回执。插入/读取/最终回写不明返回 503 `MEDIA_STORAGE_UNAVAILABLE`，客户端保留原 ID 查回执，不重发、不换 ID；404 同样不能证明未接单。
- SUBMITTING 的 submissionDeadline 为自占用起两分钟；读取/重放发现超时会持久转为 `SUBMISSION_UNKNOWN`。claim 确认返回后、submit 前也检查期限，若确认已超过两分钟则转 UNKNOWN，不 dispatch。不是后台任务；转后 canQuery/canCancel/canDownload=false、pollAfterMs=null，仍可读回执，但不查询适配器、不自动补提，不把 UNKNOWN 当成失败后可以重做。
- 服务端读取冻结 configuration 使用严格 Zod 与回执/requestId、profile/configVersion、count、参考 ID/hash 长度一致性检查；损坏统一返回 503 `MEDIA_STORAGE_UNAVAILABLE`，不执行未经验证的快照，客户端不能用换 ID 重生成规避。
- 服务端以 revision CAS 保存回执，查询/取消竞争时返回数据库最新状态；不能把取消请求已发出视作 CANCELLED，也不能让迟到结果覆盖已持久化 UNKNOWN。
- 撤销旧的“每类单进程 1000 条”上限，不删回执、不释放幂等 key；尚无自动数据库清理或生产配额。参考 15 分钟、报价 60 秒、结果 5 分钟只限制 mock 使用有效期，不意味着到期删库，更不是生产缓存政策。现有全局业务限流仍有效。
