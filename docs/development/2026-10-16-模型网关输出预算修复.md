# 模型网关输出预算修复

日期：2026-10-16。范围：SEP 平台后端及后端部署配置。

## 问题

2026-10-15 的生产版本在模型目录未配置 `maxOutputTokens` 时，把 `GATEWAY_DEFAULT_MAX_TOKENS=4096` 同时作为显式请求的硬上限。客户端尝试增大输出预算会被拒绝。

当前分支的运行策略快照路径已经区分默认值与平台上限，但无快照的兼容路径仍保留旧逻辑；三份 Compose 也没有透传 `MODEL_MAX_OUTPUT_TOKENS`。

## 实现

`GatewayModelPolicyService.validateResources()` 统一调用现有 `normalize()`，兼容路径使用配置回退值，快照路径继续使用请求捕获的策略版本。

```text
默认预算 = GATEWAY_DEFAULT_MAX_TOKENS，默认 4096
平台上限 = MODEL_MAX_OUTPUT_TOKENS，默认 32768
有效上限 = min(平台上限, 模型 maxOutputTokens ?? 平台上限)

省略 max_tokens：min(默认预算, 有效上限)
显式合法 max_tokens：保留原值
显式 max_tokens > 有效上限：调用上游前返回 400
```

模型独立能力、鉴权、可用状态、工具/流式能力和请求字节数检查继续执行。不修改数据库模型能力，不声称供应商一定支持 32768。

超限统一返回 `MODEL_OUTPUT_LIMIT_EXCEEDED`、`source=platform`、`param=max_tokens` 和实际 `limit`；快照路径保留 `policyVersion`。非正整数等非法值仍返回 `INVALID_PARAMETER`。

单服务、蓝绿、开发三份 Compose 均透传独立平台上限。环境示例和生产部署说明同步更新。

## 行为验收

| 模型能力 | 平台上限 | 请求 max_tokens | 结果 |
|---|---:|---:|---|
| 未配置 | 32768 | 省略 | 注入 4096 |
| 未配置 | 32768 | 4096 | 保留 4096 |
| 未配置 | 32768 | 8192 / 16384 / 32768 | 原值转发 |
| 未配置 | 32768 | 32769 | 400，limit=32768 |
| 65536 | 8192 | 8193 | 400，limit=8192 |
| 2048 | 32768 | 省略 | 注入 2048 |
| 2048 | 32768 | 2049 | 400，limit=2048 |

修复前先运行新增回归，四个场景均失败，复现了兼容路径错误。修复后检查结果：

- Gateway 全部适用测试、运行策略 service 测试、共享策略 schema 测试：15 个测试套件通过，478 项通过。
- 43 项需要专用 Redis/数据库环境的集成测试由原有条件跳过，本次未运行。
- 后端 TypeScript typecheck 通过。
- 后端构建通过。
- 三个修改的 TypeScript 文件定向 ESLint 通过，git diff --check 通过。
- 三份 Compose 使用 `docker compose config --no-interpolate --format json` 解析通过，并验证每个 backend 服务都透传独立上限与默认预算；未读取生产私有 env。
- HTTP 测试确认显式较大预算进入实际转发和资源预留；超限在创建 execution、准入和调用上游之前拒绝，响应保留具体上限。

## 发布与边界

本次完成本地修复，尚未提交、push 或部署。发布后需重建后端容器；数据库中的运行策略覆盖值优先于环境变量，应先检查管理端生效值。

客户端继续显式发送 4096 时，实际预算仍为 4096。客户端可在供应商支持范围内显式请求更大预算；本次不擅自把既有请求改成更高预算。

中转层丢弃 thinking 参数、部分终止状态转换为 stop 的问题不在 SEP 后端代码中，本次未修改 sub2api。原始供应商 SSE 和 reasoning token 分类缺口仍需补证，本次没有进行收费模型调用，不能宣称已经证明或解决所有“仅思考无正文”响应。

模型目录当前返回原始能力元数据，不包含结合运行策略后的有效上限。客户端在请求超限时可读取本次明确的错误 limit；若需要事前发现平台限制，后续可给模型目录增加独立有效上限字段，保留现有 maxOutputTokens 的原始能力语义。
