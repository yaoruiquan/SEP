## 1. 背景与范围

## 3. 请求生命周期

执行顺序：入口中间件和 body parser → JWT 和会话校验（失败进入独立认证限流）→ 原有订阅身份 RPM → DTO → 同步检查本实例排空状态并登记活动请求 → 订阅/成员/授权/余额 → 模型策略和资源校验 → 创建执行日志 → Redis 聚合及并发准入 → sub2api → 用量持久化 → 响应完成/异常断开 → 标记可结算或待对账 → finally 释放租约和活动计数。持久记录由后台补偿任务幂等结算，HTTP 请求不等待完整扣费。

原则：

- 在 sub2api 请求之前必须成功写入执行日志。数据库故障时返回 503，不发起无法追踪的消费。
- 准入或授权失败不调用上游；已创建日志而准入失败，记录 FAILED。
- 客户端断开时取消上游；已观察到的合法 usage 仍结算，不能因为结果不完整而免单。
- 结果完整性与财务结算是两个独立维度：有完整结果但缺 usage 要对账，有 usage 但断流仍扣已发生的成本。
- 不自动重发模型请求。相同客户端关联 ID 的两次实际执行分别计费。要实现业务执行去重，未来需独立的请求指纹和结果回放协议，不能只去重扣费。
- 控制器内授权、模型策略、执行日志、Redis 准入和释放各有固定 5 秒等待上限，不用上游 body 超时代替这些阶段的等待预算。超时不意味着数据库/Redis 操作被取消；晚到准入会尝试释放自己的租约，晚到写入仍受状态条件约束。不将超时响应解释为业务安全重试承诺。守卫阶段的认证数据库查询与身份 RPM、入口连接时间仍需入口/数据库配置保护，不包含在控制器的 5 秒保护内。

## 4. 认证与入口

### 4.1 可撤销 employment token

签发继续复用桌面 refresh rotation，增加 `sid = rotated.sessionId`。每次模型请求校验：签名/type/exp/字段 → sid 存在 → AuthSession 属于 sub、type=DESKTOP、未撤销、未过期 → User.status=ACTIVE → Device 属于同一用户且未撤销。会话轮换不更换 sid，退出登录、设备撤销、用户封禁通过数据库状态立即阻止新请求；refresh rotation 在事务条件中再次检查状态，避免校验后的撤销竞态。

旧无 sid token 默认返回 401，客户端通过现有获取 employment token 接口即可获得新令牌，无新增客户端协议。上线会使旧令牌短暂需要刷新，必须在发布说明注明。不能长期开放无会话 token 兼容通道。已开始的流不轮询撤销状态，本轮保证的是下一次请求拒绝。

### 4.2 无效认证资源防护

不恢复把所有合法用户按代理 IP 汇总到普通 REST 桶。限制 Bearer header 长度及格式；对失败认证单独限流，计数不把真实 token 写入 Redis/日志。合法认证不消耗失败认证额度。来源取值不能相信任意 X-Forwarded-For；无效令牌的同来源/同令牌散列防护使用有界窗口。Redis 不可用返回 503，而不是悄悄关闭防护。

应用 JSON body 原有限制仍保留。代理连接/带宽防护由生产入口承担；本轮应用修复不能宣称能抵抗分布式 DDoS。

### 4.3 CSRF

对已知 Bearer 网关路径去掉尾斜杠后精确比较，保留其他写接口 CSRF 校验，不用 gateway 前缀整体豁免。

## 5. 模型策略与资源

平台可调用模型集合必须 enabled=true、isStale=false。企业白名单与部门白名单取交集，空列表表示该层不限制；不能用部门配置扩大企业范围。成员必须属于 claims 中企业和用户，部门从当前成员记录取得，不信任客户端字段。

复用 EnterpriseModelConfigService 的默认模型解析。禁止切换或 FORCE_DEFAULT 时只允许有效默认模型；默认模型失效时返回明确配置错误，不偷偷切换到昂贵模型。客户端订阅列表与网关执行使用相同策略入口。订阅/模板默认值仍保留原来的优先级。

DTO：messages 至少 1 条且数量有上限；限制工具数量、工具名/ID、参数 schema 结构及字符串长度；正整数输出上限；tool 消息必须关联此前 assistant tool_calls 中的 ID。允许一轮多个工具、reasoning_content、assistant 的 null content 和合法工具续轮，不强制不必要的“用户-助手”交替。

执行资源校验：max_tokens 超过模型 maxOutputTokens 时返回 400，模型输出元数据缺失时以平台默认值为硬上限，避免显式传入超大值绕过限制。未指定时注入平台默认上限（默认 4096，受模型上限收窄）。supportedFeatures 明确 false 时拒绝 functionCalling/streaming，不把未知元数据当 false。上下文精确 token 数没有通用 tokenizer，本轮只做有界序列化输入和输出限制；可启用保守的流量预算，不能把字节估算宣称为精确模型 context 校验。

输入大小有多个阶段：`main.ts` 的 JSON parser 现有默认 `REQUEST_JSON_LIMIT=2mb`，先于 DTO 和网关资源校验；网关序列化默认 `GATEWAY_MAX_REQUEST_BYTES=4194304`。实际可接受大小取入口代理、parser 和网关预算中更小者，不因为网关设成 4 MiB 就自动接受 4 MiB HTTP body。本轮不扩大其他 REST 接口的默认解析上限。网关 messages 上限 512、tools 上限 128，tool parameters 的预检限制深度和节点数量，防止递归校验耗尽堆栈。

## 6. 限流和并发

原有规则不变：默认 60 次 / 60 秒，维度 enterprise/member/subscription；每个模型续轮和每次重试各计一次。拒绝不延长窗口，Redis 不可用 fail closed。

新增规则在授权和 DTO 后执行，Lua 在一次操作里检查所有预算后再写入：

| 配置 | 默认 | 维度/含义 |
| --- | --- | --- |
| `GATEWAY_MEMBER_CONCURRENCY` | 4 | 同企业同成员，跨订阅/模型的活动执行 |
| `GATEWAY_ENTERPRISE_CONCURRENCY` | 32 | 同企业所有活动执行 |
| `GATEWAY_MEMBER_RPM` | 120 | 同企业同成员跨订阅，60 秒窗口 |
| `GATEWAY_ENTERPRISE_RPM` | 600 | 同企业总请求，60 秒窗口 |
| `GATEWAY_ENTERPRISE_TOKEN_BUDGET` | 0 | 0 禁用；启用时每 60 秒保守预留输入字节单位+max_tokens，不用于扣费 |

并发 ZSET 以 execution ID 为成员、绝对到期时间为 score，租期至少覆盖请求总预算+清理余量。准入先清理过期租约，再检查成员和企业集合；finally 使用同一个 ID 幂等删除。进程崩溃不会永久占用名额。不能在第一次拒绝时删除别人的租约。

聚合 RPM 在准入成功后计数，失败和取消不退回已消耗请求额度。可选 token 流量预算采用保守预约，不在缺 usage 时退回，避免未知成本被当成零。不是 sub2api 的 TPM 精确镜像，也不是资金预占。

429 返回 `source=platform`、独立 code、rule、dimension、limit/count/windowMs/resetAt/retryAfterSeconds；并发恢复时间是当前最早租约到期上界，其他请求提前结束后可以更早恢复，不承诺固定时刻一定成功。上游 429 保留 source=upstream 和真实 Retry-After。

## 7. 执行日志与财务补偿

新增 `GatewayExecution` 表（Prisma cuid、snake_case 表名，工具生成迁移）。字段：身份 enterprise/user/member/subscription/employee、model、requestId/upstreamRequestId、状态、inputTokens/outputTokens、finishReason、done、errorCode、settlementAttempts、settlementReady、settlementLeaseUntil、usageRecordId、createdAt/updatedAt/expiresAt。只保存执行与结算元数据，不存 prompt、工具返回、凭证或响应正文。身份使用快照字段，避免因订阅删除而丢失执行追踪。

状态：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| STARTED | 上游执行可能开始，用量尚未持久化 | 正常采集或过期后待对账 |
| USAGE_PENDING | 已有合法实际 usage，尚未完成扣费 | 已确认 ready 的由补偿任务结算；未 ready 超期转待对账 |
| SETTLED | 已有统一账本 usageRecordId | 不再扣费 |
| NEEDS_RECONCILIATION | 结果/用量未知或无 usage | 不估算扣费、不当作免费，保留待查 |
| FAILED | 未发起上游请求，或收到明确的上游 4xx 拒绝 | 不扣费；5xx/传输错误保守保留待对账 |

每次实际执行生成独立 ID。网关账本 session 使用固定服务端命名空间，message 使用执行 ID，不再用 x-sep-session-id/x-sep-message-id/x-request-id 作财务键。那些 header 只是追踪信息，不提供执行幂等承诺。

流式强制传 `stream_options.include_usage=true`。observer 仍只旁路解析、不改输出字节；完整事件中的合法 usage 在转发该数据块前写入日志（不阻塞此前文本）；没有事件结束分隔符的尾部 usage 到 EOF 才能识别和落库，但尾部 finish/DONE 不证明成功结束。非流式合法 usage 先落库，再独立校验结果完整性；即使结果无效，也不能把已发生的消费当作免费。校验 token 为非负整数且不超 PostgreSQL Int，非法 usage 不入账，执行保留待核查。

结算使用持久状态和 120 秒 DB lease，只有 `settlementReady=true` 才能领取；活跃流可多次更新 usage，但不会被 Cron 提前按中间用量结账。成功写回、失败释放均同时匹配 execution ID、USAGE_PENDING 状态和领取时的 leaseUntil，旧 worker 迟到不能覆盖新 owner。重复恢复使用相同执行键调用统一 ComputeCreditService。账本成功但日志更新失败，下次重试由账本唯一键防止重复扣费。后台失败记录重试次数和安全错误码，日志保留 execution/request ID；数据库查询与扣费各最多等待 5 秒，超时保留 lease 至到期，因为实际操作可能稍后提交。

`finish()`/`fail()` 只持久标记、不等待扣费。Cron 每分钟触发、每轮最多扫描 100 笔，单实例不重入；结算通常延迟到下一轮，堆积或慢数据库时可能超过一分钟，不承诺实时余额。进程重启继续补偿。超期状态清扫按 status/expiresAt 索引过滤；数据保留/归档策略需运维另行确定，本轮不自动删除账本或执行历史。

checkpoint、收尾、失败记录都有 5 秒等待预算；checkpoint 失败后不重复等待同一个存储操作。超时不虚报 usage 已保存：将执行冻结为 NEEDS_RECONCILIATION、settlementReady=false，禁止后台按旧快照扣费。checkpoint 仅能更新未 ready、无结算租约的 STARTED/USAGE_PENDING；更新零行返回显式错误，晚到失败被观察、不会产生未处理 rejection。超期且未 ready 的 USAGE_PENDING 也转待对账，不自动开放结算，避免进程崩溃后无法判断是否还有晚到 usage 写入。无法确认持久化时结束 transport 并保留已有执行记录待恢复/对账。Redis 释放超时不阻止本实例活动计数归零，真实并发租约仍按到期时间恢复。

本轮沿用统一账本在结算时加载计价配置和成员额度周期的行为，不增加执行时价格快照或冻结消费周期。因此长时间补偿期间价格/额度周期变化仍有业务口径风险，严格资金预占方案需要同时定义这两者。

超过执行总预算和余量仍 STARTED，或 USAGE_PENDING 但未确认可结算的记录转 NEEDS_RECONCILIATION。sub2api 未确认提供可按 requestId 查单的稳定接口，因此本轮不猜造自动对账 API。运维根据关联 ID 查上游记录，核实实际 tokens 后才能补账。完全丢失 usage 或只留有未确认最终性的旧快照时，问题被持久暴露，但尚不能自动恢复真实消费。

人民币预占后续设计：在同一事务中预占赠送/成员/企业/个人各资金来源，记录价格快照和预占金额；实际 usage 结算时转换预占、差额继续按现有欠费规则处理；执行失败释放，未知执行不能贸然全退，必须对账；多钱包与成员额度窗口需要共享锁序和乐观锁策略。本轮不改动现有扣费来源顺序或 unpaid 语义。

## 8. 协议与转发边界

- SSE 成功响应必须 Content-Type=text/event-stream，缺 body/MIME 不符在发送下游 SSE 头前返回 502，取消上游读取。
- 有界读上游错误 JSON（默认 64 KiB）和非流式 JSON（默认 8 MiB），超限取消 reader，返回明确 502；不透出 HTML、内部连接细节或无限长错误字段。
- 非流式使用独立可配置总预算（默认 120 秒），body 读取包含在预算中，同时支持客户端取消。
- 非流式要求 choices 非空且各项包含 assistant message、非空 finish_reason；兼容合法工具调用、refusal 和 content_filter。`[null]`、`[{}]` 或 finish_reason=null 不作为成功返回。
- 正常 SSE EOF 在 pipeline 结束响应前检查至少有完整、以空行闭合的有效 finish_reason 事件。只有无分隔符尾帧中的 finish_reason 即异常断流；完整 finish 无 DONE 兼容已有客户端但记录诊断，不补 DONE。finish_reason=length 属于上游真实截断，由客户端展示，本轮不改结束语义。
- observer 单事件及未闭合行最多 1 MiB UTF-8 字节成本，单事件最多 4096 行，计入字段、分隔符和空 data 行；超限丢弃旁路观察至下一空行边界，再恢复后续事件，不修改透传字节。超限事件的 usage 无法确认时仍需对账。
- idle 只在等待上游 reader.read 时计时；背压暂停期间停止 idle，总时限仍有效。客户端慢读不能无限占住执行。
- 失败认证返回独立限流信息；准入、响应头、请求失败、断流、流结束和结算记录关联日志。已有 requestContext 与 HTTP 日志保留 requestId，执行日志提供 executionId/upstreamRequestId，不记录凭证与完整业务正文。本轮不新增日志查询 UI 或外部监控存储。

## 9. 发布排空

不新增对外可调用 drain 接口。容器内排空标记 `/tmp/sep-runtime/gateway-drain.json` 由可信 Docker 操作者原子写入，内容绑定本次 `{bootId, token}`；0700 私有目录、0600 标记，不挂载共享卷。进程重启后旧 bootId 标记不误阻止新实例。活动模型请求从进入控制器、授权/转发之前开始，到最后有界 journal/准入清理结束；后台补偿不计入 HTTP 活动数，待结算记录由数据库保留。health 增加只读的 gateway draining/active 字段，readiness 在 draining、stopping 或控制标记异常时返回 503。

切流后标记旧实例 draining，轮询活动请求至 0，再停止旧 Web/Backend。排空上限默认覆盖 600 秒请求预算+余量，不能沿用 15 秒。超时不静默硬杀：明确警告/失败和保留旧实例，强制停止必须另行显式操作。回滚同样排空候选实例。后台 shutdown hooks 与 compose stop_grace_period 配合，不能把 TCP 停止视为业务成功。

发布兼容变化：`deploy`、`deploy-web`、`deploy-backend` 都成对发布 Backend/Web，避免只换半侧留下代理/后端不匹配；单角色 restart 仅停止指定角色，但恢复检查整对服务，restart 不刷新环境变量。旧基线 `e868f59` 没有 lifecycle 字段，首发切流后的旧实例排空会 fail closed 保留容器，失败不代表新色已撤回；回滚该旧镜像也不能自动确认恢复。首次升级和旧版本回滚必须受控窗口人工核查，具体步骤见 production README。恢复 readiness 有短暂准入窗口，不宣称原子恢复。

## 11. 上线与回滚条件

本轮只开发与本地验证。上线顺序：备份 → 增量迁移 → 配置预算 → 发布候选 → 合成 SSE/非流/429 smoke → 切流 → 排空旧实例。新表是增量，不删除账本或历史字段。老代码可忽略新表，回滚不能删除待结算数据；补偿服务停用期间需持续追踪 pending/needs_reconciliation。

监控：各来源 429、每维度并发、body/idle/total timeout、未完成 EOF、usage 缺失率、pending 年龄与重试次数、待对账数量、排空超时。人工应能回答历史事故要求的“哪一层、哪条规则、阈值/计数、预计恢复时间”。
