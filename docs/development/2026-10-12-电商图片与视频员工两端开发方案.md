## 1. 一句话说明

**SEP 把员工和工作手册上架，并提供安全的模型通道；客户端真正干活、跟进生成、保存和展示成品。**

组合不变：**数字员工 + 电商 Skill + 受控图片/视频工具 + 后台任务 + 素材交付**。改变的是各部分在哪里运行。

### 1.1 已经确认的决定

| 决定 | 具体含义 |
| --- | --- |
| 继续使用员工和 Skill 体系 | 不另建一套电商 Agent 平台 |
| SEP Web 不执行员工 | 做上架、审核、配置、授权和已有监控，不做新的电商制作工作台 |
| 客户端负责到底 | Pi 执行、工具调用、任务轮询、恢复、成品下载和交付都在客户端 |
| 完全退出后不做云端托管 | SEP 不定时查生成进度，不自动收成品，不代替客户端推进下一步 |
| 模型配置入口独立 | 图片和视频不混入会话模型选择、默认模型或聊天白名单 |
| 沿用模型中转约束 | 客户端 -> SEP 受控网关 -> sub2api -> 已有上游，不向客户端分发上游密钥 |

**“后台”指客户端主进程里的持久任务，不是浏览器后台，也不是 SEP 的 BullMQ 工作流。** 主进程结束或电脑关机后，本地跟踪停止；已提交的上游任务是否继续由上游协议决定。

### 1.2 这次不做什么

- 不改 SEP 的旧 Web 对话执行器来运行这些员工。
- 不把 `CapabilityService.execute()`、Coze/OpenCode 适配器作为新员工的必经路径。
- 不新增 SEP 媒体任务 worker、定时轮询、回调驱动的员工流程或云端成品库。
- 不要求用户配置 API key，不让下载的 Skill 用 shell 直连收费模型。
- 首期不承诺自动上架、整套详情页、多镜头完整带货广告或商品像素级不变。

## 2. 谁开发什么

```text
SEP Web：员工/Skill 发布 + 图片/视频模型配置 + 企业权限/额度设置
    |
SEP 后端：批准版本分发 + runtime 清单 + 授权/报价/请求回执/账务
    ^
    | HTTP 请求；不接管员工流程
    |
sep-client renderer：需求输入、审批、进度、图片/视频预览与导出
    |
Electron 主进程：Pi + 电商 Skill + 媒体工具 + 本地任务记录 + 文件保存
    |
    +-> SEP 媒体网关 -> sub2api -> 图片/视频上游
```

| 工作 | SEP Web | SEP 后端 | 客户端 | sub2api / 上游 |
| --- | --- | --- | --- | --- |
| 员工上架、Skill 审核与版本 | 管理界面 | 归属、批准、版本与分发 | 安装、选择、锁定实际版本 | 无 |
| 创作方案、提示词、分镜 | 不执行 | 只提供会话网关 | Pi 根据 Skill 组织 | 会话模型推理 |
| 图片/视频模型接入配置 | 独立管理入口 | 加密配置、能力描述、路由 | 只读取可用能力 | 真实模型/协议适配 |
| 参考商品图 | 不建操作页面 | 必要的传输/授权，不默认永久存储 | 选择、本地复制、校验、引用 | 接收必要参考图 |
| 工具审批和费用确认 | 不执行 | 再次校验权限、报价和硬限制 | 展示审批并执行受控工具 | 按请求生成 |
| 提交生成 | 不执行 | 校验并转发一次，保存安全回执 | 持久化意图后请求提交 | 接单与计算 |
| 查询与恢复 | 可显示既有监控 | 被客户端请求时查询、更新回执 | 定时查询、断线/重启恢复 | 返回原任务状态 |
| 成品保存 | 首期无云端素材库 | 必要时按请求流式转发 | 下载、校验、原子落盘、关联版本 | 提供结果及有效期 |
| 用量和费用 | 管理与查看 | 权威账本、对账、去重结算 | 展示报价和账单状态 | 提供真实消耗 |

### 2.1 后端有“回执”，不等于后端运行任务

即使客户端负责执行，后端仍需要最小持久记录，防止一个企业查询另一个企业的任务、重复提交或重复扣费。

**MediaRequestReceipt（请求回执）建议保存**：归属、员工订阅、客户请求 ID、请求 hash、模型配置版本、报价/预算关联、上游任务 ID、最近一次被动查询结果、结算状态和时间戳。

它不保存 Pi 会话，不读 Skill 来规划，不跑下一镜头，不主动定时查询，不自动下载成品。只有客户端请求才推进查询/下载；财务对账属于平台账务，不是员工执行。首期不靠临时签名 token 保存全部归属，否则任务重启、密钥轮换和去重记账难以可靠处理。

## 3. 当前代码支持到哪一步

以下为静态检查结果，不代表线上已验证。源码定位见第 12 节。

| 环节 | 当前证据 | 本需求需要补什么 |
| --- | --- | --- |
| 平台 runtime | `GET /client/subscriptions/:subscriptionId/runtime` 已有，`manifestVersion: 1`，含员工信息、提示词、聊天模型范围和 Skill 正文 | 增加可用媒体能力、工具要求、版本与兼容性描述 |
| 客户端员工授权 | `EmployeeAuthorizer` 读取订阅目录，再调用 `SkillStore.prepare()`；当前这条链路未读取上述 runtime | 接入 runtime 合同并验证身份/版本，不能只改后端就认为客户端收到配置 |
| 提示词注入 | 当前授权/SDK 配置链路未见员工 `systemPrompt` 注入 | 验证并实现 Pi SDK 的受控提示词注入，不能依赖 Markdown 被“碰巧”读到 |
| Skill 内容安装 | `SkillStore` 从预览接口取正文，写入 `SKILL.md` 和本地 manifest | 保留合法 frontmatter；锁定任务使用版本；需要参考文件时支持完整包 |
| Skill ZIP | SEP 已解析、存储原 ZIP，并有贡献版本包下载接口 | 核对批准版本/订阅的可下载权限；客户端现安装器不是完整 ZIP 安装器 |
| ZIP 正文处理 | `SkillPackageService` 提取正文时剥掉 frontmatter | 不能把这段正文当原始规范入口；安装原包或按批准元数据重建入口后校验 |
| Pi 工具扩展 | `pi-coding-agent-adapter.ts` 已通过扩展注册 MCP 工具并做策略审批 | 加受信任的宿主媒体工具，不需要为此新增 MCP 服务 |
| 本地持久化 | `ScopePath`、原子 JSON、运行记录和事件日志已有 | 新增媒体任务/素材记录，沿用企业与成员隔离，首期不新增本地数据库依赖 |
| 退出与恢复 | `stopAll()` 中断任务；恢复记录能标为 `interrupted` | 媒体恢复必须查询原上游任务，而非重新执行生成工具 |
| 交付物 | `ClientTask.files` 为字符串列表；成果面板显示文件名称/摘要 | 首期新增媒体素材投影、图片预览、导出与文件缺失状态；视频播放后续接入 |
| 平台模型 | `PlatformModel` 和企业配置主要服务聊天/token 定价；客户端 runtime 按 enabled 范围读模型 | 独立媒体白名单和价格；阻止图片/视频模型混入聊天列表 |
| SEP 网关 | 当前 controller 只有 `POST /gateway/v1/chat/completions` | 媒体提交、查询、内容读取及引用素材传输接口 |
| 监控 | 客户端可同步状态及脱敏用户输入/模型输出，原始工具参数/结果不默认同步 | 沿用现有协议；媒体二进制、本地路径、临时 URL 不作为监控正文 |

注意：当前 runtime 虽有 `templateVersion`，员工提示词等字段仍从当前 employee 行读取；Skill 安装目标也会被替换。因此，**不能把现状说成完整不可变版本锁定**。首期至少冻结每次运行的提示词、实际 Skill 版本/内容 hash 和媒体配置版本；后续发布不覆盖正在运行的任务资源。

## 4. 电商 Skill 怎么复用

### 4.1 推荐的组织方式

长线规划两个员工，各绑定一份清晰的业务 Skill；首期只启用图片员工，视频员工暂不发布为可执行能力：

| 员工 | 业务 Skill | 第一阶段交付 |
| --- | --- | --- |
| 电商商品视觉设计师 | `ecommerce-product-visuals` | 基于真实商品参考图的小批量场景图/主图整理 |
| 电商短视频制作师 | `ecommerce-product-video` | 基于用户已确认图片的单镜头短视频 |

Skill 决定“先问什么、怎样创作、检查什么”；受控工具决定“有没有权限、能花多少、真正怎样调用 API”。把更多参考资料拆到 `references/` 是可选增强，不要为了格式先造一大堆空目录。[S1]

### 4.2 GitHub 已核实候选

下列结论针对固定 commit 原文件，而不是搜索摘要。选择这些仓库不代表要购买它们的服务，也不把仓库承诺的“电商合规”当平台认证。

| 候选 | 已核实内容 | 原执行依赖 | 对我们的用途 |
| --- | --- | --- | --- |
| `motiful/product-shots` [S2] | 主图、多角度、副图、广告创意和底层生图 Skill；先主图再参考主图派生 | Python、requests、Pillow；OmniMaaS/Cloubic 或自定义网关 | 商品图片首选流程来源；替换 Python/API 入口和专属 Skill 调用 |
| `nexu-io/open-design` [S3] | `ecommerce-image-workflow`，真实商品参考图、不可改变特征、检查清单、image manifest | OpenDesign Node CLI/daemon 的 `media generate/wait` | 借鉴商品一致性约束与交付清单，不引入整个 OpenDesign 应用 |
| `ymh3753201/ai-commerce-video` [S9] | 真正的商品视频 Skill：商品事实锁、人物/旁白/无语音模式、参考图审批、分镜、字幕和交付检查 | MikuAPI、xAI、119337、fal 等供应商配置，另依赖 imagegen 和 FFmpeg/ffprobe | 商品视频优先流程来源；只复用与首期相关的规则，不接其供应商或剪辑依赖 |
| `novoads/agent-skills` [S4] | `novoads-api`，素材上传、估价、提交、轮询、质检；另有 UGC 提示词模板 | Novoads REST API、专属 key、素材 ID、credits | 后续视频流程和模板来源；首次接入视频时收缩到单镜头，不照搬其参数和计费 |
| `openai/skills` [S5] | 通用生成/参考图编辑/遮罩/批量及商品图模板 | 宿主图片工具或 Python OpenAI SDK/API key | 编辑约束与通用工作方法补充，不照搬直接认证或工具优先级 |
| `Advibly/skills` [S6] | `ugc-ads`，商品/人物图、五镜头、视频生成与合成 | Advibly MCP、品牌数据、素材存储、credits | 仅流程参考；未核实明确许可证，暂不复制、改包或分发 |

**建议选型**：图片 Skill 以 product-shots 的交付流程为基础，参考 open-design 的商品一致性清单；后续视频 Skill 以 ai-commerce-video 的商品事实/镜头规则为基础，NovoAds 作为 UGC 补充。首次接入视频时裁剪为“确认图片 -> 单镜头生成 -> 检查 -> 本地交付”，不纳入本次图片首期。不是把候选仓库全装上。

### 4.3 许可与复用边界

- product-shots、ai-commerce-video、NovoAds 对应快照根许可证为 MIT；保留适用版权和许可声明。NovoAds 根许可列出 NOVO SpA 与 Caleb Kruse / Kruse Media LLC 两项版权，不能只保留一项。[S2][S4][S9]
- open-design 根许可证、OpenAI imagegen 目录许可证为 Apache-2.0；复制时保留许可/适用声明、标明修改，并处理实际存在且适用的 NOTICE。[S3][S5]
- Advibly 的固定快照未核实明确许可证，不能因 GitHub 公开就当成可商用复制授权。[S6]
- 上述只处理代码/文档许可，不自动获得人物、商品照片、字体、音乐、商标和生成素材的权利，也不等于外部云服务可免费使用。
- 首期只是设计，不下载发布第三方包。真正导入时逐文件记录来源、commit、许可证和改动，复核嵌套许可/NOTICE，不能只把首页仓库名写进说明。

固定快照中 product-shots、ai-commerce-video 未发现独立 NOTICE；open-design 的目标 Skill 无独立许可/NOTICE，其他目录可能另有许可。NovoAds 的 claymation/pixar 目录有改编说明 NOTICE，若后续复制这些内容要一并处理，不扩大此次模板许可结论。[S2][S3][S4][S9]

NovoAds 的 UGC v2 模板明确依赖 v1，不能只摘 v2 当独立完整 Skill；其语速、时长、引用语法和价格等观察不当成我们的模型能力或定价规则。[S4]

### 4.4 必须改掉哪些部分

1. 删掉原供应商认证和接入指令，不要求客户端用户填写任何上游 key。
2. 把原 `Skill(...)`、`advibly_*`、`OD_BIN media` 或 curl 调用改为我们的 `media_*` 受控工具。
3. 把“参考图路径/公共 URL”改为客户端批准的 `localAssetId`；只有宿主可解析实际文件。
4. 把模型名、画质、时长和数量硬编码改为 runtime 下发的媒体 profile 能力。
5. 保留真实商品约束；人物 UGC、配音、音乐、多镜头合成留到后续，不先承诺。
6. 用本地 `jobId`、素材 manifest 和明确保存状态交付，不把“已提交”写成“已完成”。
7. 增加费用确认、修改次数上限、提交不明停止规则及重启查询原任务规则。

**当前工作区的 relay 生图 CLI 仅是本次开发助手的执行约定，不是 SEP 产品的客户端依赖。** 不向客户分发本机路径、开发者 key 或开发环境供应商配置。

### 4.5 发布与安装合同

Skill 上架应包含：业务用途、合法入口、来源许可、内容/包 hash、批准版本、所需工具、最低工具协议和客户端兼容范围。工具依赖放在 SEP 受控发布元数据里，不伪造 Agent Skills 的通用标准字段。

两种交付形态：

- **单文件版**：复用原流程后重新整理为自包含 `SKILL.md`，不引用未下发文件；批准元数据用于恢复/验证 `name`、`description`。适合先做闭环。
- **完整包版**：需要 `references/` 等文件时，按批准版本下载 ZIP，校验 hash、解压路径/符号链接/大小/条目数，再原子安装到不可变版本目录。禁止自动运行 setup 脚本或包内扩展。

原贡献版本下载接口可作为已有实现参考，但它不等于“任意订阅成员都能下载当前批准 SkillVersion”；需核对 ID/权限来源，必要时增加按订阅和批准版本下载的端点。客户端不得从模型输出的 URL 下载包。

## 5. 图片/视频模型配置怎样独立

### 5.1 三处界面的边界

| 位置 | 入口建议 | 负责什么 |
| --- | --- | --- |
| SEP 平台管理 | “媒体模型”独立页，图片/视频两栏 | sub2api 连接配置、模型 profile、能力、启用/健康状态、报价规则 |
| SEP 企业管理 | “媒体能力与额度”独立于会话模型设置 | 图片/视频可用 profile、默认 profile、单次规格上限和预算 |
| 客户端制作流程 | “图片规格”或“视频规格” | 从授权 profile 选择比例/画质/时长；不出现密钥和上游地址输入框 |

入口名称/最终路由可沿用项目导航习惯。核心验收是：改会话模型不影响媒体默认模型；禁用视频不影响聊天；图片和视频各有允许范围。

### 5.2 配置结构建议

**不要只在现有聊天模型后加两个名称。** 建议新增媒体 profile 和企业媒体策略；复用 `SettingService` 的加密秘密配置，不另造密钥仓库。

| 字段组 | 示例字段 | 说明 |
| --- | --- | --- |
| 标识 | `profileId`、`kind`、`displayName`、`configVersion` | kind 区分 image/video；版本用于固定请求与恢复路由 |
| 接入 | `adapterKey`、`upstreamModelId`、`connectionRef` | 后端枚举适配器，不允许任意 handler、供应商 URL 或包内代码 |
| 图片能力 | 参考图/编辑/遮罩、允许比例/尺寸、数量上限 | 人工核实并经接口测试；不能靠模型名字猜 |
| 视频能力 | 图生视频、时长/分辨率、音频、取消、异步查询 | 分项布尔/范围，不默认全部支持 |
| 安全限制 | 输入大小、并发、超时、最大预算 | 企业可以收紧，不能突破平台上限 |
| 价格 | `pricingVersion`、单位、估价规则、生效时间 | 按张/秒/次等真实协议，不伪装聊天 token |

图片、视频可使用同一 sub2api 部署，但拥有独立的媒体连接引用/设置；需要不同分组 key 时，分别保存媒体专用 key。所有地址仍必须指向批准的 sub2api，**不是允许管理员在此直填厂商 URL 绕过项目约束**。

具体 key 名、是否共用连接只在拿到部署能力后确定；不能把会话配置的隐式 fallback 当媒体已配好。前台只显示 `configured` 等状态，不回显密钥。

### 5.3 防止污染聊天模型清单

现有聊天列表/runtime 对 enabled 模型的筛选并非全部按用途隔离。新媒体启用逻辑不能自动打开聊天模型；聊天同步即使看到了媒体 ID，也不能将其作为聊天可选项。

需要补回归测试：图片模型启用后不出现在会话列表，企业 `allowedChatModels` 不控制媒体权限，媒体接口不能因聊天模型白名单通过而放行。

### 5.4 运行时只下发“能力”，不下发接入秘密

建议保持当前 `manifestVersion: 1` 的旧客户端响应兼容；通过显式客户端协议能力协商提供扩展清单。新增客户端启用媒体能力时必须验证，不认识协议就提示升级，不能静默降级为脚本直连。

扩展示意，均为**待实现字段**，不是当前 API；下例只启用首期图片，视频确定后再协商扩展：

```json
{
  "media": {
    "protocolVersion": 1,
    "tools": ["media_get_capabilities", "media_generate_image", "media_get_job"],
    "profiles": [
      {
        "profileId": "product-image-standard",
        "kind": "image",
        "configVersion": "cfg_001",
        "capabilities": { "referenceImage": true },
        "allowedAspectRatios": ["1:1"],
        "maxCount": 2
      }
    ]
  }
}
```

上例数值只是协议形状，不是对现有上游的能力承诺。runtime 不含 API key、供应商鉴权、私有内网地址；网关基地址来自客户端可信部署配置，不由 Skill 决定。

## 6. 客户端具体要配合哪些开发

### 6.1 受控工具

工具规划如下；首期图片工具可实现，视频生成工具只保留设计，不能注册到实际允许工具集中：

| 工具 | 作用 | 副作用 |
| --- | --- | --- |
| `media_get_capabilities` | 读取授权 profile 及允许规格 | 不发起收费生成 |
| `media_generate_image` | 提交图片生成/编辑，返回本地 jobId | 需要费用/输入传输授权 |
| `media_generate_video`（后续） | 用已确认图片提交图生视频 | 模型未定，首期不启用 |
| `media_get_job` | 读取本地状态；必要时由调度器查询一次原任务 | 不新建生成 |
| `media_cancel_job` | 停止本地后续动作，按能力请求上游取消 | 不承诺退费或一定取消 |

下载/打开/导出素材走宿主 API 和 IPC；不必把每个 UI 操作都开放给模型。首期也不需要开放自由 curl/bash 能力。

工具业务代码放客户端 service/domain，持久路径与文件操作放 data/runtime，Pi 注册放 `electron/pi/sdk/`。service 不直接 import SDK；通过端口和组装根连接。扩展 `registerTool` 与允许工具集，计划器 `disableTools` 时仍不得暴露媒体工具。

当前 `full-local + auto-approve` 模式会放宽一般工具审批。**媒体费用、报价绑定和硬预算仍必须在媒体服务及网关执行，不能被这个模式绕过。** 普通任务确认也不等于无限额度的所有生成授权；许可应绑定本次规格、输入、次数与有效期。

### 6.2 本地媒体记录

沿用 `ScopePath` 和原子持久化，在企业/成员/任务作用域内加媒体 job 与素材 manifest，不把正文和二进制塞进 `ClientTask.files` 字符串。

**LocalMediaJob 建议字段**：本地 jobId、taskId、runId、subscriptionId、Skill 版本/hash、profile/configVersion、客户端生成的稳定 requestId、请求 hash、原素材 ID、规格、授权/报价 ID、回执 ID、上游状态、轮询时间、保存状态、错误与时间戳。

**LocalMediaAsset 建议字段**：localAssetId、父素材/job、来源（输入/生成）、任务内相对路径、MIME、字节数、宽高/时长、文件 hash、缩略图/封面、保存与缺失状态。

客户端负责维护 job，SEP 回执负责授权和账务归属，二者通过 receiptId 关联。任务恢复后可以使用新 runId，但必须沿用原 jobId/requestId/receiptId，不能因新 run 重新生成。

### 6.3 本地后台调度

- 独立于当前聊天请求和组件生命周期；切换任务、关闭制作面板不停止调度。
- 仅在客户端主进程存活、认证有效时运行，不承诺退出后后台进程继续工作。
- 持久化后再提交；并发有限、查询退避，遵守 `Retry-After`，不持续占用 Pi 推理。
- 上游未完成时，不把依赖成品的步骤记为成功；“等待原任务”不能替换为生成新任务。
- 主进程退出/崩溃时保存或恢复跟踪状态；新启动先展示可恢复任务，再恢复不收费的查询/下载。新生成与创意重做仍需授权。
- 登出/换企业停止当前 scope 的网络活动，防止旧异步响应写进新用户目录。

首期无需新增 Agent 框架、持久系统守护进程或云端队列。

### 6.4 UI 与安全素材访问

首期在现有任务详情/成果面板增加图片网格、大图查看、规格、生成与保存状态、预计/实际费用、导出和重做。支持部分成功和文件被移动/删除后的明确提示。视频播放器/封面与“用此图生成视频”留待视频接入，首期不提供可点击入口。

renderer 只拿安全投影和授权素材句柄。通过受限 IPC/custom protocol 读取批准素材，不能接受任意路径的 `file://`、暴露整个磁盘或由模型传一个 URL 就播放。视频需要支持范围读取，预览对象 URL 用后释放；跨企业引用拒绝。

## 7. 任务生命周期与退出后恢复

生成状态和跟踪状态要分开，避免退出客户端就错误显示“上游取消”。

```text
生成：QUEUED -> SUBMITTING -> RUNNING -> SAVING -> SUCCEEDED
                  |                         |
                  +-> SUBMISSION_UNKNOWN    +-> SAVE_FAILED（仅重试保存）
其他：FAILED / CANCELLED / RESULT_EXPIRED

本地跟踪：ACTIVE / PAUSED / INTERRUPTED / AUTH_REQUIRED
```

状态是建议，不要求一次替换整个客户端任务枚举。上游完成但本地还没保存时，只能显示“生成完成，正在保存”；最终成功以本地文件校验与 manifest 持久化为准。

| 场景 | 处理 |
| --- | --- |
| 切换页面/结束本轮聊天 | 主进程继续查询和保存；依赖步骤等待媒体完成 |
| 完全退出/关机/休眠 | 停止本地跟踪；不自动取消上游，不声称费用停止 |
| 重启且已有 receiptId | 重新鉴权，先查原回执/原上游任务，再下载，不重新提交 |
| 提交成功但响应丢失 | 用原 requestId 查回执；查不到也不证明上游没接单 |
| 已提交但 taskId 丢失/无法查 | 保留 SUBMISSION_UNKNOWN；对账/人工确认前不自动再次生成 |
| 上游任务查询超时 | 退避查原任务；不创建替代生成 |
| 文件保存失败/磁盘满 | 保留原任务和 URL 有效期；修复后只重试下载与保存 |
| 上游结果过期 | 标记 RESULT_EXPIRED；有官方刷新方式则使用，否则说明无法恢复；重新生成必须另行授权 |
| 用户停止任务 | 停止后续本地步骤；是否能取消上游按 profile，显示真实费用状态 |
| 批量 2 张成功 1 张失败 | 交付成功项；失败项单独处置，不重跑整组 |

Runway 官方说明输出 URL 通常在 24-48 小时过期，万相也说明视频 URL 有有效期；这些只证明风险存在，不代表用户上游采用相同期限。[S7][S8]

**本方案不保证关机数天后还能找回结果。** 这是用户选择客户端负责到底的明确限制，应在提交及恢复失败时准确提示。能否刷新链接必须写入实际模型能力表。

同步且无任务查询接口的图片生成，进程退出/响应丢失后可能既拿不到图，也无法判断是否收费。优先使用可查询任务协议；没有幂等/恢复能力时，将其作为已知风险而非承诺“恰好一次”。

## 8. SEP 媒体网关合同草案

以下是建议新增接口，**不是上游厂商 API，也不是当前已有端点**。应用全局 `/api` 前缀按现有部署处理。详细字段与错误处理见 [媒体接口协作合同](../对接/2026-10-12-电商媒体接口协作合同-v1.md)，后续合同修改先更新该文件并同步两端。

| 建议接口 | 令牌 | 行为 |
| --- | --- | --- |
| `GET /client/subscriptions/:id/runtime` 扩展 | 普通 access token | 下发批准 Skill 与媒体能力，无秘密 |
| `POST /gateway/v1/media/references` | 雇佣令牌 | 必要时上传临时参考图，限定企业/成员/订阅及有效期 |
| `POST /gateway/v1/media/quotes` | 雇佣令牌 | 规格校验、服务器估价，返回绑定输入与有效期的 quote |
| `POST /gateway/v1/media/requests` | 雇佣令牌 | 校验、建立幂等回执、转发一次生成请求 |
| `GET /gateway/v1/media/requests/by-client-id/:requestId` | 雇佣令牌 | 找回原回执，不生成 |
| `GET /gateway/v1/media/requests/:receiptId` | 雇佣令牌 | 请求驱动查询原上游任务；返回状态/结算/结果元数据 |
| `GET /gateway/v1/media/requests/:receiptId/outputs/:outputId/content` | 雇佣令牌 | 按归属从已记录结果流式转发，不落成品库、不接受自由 URL |
| `POST /gateway/v1/media/requests/:receiptId/cancel` | 雇佣令牌 | 仅在实际支持时请求取消；不能伪造成功 |

复用雇佣令牌验证，再做当前成员、订阅、媒体 profile 授权和额度检查；客户端声明的企业/成员 ID 不作为鉴权依据。请求/返回用共享 Zod 校验，Swagger 和异常沿用项目规则。

### 8.1 输入和工具返回示意

模型调用本地工具：

```json
{
  "profileId": "product-image-standard",
  "sourceAssetIds": ["local_asset_product_front"],
  "creativeBrief": "明亮厨房，保留杯身形状、颜色与 Logo",
  "aspectRatio": "1:1",
  "count": 2
}
```

`localAssetId` 只在客户端解释。宿主校验后，通过受控上传/请求把参考图传给模型；SEP 不接受该 ID 就去读取客户端路径。

宿主向网关的生成请求示意：

```json
{
  "clientRequestId": "request_immutable_001",
  "profileId": "product-image-standard",
  "configVersion": "cfg_001",
  "quoteId": "quote_001",
  "referenceIds": ["reference_short_lived_001"],
  "creativeBrief": "明亮厨房，保留杯身形状、颜色与 Logo",
  "parameters": { "aspectRatio": "1:1", "count": 2 }
}
```

工具受理返回：

```json
{
  "accepted": true,
  "jobId": "local_job_001",
  "status": "RUNNING",
  "artifacts": []
}
```

前两个请求形状、比例及数量只是说明。实际参数集合按已验证 profile 校验；不开放任意 vendor payload 透传。

模型不提供鉴权 scope、账务金额、secretRef、幂等键或真实 Skill 版本。宿主生成可信 requestId 并绑定批准配置；服务器校验归属、报价与授权。Skill 版本是审计信息，不是权限凭证。

### 8.2 幂等和配置变更

- `(enterpriseId, clientRequestId)` 唯一，另存 requestHash；同 ID 同请求返回旧回执，不同请求返回冲突。
- 创建回执后原子抢占提交；响应丢失不再次创建上游任务。上游幂等能力不足时只能保守处理，不能凭数据库宣称上游一定只接单一次。
- 配置变更后旧回执仍通过原连接/profile 版本查询；禁用模型阻止新生成，不把旧任务迁移到新模型。
- 401 可刷新认证；生成提交重试仍使用原 requestId，不能应用普通聊天自动重试逻辑新建任务。
- 当前授权失效的访问仍按平台权限拒绝；“过期用户能否取回历史结果”不是偷偷新增的权限豁免。如需支持，应另行确认和设计只读取回权限。

### 8.3 输入与输出传输

本地文件默认本地交付，**不代表模型调用完全不经云端**：prompt、必要商品图需通过 SEP/sub2api 传给上游。界面应在生成授权中明确这种传输。

输入优先使用受控二进制上传或短期引用。上游只支持 URL 时，需临时可访问对象或上游素材上传接口；不能把 localhost/本地路径传给云端。临时参考存储有访问隔离、TTL 与删除规则，它不是云端成品库；具体方式待上游协议确定。

输出优先经回执限定的 content 接口流式下载；已由服务器审核的短期结果 URL 可作为特定适配器优化，不能让模型自由指定下载网址。限制域名、重定向、内网地址、大小、超时，禁止透传带上游 key 的 URL。原文件、缩略图、封面均在客户端安全目录落盘。

## 9. 费用、安全与商品质量

### 9.1 费用必须由平台说了算

本节的报价、预算占用与结算机制是工程建议，不代表用户已经确认收费产品规则；实际单价、失败收费和占用期限必须在实施前确认。

分开员工订阅、创作对话和媒体生成。客户端显示和审批，后端按真实报价/账本校验；本地 `budget` 或模型输出的金额不是权威。

提交前绑定报价和预算，生成后按实际协议结算；失败、审核拦截、取消是否收用户费尚未确认，不在这里编造规则。状态不明保留待对账，不立即释放全部预算也不重复扣款。

客户端关闭后，媒体状态和账务可能无法及时更新：如果用量只能在查询响应取得，要等客户端下次查询或经已有财务对账处理。**不能为了记账在后台偷偷新增媒体任务轮询服务。** 冻结最长保留期、人工处理和失败收费规则是上线前需要确认的账务事项。

客户端不能成为唯一用量依据。若 sub2api 已记上游消耗，SEP 消费/核对其真实记录，不再把同一消耗当聊天 token 重复结算。

### 9.2 安全约束

- 上游 key 仅留后端/sub2api，不进入 Skill、renderer、IPC、日志或 Pi 会话。
- 工具 schema、输入文件 scope、允许规格、上传大小、预算同时做宿主与服务端校验。
- 下载写 `.part`，流式校验 MIME/文件头/大小，再原子改名；manifest 成功写入后才宣称交付。
- 用户选中的路径、软链接、ZIP 路径、结果 URL 都视为不可信；不能越出任务和用户授权目录。
- 不自动执行下载 Skill 的脚本；引用资料不获得工具权限，提示词也不能扩大预算。
- 现有监控已可同步部分输入/输出，不把它写成“只有摘要”。新增媒体元数据需要显式协议，二进制和秘密不进入文本监控事件。

### 9.3 电商质量不能只看画面好看

确认用途、目标平台、真实商品图、不可改变特征，再生成。Logo/包装/颜色/比例/配件数逐项检查；价格、规格、促销条件来自用户确认的信息。

生成模型的“保留商品”指令不是像素级保证。准确文字优先后期确定性排版；抠图合成、OCR 或视觉质检只能辅助，发布前仍要人工复核。食品商品不编造配料、功效、认证或包装信息。首期不承诺跨平台通用上架合规。

## 10. 开发顺序与文件边界

下面是建议拆分，不是本次新增的代码文件。不需要一次实现全表或引入新依赖。

| 阶段 | SEP 交付 | 客户端交付 | 通过条件 |
| --- | --- | --- | --- |
| P0 合同与 mock | 按共用合同定义 DTO/Zod、独立图片配置、批准 Skill/runtime 和安全回执 | 按相同 fixtures 开发 runtime 消费、Skill 版本快照、本地 job/asset | 不调用真实模型；共同覆盖异步、同步不可恢复及失败场景 |
| P1 图片实现与本地验证 | profile/企业策略；媒体授权、报价、回执、提交/查询/内容读取及适配器 | 宿主图片工具、审批、查询、保存与图片预览 | mock/单测/typecheck 等通过；无视频可执行入口 |
| P1.5 图片真实联调 | 开发完成后核实测试地址路由、四个模型生成/编辑能力、真实用量 | 验证真实商品图到本地交付、断线与保存失败；只按实测启用能力 | 未证实能力不标已支持，未测模型不标可用 |
| P2 图生视频（暂缓） | 视频模型确定后，在同一合同内加已验证能力 | 确认图片交接、视频跟踪/播放、恢复、结果过期处理 | 不阻塞首期图片上线 |
| P3 有数据后增强 | 需要时补真实定价和更多 profile | 批量模板、确定性图文/字幕、剪辑、配音、多镜头 | 先验证成本、商品一致性和依赖授权，再扩范围 |

### 10.1 SEP 工作范围

- 复用 `modules/setting` 存秘密与配置状态；在 `shared` 增加媒体 DTO/Zod 与公开能力类型。
- 新增 `media-config` 一类小模块维护 profile/企业策略；注册到 AppModule，Prisma 数据经 PrismaService。
- 扩展 `modules/client` runtime 的协商式媒体合同；复用 Skill 审核/分发，补批准包下载权限与 hash。
- 扩展 `modules/gateway` 的媒体受控请求服务，不把 polling processor 放到 `task-execution`。
- 回执与账务复用现有钱包/事务习惯；schema 改动由工具迁移/generate，不手改历史迁移。
- Web 新增独立媒体模型与企业媒体设置视图，使用 TanStack Query/共享 Zod；现有聊天和认证协议不受影响。

### 10.2 客户端工作范围

- `electron/common/platform/`：runtime/媒体 HTTP client，雇佣令牌续期与请求错误合同。
- `electron/service/` 与 `domain/`：媒体用例、授权与预算绑定、状态转换，通过端口访问工具/存储。
- `electron/data/`：沿用 scope/原子文件，媒体 job/asset、版本快照、素材路径与文件操作。
- `electron/runtime/`：生命周期、安全下载与后台调度；关联现有任务等待/退出/恢复。
- `electron/pi/sdk/`：宿主工具注册、允许工具集和实际 Skill 路径注入；保持动态导入边界。
- `electron/controller/`、preload 与 renderer：新增经过 Zod 校验的 IPC/安全投影、媒体任务和成品 UI。

保持 `renderer -> controller -> service -> data/runtime -> pi/sdk` 分层。注册和文件归属按客户端现有边界测试，不为方便从 renderer 引入 Node 或在 service import Pi SDK。

## 11. 联调验收清单

| 检查 | 预期 |
| --- | --- |
| SEP Web 上架员工 | 不启动任何 Pi 会话或媒体后台 worker |
| 媒体模型配置 | 图片/视频独立；API key 不回显，不进入 runtime；聊天列表没有媒体模型 |
| 客户端缺工具/协议旧 | 明确不可用/提示升级，不回退执行 curl/setup |
| Skill 版本 | 合法 frontmatter，引用文件存在，实际版本/hash可追溯；任务中途不被新版替换 |
| 跨企业素材/回执 | 查询、下载、预览、导出均拒绝越权 |
| 审批拒绝/超时 | 不提交、不收费；full-local 也不能绕过媒体硬额度 |
| 连点提交/响应丢失/崩溃窗口 | 原 ID 找回回执，SUBMISSION_UNKNOWN 不盲目再次生成 |
| 结束聊天/切换界面 | 主进程继续原媒体任务；依赖步骤不提前完成 |
| 完全退出后重启 | 查原任务，不自动重新生成；明确过期风险 |
| 登出/令牌过期/切换企业 | 暂停正确作用域，续期不重建生成，旧响应不污染新账户 |
| 上游完成但磁盘满/下载失败 | 只重试保存，无新增上游任务/费用 |
| 部分成功/结果过期 | 成功项可交付；失败/过期准确显示，不伪造完成或永久可下载 |
| 模型配置更新/禁用 | 新提交按新策略；旧回执路由保持原配置，不切换模型重做 |
| 图片/视频安全预览 | 桌面实际预览/播放/导出可用；路径穿越/内网 URL/超大文件拒绝 |
| 费用 | 报价/实际/待对账区分；重复查询或恢复不重复结算 |
| 商品质量 | 形状、颜色、Logo/文字和视频帧一致性有人工复核记录 |

实现时 SEP 跑改动相关后端测试和 Web typecheck；客户端跑相关任务、并发、IPC 边界测试。改 Pi SDK/启动加载须遵守客户端 AGENTS 的 POC01-04/typecheck/build；UI 要实际截图及图片/视频播放验证，不能仅编译通过。
