# 统一模型配置与客户端媒体参数优化开发文档

日期：2026-10-20

状态：第一、二、三批代码、本地 mock 与 Electron 实机验证完成。生产盘点、配置迁移和上线验收仍待执行。本文不代表已经修改生产连接或开放新的模型。

实现范围：统一模型配置入口、独立图片/视频连接、检测后的自动能力同步，以及客户端质量、固定音轨、参数联动和恢复体验。图片/视频独立协商 v2，保留 v1 兼容。本轮修改 SEP 和 Electron；不修改 sub2api，不部署、不发起真实生成或收费请求。

本地实现和验证记录见：[第一、二批开发进度](../progress/2026-10-20-统一模型配置第一二批开发进度.md)、[第三批开发进度](../progress/2026-10-20-客户端媒体参数与恢复体验第三批开发进度.md)。下文“当前实际情况”保留调研时的改造前基线，实际进度以进度记录为准。

## 1. 结论

用户提出的方向成立：**Web 管连接、检测模型；客户端选择本次生成规格。不要让管理员手工创建和维护媒体 Profile。**

但“参数在客户端选择”不等于“规格约束只存在客户端”。服务端必须知道并验证实际支持的参数，才能保证授权、正确转发、报价与扣费一致。

目标分工：

| 位置 | 应负责什么 | 不应负责什么 |
| --- | --- | --- |
| 平台 Web | 会话、图片、视频三个独立连接的 API 地址/key；检测结果和连接状态 | 手工填写 Profile ID、时长列表、尺寸列表、帧率、执行协议等技术规格 |
| SEP 后端 | 模型目录同步、协议适配和能力约束、企业授权、报价、回执、幂等与计费 | 依赖管理员手抄厂商规格；相信客户端声明的能力或价格 |
| Electron 客户端 | 选择模型、生成方式及本次规格；审批、保存、恢复与导出 | 保存平台上游 key；自行扩大模型能力；自行决定收费标准 |
| sub2api | 有效模型目录、上游转发、当前分组的权威报价与实际账务 | 把普通模型列表当成完整能力清单 |

推荐保留现有内部 Profile 数据结构和标识兼容，改为程序自动维护，不再把 Profile 当成用户要操作的产品概念。**取消人工配置流程，不是删除执行合同。**

### 2.3 外部资料的适用边界

- OpenAI 官方 Models List：`https://developers.openai.com/api/reference/resources/models/methods/list`。标准模型对象用于模型身份信息，不是媒体尺寸、时长等完整能力描述。

- 上述资料仅作协议结构参考；`minimax-h3` 在本项目中是经 sub2api/A6 接入的实际模型 ID。官网示例不能证明该别名支持其他时长、分辨率或关闭音轨。
- 价格继续以当前连接、key 所属分组的 sub2api 报价和账务为准，不使用官网公开价格替换。

## 3. 当前实际情况

### 3.1 图片并非完全在客户端配置

图片已经具备正确的部分体验：用户在客户端选择本次生成参数。

但底层仍需要管理员在 Web 维护 `MediaModelProfile`：选择候选模型、创建 Profile、校验、启用，再通过企业策略下发 runtime。因此“图片已完全不需要 Web Profile”并不符合当前实现。

应同时简化图片和视频的后台配置，不能只把视频表单搬走后保留图片的重复操作。

### 3.2 视频已经有客户端规格表单

不需要重新开发视频参数页。现有客户端已经按 runtime 能力展示参数列表；Web 又提供一套填写相同能力列表的表单，造成管理员误以为要手工定义模型规格。

尤其当前真实 H3 只适配以下请求：文生/图生、4 秒、16:9、720p、24fps、带音轨、MP4。管理员即使在 Profile 中添加 10 秒或 1080p，也无法让适配器获得这些能力。

之前成品存在实测 15 秒等输出差异，按已批准兼容策略处理；本轮不改变请求时长、报价口径或已保存文件元数据，不把实测输出反填为新的可请求规格。

### 3.3 地址/key 管理不统一

- 会话连接使用 `SUB2API_BASE_URL` / `SUB2API_API_KEY`。
- 图片连接使用 `MEDIA_BASE_URL` / `MEDIA_API_KEY`，已有 Web 保存接口。
- 视频使用 `MEDIA_VIDEO_BASE_URL` / `MEDIA_VIDEO_API_KEY` 环境变量，没有对应的 Web 保存界面；缺省还会使用图片连接。
- 常规 `SettingService` 是数据库配置优先、环境变量兜底；视频单独直接读环境变量，行为不一致。

应统一管理方式和生效来源显示，三类值仍然独立。统一界面不等于合并三个 key，更不能让客户端直接访问 A6 或厂商。

### 3.4 已发现的能力表达缺口

1. 视频 `supportsAudio: true` 只能表达“支持音频”，不能表达“此模型强制带音轨”。客户端目前可选择无音频，真实 H3 服务却拒绝 `audio: false`。仅搬页面不能解决这一问题。
2. 图片 v1 runtime 的能力字段不包含完整的每模型质量枚举和默认值。客户端 UI 虽支持 `allowedQualities`，真实 runtime 转换却没有产生该字段，因此真实链路目前没有可用的质量选择；HTTP adapter 对未填质量使用 `medium`。图片的 `defaultProfileId` 也未转换到本地能力，表单实际默认首项。
3. 当前多个枚举列表不能表达“某分辨率只允许某时长”之类组合约束。不能默认各列表的任意笛卡尔积都有效。
4. 模型目录出现一个 ID，不等于具备生成、编辑或任务查询能力，也不等于已配置价格。
5. 图片客户端真实分支的报价绑定摘要未纳入 `quality`；网关适配器也重算本地摘要，没有校验服务端 `semanticSha256`。服务端摘要包含完整参数，这不是已证实的服务端错扣费，但开放动态质量前必须修复两端摘要绑定。
6. 图片比例和尺寸目前是独立控件，宿主只验证各自处于允许列表，未验证二者配对；默认尺寸解析还包含固定比例映射。新增尺寸前需要消除“选了横图比例却提交方图”等风险，不能默认适配器的兜底尺寸即用户意图。
7. 视频能力指纹变化会影响客户端授权 revision，历史读取、预览/导出的部分路径还依赖当前可执行 runtime。图片也存在能力缓存与无 Profile 时归档门控的耦合。不能假设后台改为自动同步后，旧任务恢复和本地查看天然不受影响。

这些缺口应在能力合同中修正，不能靠新增后台技术字段让管理员补洞。

## 4. 产品与权限边界

### 4.1 平台 Web 的目标页面

统一为：`系统设置 → 模型配置 → 会话 / 图片 / 视频`。

三个 Tab 各自包含：

- API Base URL、API Key 输入框及保存状态。
- 当前生效来源、最近检测时间、检测错误和刷新入口。
- 检测到的模型列表：名称/ID、已适配/未适配、可用/连接异常等结果。
- 不再出现“导入 Profile → 编辑规格 → 校验 Profile → 启用 Profile”的操作链。

用户只需保存连接并检测；已适配模型的内部记录由程序同步。模型列表可展示只读能力摘要，但不要求填写技术规格。

安全边界：

- 保留已有会话模型的启停、白名单、默认模型等治理能力，不因统一页面自动启用原本禁用的聊天模型。
- 媒体检测成功不自动授权任何企业，不替企业选择默认模型，不打开生产执行总开关。
- 既有人工禁用的媒体模型不能在刷新目录时被自动重新开放；禁用状态作为平台拒绝项保留，不再要求每个新模型逐个手工启用。
- 如需平台媒体停用操作，应归为运维/权限操作，而非恢复 Profile 规格编辑流程。

### 4.2 企业管理与生成规格分离

企业仍然可以管理允许使用哪些模型、允许哪些操作、默认模型、预算和并发等治理限制；界面使用“图片模型”“视频模型”，不暴露 Profile ID。

现有企业尺寸/时长上限等限制在迁移时保留，视作权限上限，不解释为每次生成的默认参数。客户端只能在有效能力与企业限制的交集中选择。

本文不授权将“检测到的全部模型”自动开放给所有员工。若后续要全企业默认开放，应独立定义授权策略，不与本次配置优化绑定。

### 4.3 客户端的目标体验

```text
平台配置对应类型的 API/key 并检测
  → 后端匹配受支持协议，自动维护模型能力
  → 企业已有授权/管理员明确授权后，下发有效模型目录
  → 客户端选择模型与本次规格
  → 后端按相同规格报价
  → 用户审批
  → 原规格提交、保存、恢复与计费
```

模型只有一种合法规格时，显示固定值，不提供无效切换选项。切换模型或操作后重新校验所有选择，不能携带上一模型参数提交。

## 5. 自动能力管理方案

### 5.1 不依赖万能的模型发现接口

当前 sub2api `/v1/models` 不具备完整能力元数据。近期方案不要求先改造 sub2api，也不新增依赖或独立 Gateway。

复用现有图片/视频适配器，将散落的已适配能力收敛到对应模块的受控能力定义，由代码和回归测试维护：

- 精确匹配 `kind + modelId + adapter`；不以名称包含 image/video 就认定可用。
- 返回已验证支持的操作、参数范围、固定值、默认值及组合限制。
- 能力仅描述当前 SEP 适配器真正会发送和验证的协议，不是厂商所有理论能力。
- 同族模型复用定义必须有协议证据；新增别名不能自动继承任意生成/编辑能力。
- 若将来 sub2api 提供正式能力接口，可以作为经版本校验的来源；仍需与本地适配器能力取交集，不能直接信任任意 JSON。

这不是新增人工“发布清单”或 Skill 审批流程，而是复用并整理当前已有的协议校验代码。

### 5.2 自动同步内部 Profile

近期复用 `MediaModelProfile`，保持已有 `profileId`、`configVersion` 和企业 JSON 引用。第一批不删除数据表、不批量改 ID、不要求数据库迁移。

同步原则：

1. 只使用已经保存且当前生效的对应类型连接，前端不向发现接口传临时 key。
2. 拉取目录并匹配适配器能力；未知模型显示“未适配”，不得自动生成可执行授权。
3. 对已适配模型自动创建或同步内部记录，完成以前人工承担的协议/环境检查。
4. 连接校验、模型可见、协议适配与真实生成已验收分开记录或返回，不能用一个“已验证”暗示全部成功。
5. 新记录可以进入平台可供授权的模型列表，但企业允许列表保持原样；runtime 仍按企业授权筛选。
6. 无实质变化的重复检测不轮换 `configVersion`，不影响待审批报价和已冻结任务。
7. 模型消失时停止新任务，不物理删除记录，不把历史任务映射到其他模型。目录请求失败不能被当作成功的空目录批量撤销。
8. 相同模型有多个历史 Profile 时保留旧 ID/授权及其限制。新增默认映射需唯一、确定，冲突报告而非擅自合并。
9. 同步必须具备幂等、并发保护和按类型隔离。旧连接检测返回时若连接已变更，丢弃结果，不能覆盖新连接目录。
10. 当前 Profile 的人工收紧范围不得因自动同步被扩大；历史不兼容配置隔离提示，不用自动“修正”扩大权限。

自动化不得只是删除 Web 按钮却仍要求用户调接口创建、校验、启用，否则目标未达成。

### 5.3 报价按实际选择执行

不再要求管理员校验每个模型的全部参数组合后才能在客户端看到它。已适配模型可以显示“规格报价待确认”，选择具体规格时调用现有报价接口。

- 无副作用的连接/目录检查在检测阶段进行，默认不调用生成或编辑端点。
- 实际参数选择后，后端调用该连接的权威报价；失败或过期就禁止提交。
- 一种规格报价缺失不证明模型所有规格都不可用，也不能推断其他规格免费。
- 价格不是客户端可编辑字段；保持报价版本、有效期、输入 hash、参数和配置版本绑定。
- 不能为提高“检测成功率”放宽当前禁止未知价格、错误模型或不可信报价的校验。
- 现有 `verified` 如继续用于执行门禁，只能表示自动完成的明确前置检查；动态报价保护继续存在，不将其解释为全参数或真实生成验收。
- 开放动态质量前统一两端规范化请求摘要：实际默认质量也应纳入摘要；校验服务端返回的语义绑定，不用另算一份不同语义的 hash 代替。模型、输入、质量等任一改变都不能复用旧报价。采用双方一致的字段顺序/规范化规则及 fixtures，不仅增加一个本地字段。

现有图片 `verifyProfile()` 的全组合报价逻辑不能直接照搬为每次自动刷新流程，应拆分协议检查与按需报价。

## 6. 独立连接实现要求

沿用当前 `SystemSetting` 加密、脱敏、来源展示和事务保存机制，补齐独立视频配置键，不新建一套密钥存储。

| 类型 | 配置键 | 处理方式 |
| --- | --- | --- |
| 会话 | `SUB2API_BASE_URL` / `SUB2API_API_KEY` | 保留现有行为，整合入口 |
| 图片 | `MEDIA_BASE_URL` / `MEDIA_API_KEY` | 保留存储键，界面明确标为图片连接 |
| 视频 | `MEDIA_VIDEO_BASE_URL` / `MEDIA_VIDEO_API_KEY` | 注册为正式设置项，接入 Web 保存和读取 |

具体要求：

- 目标优先级为完整数据库连接对优先、同类型环境变量连接对兜底；避免新地址意外配上旧来源 key。首次保留 key 必须明确当前使用的连接，修改地址/key成对验证和保存。
- 视频不再静默回退图片或聊天连接。生产现有独立视频环境变量可继续兜底；若其他环境历史依赖图片回退，应先明确复制配置并验证，再移除回退，不在部署时直接中断。
- key 留空表示保留，不返回原 key；清空/停用须明确操作，不把展示用掩码当真实 key 保存。
- 来源、配置状态可显示，key、连接指纹、分组私密信息不得下发 runtime 或 renderer。
- 使用 HTTPS 和已有连接安全约束，不接受用户信息段、任意跳转或 vendor payload；连接变化需审计，但不记录密钥。
- 配置更改只使对应类型的新报价/能力检查失效；不能误伤另一类型连接和企业策略。
- 视频冻结连接指纹必须保持可核对。迁移后地址标准化与 key 不变时不能产生无意义路由变更；实际变更后不能拿新 key 查旧任务。

迁移前须盘点进行中的任务。无法安全恢复原路由时应暂停跟踪并给出原因，不能自动重新生成；本次不额外设计长期保存历史明文 key 的机制。

## 7. 合同与客户端改造

### 7.1 第一批保持 v1 的可兼容范围

自动 Profile 和页面整合可以先沿用现有图片、视频 v1 runtime：`profileId`、`configVersion`、operations、capabilities 不变，旧客户端无需知道后台已改为自动维护。

现有调用链、请求 ID、quoteId、receiptId、任务保存和幂等合同不改名。对外 UI 改称“模型”，内部无需立刻把全部 Profile 标识重命名。

单靠 v1 无法完整表达质量枚举、强制音轨和复杂组合约束，不能为了少改协议宣称全部目标已经完成。

### 7.2 能力表达扩展

需要新增严格字段时，使用明确协商的图片/视频 v2，而不是向 v1 严格 schema 偷塞字段。图片与视频独立协商；旧版本和未协商请求继续保持原响应。

v2 的最小能力内容：

| 内容 | 图片 | 视频 |
| --- | --- | --- |
| 允许值 | 尺寸、质量、张数上限、参考图限制 | 时长、比例、分辨率、帧率、格式、参考图限制 |
| 固定值 | 单一输出格式等已锁定项 | 例如 `audio` 固定为 `true`，不能只返回 `supportsAudio` |
| 默认值 | 当前模型的合法质量/尺寸等默认选择 | 当前模型合法默认规格，不拿列表首项默认为业务默认 |
| 操作差异 | 生成与编辑可以有不同输入和参数要求 | 文生与图生可以有不同参数组合 |
| 组合限制 | 特定质量/尺寸/张数组合 | 特定分辨率/时长/音频组合 |

优先扩展现有 DTO 与 fixtures，不引入通用表单 DSL。无组合约束的当前模型不需要复杂规则引擎。

固定音轨问题应作为能力兼容补丁优先处理：在旧合同仍缺表达力时，客户端真实 H3 路径不得展示不可执行的无音频选项；也不能偷偷把用户选择的 false 改成 true 后收费提交。客户端不能可靠识别限制时明确禁用不支持的操作，待新版支持。

### 7.3 Electron 实施要点

- 复用 `MediaArtifactsPanel` / `VideoArtifactsPanel`，不新增第二套规格配置页面。
- 模型列表来自当前授权 runtime；在渲染层、主进程 service、SEP 三层保持相同参数校验边界。
- 图片保留并使用服务端默认模型，不能在转换 runtime 时丢弃 `defaultProfileId`；尺寸与比例联动，默认值在发起报价前解析成唯一且合法的实际参数。
- 用户偏好按企业/成员及模型保存，能力变更后重新验证。不得跨账号复用上游凭据或历史授权。
- 多个合法值显示选择控件；固定值只读展示；二元可选项用开关。强制带音轨不能显示可关闭开关。
- 模型/操作/参考图/参数变化后旧报价和审批立即失效，禁止沿用；审批展示最终实际提交规格。
- Pi 工具和手动表单使用同一有效能力与校验，不允许模型通过自由参数绕过。
- 新任务使用新 runtime；历史任务保留原请求、版本、模型和参数。恢复不能重新套当前默认模型。
- 本地已保存结果仍可离线查看/导出；再次联网查询或重新下载继续服务端验权。撤权不等于删除本地文件，也不意味着可绕过远端权限。

最后一条是优化目标，不代表当前所有视频路径已经满足。应区分“不能创建新任务”“原任务是否仍有读取权限”“当前账号是否有权访问本地文件”，不得把三者都绑在 `executionAvailable=true` 上。目录变化与权限撤销也需分开处理，避免刷新模型列表就使已有本地操作失效。

## 8. 接口与改动入口

### 8.1 接口最小演进

保留现有图片连接接口，新增同构视频连接接口；URL 以工程现有 `/api` 全局前缀为准：

```text
保留 GET/PUT /api/admin/media/connection
新增 GET/PUT /api/admin/media/video/connection
演进 POST /api/admin/media/models/discover
演进 POST /api/admin/media/video/models/discover
```

发现接口从“只返回候选”演进为“检测并自动同步内部模型配置”。这是行为变化，必须更新 Swagger、hooks 和回归测试，返回明确的同步结果、时间及失败原因。

旧 Profile 读接口保留兼容；旧写/校验接口在迁移期只用于受控旧版本兼容，不再是新流程的前置步骤。能力进入自动管理后，旧写接口不得反向覆盖程序能力；应明确限制或拒绝技术能力编辑，并通过测试验证。

企业策略接口继续使用现有 Profile ID 引用，UI 展示模型名称。v2 只在双方实现、fixtures 对齐后开放，不同时改造整个会话模型协议。

## 9. 分批开发与上线

### 第一批：统一入口和独立连接

1. 统一模型配置导航与三个 Tab，保留已有会话治理功能，旧链接兼容跳转。
2. 视频连接正式进入设置系统，补 Web 保存、脱敏、生效来源与独立检测。
3. 完成现有生产配置的脱敏只读盘点；保留现有授权、钱包与执行总开关，不自动变更。
4. 增加对应 DTO、权限、加密、并发保存、连接来源及不同类型互不影响测试。

本批只是配置入口完成，不能宣称已取消人工 Profile 依赖。

### 第二批：自动能力同步，移除人工 Profile 操作

1. 整理已有适配能力，拆分自动前置校验与按规格报价。
2. 实现检测后幂等同步，兼容旧 Profile/企业授权、显式禁用和历史收紧范围。
3. 图片和视频同时移除人工导入、编辑规格、校验/启用前置操作；保留只读状态和异常诊断。
4. 继续使用兼容的 v1 runtime，验证旧客户端和现有任务不被无意义版本变化打断。

### 第三批：能力表达与客户端体验收尾

1. 修复固定音轨、动态质量/默认值及组合参数表达问题，必要时实施独立协商的 v2；先修图片质量的报价摘要绑定，再开放质量选择。
2. 客户端消费能力并联动参数，Pi/手动入口一致，完成界面及重启恢复测试。
3. 客户端新安装包/自动更新单独安排，后端部署不等于客户端用户已获得新版。
4. 本地 mock/跨仓联调通过后，按标准蓝绿流程部署，先无生成验收，再执行单独授权的真实收费验收。

## 10. 验收与风险控制

### 10.1 必须通过的验收

| 场景 | 通过标准 |
| --- | --- |
| 三类连接独立 | 修改视频地址/key不改变图片和会话的有效连接、授权和任务 |
| 新环境只填地址/key | 对已适配模型，保存并检测后自动出现可授权模型，不手工创建 Profile |
| 检测不扩大授权 | 新模型不自动加入既有企业允许列表；已禁用和已收紧规则保留 |
| 目录不是能力 | 混合目录、默认目录、未知模型均不误判为可生成/可编辑 |
| 检测无费用 | 没有生成/编辑/视频创建 POST，没有钱包变更；报价调用可单独审计 |
| 同步幂等/竞争 | 重复检测不新增重复记录、不刷新无变化版本；旧连接响应不覆盖新连接 |
| 检测异常 | 超时不清空有效目录；已确认下线模型阻止新提交，旧记录不删除 |
| 客户端动态选项 | 只展示当前模型/操作合法值；强制音轨无错误开关，换模型清理无效选择 |
| 服务端强校验 | 构造越权或非法规格请求，在生成和计费提交前拒绝 |
| 报价与审批 | 更改任意计费相关输入后重新报价/审批；不存在客户端算价或默认模型回退 |
| 图片质量与尺寸联动 | low/medium/high 和实际默认值进入相同语义摘要；质量变化使旧报价失效，比例与像素尺寸一致，默认模型不丢失 |
| 兼容与恢复 | 未协商/v1/v2/损坏片段按约定处理，旧聊天正常；旧任务查原回执不重复生成 |
| 能力变化与撤权分离 | 无变化检测不改变授权 revision；禁止新生成不误删历史，本地读取和远端恢复各自按对应权限验证 |
| 保存与退出重进 | 文件 hash、已保存状态、历史参数保持；原任务恢复不新增账务 |
| 生产配置迁移 | 新旧连接实际路由一致，密钥不输出、不入 Git，能回滚但不恢复过期能力写入 |

### 10.2 验证执行顺序

先跑对应后端 service/HTTP/DTO 测试、Web hooks/页面测试、客户端 runtime/gateway/service 测试，再做两端 typecheck/build 和实际浏览器/Electron mock 验收。记录执行过的命令与结果，不能把方案里的检查项当作已通过。

真实收费验收需另行明确预算。本轮此前视频验收的 8 美元授权已使用，不能重复生成或沿用该额度；配置检测和 mock 验证不需要新增收费调用。

### 10.3 迁移和回滚

- 新流程上线前导出脱敏的 Profile ID、企业引用、停用状态、能力约束及任务状态盘点，不导出明文 key 到仓库。
- 首期避免破坏性数据库变更；旧 ID、回执、账务唯一约束和历史文件均保留。
- 协议新增字段按版本返回，先兼容再开放；老客户端无法表达新规格时不得错误开放。
- 回滚可恢复旧页面和自动同步开关，但不能把已撤销授权恢复，也不能让旧写接口覆盖新版自动能力。
- 如发现连接变更导致原任务无法查询，应保留原回执、明确暂停，不能重新 POST 任务“补偿”。
