## 1. 这份文档管什么

**SEP 负责把员工和 Skill 安全上架、配置媒体能力、校验权限、转发模型请求并记账；客户端负责真正执行员工、跟进任务和交付图片。**

这份文档可以独立交给 SEP 项目开发。总纲解释整体架构和选型，客户端文档安排客户端任务，共用合同规定 HTTP 行为。本文件不另起一套接口字段；合同有变动时先同步 schema、fixtures 和两份任务书。

### 当前实现边界（2026-10-13）

- 已实现独立媒体连接/图片 Profile 管理、企业媒体策略，以及订阅 runtime 的媒体配置协商。实现位于 `backend/src/modules/media-config/`、`backend/src/shared/media.dto.ts` 和对应 Web 设置页面。
- 协商参数为 `?mediaProtocolVersion=1`；旧客户端不传时不增加 `runtime.media`。配置阶段恒返回 `executionAvailable: false` 与 `tools: []`，不允许客户端据此发起生成。
- Profile 创建时未验证，配置变更可撤销验证；本批没有真实模型验证接口，也没有把候选模型标为可用。
- 已实现批准 Skill 安装分发：独立 `skillArtifactProtocolVersion=1` 协商、按当前订阅授权选择实际生效批准版本、单文件/ZIP descriptor、二进制下载、hash/入口/ZIP 安全校验。实现位于 `backend/src/modules/client/`、`backend/src/shared/client-skill-artifact.dto.ts`。
- 第三批已实现独立图片网关 mock：静态参考上传、模拟报价、幂等提交、请求驱动查询、取消和静态 PNG 下载。仅显式 development/test 开关开启，生产 runtime 仍不可执行；不调用上游、不读写钱包、不保存真实素材，也不改数据库。
- Skill 沿用现有创建、审核与批准版本分发，不新增独立“媒体依赖清单”发布制度。宿主工具白名单、实际 profile 能力和每次网关授权仍须校验，Skill 正文及 `allowed-tools` 不产生执行授权。
- 配置样例为 `backend/src/shared/fixtures/media-runtime-v1.json`；mock 执行字段为 `backend/src/shared/media-gateway.dto.ts` 与 `backend/src/shared/fixtures/media-gateway-v1.json`。真实参考上传、适配器、持久回执和计费仍待实现，收费与结果留存政策仍需确认。

### 1.1 已确认范围

| 事项 | 首期决定 |
| --- | --- |
| 员工形态 | 数字员工 + 电商 Skill + 客户端受控图片工具 |
| Web 职责 | 上架、审核、配置、授权和必要的回执查看，不做生图工作台 |
| 后端职责 | 批准版本分发、runtime、媒体网关、请求回执、权威账务 |
| 执行位置 | Pi、提示词编排、本地任务、轮询、下载、预览、导出全部在客户端 |
| 模型链路 | 客户端 -> SEP -> sub2api -> 上游，不下发供应商密钥 |
| 配置隔离 | 图片/视频入口、默认 profile、授权范围与会话模型独立 |
| 视频 | 不接入、不发布可执行视频能力、不出现可点击的生成视频入口 |
| 验证顺序 | 开发期间 mock/单测；实现完成后才调用真实模型 |

用户已提供测试地址和四个候选图片模型：`gpt-image-2`、`gpt-image-2.5`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`。**已有地址/key 足以作为后续接入测试起点，不要求用户另外编写 API 文档。** 真实路径、生成/编辑协议、查询/取消和价格由研发后续验证，不从模型名推断。地址是否就是产品部署的 sub2api 仍需核实；测试凭据不得进入仓库、文档、mock、日志或客户端。

### 1.2 明确不做

- 不新增 SEP 媒体 worker、定时查询上游、回调驱动的员工流程、云端成品库或独立 Agent 平台。
- 不通过旧 Web 对话执行器、`CapabilityService.execute()` 或 OpenCode 适配器运行新员工。
- 不把图片模型塞进聊天模型列表，不用聊天第一段流响应测试代替图片验证。
- 不运行第三方 Skill 的供应商脚本，不把本机 relay CLI 变成产品依赖。
- 不承诺客户端退出后平台继续制作、自动下载、自动上架或商品像素级不变。

客户端彻底退出、休眠或关机后，本地跟踪停止，但已接单的上游可能继续生成和收费。SEP 保留回执不等于接管任务；客户端重启后查原请求，不自动重新生成。

## 2. 与客户端的开发边界

| 功能 | SEP Web/后端交付 | 客户端必须配合 |
| --- | --- | --- |
| 员工和 Skill | 发布、审核、批准版本、来源许可、hash、工具依赖 | 安装合法入口，冻结实际版本与提示词 |
| runtime | 当前订阅授权下的媒体能力，不含秘密 | 入队前解析、协商协议、检查必需能力 |
| 参考图 | 校验并接收批准图片字节，生成隔离引用 | 用户选择、宿主审批、本地素材 ID 与文件校验 |
| 报价与提交 | 权威报价/硬限制、幂等回执、受控转发 | 费用审批、稳定 requestId、先落本地意图再提交 |
| 查询与恢复 | 被客户端请求时查原任务、更新回执 | 调度、退避、断网/重启恢复、禁止盲目重发 |
| 内容交付 | 归属校验后按请求提供内容，不自主收成品 | 校验、原子落盘、预览、导出和保存失败恢复 |
| 取消 | 有能力才转发取消，返回真实结果 | 区分停止跟踪、取消上游和退款 |
| 用量与费用 | 权威账本、幂等结算、明确待核对状态 | 展示报价/费用，不自行认定免费或已退款 |

**客户端同步开发的先决条件是共用 schema/fixtures，不是真实模型已经测通。** SEP 先提供脱敏 mock，客户端通过 HTTP port 替换实现；两端各自完成本地测试后再联调。

## 4. Web 需要开发什么

### 4.1 平台管理：独立“媒体模型”入口

建议路由 `/admin/settings/media-models`，对应新增 `web/src/app/(platform)/admin/settings/media-models/page.tsx`；最终位置沿用现有导航。这是新页面建议，不是现有路由。不能只把密钥字段埋到“会话模型”表单里。

首期页面分“接入配置”和“图片能力”两部分，使用现有表格、表单、开关、菜单和 TanStack Query hooks：

| 区域 | 需要的操作与状态 |
| --- | --- |
| 接入配置 | 选择批准的 sub2api 连接、配置媒体凭据、显示 configured/未配置；可替换、不回显密钥 |
| 图片 profile 列表 | 显示名称、上游模型 ID、适配器、配置版本、已验证能力、启用状态 |
| profile 编辑 | 生成/编辑、参考图能力、规格、张数、大小、超时和并发等平台上限 |
| 计价配置 | 计价单位、规则版本、生效时间；未知价格明确显示未配置，不显示免费 |
| 验证状态 | 未验证/验证通过/验证失败与验证时间；与 enabled 分开 |

四个候选 ID 可作为待配置清单，不能默认认为已可用。未验证能力不出现在生产 runtime。参考图编辑未验证时，不发布必须依赖该能力的“商品图改造”操作。

页面加载、保存配置、切换启用状态**不能自动调用收费模型**。开发完成后再提供显式测试动作，限制模型、张数与预算并要求确认；测试与生产请求分开标记。视频入口首期不提供可执行配置操作。

### 4.2 企业管理：独立“媒体能力与额度”入口

建议路由 `/settings/media`，对应新增 `web/src/app/(enterprise)/settings/media/page.tsx`。企业管理员只能从平台启用且验证通过的 profile 中授权，不能填写上游地址/key。

- 配置允许的图片 profile、默认图片 profile 和允许的操作。
- 配置单次张数/规格、并发和预算限制；企业限制只能收紧平台上限。
- 展示未配置、无权限、已禁用和价格待确认状态；缺少媒体能力不影响普通聊天。
- 保存时共享 Zod 校验，服务端再校验角色和平台边界；不能只禁用 UI 按钮。
- 聊天设置与媒体设置互不覆盖；媒体默认项不能写入聊天默认模型或 `allowedChatModels`。

预算的金额、周期和成员粒度涉及产品政策，尚未确认的不填虚构生产默认值。可先完成受限字段/schema/mock；开启真实收费前确定有效策略。

### 4.3 员工与 Skill 上架

在原有创建、版本审核、绑定员工和批准发布流程中补齐，不新建“电商员工”平行体系：

1. 明确员工运行位置为客户端，工作说明不承诺云端托管执行。
2. 复用现有批准版本和安装 descriptor，校验入口/包形态、正文及产物 hash；不新增必需工具/操作的独立批准发布清单作为开发前置条件。
3. 保留有效 `SKILL.md` frontmatter；正文提取会剥掉 frontmatter，不能把预览正文直接当可安装原文件。
4. 单文件版应自包含；需要 references 等资源才提供完整包，不能留下不存在的引用。
5. 记录第三方来源、固定 commit、许可证和修改说明；导入方案沿用总纲已核对的候选，不复制供应商认证/收费调用脚本。
6. 沿用现有审核流程；实际导入时检查生成次数/审批规则、提交不明停止规则和禁止绕过网关的指令。执行时由宿主和网关校验工具、profile、操作与权限，不把正文声明当授权。

不为媒体 Skill 另建当前普通 Skill 没有的依赖清单。`product-shots` 工作流与 `open-design` 的商品一致性检查可按总纲方案改编；实际导入时逐文件复核许可，不因为公开可见就复制未授权内容。

### 4.4 回执查看不是任务工作台

首期只需为运维/账务提供按 requestId/receiptId 定位的必要查询能力，可复用既有管理入口。展示归属、模型版本、状态、脱敏错误和结算状态，不展示密钥、临时 URL 或默认暴露完整商品素材。

查看列表/详情不自动轮询上游、不自动下载，也不提供“自动重生成”。完整媒体运营仪表盘不作为首期阻塞项；现有客户端监控不扩展为二进制上传入口。

## 5. 配置、授权与 runtime

### 5.1 三层配置分别存储

| 层级 | 保存内容 | 禁止行为 |
| --- | --- | --- |
| 媒体连接 | 批准 sub2api 地址/连接引用、加密凭据、连接版本 | 允许任意厂商 URL、隐式借用聊天 key、向客户端返回秘密 |
| 平台 profile | kind、上游模型、适配器枚举、configVersion、验证能力/限制、价格版本 | 任意 handler、自动启用 `/models` 发现项、按名称猜能力 |
| 企业策略 | 允许/default profile、操作/规格/预算边界、策略版本 | 把聊天白名单当媒体授权、空列表意外变成全部允许 |

图片和视频可以共用同一个 sub2api 部署，但媒体使用明确的连接引用和配置入口。共用凭据也必须显式配置引用，不能“没填就默认读聊天密钥”。是否需要独立分组 key 由实际部署能力决定。

地址规范化应使用 URL 解析和明确的 base path 规则，覆盖根地址和已有 `/v1`，避免重复拼接。只连接批准 sub2api，不接受 Skill、客户端或普通企业成员指定目标地址。新增设置需进入 `SETTING_FIELDS`、`SETTING_KEYS`、`SECRET_SETTING_KEYS` 等现有注册机制；沿用加密实现，不更换认证主密钥。

### 5.2 版本和旧请求

编辑产生新 configVersion，新请求使用新版本；回执冻结适配器、模型、连接引用/版本、能力和价格版本。不得只保存一个会被覆盖的 profileId，然后用新模型查询旧任务。

冻结的是路由/审计信息，**不是复制明文密钥**。凭据轮换、旧连接保留与任务查询兼容需要有明确策略；旧凭据失效导致无法查询时返回真实状态，不切换供应商后重新生成。禁用 profile 默认阻止新提交，既有回执是否允许查询/下载要与撤权、账务政策一起锁定，不能绕过当前订阅权限。

### 5.3 runtime 与批准包分发

沿用 `GET /client/subscriptions/:subscriptionId/runtime` 的普通 access token 校验。保留 manifest v1，传 `?mediaProtocolVersion=1` 才扩展 `runtime.media`；实际字段及配置阶段不可执行状态已在共用合同落定。

只下发当前订阅可用 profile、configVersion、操作/规格交集、执行模式和能力标记。不下发供应商地址/key；媒体不可用时旧聊天合同仍有效。当前员工提示词来自实时行，`templateVersion` 不代表完整不可变快照，客户端必须保存实际提示词和 Skill 内容版本。

批准 Skill 下载已落地：独立 `skillArtifactProtocolVersion=1` 协商，仅描述当前实际生效批准版本；接口为 `GET /client/subscriptions/:subscriptionId/skills/:capabilityId/versions/:versionId/artifact`，普通 access token、二进制裸响应、逐次订阅 ACL 校验、产物与入口 hash。完整行为及字段以共用合同 2.1 和 shared schema 为准。不能把贡献版本 ID 当 SkillVersion ID，也不能把贡献下载接口无条件开放给订阅成员。不新增媒体工具依赖发布合同；执行权限来自宿主白名单和网关当前授权，不从可变元数据推导。

聊天模型同步、平台列表、企业列表和 runtime 都检查用途隔离：启用媒体 profile 不会启用同名聊天模型，媒体授权不继承 `allowedChatModels`。

## 6. 后端网关与最小持久化

### 本批 mock 边界（2026-10-13）

实现位于 `backend/src/modules/media-gateway/`。只有 `NODE_ENV=development` 或 `test` 且 `MEDIA_GATEWAY_MOCK_ENABLED=true` 才开放；其他环境一律拒绝。接口使用现有 employment token，每次重新检查有效成员、订阅及成员/部门授权。生产 runtime 保持 `executionAvailable: false`，客户端须通过独立测试端口联调，不能据此打开正式工具。

完整启动与场景合同见共用合同 3.1。参考只接受 profiles 返回的固定 1×1 PNG，下载返回同一静态文件；不接收真实商品图。报价和账务均标记模拟，`MOCK_NOT_CHARGED` 不表示正式免费策略。回执、参考与报价只在进程内存，各最多 1000 条；重启或多实例无法保证恢复/幂等，不能以本批测试宣称数据库并发安全或真实生图完成。mock TTL 不代表已批准生产结果缓存。

### 6.1 模块职责

| 模块职责 | 首期交付 |
| --- | --- |
| 媒体配置/策略 | 管理连接与 profile、版本、企业授权、能力交集 |
| runtime/批准分发 | 授权后的清单、合法 Skill 入口、批准包权限 |
| 媒体网关 | 参考上传、报价、提交、查询、内容转发、能力允许时取消 |
| 适配器 | 受控参数映射、sub2api 调用、上游状态/输出/用量规范化 |
| 回执/账务 | 幂等与归属、提交不明、用量证据、去重结算 |

controller 只管 HTTP/Swagger，业务在 service。DTO/Zod 使用 `shared` alias；受保护接口按普通 JWT/平台角色或 employment token 分工鉴权。新模块注册到 `app.module.ts`，数据库统一注入 PrismaService，使用 Nest HTTP exceptions。

### 6.2 建议数据职责，不预先承诺完整表结构

| 建议实体 | 最小信息与边界 |
| --- | --- |
| MediaProfile/版本 | 可用能力、适配器/连接引用、验证和价格版本；秘密留在加密设置机制 |
| EnterpriseMediaPolicy | 企业可用 profile 与收紧限制，不复制聊天配置 |
| MediaQuote | 归属、语义请求 hash、计价版本、金额状态、有效期；不是生成任务 |
| MediaReference | 归属/订阅、内容 hash、MIME/大小、存储引用/有效期；是临时输入，不是素材库 |
| MediaRequestReceipt | 企业/成员/订阅/员工、稳定请求 ID、语义 hash、配置快照、上游 ID、状态和账务关联 |
| Output 元数据 | outputId、MIME/尺寸/有效期、受控上游引用；不默认长期保存图片字节 |

可复用现有实体/存储，不为表格每行机械建一张表。确需新表时使用 cuid、createdAt/updatedAt、snake_case 复数映射；通过 Prisma 工具生成迁移并执行 generate，不手写修改历史迁移。

临时参考的存储方式、TTL、大小、清理与配额在实现前明确，清理器只清临时数据，不查询生成进度。它与同步输出短期缓冲分别设计，不能用“临时”名义无上限保存二进制。幂等/账务记录保留期限与输入/输出字节分开；删除回执前也不能让旧 ID 静默重新生成。

### 6.3 受控 HTTP 行为

端点、请求字段、回执状态和错误码以共用合同第 2 至 5 节为准。首期实现 references、quotes、requests、by-client-id、receipt 查询、output content；cancel 仅在能力支持时可用。

适配器只接受 schema/profile 允许的参数，不透明转发任意 payload。生成和编辑按已验证操作区分；必需参考图不能被静默忽略。保存全部 output 元数据和逐项错误，支持部分成功；上游完成不等于客户端落盘完成。

## 7. 幂等、恢复与同步图片风险

### 7.1 提交顺序

1. 从鉴权上下文取得企业/成员/订阅，校验当前访问授权，先按稳定 clientRequestId 查原回执；唯一键不是访问授权。
2. 若回执已存在，校验原成员/订阅归属和语义一致性后返回，不再次转发；不同语义返回冲突。报价过期、参考字节清理或 profile 更新不能把原订单变成新订单，恢复优先使用按 ID 查询端点。
3. 只有新请求才校验当前 profile/version、报价、参考、规格和硬预算；规范化语义 hash，参考图按内容 hash 参与，瞬时 quoteId、token、重复上传得到的 referenceId 不改变订单语义。
4. 利用 `(enterpriseId, clientRequestId)` 数据库唯一约束和条件更新，持久化回执/提交占有状态后才调用上游；并发插入冲突回到原回执处理，不转发第二次。
5. 转发一次并记录上游 ID、状态和可取得的用量；网络或落库结果不明时保留 `SUBMISSION_UNKNOWN`/待核对，不自动抢占后重提交。
6. 后续由客户端请求驱动查询、内容交付或取消；已有请求不因报价更新、token 续期或配置变化而重新生成。

不要把长时间上游 HTTP 放进数据库事务。测试数据库写入超时但稍后提交成功的窗口；等待超时不代表 underlying write 没发生。接单后响应丢失、收到响应但回执未更新、并发重放都要有独立用例。

没有上游幂等/查询保证时，SEP 只能确保本平台不主动重复转发，不能承诺端到端 exactly-once。查 ID 返回 404 也不是“上游肯定没接单”；提交不明需要保守处理，而不是自动换 ID 重试。

### 7.2 同步与异步不能混为一谈

| 模式 | SEP 行为 | 恢复限制 |
| --- | --- | --- |
| async-query | 保存原上游任务 ID；只在客户端查询时访问上游 | 能否按请求 ID 找回须实测，不自动宣称支持 |
| sync-response | 在本次请求得到图片/URL/错误并记录回执 | 上游无查询能力时，响应丢失可能无法找回 |

**只有回执，不一定有可重取的图片。** 同步 Base64 结果的交付必须先在合同中选定：本次请求受控传输，或有明确 TTL/大小/清理的请求级短期缓冲。前者不能承诺重启可重取，后者需要明确存储和隐私成本；不能默认引入长期云端成品库。

这是 HTTP 实现前的两端对齐项；若涉及新增留存产品政策，先向用户确认。未定之前可以完成 mock/接口骨架，但不发布一个“content 接口存在、实际却无法取回”的生产适配器。四个模型究竟属于哪种模式，开发后验证。

## 8. 账务、安全与可观测性

### 8.1 账务原则

- 媒体按实际协议的张/次/规格或真实用量计价，沿用平台金额单位和精度，不用浮点金额或伪造 token。
- 报价绑定语义请求和计价版本；未知价格为 unavailable，不等于零元。审批不代替服务端余额、企业/成员额度和并发校验。
- 并发请求不能都读到同一余额后超额放行；采用与账本兼容的原子预占/硬限额机制，具体扣费时点和释放规则先确认。
- 同一回执最多结算一次，保留去重键和真实用量证据。失败、部分成功、取消、未知结果分别表达，上游失败不自动推断零费用。
- 现有 `GatewayExecutionService` 面向聊天 usage，`requestId` 普通索引不能代替媒体唯一幂等键；复用其审计/结算思想，不直接塞入媒体请求。
- 已收到的计费证据可做幂等补偿处理；缺少证据标为待核对，不新增自主轮询上游的媒体 worker，也不让客户端上报金额成为扣费依据。

真实收费、失败退款、无报价是否允许调用、额度周期等政策未确认前保持生产关闭。可用 mock 做完流程，不用虚构价格当生产默认，也不把未知调用设成免费。

### 8.2 安全底线

| 风险 | 服务端要求 |
| --- | --- |
| 跨企业/跨成员访问 | 逐次校验 scope、有效订阅和授权，所有 reference/quote/receipt/output 均绑定归属 |
| 越权配置 | 平台管理员维护接入/能力，企业管理员只收紧本企业策略，成员不能配置凭据 |
| SSRF/任意文件读取 | 不接收任意下载 URL/本地路径；引用只指向已登记对象；校验 DNS/IP、重定向和 TLS，避免带鉴权跨主机转发 |
| 超大或伪装文件 | MIME 与文件内容校验、大小/像素/条目限制、流式背压和超时；不在日志输出 Base64 |
| 绕过预算/并发 | 沿用网关准入、认证限流和企业配额；生产不能因测试开关无限制调用 |
| 重启/发布排空 | 停止接纳新提交，正在提交的记录保留可核对状态；断开连接不等于取消上游或可以再发 |
| 秘密泄漏 | 前端只见 configured/脱敏状态，错误脱敏，不记录 key、鉴权头、临时签名 URL |

现有认证 token 存储、refresh cookie、CSRF、聊天 SSE 和网关加固逻辑保持不变；媒体有不同超时/并发需求时单独配置，不直接放宽聊天全局阈值。

日志使用 clientRequestId、receiptId、企业/订阅、profile/configVersion、耗时、状态和脱敏业务码。完整提示词、商品图和输出不默认进入普通日志；必须留存的业务内容另行定义权限和期限。管理页面查看记录不触发上游查询。

## 10. 验收与测试清单

| 类别 | 必测情况 |
| --- | --- |
| 配置/UI | 媒体独立入口、秘密不回显、未验证与启用区分、无自动收费测试、移动/桌面表单可用 |

| runtime/Skill | manifest v1 兼容、协议不支持、撤权/过期、合法 frontmatter、批准 ID/包 hash/ACL |
| 请求安全 | 跨企业/成员引用与下载、任意参数/URL、非法图片、超大上传、过期参考和报价 |
| 幂等/崩溃 | 同 ID 并发只转发一次、语义冲突、响应丢失、晚到数据库提交、查不到回执不盲重发 |
| 模式/输出 | 同步成功/不可恢复、异步查询、部分成功、多 output、下载断开/结果过期、取消不支持 |
| 账务 | 并发余额/额度、报价未知、计价版本固定、重复结算、失败/取消/未知结果不伪造退款 |
| 生命周期 | 客户端退出后 SEP 不自主推进、配置/凭据轮换、服务排空、准入/限流和错误脱敏 |

后端单测与实现同目录 `*.spec.ts`，mock Prisma 和上游，不连接真实 DB/收费模型。数据库唯一约束/事务行为用独立测试环境的集成测试验证，不能只靠 mock 宣称并发安全。Web 验证 hooks/表单与导航，并用实际页面/截图检查布局；两端契约测试复用 fixtures。

按实际改动运行针对性测试及相关检查；以下是实施阶段命令，不表示本文编写时已执行：
