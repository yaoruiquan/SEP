## 契约

- 三端业务状态增加 `INTERRUPTED`；`UNKNOWN` 只保留读取兜底，不接受写入/筛选。
- `completedAt` 只用于 `COMPLETED`、`FAILED`、`CANCELLED`。非终态停止时间放入状态来源证据的 `runEndedAt`。
- `monitor_state`、`content_manifest`、`content_recovery` 使用现有事件 `message` 字段保存受严格校验的 version=1 JSON，最多 1000 字符，必须明确 clientRunId。metadata 不独立更新任务状态、进度或心跳。
- 新正文单片和多片都使用 `content:v1:<稳定编码ID>:<index>:<total>`。编码 ID 只允许字母、数字、下划线和短横线，最多 100 字符。旧消息与替代关系通过同 run/participation 下唯一事件引用核实。
- 列表可选 `stateEvidence` 只取当前 run 最新、且状态匹配的证据；无证据不把默认 0% 当成真实进度。
- 查询新增 `scopeSubscriptionId` 固定范围，与可变 subscriptionId 取交集。`filter-options` 新增 scopeTotal 和 counts.byStatus；各候选忽略自身可变选择，不能解除固定范围。
- `activityAt_desc` 在数据库聚合、排序后分页，返回 activityAt 和 activityTimeSource。只采用明确业务事件发生时间，不以心跳、接收 metadata 或 updatedAt 提升排序。

## 实施要点

- Web 默认全部历史，以单一状态选择替代原来的分类/状态交集。搜索延迟自动生效，下拉立即生效，高级条件折叠；重置、刷新和深链始终保留员工入口的固定范围。
- 详情始终保留输入和员工回复区域，区分完整、部分、待核实、缺片及源正文无法恢复；技术事件折叠，员工使用记录复用同一展示语义，不改用全局详情绕过授权。
- 客户端停止结果保留真实 PAUSED/INTERRUPTED，历史快照不能覆盖已有停止或终态证据；一个 run_completed 不能给多条未知来源回复全部盖上“完整”标记。
- 补传保留原 outbox、镜像、run 和事件身份。已有 outbox 也会对照可归属的本地消息及授权的云端详情补漏，缺少唯一证明时保留歧义而不猜测替代关系。
- 队列区分入队与发送确认指纹。HTTP 接受后本地确认写入失败时保留同一事件重放；确认与重试时间都无法落盘时结束本次发送，不立即循环；失败的 mutation 不阻断后续已排队正文。
- `ClientMonitorService.previewRecovery()` 提供内部只读 dry-run：仅查看当前 scope 的既有存储并计算可规范化操作、消息/片数、metadata、歧义及源缺失数量。outbox 使用只读 inspect，计划使用只读 diagnose，不发送请求、不保存、不启动恢复定时器。账号变化丢弃结果。该入口没有新增 IPC/UI，也没有执行生产预览。
- dry-run 的 `cloudReconciliationRequired` 明确表示尚需授权云端核对，不把本地预测当作云端已确认差异。生产前应将此内部入口接入受控验收工具，并确认实际安装包与部署版本。

## 发布边界

先发布支持新契约的后端，再发布 Web，最后验证新客户端。历史补偿保留原镜像、run 与事件身份，不能清空 outbox、伪造 v2 员工参与或猜测不可恢复正文。新状态入队后不能直接降级到会过滤该 pending 的旧客户端。

生产前仍需确认实际安装包/部署版本，并对有输出、暂停、中断等样本执行只读基线与授权后的补传对账。代码测试通过不等于线上 33 条已经修复。
