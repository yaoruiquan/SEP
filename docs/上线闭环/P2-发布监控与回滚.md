# P2 发布、监控与回滚手册

本手册对应生产脚本 `deploy/production/sep-deploy.sh deploy-bluegreen`。它把候选版本作为隔离环境完成验证，再执行一次整体蓝绿切换；当前不是按百分比逐步放量的流量灰度。

## 发布前检查

1. CI 必须完成 lint、typecheck、unit、build、smoke test 和依赖扫描。
2. 服务器工作树必须已经 checkout 到 CI 通过的完整 commit。通过 `DEPLOY_SHA` 传给部署脚本；脚本会拒绝不同 SHA，且不会在发布过程中再次 `fetch` 或 `merge`。
3. 检查共享 PostgreSQL、Redis、Docker 网络和 Caddy：

   ```bash
   ./deploy/production/sep-deploy.sh status
   docker exec longdao-caddy caddy validate --config /etc/caddy/Caddyfile
   ```

4. 确认备份窗口、数据库迁移风险和当班人员。迁移成功后不能依靠应用回滚自动撤销 schema 变更，必要时先执行隔离恢复演练。

## 发布流程

```bash
DEPLOY_SHA="$GITHUB_SHA" \
SEP_POST_DEPLOY_CHECKS=6 \
SEP_POST_DEPLOY_INTERVAL_SECONDS=10 \
./deploy/production/sep-deploy.sh deploy-bluegreen
```

脚本按以下顺序执行：

1. 校验环境、Compose 边界和 checkout SHA，使用 commit tag 构建候选后端/前端镜像。
2. 执行数据库迁移，启动候选色并等待容器健康。
3. 请求候选后端 `/health/ready`，确认 PostgreSQL、Redis、任务队列、知识队列以及生产模型依赖可用；同时检查候选前端首页。
4. 更新并校验 Caddy 配置，把 Web upstream 和 `/ws/*` backend upstream 一起切到候选色。reload 失败、运行态 upstream 不匹配或校验失败时，脚本会恢复切换前的 Caddy 备份。
5. 在有界观察期内重复 readiness 检查。旧色在观察期和排空时间内保持运行。
6. 观察成功后才停止旧色并写入 active/previous 状态。

## 监控信号与停止条件

发布期间和值班窗口至少观察以下信号：

- `GET /health` liveness 与 `GET /health/ready` readiness；readiness 失败即停止发布。
- 后端/前端容器健康状态、重启次数、CPU/内存上限和日志中的未处理异常：

  ```bash
  docker ps --filter name=sep-
  docker stats --no-stream sep-blue-backend sep-blue-web sep-green-backend sep-green-web
  docker logs --since=10m sep-blue-backend
  ```

- Caddy 错误日志、5xx、请求延迟和 WebSocket 建连失败。切换后应分别验证页面请求、`/api` 请求和 `/ws/employee-status`、`/ws/notifications`。
- PostgreSQL/Redis 可用性、任务/知识队列积压、模型中转和 Embedding 依赖。任一队列不可用时不接收新任务。

发布后观察失败、readiness 不通过、5xx/延迟持续上升、WebSocket 无法建立、文件上传失败或核心 smoke 流程失败，都应触发回滚判断。生产监控平台应把这些信号接入告警；目前仓库内脚本提供健康检查和日志/容器检查，目标环境的阈值与通知通道仍需线上演练确认。

## 自动和人工回滚

自动回滚发生在候选已切换但有界观察失败时：脚本在旧色仍存活的情况下恢复 Caddy 的 Web/WS upstream，写回 active 状态，并停止候选色。若 Caddy 恢复本身失败，脚本会保留候选色并报错，值班人员必须先恢复 Caddy，再执行人工回滚。

```bash
./deploy/production/sep-deploy.sh rollback-bluegreen
```

人工回滚会重新启动 `previous-target` 对应颜色，重新等待健康和 readiness，再把 Web/WS 一起切回。回滚后保留候选容器日志、Caddy 配置备份、commit SHA、迁移日志和告警时间线，便于根因分析。

## 灰度边界与待演练项

当前“灰度”仅指候选色隔离构建、依赖检查和有界观察；切换动作仍是 Web 与 WebSocket 的整体蓝绿切换，不支持按租户、用户或流量百分比放量。目标生产环境尚未完成真实的发布后告警、自动回滚、数据库迁移失败和 WebSocket 切换演练；完成演练并保存证据前，P2 不能标记为全部通过。
