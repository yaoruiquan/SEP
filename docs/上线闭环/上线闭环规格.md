# SEP 上线闭环规格

## 1. 目标

本规格定义 SEP 从“功能开发完成”到“可公开生产上线”的最低门槛。上线必须同时满足：

- 权限与多租户隔离可证明；
- 计费、订阅、退款和订单状态可追溯；
- 生产依赖、队列、实时连接和文件存储可用；
- 数据可备份、可恢复、可回滚；
- 核心用户流程有浏览器级回归证据。

能力适配器覆盖不完整（RPA / AI_APP / SKILL）不属于本阶段阻断项，按现有产品决策暂不纳入本规格。

## 2. 上线门禁

### P0：阻断上线

1. **平台权限**
   - 公告创建、修改、删除、发布、后台查询仅允许 `ADMIN`。
   - 钱包手动调账仅允许 `ADMIN`，请求必须经过 DTO 校验并记录审计。
   - 成本分析所有接口必须从当前用户服务端解析企业，不接受客户端传入企业作为授权依据。
   - 数字员工内部详情与公开市场详情分离；公开接口不得返回 `systemPrompt`、`modelId`、密钥或内部配置。

2. **订阅与计费**
   - 所有使用入口同时校验 `status=ACTIVE`、`endDate` 未到期和有效授权。
   - 多周期订单的退款金额必须基于实际订单金额/订阅快照，不能固定使用年费。
   - 支付回调、主动对账、重复通知必须幂等；履约失败必须允许重试并产生告警。

3. **生产配置**
   - `JWT_SECRET` 缺失、过短或使用默认值时，生产启动失败。
   - 所有模块从同一配置源读取 JWT 密钥，不得存在默认密钥回退。
   - 生产前端必须显式配置 `NEXT_PUBLIC_WS_URL`，使用 `wss://`。
   - CORS 变量统一为 `CORS_ORIGIN`，生产不得回退 localhost 白名单。
   - 普通和蓝绿生产 Compose 统一使用 `SEP_DB_USER` / `SEP_DB_PASSWORD` 低权限数据库账号。

### P1：上线保障

- `/health` 作为 liveness；新增 readiness 检查 PostgreSQL、Redis、sub2api、Embedding 和队列。
- Redis/队列不可用时生产拒绝接收任务，不得静默降级为进程内执行。
- 审计日志的写入失败策略、保留期限、清理任务和告警明确化。
- 登录、上传、支付、邀请和模型调用接口具备限流、请求体上限和统一异常格式。
- WebSocket 不在 URL 查询参数中长期传递访问令牌，并校验 Origin。
- 完成 PostgreSQL、上传文件、员工包的备份恢复演练，记录 RPO/RTO。
- 完成支付宝沙箱/生产回调验收和异常订单人工处理流程。

### P2：规模化与运营

- WebSocket 员工状态和通知广播避免按在线用户高频查库。
- 成本、用量、审计查询具备索引、分页上限和慢查询监控。
- Docker 运行容器使用非 root 用户；镜像使用固定版本或 digest。
- CI 固定执行 lint、typecheck、unit、build、smoke test 和依赖漏洞扫描。
- 完成灰度发布、自动回滚和发布后告警手册。

## 3. 本阶段实施顺序

### 阶段一：P0 安全与生产阻断

- 平台角色守卫补齐；
- 成本分析改为服务端企业上下文；
- 数字员工内部响应字段收敛；
- 订阅到期和多周期退款规则修正；
- JWT fail-fast；
- 生产 WebSocket/CORS/数据库变量统一。

### 阶段二：P1 可靠性与验收

- readiness 与依赖检查；（已完成基础 PostgreSQL/Redis 检查）
- 生产队列 fail-fast；（已完成 Redis 不可用时 503）
- 审计可靠写入/清理；
- 安全基础设施；
- 备份恢复与支付回调演练；
- Playwright 核心流程。

### 阶段三：P2 性能与运维

- 压测、索引和状态广播优化；
- 监控、告警、灰度和回滚；
- 文档、值班和故障处理手册。

## 4. 验收证据

每个门禁必须至少有一种可复核证据：

- 自动化测试：权限、越权、状态机、计费和幂等；
- 类型检查、构建和静态扫描输出；
- 生产配置检查结果；
- Playwright 流程录屏/报告；
- 备份恢复演练记录；
- 支付回调和队列故障演练记录。

## 5. 发布停止条件

出现以下任一情况，停止发布并回滚到上一版本：

- 任一跨企业读取或写入测试失败；
- 支付成功但订阅/钱包未履约且无法自动重试；
- readiness 不通过或队列不可用；
- 数据库迁移失败；
- WebSocket、HTTPS Cookie 或文件上传在生产域名下不可用；
- 核心 Playwright 流程出现未解释失败。
