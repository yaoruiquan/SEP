# P1 备份恢复与支付演练

## 备份策略

- PostgreSQL：每天一次 `pg_dump` custom 格式，保留 30 天；上传目录同步保存压缩包和 SHA-256 校验文件。
- RPO：最多 24 小时（正式接入对象存储后目标降为 1 小时）。
- RTO：数据库恢复目标 60 分钟，应用重新部署目标 30 分钟。
- Redis 不作为事实数据备份；任务和会话状态以 PostgreSQL 为准。

生产备份：

```bash
cd /opt/sep/app
./deploy/production/backup-sep.sh
```

恢复必须先在隔离数据库演练，禁止直接覆盖线上库：

```bash
CONFIRM_RESTORE=YES ./deploy/production/restore-sep.sh /opt/sep/backups/<timestamp>
```

恢复验收至少核对：迁移状态、企业/订阅/钱包记录数量、上传文件 SHA-256、`/health/ready`、登录、对话和通知。

## 支付回调演练

1. 沙箱创建 1/6/12/24 个月订单，确认 `Order.status` 从 `PENDING` 到 `PAID`，订阅保存 `purchaseAmountCNY` 和 `purchasePeriodMonths`。
2. 重放同一个 `trade_no` 两次，第二次必须返回 `success` 且不得重复扣款、发放额度或创建订阅。
3. 让首次履约故意失败，确认通知记录保持 `processed=false`，支付宝重试后能够继续履约。
4. 不发送回调，调用 `/payment/alipay/reconcile`，确认已支付订单被补偿履约。
5. 核对钱包交易、订单、订阅、通知四条记录的关联关系，并记录演练时间、订单号和日志链接。
