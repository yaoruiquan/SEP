## 已实现

| 范围 | 行为 |
| --- | --- |
| 平台设置 | 独立图片模型页面 `/admin/settings/media-models`，不复用会话模型表单；管理连接与图片 Profile |
| 媒体连接 | 独立 `MEDIA_BASE_URL` / `MEDIA_API_KEY`；沿用现有加密存储；接口不回传 key，空 key 保留旧值 |
| 图片 Profile | 创建时未验证；服务端生成 configVersion；更新必须提供 expectedConfigVersion；能力/模型变更撤销验证 |
| 连接变更 | 有效 URL/key 真正变化才撤销 Profile 验证；重复保存相同连接不使版本失效；不读写聊天连接作为媒体回退 |
| 企业设置 | `/settings/media` 设置允许列表、默认 Profile、操作、数量与宽高限制；普通成员只读；企业接口不下发上游 modelId |
| runtime | 仅 `?mediaProtocolVersion=1` 增加 runtime.media；保留 manifestVersion 1 和原有订阅/成员授权；按企业策略取交集 |
| 执行保护 | 当前 executionAvailable 恒为 false、tools 为空；视频不可创建；未配置、未验证或无有效规格时不提供可用 Profile |

共享 schema：`backend/src/shared/media.dto.ts`。客户端解析样例：`backend/src/shared/fixtures/media-runtime-v1.json`。Profile 的配置与验证状态不同，本批没有真实验证接口，不允许手工在 Web 勾选“验证通过”。

## 数据库处理

常规 `prisma migrate dev` 遇到既有历史迁移校验异常，未执行 reset，也未改写历史 migration。本次从 Git 基线 schema 到当前 schema，用 `prisma migrate diff --script --output` 生成迁移，人工核对只包含媒体新增表/列/索引后，在本地 `localhost:5432/sep_platform` 执行：

```bash
pnpm --dir backend exec prisma db execute --schema prisma/schema.prisma --file prisma/migrations/20261012040000_add_media_configuration/migration.sql
pnpm --dir backend exec prisma migrate resolve --applied 20261012040000_add_media_configuration
pnpm --filter backend db:generate
```

本地另有 `20261012025555_add_gateway_execution_journal` 尚未执行，启动后其定时任务会记录 `gateway_executions` 表不存在的错误。本批没有代为执行其他模块迁移，也没有修复其历史迁移问题；不能宣称整个数据库迁移状态已经健康。上述命令仅记录本地处理过程，不是生产环境自动部署方案。
