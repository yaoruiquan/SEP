## 后续与回滚

部署后用户再次反馈发送失败，客户端日志显示 `arrange:confirm-and-start` 在 Skill 下载时抛出 `Skill artifact content length mismatch.`。公开接口复查“UI 设计师”的两份 Skill，响应均为 `Content-Encoding: gzip`、`Transfer-Encoding: chunked`，没有 `Content-Length`；解压后分别为 13388 和 11782 字节，长度与 SHA256 均正确。这是客户端下载器将传输长度误当作文件长度的问题，不是模型请求失败。

客户端本地修复 `electron/common/platform/skill-artifact-api.ts`，并在同名测试文件补回归覆盖：允许缺失传输长度；压缩响应不将线缆长度与解压后文件长度比较；已声明长度仍需合法且不超过 20 MiB + 1 MiB 压缩开销。实际正文仍严格受描述符长度及 20 MiB 上限约束，并验证完整 SHA256、MIME 和校验头，禁止重定向与鉴权约束保持不变。分块压缩响应的原始线缆字节没有独立计数，仍由 30 秒超时约束；解压后字节有独立流式预算。

修复后，使用本地客户端下载函数通过生产公开接口下载两份真实 Skill 均成功；再使用实际 `SkillStore.prepare()` 在隔离临时目录完成两份 Skill 安装及入口 hash 校验，临时目录已清理。没有改用户实际 Skill 缓存或任务，没有发送聊天、图片请求或收费验收。本地开发客户端已自动重载，本次不涉及再部署生产或发布客户端安装包。

客户端验证：下载器、共享合同、Skill 安装与员工授权共 120 项测试通过；另含本地版本存储的首轮相关测试共 67 项通过。`npm run typecheck`、改动文件 ESLint、`npm run check:boundaries` 和 `git diff --check` 均通过。开发主进程增量构建及重载成功，没有执行会重写本地生产 API 配置的打包命令。
