## 二、遇到的问题和解决办法

### 2.1 普通 AI 回复超时 135 秒无响应（P0）

- **现象**：发"你好"后，用户消息入库了，但一直没有助手回复；数据库里只有 `USER` 消息，没有对应 `ASSISTANT`。
- **定位**：`conversation-stream.service.ts` 的 `for await (result.fullStream)` 消费流时，如果 sub2api 抛异常，被外层过大的 `try-catch` 吞掉，前端既收不到 `text_delta` 也收不到 `error`，只能干等到超时。手动 curl sub2api 验证上游本身正常（200，4.5s），确认是应用层问题。
- **解决**：给流消费单独包 `try-catch`，异常时 `yield { event: 'error' }` 并落一条兜底 `ASSISTANT` 消息；同时在关键节点加 `logger.debug`（provider 初始化、stream 创建、finishReason）便于后续排查。

### 2.2 工具调用报 `undefined.id` + 工具名乱码（P0）

- **现象**：触发工具调用时页面出现 `Cannot read properties of undefined (reading 'id')`，工具卡片名显示成 `____`、`tool`。
- **定位**：两个叠加问题。一是 `capabilityByToolName.get(toolName)` 找不到时返回 `undefined`，代码直接访问 `cap.id` 崩溃；二是工具名由 `cap.name.replace(/[^a-zA-Z0-9]/g, '_')` 生成——**中文能力名会被整体替换成下划线**，导致模型回传的 toolName 和映射表对不上。
- **解决**：
  - 执行前判空：`if (!cap) { yield 友好错误; continue; }`，不再裸访问 `.id`。
  - 工具名生成改用 `cap.id`（cuid，纯字母数字，稳定唯一），彻底避开中文转换问题；映射表 key 同步改成 id。

### 2.3 工具结果原始 JSON 泄漏给用户（P0）

- **现象**：聊天区直接显示 `[{"type":"tool-result","toolCallId":...}]` 这种原始数组。
- **定位**：`TOOL` 消息持久化时直接 `JSON.stringify(toolResults)` 存库并透传前端。
- **解决**：存库前转人类可读文本（`🔧 工具: xxx\n📋 结果: xxx`）。**注意**：前端某处仍按 JSON 解析 TOOL 内容，导致天气场景报 `Unexpected token '🔧'... is not valid JSON`——这个已识别，列入下一轮修复。

### 2.4 工具失败后无最终助手回复（P0）

- **现象**：工具失败后流结束，但没有助手总结，留一条空 `ASSISTANT`。
- **解决**：while 工具循环结束后加兜底——若达到 `maxSteps` 仍未产出最终回复，补一条说明性 `ASSISTANT` 消息，保证每轮对话都有收尾。

### 2.5 切换账号后展示上个账号缓存数据（P1，隐私风险）

- **现象**：A 退出、B 登录后，侧栏身份已变但工作台主体仍显示 A 的欢迎语/统计，约 2.6s 不恢复，刷新才对。
- **定位**：`useLogout` 只清了 auth store（内存 token），没清 TanStack Query 缓存，B 登录后命中了 A 的 `['users','me']`、`['subscriptions']` 等缓存。
- **解决**：`useLogout` 的 `onSettled` 里加 `queryClient.clear()`，登出即清空全部查询缓存。

### 2.6 SSR 水合报错 `hydration mismatch`（P2，非代码 bug）

- **现象**：Console 报 `<html>` 属性不匹配，diff 指向 `data-immersive-translate-page-theme="light"`。
- **定位**：「沉浸式翻译」浏览器扩展在 React 水合前往 `<html>` 注入了属性，非应用问题。
- **解决**：`layout.tsx` 的 `<html>` / `<body>` 加 `suppressHydrationWarning`（Next.js 官方对"扩展/主题脚本改 html/body"的推荐做法，只抑制该元素属性层，不影响子树水合校验）。

## 三、开发方法上的改进

### 3.1 建立 `.codeindex` 项目索引，降低 token 消耗

- **背景**：修复时反复分段 `Read` 同一文件、重复 `grep`，单轮烧掉 100k+ token。
- **做法**：GitHub 调研后（ctags/aider repo-map 思路），在项目根建 `.codeindex`——一份纯文本索引，列出核心文件的关键方法、职责、配置位置、最近修复点。后续先读索引（~2k token）定位，再精准读目标行，避免全文件扫描。
- **注**：macOS 自带 ctags 是老版 BSD 版（不支持 `-R`），故用手写索引而非生成式 tags。

### 3.2 修复—验收闭环 + 文档编号

- **闭环**：每轮「测试报告 → 修复清单 → 修复 → 交 Codex 验收 → 验收报告」形成闭环，验收不过的项进下一轮，不靠自测自评。
- **编号**：`docs/test/fix/` 下文档统一 `NN-名称.md` 前缀（00~06），按时间线可追溯，交接时一眼看清顺序。

### 3.3 零依赖 Toast 组件

- 项目是手写 shadcn 风格、无 toast 库。新增 `components/ui/toast.tsx` 用 zustand 存队列 + 纯 CSS 过渡（`tailwindcss-animate` 未装，故不用 `animate-in`），对外暴露 `toast.success/error/...` 命令式 API，挂在 `providers.tsx`。替换了 Coze 导入、员工删除、取消订阅的所有 `alert()`。

### 3.4 native confirm → 应用内确认弹窗

- 测试报告 ADMIN-05：浏览器原生 `confirm()` 导致自动化测试连接超时。删除员工改为应用内确认弹窗（state 驱动），既解决自动化阻塞，也统一了交互风格。

## 四、技术决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 工具名标识 | 用 `cap.id`（cuid）而非 name 转换 | 中文名 regex 转换会全变下划线，id 稳定唯一 |
| Coze PAT 存储 | 混合：优先 `agentConfig.apiKey`，回退全局 `COZE_PAT` | MVP 演示用全局最省事；保留未来贡献者自带凭据的扩展性 |
| 能力接口字段 | `FULL_INCLUDE` 的 `agentConfig` 改精确 `select`，永不返回 `apiKey` | 调研文档反复警告的凭据泄漏漏洞，零成本堵上 |
| 模型目录 | 前后端各存一份 `MODEL_CATALOG` | 前端不直接 import 后端 shared（既有实践是镜像类型） |
| 水合警告 | `suppressHydrationWarning` 只加在 html/body | 扩展注入属性，只抑制属性层不影响子树校验 |
