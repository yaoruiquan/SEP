| B08 存储 | 使用既有 versioned JSON 保存新报价与执行快照；不迁移或重算历史任务，不新增表。 |
| B09 主体 | 复用现有员工订阅 employment token 与真实授权校验；草稿预览不写入配置。独立通用助手账号授权未新增，不允许借用员工身份。 |

## 可核验边界

- 新任务须显式传 protocolVersion:3；runtime 使用 mediaProtocolVersion=3 / videoProtocolVersion=3。旧客户端仍使用其原合同，不能把 V3 规格静默投影为旧默认。
- 当前图片适配器接收 PNG、最多 4 个输出及 4 张参考图；视频原生路径支持单张 PNG 参考图与可安全解析的 MP4。其他格式或数量属于适配器实现边界，返回字段未映射，不是供应商能力结论。
- 图片报价仍需 size（或等价 width/height）、count、quality；视频报价需 durationSeconds 及 resolution（或完整 width/height）。缺失只返回 MISSING_SPEC，不通过收费探测补默认。
- 图片 quality 无法由像素文件实测，因此 acceptance 可以为 unknown；不同输出仍各自带实测宽高。视频 deliveryStatus 为 matched/mismatched/unknown，确认不匹配优先，未知命名分辨率不冒充验证成功。
- 视频时长容差限于一个实测帧时间，避免容器末帧时间误差被当作业务降级；历史 V1/V2 特例仅用于历史合同。
- V3 帧率只容忍有理数测量转数值的舍入误差（1e-6）；30fps 与 30000/1001fps 不视为匹配。
- V3 图片即使收到 4xx 或明确规格错误码，也不凭 HTTP 状态推定未执行或免费；无可信提交前拒绝证据时保留未知状态与预留，后续仅查原请求。
- Sub2API 图片接口目前没有视频同等的提交价格版本保护。SEP 在提交前重新核对图片报价版本和金额，但跨服务读报价到执行之间仍非原子保护；严格上游价格锁定需 Sub2API 配套。
- Sub2API 现有报价范围仍可能限制分辨率、时长、质量和尺寸。没有可核验报价时拒绝收费提交，不将价格合同失败改称供应商规格不支持。

## 本地验证

新增真实 HTTP 集成测试使用生产适配器、生产存储合同及生产文件缓存，数据库和 fetch 上游以测试替身隔离；视频用 ffmpeg 合成 MP4，无真实生成调用。

- 图片：未知配置模型、非旧尺寸/质量、多张输出、dot Profile ID、报价/规格改动、原件下载、实际 usage 结算、幂等重放与规格不符。
- 视频：非 4 秒、竖屏、非 24fps、明确静音，报价→提交→查询→下载→文件实测→usage；8 秒请求得到 15 秒原件仍可下载并独立结算；未指定可选字段不被补齐；WebM 在报价前拒绝。

## 审查与修复

审查基线为 `68d4b5e` 至本次工作区，分项目规范与需求符合性两路独立检查。以下均已补充回归并修复；针对性后端 6 suites、251 tests 通过，随后完成上述全量检查。

### Standards

- 高：图片预留成功后未复查执行授权。现于 dispatch 前重新核验订阅、企业授权、Profile、执行开关及冻结模型，变化时不调用上游并释放预留；覆盖 reserve 等待期间五类撤销/变化。
- 中：视频音轨不符被当成下载安全失败。V3 改为校验缓存与保存的 actualSpec 音轨证据一致；实测不符只影响交付验收。legacy 的音轨校验保留。
- 同步修正新代码的共享 DTO alias 导入，以及管理端连接表单同步 effect lint 问题；不增加依赖。

### Spec

- 高：图片 V3 按 HTTP 状态直接认定拒绝并退款。现仅保留安全错误分类，不据此释放资金；未知提交保留原请求及对账状态，legacy 继续隔离。
- 中：命名 size 与显式宽高可能同时接受但丢掉宽高。报价、执行及配置校验现共用规格解析；无法证明等价的组合在上游请求前返回字段未映射，完整宽高可等价转为 size。
- 中：请求有音轨、产物静音时回执可下载但实际返回 502。已修复同上 Standards 的下载问题；生产 HTTP 回归验证静音原件可下载，另验证缓存音轨证据被篡改时仍拒绝。

两个审查维度分别发现 2 项行为问题与 3 项需求偏差，其中视频下载为同一问题，共 4 项独立行为问题，全部已修复。
