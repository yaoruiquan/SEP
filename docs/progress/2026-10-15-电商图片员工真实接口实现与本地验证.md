# 电商图片员工真实接口实现与本地验证

日期：2026-10-15。状态：SEP、sub2api 和 Electron 客户端的真实接口代码已接线并进行本地回归；尚未部署新 sub2api 接口，尚未进行真实收费生成、参考图编辑或 Electron 真实端到端验收。不得把本记录称为真实闭环已跑通。

## 实现范围

### SEP

- 独立 `/gateway/v1/media/real` 路由，使用 employment 认证和现有订阅/成员授权；与 `/mock` 分离，默认不启用真实执行。上传、报价、提交逐次检查开关和授权；查原回执、原结果补下载仍需授权，但不受新执行开关关闭影响。
- 真实 Profile 必须启用、verified、配置版本匹配且为 `gpt-image-2`。当前仅同步生成/参考编辑，PNG 输入输出；不承诺上游任务查询、取消、批量或视频。
- `sub2api-image.adapter.ts` 通过现有媒体连接获取图片报价，转发生成/编辑并按响应头尽早持久化上游 request ID；结果不明只查原 ID，不补提交。
- 参考字节使用 Redis TTL 15 分钟，结果 TTL 24 小时，下载校验 byteLength/SHA256。数据库只存作用域、配置、引用 hash、回执和账务，不存提示词、图像字节或凭据。Redis 丢失不触发重新生成，不能把 TTL 缓存称为永久存储。
- 新增 `MediaRealReference`、`MediaRealQuote`、`MediaRealRequest`、`MediaRealBillingReservation`。企业/clientRequestId 唯一，回执使用 revision CAS；未知创建结果不得执行。输入和金额/配置先校验，再持久化。
- 报价绑定语义 hash、参考内容 hash、价格版本和有效期，并在服务端冻结汇率；报价只读，不冻结资金、不创建成员额度周期。提交前事务预占：订阅赠送 → 成员企业充值 → 个人钱包，不读企业公共钱包、不新增欠费。
- 结算只接受 sub2api 原请求已提交账务的 USD 实际金额，再按冻结汇率转换；相同回执幂等结算，实际低于预占时按原资金来源退差额。零实际费用可结算，未知价格不允许执行。
- 明确拒绝才释放资金；释放失败继续对账。预占提交结果不明但确认未执行时可安全释放；缺少可靠账单或实际超过预占保留 RECONCILING，不额外扣款。
- 每分钟有界扫描最多 20 行，只处理原请求状态和结算，不执行图片模型。游标按原始行推进，损坏行隔离并记录固定类别告警，避免阻塞后续账务；晚到图片/响应头与超时扫描 CAS 冲突时合并原执行结果，不覆盖已确认的账务终态。
- 共享成员额度统计计入未结算媒体的企业资金预占，不把个人钱包计入企业额度；历史结转显式排除当前预占，防止新周期重复计算。

主要文件位于 `backend/src/modules/media-gateway/media-real*`、`sub2api-image.adapter*`、`media-byte-cache*`、`media-png*`、`backend/src/shared/media-real.dto.ts` 及共享 `compute-credit/member-allowance-window*`。

### sub2api

- 新增 `POST /v1/sub2api/images/pricing`：API key/group/model 范围内只读询价，返回 USD 金额、计价模式、来源、版本和过期时间。缺少可核验图片/次价格时 unavailable，不用聊天 token 默认价或 fallback 授权。
- 新增 `GET /v1/sub2api/usage?request_id=...`：限定当前 key/user，必须唯一归属、模型/图片用量有效且去重账务提交已确认，才返回 settled 和用户实际 billed cost；否则 pending 且无金额。不能用共享 key 的汇总费用差值推断单次成本。
- 主要文件：`backend/internal/{handler,repository,service}/gateway_image_billing.go`、网关路由及 usage 接线；当前仅本地工作区代码，尚未部署。

### Electron

- 新增 `electron/data/sep-real-media-gateway.ts` 及测试，从主进程走真实路由，严格解析真实响应并映射既有本地 job/保存恢复合同；旧 mock 路径保留。
- runtime 为真实图片 Profile 补齐 `image_generate`/`image_edit` 工具接线，不让 renderer 接触媒体 key 或上游 URL。
- 已有保存和恢复继续使用原 request/receipt/output ID；图片成功但账务仍在对账时不能提前停止查询。默认规格必须在请求 hash 计算前统一规范化，避免恢复后误报幂等冲突。
- 下载响应将 401/403/429 分别映射为鉴权失效、权限拒绝和限流，保留已有暂停/显式恢复流程；错误响应体及时取消。读取失败、超出预算、校验失败或消费者提前停止时先取消 reader，再释放锁。
- JSON 响应先验证 Content-Type，再流式限制实际字节不超过 64KiB；不信任 Content-Length，也不使用无界 response.text()，解析与读取错误均脱敏。
