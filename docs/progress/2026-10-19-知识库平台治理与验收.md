# 知识库平台治理与验收

日期：2026-10-19。范围：平台检索限流、历史来源清理、脱敏审计监控、权限和故障回归。未提交 Git，未更改业务数据库或生产环境。

## 实现入口

- `backend/src/modules/knowledge/knowledge-rate-limit.*`：企业/成员双维 Redis 限流、受控 429/503；`SearchController` 与兼容管理员测试入口接入。
- `knowledge-retention.service.ts`、`document-processor.service.ts`：可配置历史截止、独立批量清理、共享原件保护、失败冷却和清理状态。
- `knowledge-telemetry.*`、`knowledge-monitoring.controller.ts`：操作审计白名单、日志脱敏、平台管理员聚合监控和响应内阈值告警。
- `knowledge-search.service.ts`、`knowledge-access-policy.ts`、`lexical-search.service.ts`、`bm25-scorer.service.ts`：实际 token 预算、active 判定、权限复核锁边界、隔离词法打分、依赖故障不伪装无结果。
- `backend/src/common/filters/http-exception.filter.ts`：仅知识库路由保留受控稳定业务错误码；其他业务外壳不变。
- `backend/.env.example`：新增非秘密默认配置；无新增依赖、无 schema 迁移。

## 验收边界

- HTTP 测试使用真实 JWT 签名/验签、Nest controller/guard、Zod 与全局异常过滤器；账户查询、权限解析、检索与额度存储边界为替身。这不等于完整真实 JWT + DB + Redis + sub2api 的端到端验收。
- 专用 DB 测试使用真实 TXT parser、私有文件、PostgreSQL 事务、pgvector、词法查询和清理 SQL；embedding/tokenizer 为明确的测试替身，不能用于评价语义模型质量。
- 真实 Redis 验证跨连接并发配额、企业共享额度、拒绝不扣另一侧、不续 TTL、过期恢复、异常计数器安全拒绝；Redis 未就绪/超时/中断响应由故障注入测试覆盖，未做真实网络故障演练。
- 监控是管理员 JSON 接口，不是新建的 Web 监控页面；告警仅随响应返回，没有外部投递。进程计数会随重启归零，数据库审计窗口与任务积压不受此影响。
- 上述治理批次当时没有配置 tokenizer/固定 embedding 模型。下节记录随后按用户确认完成的本地 Ollama 配置，不追溯扩大上面的数据库验收范围。生产容量配额、备份恢复、长时间并发负载、客户端联合验收和生产发布仍需后续完成。

## 后续补充：独立 Ollama 配置

用户确认 embedding 不来自 sub2api，而是独立 Ollama。已修复此前重构错误地忽略 `EMBEDDING_BASE_URL` 的行为：显式 `EMBEDDING_PROVIDER=ollama` 使用原生 `/api/tags` + `/api/embed`，每批先校验模型 manifest 摘要，关闭自动截断，不读取/转发 sub2api 密钥，也不失败后回退。生成模型出口不变；显式 `sub2api` 保留原 embedding 中转路径，旧 `openai` provider 需要按部署指南迁移。

本地根目录和 `backend/.env` 已配置发布别名 `bge-m3:sep-790764642607`、完整摘要、1024 维/cosine、batch=8、120 秒超时，以及 tokenizer 绝对目录。私密配置没有加入 Git；两个公开 tokenizer 文件保存在被忽略的 `.cache/tokenizers/`，固定 HF commit 并验证 SHA-256。新增可重复执行的准备脚本，生产/dev/蓝绿 Compose 添加配置注入和只读 tokenizer 挂载；没有在服务器应用这些模板，没有部署生产、迁移数据库或重建用户索引。
