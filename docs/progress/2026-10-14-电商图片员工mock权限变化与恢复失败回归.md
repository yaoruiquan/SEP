- 客户端 MediaService 增加 19 项：原批准 Skill/profile 与 run 快照跨重启冻结，新任务才使用新版本；查原请求、查回执和下载阶段的 AUTH_REQUIRED/PERMISSION_DENIED 持久暂停；重启不静默重试，显式恢复原 job 不重新报价、审批或生成。另补两项确定性关闭竞争回归，验证本地会话结束或明确停止不能伪装成网关撤权。

- 真实 Nest HTTP + 隔离 PostgreSQL + 客户端服务/文件持久化联调扩展 3 个场景：接单后撤权，分别发生于回执查询、提交确认丢失与结果下载。真实 MEDIA_FORBIDDEN 映射到客户端授权暂停；重建客户端后不自动重试，恢复 fixture 授权后显式续接，保留原请求、profile、报价、审批与快照，成功保存同一 PNG，额外生成提交为 0。

## Review 加固

独立只读 review 指出版本冻结用例的停止阶段缺少回执落盘 barrier，曾复现身份断言失败；另指出已有 receipt ID 被无条件归一化会削弱断言。已等待原回执存在且 RUNNING 后再停止，直接核对原批准版本快照；只有丢失确认分支允许首次取得 receipt ID，其他分支完整身份必须相等。删除“恢复不调用 authorize”这一超出版本冻结合同的约束，避免把本地快照冻结误写成跳过当前网关验权。

客户端回归和 HTTP/PG 联调都增加了权限已恢复、显式 resume 之前的自动扫描检查：原记录仍暂停，不因授权恢复本身自动重试。

加固后版本用例再次失败，定位到实际恢复缺陷：stopAll 增加 epoch 时，track 若恰好完成当前循环进入下一轮，assert(scope, epoch) 抛出的本地 AUTH_REQUIRED 会被外层 catch 优先标为授权暂停，而非 INTERRUPTED。新增确定性 barrier 回归在旧实现得到 AUTH_REQUIRED、修复后得到 INTERRUPTED 并自动交付原结果。独立复核又指出同一 barrier 下先 stopTask 再 stopAll 的明确停止分支；已补第二项回归并排除 explicitStop 被授权错误覆盖，验证 STOPPED 不自动查询，只有显式 resume 才交付原结果。

修复仅调整 `electron/service/media-service.ts` 外层异常分类：明确 stop 保留 STOPPED，旧 epoch 且不是明确 stop 的活动优先标记 INTERRUPTED；当前 epoch 的真实授权拒绝仍为 AUTH_REQUIRED。若真实授权拒绝与 shutdown 同时发生，外层 catch 优先记为 INTERRUPTED，重启可能查询原任务后再次被网关拒绝；“已记录 AUTH_REQUIRED 的任务仅显式恢复”不无条件扩大到这个竞争窗口。网关恢复过程照常每次验权，不重新提交。

独立最终只读复核确认纯 shutdown 和明确 stop 双分支问题均已闭合，限定修复范围内没有遗留发现；测试与构建结果由主代理实际运行，不把只读 review 当作额外测试。
