# 电商视频员工 V0 第一批开发进度

日期：2026-10-19。对应 [详细开发文档](../development/2026-10-19-电商视频员工详细开发文档.md)。

本批完成的是 mock 基础链路，不是可直接使用的视频员工。未调用真实视频模型、未收费、未部署。

## 已完成

- 视频独立 v1 Profile/runtime/request/quote/reference/receipt/output 合同。严格拒绝图片参数、供应商 URL 和额外字段；覆盖排队、运行、成功、失败、部分成功、未知提交、过期和不可取消。
- SEP 视频 mock HTTP 网关：参考图上传、报价、幂等提交、原请求找回、查询、下载，以及明确拒绝取消。每次调用重查当前成员和订阅授权，生产环境由既有 mock guard 关闭。
- 复用媒体 mock Prisma 表存储元数据，不修改 schema。企业级唯一键、不同语义重放 409、跨作用域隔离、revision CAS、引用过期校验及存储异常 503。提示词和媒体字节不入库。
- 客户端独立 VideoService/VideoStore、显式本地 mock gateway 和绑定订阅的 SEP HTTP adapter。冻结请求先落盘，未知提交只查原请求，重启按原 receipt 恢复，保存失败只重试原输出下载。
- 流式大小/SHA256 校验、容器标记检查、fsync/原子 rename、commit 恢复、缺失文件和损坏证据处理。企业/成员/订阅本地隔离，拒绝路径穿越、符号链接和硬链接。
- 两仓一致的可播放 mock MP4 fixture：离线纯色视频，5 秒、720×1280、24fps、无音频、7295 字节。SHA256：`ba3671acef928d1735491c8cb53995edc860923ba70504f8f6cb525977c98a6e`。

## 双端链路证据

可选测试使用隔离环回 Nest 应用、Prisma 测试替身和临时客户端目录，不接触生产系统：

```bash
SEP_VIDEO_TEST_CLIENT_ROOT=/Users/yao/LLM/sep-client \
  pnpm --dir backend exec jest --runInBand \
  src/modules/media-gateway/media-video-gateway.client-integration.spec.ts
```

实际经过客户端 HTTP adapter → Nest controller → service → Prisma store 编解码 → 异步查询 → 本地保存；在 RUNNING 后重建客户端服务及存储实例，恢复原 receipt 并保存，再次重建仍能读取文件。断言提交、报价、内容下载各一次。另对比两个仓库的 JSON fixtures，防止合同分叉。

该验证没有启动 Electron 窗口，也没有使用真实 PostgreSQL；这两项仍待验收。

## 下一步

### 本轮 Review 修复

- 撤权或认证失效会暂停同一企业/成员/订阅的恢复队列；重建和并发恢复不会继续查询其他任务，需显式恢复。
- 仅当所有非空输出均过期才将整个回执标为 `RESULT_EXPIRED`；单个过期输出拒绝下载，不阻断仍有效的其他输出。
- 显式重试保存可以修复损坏的本地文件：先校验原 manifest/commit/receipt，再隔离保留损坏字节与证据，只下载原回执输出。篡改证据、孤儿文件及链接仍拒绝处理。
- 修复后复验：SEP 视频 5 套件、57 项通过（含双仓 HTTP）；客户端视频 89 项通过；两端 TypeScript、客户端定向 ESLint 和架构边界检查通过。
