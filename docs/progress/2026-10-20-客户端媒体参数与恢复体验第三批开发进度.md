# 客户端媒体参数与恢复体验第三批开发进度

日期：2026-10-20

状态：实现、review、本地 mock 和 Electron 实机验收完成；随第一、二批分别提交 SEP 与客户端，不 push、不部署。本轮没有真实生成和收费请求。

依据：[统一模型配置与客户端媒体参数优化开发文档](../development/2026-10-20-统一模型配置与客户端媒体参数优化开发文档.md)。

## 已完成

- 图片、视频独立协商严格 v2；未协商或 v1 请求保持原响应。两仓使用字节一致的 v2 fixtures；媒体片段异常不破坏旧聊天合同。
- 图片下发模型默认项、尺寸与质量枚举和默认值。客户端优先默认模型，质量默认 `medium`，尺寸和比例双向联动；未知、冲突或过期规格不能进入报价。服务层与 UI 共用参数解析，Pi 和手动提交均冻结实际参数。
- 真实图片报价绑定双方相同的 UTF-8 SHA256 语义：模型配置、操作、按原顺序的参考图摘要、需求摘要以及规范化后的尺寸、数量、质量。客户端核对服务端 `semanticSha256`；中英文及 emoji fixture 覆盖两端一致性。
- 真实 `minimax-h3` 明确下发固定带音轨和既有 4 秒、16:9、720p、24fps、MP4 规格。固定选项只读，宿主拒绝不允许的参数；没有扩展未经验证的新规格。
- 切换模型、生成方式和能力范围后重新校验参数及参考图选择。只保存按企业、成员、媒体类型和模型隔离的参数偏好；不保存 token、需求、参考图或报价。无身份时不持久化；存储异常不阻断创作。
- 视频本地历史、已保存结果预览和导出独立于当前生成能力和员工授权。远端恢复仍验员工身份及原回执权限；授权撤销暂停，授权恢复后需显式恢复原任务，不自动重新生成。
- 已保存输出按 `savedOutputIds` 单独展示。部分保存时，已保存成果仍可预览和导出；重新保存仅针对缺失且未过期的原结果，不因其他已保存文件未过期而错误开放重试。

主要文件：SEP `media.dto.ts`、`media-video.dto.ts`、图片/视频配置服务、`media-real-semantics.ts`；客户端媒体合同与真实网关、`media-service.ts`、`mock-video-host-service.ts`、`employee-authorizer.ts`、生产 bootstrap 接线、图片/视频表单、共享参数 helper 及偏好作用域。
