# 模型网关流式断开修复

## 范围

只修平台模型网关和 Web 转发链路，不改客户端、监控上报 403、模型选择、认证与限流策略。未部署、未修改真实环境配置、未提交 Git。

## 修复

- 后端 `gateway.service.ts`、新增 `gateway-stream.ts`：移除流式请求覆盖整个 body 的 30 秒计时器，分别控制等待响应头、连续无字节空闲和总时长。正常 EOF、异常和取消均清理计时器；客户端断开时取消上游请求。非流式请求保留原有 30 秒上限。
- `gateway.controller.ts`：使用 Node stream pipeline 原字节透传并处理背压，不再逐行重写 SSE，不丢空行、无空格 `data:`、跨块 UTF-8 或 EOF 尾部。观察器仅用于用量和结束诊断，限制解析缓冲大小。
- 读流异常记录请求 ID、上游请求 ID、订阅 ID、模型、耗时和错误类别，异常关闭下游连接，不伪造 `finish_reason` 或 `[DONE]`。正常 EOF 缺少结束标记时告警，不擅自补齐。
- `web/next.config.mjs`：显式设置 external rewrite 的空闲超时。`web/Dockerfile` runner 复制配置，Compose 为蓝绿和开发 Web 服务补齐运行时 `API_ORIGIN`，避免配置加载后回落到 localhost。
- `.env.example`、`backend/.env.example`、`deploy/production/.env.example` 和三份 Compose 增加配置说明及变量透传。

## 默认配置

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `GATEWAY_STREAM_HEADER_TIMEOUT_MS` | 120000 | 等待上游 HTTP 响应头 |
| `GATEWAY_STREAM_IDLE_TIMEOUT_MS` | 120000 | 连续无上游字节 |
| `GATEWAY_STREAM_TOTAL_TIMEOUT_MS` | 600000 | 单次流请求总时长，包含等待响应头 |
| `SEP_API_PROXY_TIMEOUT_MS` | 180000 | Web 外部 API rewrite 空闲超时 |

Web 空闲超时应大于后端空闲/响应头超时。变量均为正整数毫秒且不超过 2147483647；后端非法值拒绝请求，Web 非法值回落默认值。以上均为保护上限，不是重试次数；本次没有新增自动重试。
