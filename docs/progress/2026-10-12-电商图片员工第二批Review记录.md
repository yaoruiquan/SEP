## 结论

代码审查初始为 `REQUEST CHANGES`，确认一个 HIGH 安全缺陷和一个 MEDIUM HTTP 合同缺陷。两个缺陷已修复并由回归验证。修复后综合结论为 `COMMENT / WATCH`：本批分发范围没有已知未修复阻断项；架构可用性观察项及客户端验收仍需跟进。

## 已修复发现

### HIGH：ZIP 本地文件头路径未经一致性验证

原 `readInstallablePackage()` 检查的 `rawEntryName/entryName` 均来自中央目录，`adm-zip.getData()` 不验证本地文件头名称是否相同。将附件本地名称从 `aa/resource.txt` 改为等长的 `../resource.txt`，中央目录仍为安全名称，重算 SHA256 后原实现会接受并原样分发。采用本地名称的解压器可能出现路径穿越；即使客户端拒绝，也违反服务端可安装声明的路径合同。

修复位于 `backend/src/modules/skill-package/skill-package.service.ts` 的 `assertInstallableLocalHeader()`：解压前检查本地头偏移/签名/边界，要求原始名字节与中央目录一致，要求 flags/method 一致，严格 UTF-8 解码并执行安全相对路径检查。仅收紧新安装读取，不改变旧 store/read 的历史兼容规则。

五个包层用例在修复前均失败：恶意及安全的不同名称、flags/method 不一致、两处一致但非法 UTF-8 的名称。修复后通过；新增真实恶意 ZIP 的 artifact service 及 HTTP 回归，确认 `BLOCKED/INVALID_ENTRY` 和 `409 SKILL_ARTIFACT_BLOCKED`，不返回包字节。

### MEDIUM：合法 URL 变体丢失 artifact 409 字段

Express 接受尾斜杠、大小写不敏感及合法 ID 百分号编码，但全局 filter 原正则只匹配字面规范路径，导致 409 没有 `code/reason`。四个 HTTP 用例在修复前均失败。

修复位于 `backend/src/common/filters/http-exception.filter.ts` 的 `isSkillArtifactRoute()`：保留 URI 保留字符，处理合法编码、大小写和可选尾斜杠，维持 ID 长度与允许字符限制。仍只转发已知 code 和 schema 白名单 reason。另补五个负例，确保额外路径、编码分隔符、非法编码、超长 ID 不扩展错误 envelope。

## 架构观察项

- 正文提交不继承父版 ZIP。`parentVersionId` 只提供谱系及来源校验，企业批准复制提交记录自身的包字段。已在 v1 合同、客户端任务书及技能提交对接 v3 澄清；资源引用没有对应包时为 `PACKAGE_REQUIRED`，不拿父包冒充新批准内容。
- 企业审核通过会切换默认，但不预检查安装可用性。历史包与批准正文不一致时可成为默认，随后 runtime 返回 `PACKAGE_CONTENT_MISMATCH`、下载 409。当前失败关闭符合 BLOCKED 合同；本轮不改审核事务及启用策略。后续需考虑审核回执/UI 暴露安装状态，补提交→审核→默认→分发的跨服务回归。
- 协商安装协议的 runtime 同步读取包存储，短暂故障可能导致整个 runtime 503；旧客户端不读取安装包。已在合同明确有限重试，未增加缓存或静默回退。
- 大小写及 Unicode 等价路径可能在不同文件系统发生碰撞。现有服务端重复路径判断是大小写敏感；客户端安全 staging 必须按目标文件系统拒绝冲突、文件/目录覆盖及符号链接。尚未在客户端仓库完成这些验收，不宣称跨平台安装已通过。

这些不是分发权限绕过。S1 来源/许可、工具/操作依赖批准发布元数据及 S2 媒体执行仍是文档已明确的后续工作，不在本轮擅自实施。
