## 本批范围

本地实现统一管理入口、独立媒体连接、检测后的自动能力同步。继续沿用图片/视频 v1 runtime；没有修改 Electron 或 sub2api，没有数据库结构迁移，没有部署、真实生成或收费验收。

## 后端实现

- 视频新增 `GET/PUT /api/admin/media/video/connection`，沿用图片连接共享 DTO、管理员权限和系统设置加密。返回地址、是否配置和来源，不返回 key。
- 图片、视频各自使用完整数据库连接对；未保存时使用同类型完整环境变量对。半对配置或坏密文停止媒体使用，禁止跨来源拼接，视频不再回退图片。
- 保存连接与对应类型能力失效处于同一个 Serializable 事务；保留 key 会固化完整连接。实际连接变化写入脱敏审计；等价路由写法不轮换模型版本。
- 图片/视频检测使用固定连接快照，成功后事务内重新核对连接指纹。连接过时或并发冲突返回 409，不把旧目录落入新连接。
- 新增 `MediaModelSyncService`：只对目录中已适配的模型自动建内部记录；保留历史 ID、企业引用、人工收紧范围和停用状态。成功目录中消失的模型撤销校验，失败请求不清空目录；重复检测无变化时不更新版本。
- 自动记录的技术能力不能通过旧 Profile 写接口修改。企业允许列表和执行总开关仍独立，检测不会自动授权企业。
- 检测只做目录/协议/运行条件检查；不调用生成、视频创建或报价。用户选定实际规格后的报价和审批仍是提交前提。`verified` 表示这些前置条件，不表示真实执行已经验收。

关键文件：`backend/src/modules/setting/setting.service.ts`、`backend/src/modules/media-config/media-model-sync.service.ts`、图片/视频配置 service/controller 和两个 sub2api adapter。

复核修复：真实视频 runtime 在独立连接缺失、坏密文或格式无效时不再下发可执行能力；显式开发 mock 保留原行为。规范化后相同的 URL 不触发版本轮换，大小写敏感路径仍按实际路由区分。

## Web 实现

- 系统设置 → 模型管理统一包含会话、图片、视频三个 Tab。会话地址/key 移入会话 Tab，原有同步、筛选和模型治理保留；通用设置不再重复显示连接。
- 图片、视频各有独立连接表单，显示生效来源。连接读取失败时表单仍可填写完整新连接修复；key 不回显，留空保留。
- 检测后直接显示已同步模型、适配/可用状态及检测时间，取消人工导入、规格编辑、校验和启用前置流程。未知模型不能直接启用；真实生成未验收标记与协议适配状态分开。
- 同模型多条历史配置逐条保留，停用操作只作用于对应记录，不以模型 ID 覆盖历史。原有禁用记录不会因检测重新启用。
- 编辑/保存连接清除旧检测结果；草稿未保存或检测未完成时禁止并发检测/保存。两种媒体复用共享连接 DTO 及相同页面交互。
- 取消独立“图片模型”侧栏入口，旧 `/admin/settings/media-models` 地址跳转到统一图片 Tab。Tab 状态随 URL 更新，配置中心的模型管理链接可正常切换。

主要页面：`web/src/app/(platform)/admin/settings/page.tsx`；新增 `chat-model-connection.tsx`、`media-models-panel-view.tsx`，图片/视频面板复用现有 hooks。
