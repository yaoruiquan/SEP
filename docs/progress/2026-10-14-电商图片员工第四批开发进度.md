## 3. 幂等、竞争与恢复

1. 数据库唯一键为 `(enterpriseId, clientRequestId)`，不是访问授权。先查原记录，校验 scope 与语义；唯一冲突回读原回执，不再次 submit。原参考 ID 相同时使用冻结内容 hash，不因参考/报价过期创建新订单。
2. 只有数据库确认本次 SUBMITTING 插入成功后，才允许调用适配器 submit。数据库失败、插入结果不明、唯一冲突后回读不明，均返回 503 `MEDIA_STORAGE_UNAVAILABLE`；不回退进程内存，不重发，不释放 key。
3. 适配器调用后的最终回写失败仍返回存储 503，不将其误判为可重新提交的适配器失败。客户端保留原 ID 查询；404 也不证明没有接单，不能自动换 ID 重生成。
4. 回执更新使用 `receiptId + revision` 的 CAS，成功递增 revision；竞争失败读取并返回数据库最新记录。查询/取消不能用旧状态互相覆盖，迟到提交结果也不能覆盖已持久化 UNKNOWN；适配器调用不跨数据库长事务。
5. SUBMITTING 保存自占用起两分钟的 submissionDeadline。读取/重放发现超时后持久转 `SUBMISSION_UNKNOWN`（UNKNOWN）；claim 确认返回后、submit 前也检查期限，若确认已超过两分钟则先持久转 UNKNOWN，不 dispatch。errorCode 同名、pollAfterMs=null、canQuery/canCancel/canDownload=false；仍可读取原回执。写入失败返回存储 503，不仅修改返回值。
6. 没有后台计时器、worker 或自动补提；无人读取时不自动转状态，即使可能未实际调用适配器也不抢占后重提。by-client-id 不推进异步适配器，receipt GET 才推进 QUEUED/RUNNING。

## 4. 容量与留存

- 撤销第三批每类单进程 1000 条的容量上限及对应容量不足 429；现有全局默认业务限流仍保留，不能据此宣称生产无限配额。
- 当前不删回执、不释放幂等 key；请求表不通过归属对象关系级联删除。尚无自动数据库清理或生产配额，过期参考/报价也不会自动删除。
- 参考 15 分钟、报价 60 秒、静态输出 5 分钟只用于 mock 有效期判断，不等于到期删库，不是已批准的真实输入/输出缓存政策。
- 跨实例恢复依赖同一已迁移数据库。本批真实 PG 验证使用两独立连接及 service/store/adapter 实例重建，不声称完整进程杀掉重启、Redis 或真实 auth DB/完整应用启动验收，也不承诺真实链路端到端 exactly-once。
