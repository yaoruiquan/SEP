## 2. 本批实现

- 客户端默认同时、独立协商媒体配置和 `skillArtifactProtocolVersion=1`。协议未确认或缺失 descriptor 时明确失败，不猜路径、不退回预览正文。
- 新增严格 descriptor schema，与 SEP 的 AVAILABLE/BLOCKED、路径和体积约束对齐；批准正文 SHA256 与 runtime 原始 UTF-8 内容一致。
- 使用普通 access token 下载批准产物，不用 employment token。保留部署 API 前缀，禁止重定向；复核 MIME、Content-Length、X-SHA256、流式实际长度和实际 SHA256。
- 优先实现自包含单文件：严格 UTF-8、frontmatter、目录名和入口校验，安装原始字节，不改写 CRLF 或批准内容。独立 staging 原子发布到企业/成员/订阅隔离的不可变版本/hash 目录；已有入口不覆盖，损坏则拒绝准备。
- 每次新任务重新下载验权，缓存不替代授权。BLOCKED、撤权及下载失败不得退回旧正文；下载结束检查会话代次，登出后的结果不选中、不用于新账户。
- 员工授权结果冻结实际批准版本、完整 descriptor、入口 hash 和安装路径。核对准备结果与批准资源一一对应，拒绝额外路径及伪造 descriptor。个人本地版本继续走既有自包含路径，但不能冒充批准产物来源。
- 独立 review 发现并修复默认选择阻断批准升版：默认选择记录 `automatic: true`，新任务可随当前批准版本从 v1 升到 v2；显式选择和旧无标记记录视为手动固定，不自动覆盖，不复用已过时批准产物。选择写入串行化，自动升级不能覆盖并发手动选择。已有任务的入口文件和快照不变。
- `MediaService.prepareRun` 继续使用既有 runtimeSnapshot 持久化合同；不修改生产 bootstrap，不开放真实图片工具，不新增依赖或媒体发布清单。

## 4. 明确边界与下一步

- ZIP 的 descriptor 和下载合同可读取，但本批不解压安装 ZIP，明确失败且不降级。需要完整包时另补安全解包和跨平台验收，不能把单文件通过当完整包通过。
- 生产仍 `executionAvailable: false`、`tools: []`，mock 仅由测试显式注入。不得用此进度作为真实图片能力已上线的依据。
- 真实订阅账号登录、Pi 对话驱动图片工具、原生文件对话框、窗口关闭/休眠及退出重启，需要 Electron 实机验收；自动化 service/HTTP 组合不替代该验收。
- 历史选择记录未区分默认与手动，保守当作手动固定；遇到旧批准版本失效需显式选择当前可用版本，不能猜测用户意图自动覆盖。
- 后续真实 sub2api 生成/编辑、权威计费和结果缓存/留存政策尚未完成。本批未读取供应商密钥、未调用收费模型、未修改既有业务数据库或执行迁移。
