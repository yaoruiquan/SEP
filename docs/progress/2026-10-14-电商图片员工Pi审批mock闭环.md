## 实现

- 自编单文件 `backend/test/fixtures/ecommerce-image-mock/SKILL.md`，frontmatter 名称 `ecommerce-image-mock`，不引用外部资源或供应商脚本。要求先读批准入口、再查能力、使用任务内参考 ID、等待宿主审批、保留原 job 恢复，并区分生成、保存与计费状态。正文不产生执行授权。
- `backend/test/prepare-ecommerce-image-mock.mjs` 通过真实 HTTP 走平台创建/批准/绑定、成员提交、企业管理员预览/审核、成员读取实际生效版本。无业务 SQL 写入、auth bypass 或模型调用；失败不自动重试，允许隔离库留有部分记录。
- 复用既有批准 descriptor 下载与安装、冻结快照、Pi 媒体工具、MediaService/MediaStore、任务详情图片面板和恢复机制，不修改生产媒体执行代码。

- 新实机脚本 `scripts/test-electron-pi-media-mock.mjs` 通过实际 conversation task、Pi timeline、renderer 审批和本地文件验证拒绝、参考编辑、异步恢复。静态 1x1 PNG 只证明传输/解码/hash，不证明商品图片质量或真实模型自主选择 Skill。

## 审核与数据隔离

现有平台批准会把新能力置为 `MARKET_PUBLIC`，员工绑定修改全局模板。因此只在本地业务库副本 `sep_pi_media_mock_20261014_02` 执行，不能把独立媒体库误当作业务发布隔离。媒体回执库仍为 `sep_media_mock_20261014`。未在原业务库批准/绑定该能力，未修改原电商 operator Skill。

认证与媒体 helper 均在 review 开关开启时要求同一个显式 `SEP_PI_MEDIA_MOCK_DATABASE`；业务连接必须为 loopback PostgreSQL、精确匹配声明库名且无 `host` query override。审核脚本的 `databaseIsolationVerified:false` 表示脚本本身不能证明服务端 datasource，实际启动配置和原库缺少新能力的只读检查另作证据。

## Review 修正

- Electron 测试 fetch 白名单统一使用 `redirect: 'error'`，防止合法初始地址重定向到外部/模型地址；无实际泄漏证据。
- 两端 helper 共用 review 数据库校验；35 项配置边界测试覆盖声明缺失、错库、远程地址、host override、畸形 URL 和脱敏错误。
- 验收脚本修正 display name/raw/local 版本 ID 的错误等值断言，并保留失败审计。
- 宿主审批与 worker 事件独立写入，sequence 为持久化顺序，不必等于跨生产者发生顺序；按 `occurredAt` 验证生成期间的审批边界，同时保留序号、身份、工具配对与完成顺序检查。新增 4 项回归，不修改 runtime 事件协议。
- runtime 保留真实认证限流。独立场景间等待 62 秒，不设置 E2E bypass、不放宽限制；测试 Web Origin 固定为现有开发白名单 `http://localhost:3000`，不修改 CSRF 策略。
- 重启后工作列表默认进入“需要我处理”，已结束任务会被隐藏；验收通过真实筛选控件切换全部状态/类型并清空搜索，不修改任务或恢复逻辑。
- 独立 review 发现测试子进程可能继承 MCP/远程 renderer 配置，以及 renderer 请求不受主进程 fetch 白名单约束。新增纯策略 helper，清除 `SEP_MCP_CONFIG` / `ELECTRON_RENDERER_URL`，强制关闭 Playwright MCP，入口再校验；在窗口创建前安装 session 请求白名单，仅允许本地 file/data/blob 资源。11 项策略回归和实机外部图片负向探测验证拒绝。该边界不声称操作系统级全进程网络沙箱。
- 测试入口复用正式 `installShutdownHandler()` 等待 `backend.stopAll()`；完成后写本次进程独立 nonce 标记。验收同时要求 exit 0/无信号、标记匹配，拒绝未完成/超时/失败清理，不能仅凭退出码成功。恢复前后另核对原 `receiptId`、`clientRequestId`、request hash、`configVersion` 和冻结 profile hash。
- 原三项网络/环境/关闭问题修复后，独立只读 review 复核 marker 绑定、拦截安装时序、环境 fail-closed 与恢复断言，未发现明确新 bug；实际集成运行由主代理独立完成。
