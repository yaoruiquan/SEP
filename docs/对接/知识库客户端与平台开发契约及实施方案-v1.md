## 2. 已确认的产品边界

### 2.1 用户与权限

本文的“员工”是登录客户端的企业成员，不是硅基员工。

| 操作 | 企业管理员 | 普通员工 |
| --- | --- | --- |
| 查看知识库列表、详情 | 本企业全部 | 仅明确授权给自己的知识库 |
| 查看文档列表、详情、解析预览 | 本企业全部 | 仅已授权知识库内的文档 |
| 检索、查看命中来源 | 本企业全部 | 仅已授权知识库 |
| 创建、修改、删除知识库 | 可以 | 不可以 |
| 上传文件、上传新版本、删除文件、重试处理 | 可以 | 不可以 |
| 查看授权名单、授予和撤销知识库权限 | 可以 | 不可以 |

- 授权粒度是整个知识库，包括其中现有和未来新增文档。
- 授权对象是企业成员记录 `memberId`，不是账号 `userId`、硅基员工 `employeeId` 或订阅 `subscriptionId`。
- 管理员权限仅限本企业。平台运维账号不因全局角色而自动取得企业知识内容访问权。
- V1 不做部门授权、知识库子管理员、单文档授权、个人知识库和跨企业共享。
- 企业中的部门主管等非企业管理员身份，在本模块一律按普通员工处理。
- 成员离职或失去成员身份后，授权立即失效；重新入职生成的新 `memberId` 不继承旧授权。
- 管理员降为员工后，失去隐式全库访问，只保留仍有效的显式成员授权。

### 2.2 包含与不包含

| V1 包含 | V1 不包含 |
| --- | --- |
| 知识库管理、成员授权 | 与硅基员工、订阅、模型绑定 |
| 文件上传、替换版本、删除、失败重试 | 在线编辑 Word/PDF、手工编辑切片 |
| 文件处理状态、失败原因、只读解析预览 | 原始文件下载接口、版本回滚界面 |
| 解析、切片、向量化、版本化索引、混合检索 | URL 抓取、外部数据同步、OCR、复杂表格重建 |
| 命中来源与真实定位信息 | 业务统计面板、面向用户的重建索引配置 |
| 检索结果供后续运行时使用 | 本轮不讨论检索问题如何生成、何时触发、如何注入模型上下文 |

建议首批格式为文本型 PDF、DOCX、UTF-8 TXT、UTF-8 Markdown，单文件最大 10 MiB。扫描 PDF、加密 PDF、旧版 DOC、图片、压缩包和可执行文件不在首批支持范围。**格式与额度是待确认的技术默认值，不是已验证的处理能力。**

撤权、删除能阻止后续读取和检索，不能收回用户之前已读到、已存入历史或已发给模型的内容。客户端应清理本模块内存缓存，但不能承诺远程销毁已有信息。

### 2.3 文件更新语义

1. 普通上传始终创建新文档，同名文件不自动覆盖。
2. 用户在已有文档上选择“上传新版本”，请求明确携带 `docId`，平台据此认定更新对象。
3. 平台计算原始文件 SHA-256；若与当前生效版本字节一致，返回 `unchanged: true`，不新建版本、不重新处理。
4. 文件名相同不代表内容相同；文件名不同也不影响对指定文档进行版本替换。
5. 新版本解析、切片、向量和词法索引全部就绪后一次性发布；构建期间旧版本继续服务。
6. 新版本失败时旧版本保持生效；没有旧版本的文档仍不可检索。
7. 同一文档只允许一个在途版本处理。发生冲突返回 409，不让两个版本争抢发布顺序。

文档 `name` 默认使用首次上传的文件名作为稳定展示名；各版本另存 `originalFilename`，替换时不暗中改文档名称。V1 不单设文档重命名接口。

## 3. 责任划分与客户端所需信息

### 3.1 系统边界

```text
客户端 React 页面
    -> preload 最小 IPC API
    -> Electron controller（输入/响应校验）
    -> service（用例）-> data（平台 HTTP、上传流、令牌）
    -> 平台 JWT 鉴权 -> 企业成员上下文 -> 知识库访问策略
    -> 知识库/文档/授权/检索服务
    -> PostgreSQL + pgvector / 私有原文件存储 / Redis + BullMQ worker
```

客户端不自行切片、生成向量或保存全企业知识索引；平台不信任客户端上传的身份、权限、处理状态和向量。文件必须经平台上传接口进入私有存储，本期不下发公开上传地址或长期可访问的原文件地址。

### 3.2 客户端需要平台返回什么

| 页面或行为 | 必需信息 | 来源 |
| --- | --- | --- |
| 首次打开，包括空列表 | 当前成员身份、能否创建、上传格式/大小限制 | 知识库列表的 `viewer`、`capabilities`、`limits` |
| 知识库列表/详情 | 名称、描述、文档数、更新时间、当前操作权限 | `KnowledgeBase` |
| 文档列表/详情 | 展示名、文件大小、当前生效版本、最新版本、处理阶段、错误及重试能力 | `Document`、`DocumentVersion` |
| 替换/删除/修改前 | 当前编辑令牌、修订号，避免覆盖其他管理员操作 | 详情 `ETag`、资源 `revision` |
| 授权选择器 | 企业成员 ID、名称、头像、岗位、必要的部门显示名 | 成员接口的专用投影 |
| 已授权名单 | 授权对象、授权时间和授权人安全显示信息 | 授权列表 |
| 预览 | 结构化纯文本块、当前位置、分页信息 | 解析预览接口 |
| 检索 | 是否命中、是否未就绪、是否降级、可引用片段与来源 | 检索接口 |
| 点击引用 | 原命中版本的准确片段、定位、是否仍为当前版本 | 来源接口 |
| 失败提示与重试 | 稳定错误码、可显示信息、请求 ID、重试等待时间 | HTTP 错误及响应头 |

列表即使为空，也必须返回创建权限和限制，不能依靠“至少有一个知识库”推断管理员身份。`capabilities` 只用于界面显示，服务器每次仍独立鉴权。

## 4. 通用接口契约

### 4.1 路由、认证与鉴权顺序

- 本文接口路径均省略平台既有 `/api` 前缀；不额外引入一套未经协调的 `/v1` 路由。
- 全部接口要求 `Authorization: Bearer <accessToken>`，令牌仅由客户端主进程持有，不进入 React 状态、日志或 URL。
- 平台根据已验证身份查询当前有效企业成员，生成 `{userId, enterpriseId, memberId, enterpriseRole}`。
- V1 沿用当前单企业上下文，不接受请求体指定 `enterpriseId` 或自报角色；未来多企业切换另行设计受控上下文。
- 权限判断使用企业成员角色，不使用全局 `user.role` 代替。没有有效企业成员关系返回 403 `ENTERPRISE_MEMBERSHIP_REQUIRED`。
- 顺序：认证 -> 企业成员有效性 -> 操作角色 -> 对象归属/授权 -> 输入及业务校验 -> 执行。上传还须在持久化之前校验角色及额度。
- 普通员工调用管理员操作统一返回 403；对于具有读取资格的调用者，资源不存在、跨企业、未授权统一返回 404 `KNOWLEDGE_RESOURCE_NOT_FOUND`，不暴露隐藏资源是否存在。
- 文档和来源必须同时属于 URL 指定的知识库，不能仅凭 `docId` 或 `sourceId` 查到内容后直接返回。
- `/knowledge-bases/search` 注册为静态路由，不能被 `/:kbId` 捕获。

客户端收到 401 复用现有主进程刷新流程，最多重放一次；非幂等写请求必须复用原 `Idempotency-Key`。403/404 不自动重试或重新解释为无命中。

### 4.2 格式与分页

- 成功响应使用平铺业务对象，不新增 `{success,data}` 包装；HTTP 层与客户端现有 IPC 响应封装分开。
- ID 是不透明字符串，不让客户端解析其内部含义；时间是 UTC ISO 8601 字符串；字节数为整数。
- 可选输入字段与明确为空不同；没有值的输出字段按下文 DTO 返回 `null`，不是随意省略。
- 列表采用 `{items,page,pageSize,total}`；默认 `page=1,pageSize=20`，`pageSize` 最大 100，必须为正整数。
- `keyword` 去首尾空格，最多 100 字符；空串按未指定。默认排序 `updatedAt DESC,id DESC`，成员排序 `name ASC,memberId ASC`，授权排序 `grantedAt DESC,id DESC`。
- `total` 只统计当前访问范围，不包含无权限数据。分页不承诺并发写入下的快照稳定性。
- 名称去首尾空格后 1～80 字符，描述最多 1000 字符；按 Unicode 码点计数，不把中文当字节。
- 请求边界使用严格 DTO/schema；未知业务字段报 400，响应允许新增可选字段以便演进。
- 所有知识内容及权限响应使用 `Cache-Control: no-store`；不允许 CDN、公用代理缓存。
- 201 返回 `Location`，202 返回可轮询的文档详情 `Location`，204 不返回 JSON。

### 4.3 修订与并发控制

| 机制 | 使用位置 | 约定 |
| --- | --- | --- |
| `revision` | 知识库/文档资源 | 单调递增整数，不是文件版本号；资源状态或业务数据变化时增加 |
| `ETag` + `If-Match` | 知识库修改/删除、文档删除 | 先 GET 详情取得强 ETag，提交原值；缺失 428，过期 412 |
| `expectedRevision` | 上传新版本、重试处理 | 提交当前文档修订号，数据库事务中比较；不一致 409 |

`ETag` 是不透明的、带双引号的当前详情表示标识，不是简单把一个不会变化的元数据版本号冒充强 ETag。平台对确定性序列化的详情表示计算标识，响应中的状态、计数、权限等变化必须反映到 ETag。`If-Match` 在锁定资源并重新读取当前详情所需状态后比较，与修改处于同一事务；只接受单个强标签，不接受 `*` 绕过检查。

后台处理改变文档状态也可能使修订号/ETag 变化；发生冲突客户端刷新后让用户重新确认，不静默覆盖。知识库文档变动、授权变动与知识库可见统计需按同一锁顺序维护，避免检查和写入之间状态漂移。

### 4.4 幂等与限流

创建知识库、上传文档、上传新版本、重试处理要求 `Idempotency-Key`（建议 UUID，最长 128 字符）。

- 记录键：企业 + 成员 + HTTP 方法 + 规范化路径 + 幂等键；另存请求摘要，包含原文件哈希及业务参数，不包含 multipart 边界。
- 同键同参数返回原 HTTP 状态和业务结果，不重复创建；同键不同参数返回 409 `IDEMPOTENCY_KEY_REUSED`。
- 同键正在执行返回 409 `REQUEST_IN_PROGRESS`，附 `Retry-After`；幂等记录建议保留 24 小时。
- 必须先重新鉴权再回放；资源已删除、成员已离职、权限已撤销时，不回放旧敏感内容。
- 持久化结果与幂等完成记录在同一数据库事务提交；未完成记录有租约和恢复机制，不能永久卡死。
- 客户端主动重新发起一次不同操作时生成新键；网络超时后重试原操作复用旧键。24 小时后不承诺去重，客户端不得无限重放历史写请求。
- 上传、查询、成员搜索分别配置企业级和成员级限流；后台向量化并发另外限制。429 返回 `Retry-After`，不让客户端立即循环请求。

### 4.5 错误响应

现有普通平台 API 错误已有 `statusCode/message/requestId/timestamp/path`，目标在知识库错误上**增补**稳定 `code`，不擅自改成网关使用的另一种错误封装。

```json
{
  "statusCode": 409,
  "code": "DOCUMENT_PROCESSING_IN_PROGRESS",
  "message": "该文档已有正在处理的版本，请稍后再试。",
  "requestId": "req-example-001",
  "timestamp": "2026-10-15T03:00:00.000Z",
  "path": "/api/knowledge-bases/kb_1/documents/doc_1/versions"
}
```

| HTTP | 稳定错误码示例 | 客户端处理 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR`、`MEMBER_SELECTION_INVALID` | 显示参数问题；无效成员批次不部分写入 |
| 401 | `AUTH_REQUIRED` | 主进程刷新一次，仍失败则重新登录 |
| 403 | `KNOWLEDGE_ADMIN_REQUIRED`、`ENTERPRISE_MEMBERSHIP_REQUIRED` | 隐藏不再可用的管理操作，刷新身份 |
| 404 | `KNOWLEDGE_RESOURCE_NOT_FOUND` | 关闭失效详情，移除缓存，不显示对象是否存在 |
| 409 | `REVISION_CONFLICT`、`DOCUMENT_PROCESSING_IN_PROGRESS`、`DOCUMENT_NOT_READY`、`VERSION_NOT_RETRYABLE`、`IDEMPOTENCY_KEY_REUSED`、`REQUEST_IN_PROGRESS`、`QUOTA_EXCEEDED` | 按 code 刷新状态、等待或提示额度 |
| 412 | `PRECONDITION_FAILED` | 刷新详情并重新确认操作 |
| 413 | `FILE_TOO_LARGE` | 展示平台返回的文件大小限制 |
| 415 | `UNSUPPORTED_FILE_TYPE` | 展示平台支持格式 |
| 428 | `PRECONDITION_REQUIRED` | 客户端缺少编辑前置条件，修复调用链 |
| 429 | `RATE_LIMITED` | 按 `Retry-After` 延后，允许用户取消 |
| 503 | `KNOWLEDGE_SERVICE_UNAVAILABLE` | 依赖不可用；不伪装成“未命中” |
| 500 | `INTERNAL_ERROR` | 显示请求 ID，服务端保留脱敏诊断 |

文档异步处理失败通过文档状态返回，不把先前的 202 改成 HTTP 500。业务错误、解析错误均不得向用户返回内部路径、堆栈、数据库语句、供应商凭据或原始上游响应。

## 5. 共享数据对象

下列 TypeScript 是目标字段契约，不是当前客户端已有类型。所有声明字段均必返，只有标注 `?` 的输入可以省略。

```typescript

type Instant = string;
type KnowledgeRole = 'ADMIN' | 'EMPLOYEE';
type ProcessingStatus = 'PENDING' | 'PROCESSING' | 'READY' | 'FAILED';
type ProcessingStage = 'QUEUED' | 'PARSING' | 'CHUNKING' | 'EMBEDDING' | 'PUBLISHING' | 'DONE';

interface Page<T> { items: T[]; page: number; pageSize: number; total: number }
interface Viewer { memberId: Id; enterpriseId: Id; role: KnowledgeRole }

  name: string;
  avatarUrl: string | null;
  position: string | null;
  departmentName: string | null;
}
interface KnowledgePermissions {
  canView: boolean;
  canSearch: boolean;
  canManage: boolean;
  canUpload: boolean;
  canManageGrants: boolean;
}
interface KnowledgeBase {
  id: Id;
  name: string;
  description: string;
  revision: number;
  documentCount: number;
  readyDocumentCount: number;
  createdAt: Instant;
  updatedAt: Instant;
  permissions: KnowledgePermissions;
}
interface KnowledgeLimits {
  allowedExtensions: string[];
  maxFileBytes: number;
  maxFilesPerRequest: number;
  maxQueryCharacters: number;
  maxSearchKnowledgeBases: number;
  maxTopK: number;
  maxResultTokens: number;
}
interface KnowledgeBaseList extends Page<KnowledgeBase> {
  viewer: Viewer;
  capabilities: { canCreateKnowledgeBase: boolean; canListGrantCandidates: boolean };
  limits: KnowledgeLimits;
}
interface SafeProcessingError {
  code: string;
  message: string;
  retryable: boolean;
}
interface DocumentVersion {
  id: Id;
  versionNumber: number;
  originalFilename: string;
  mimeType: string;
  sizeBytes: number;
  status: ProcessingStatus;
  stage: ProcessingStage;
  processedChunks: number;
  totalChunks: number | null;
  error: SafeProcessingError | null;
  createdAt: Instant;
  completedAt: Instant | null;
}
interface Document {
  id: Id;
  knowledgeBaseId: Id;
  name: string;
  revision: number;
  activeVersion: DocumentVersion | null;
  latestVersion: DocumentVersion;
  searchable: boolean;
  permissions: { canReplace: boolean; canDelete: boolean; canReprocess: boolean };

  updatedAt: Instant;
}

}

  pageEnd: number | null;
  sectionPath: string[];
  blockStart: number;
  blockEnd: number;
}

  blockId: Id;
  type: 'HEADING' | 'PARAGRAPH' | 'TABLE' | 'LIST' | 'CODE';
  text: string;
  location: SourceLocation;
}
interface DocumentPreview extends Page<PreviewBlock> {
  documentId: Id;
  versionId: Id;
  documentName: string;
}
interface KnowledgeGrant {
  id: Id;
  member: MemberDisplay;
  grantedAt: Instant;
  grantedBy: { memberId: Id | null; name: string };
}
interface SearchResult {
  sourceId: Id;
  knowledgeBaseId: Id;
  knowledgeBaseName: string;
  documentId: Id;
  documentName: string;
  versionId: Id;
  chunkId: Id;
  content: string;
  tokenCount: number;
  truncated: boolean;
  location: SourceLocation;
}
interface SearchResponse {
  searchId: Id;
  status: 'MATCHED' | 'NO_MATCH' | 'NO_ACCESS' | 'NOT_READY';
  actualStrategy: 'HYBRID' | 'LEXICAL' | null;
  degraded: boolean;
  degradationReason: 'QUERY_EMBEDDING_UNAVAILABLE' | null;
  durationMs: number;
  count: number;
  partial: boolean;
  results: SearchResult[];
}
interface KnowledgeSource {
  sourceId: Id;
  knowledgeBaseId: Id;
  documentId: Id;
  documentName: string;
  versionId: Id;
  chunkId: Id;
  content: string;
  location: SourceLocation;
  isCurrent: boolean;
}
```

约定：`activeVersion` 可以不同于 `latestVersion`；例如 v1 仍生效、v2 失败。`searchable` 由当前生效版本决定，不由最新上传版本决定。`readyDocumentCount` 统计存在生效版本的非删除文档。

普通员工可以看到授权范围内文档的安全处理状态，但看不到任务堆栈和内部作业配置。`error.retryable` 描述技术上能否重试，是否允许当前用户点击重试以 `permissions.canReprocess` 为准。

PDF 页码从 1 开始，块序号从 0 开始，`blockEnd` 为包含端。DOCX/TXT/Markdown 无可靠页码时必须为 `null`，不能编造“第几页”；未知章节用空数组。没有可提取文本时不能构造空切片并发布成功。

## 7. 逐项接口设计

所有接口继承第 4 章的认证、错误、参数边界和缓存约定。下文仅列特有规则。

### 01. 获取知识库列表

`GET /knowledge-bases?page=1&pageSize=20&keyword=产品`

- 管理员查询本企业非删除库；员工由平台按有效成员授权过滤，再计数、分页。
- 结果是 `KnowledgeBaseList`，不得先返回全企业记录让客户端过滤。
- `viewer.role` 是知识库模块归一化角色，不替代平台其他模块的角色体系。
- `limits` 必须来自服务端实际生效配置，客户端不能把文档中的建议值硬编码为服务端能力。
- 第 7 章的请求范围是协议硬上限；部署可以通过 `limits` 进一步收紧，平台与客户端同时遵守实际限制。扩大硬上限需双方重新评审，不能只改单方配置。

空列表示例：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 0,
  "viewer": { "memberId": "member_admin", "enterpriseId": "enterprise_1", "role": "ADMIN" },
  "capabilities": { "canCreateKnowledgeBase": true, "canListGrantCandidates": true },
  "limits": {
    "allowedExtensions": [".pdf", ".docx", ".txt", ".md"],
    "maxFileBytes": 10485760,
    "maxFilesPerRequest": 1,
    "maxQueryCharacters": 1000,
    "maxSearchKnowledgeBases": 100,
    "maxTopK": 20,
    "maxResultTokens": 6000
  }
}
```

### 02. 获取知识库详情

`GET /knowledge-bases/{kbId}`

返回 `KnowledgeBase` 及 `ETag` 响应头。用于详情展示、修改与删除前刷新。客户端不得把列表项中的 `revision` 自行拼成 `If-Match`。

### 03. 创建知识库

`POST /knowledge-bases`，要求 `Idempotency-Key`。

```json
{ "name": "产品知识库", "description": "产品规格与售后规则" }
```

`description` 可省略，默认空字符串。企业、创建成员和权限由平台填入，不接受客户端指定。返回 201 `KnowledgeBase`，`Location` 指向详情；名称非唯一标识，V1 允许同企业同名。

### 04. 修改知识库

`PATCH /knowledge-bases/{kbId}`，要求 `If-Match`。

```json
{ "name": "产品与售后知识库", "description": "仅维护已正式生效的资料" }
```

两字段均可选，但至少提供一个；空描述可清除，名称不可为空，`null` 不接受。返回 200 新 `KnowledgeBase` 和新 ETag。不能通过本接口改企业、创建人、授权或处理状态。

### 05. 删除知识库

`DELETE /knowledge-bases/{kbId}`，要求 `If-Match`，无请求体。

事务提交删除标记后返回 204。此后列表、文档、预览、来源、检索均不得再访问该库；原文件、索引和历史版本异步清理。删除前由客户端明确二次确认，不要求平台先逐文件删除成功才返回。

重复删除已不可见对象返回统一 404，不泄漏删除历史。不要把“幂等”解释成每次必须返回相同 HTTP 状态。

### 06. 获取文档列表

`GET /knowledge-bases/{kbId}/documents?page=1&pageSize=20&keyword=手册&status=FAILED`

返回 `Page<Document>`。`status` 可省略，只接受四种处理状态，筛选的是 `latestVersion.status`，不代表生效版本状态。界面可同时显示“v1 可用，v2 处理失败”，不能将整个文档误标成不可用。

### 07. 获取文档详情和处理状态

`GET /knowledge-bases/{kbId}/documents/{docId}`

返回 `Document` 及 ETag，包含当前与最新版本、安全失败原因、可执行动作。

V1 复用该接口轮询，不新增任务查询或 WebSocket：在途时建议 2 秒一次，持续较久退避到 5 秒；离开页面、退出登录、撤权或终态后停止。后台切换到非活跃页面时暂停轮询；返回时刷新。具体间隔是客户端策略，服务端可用 `Retry-After` 约束。

### 08. 上传新文档

`POST /knowledge-bases/{kbId}/documents`，`multipart/form-data`，要求 `Idempotency-Key`。

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `file` | 文件 | 必填，单个文件；格式、大小按 `limits` |

平台在原文件可靠持久化、文档/初始版本/处理作业及 outbox 事务落库后返回 202 `MutationAccepted`：`unchanged=false`，`acceptedVersionId` 为新建版本，`document.latestVersion.status=PENDING`，`activeVersion=null`，`searchable=false`。

202 表示可靠接受，不表示已经可检索。批量选择多个文件时客户端分别调用，分别显示成功与失败，不能伪装成平台支持原子批量上传。

### 09. 上传新版本并替换内容

`POST /knowledge-bases/{kbId}/documents/{docId}/versions`，`multipart/form-data`，要求 `Idempotency-Key`。

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `file` | 文件 | 必填，单个新文件 |
| `expectedRevision` | 十进制整数字符串 | 必填，平台解析为文档修订号，不接受小数 |

平台先检查访问、修订和在途状态，再基于字节哈希判断是否变化。不同内容创建递增 `versionNumber`，返回 202 `MutationAccepted`；与当前生效内容相同返回 200，`unchanged=true`、`acceptedVersionId=activeVersion.id`，不改变版本和修订。

如果最新失败版本和上传内容相同，但不同于当前生效版本，仍按一次新的替换操作创建新版本；用户也可直接使用失败重试接口。不能按文件名推测更新对象或跨文档合并。

### 10. 删除文档

`DELETE /knowledge-bases/{kbId}/documents/{docId}`，要求 `If-Match`，无请求体。

事务中标记文档已删除、使其所有版本不可供预览/检索/来源使用，登记清理作业，返回 204。即使后台正在处理也允许删除，worker 必须在最终发布前发现删除并放弃。

### 11. 获取文档只读解析预览

`GET /knowledge-bases/{kbId}/documents/{docId}/preview?page=1&pageSize=20`

返回 `DocumentPreview`，`items` 是解析块而非检索结果。仅预览当前生效版本，不支持客户端指定任意未发布版本。没有生效版本返回 409 `DOCUMENT_NOT_READY`。

为避免翻页混入新版本，后续页携带可选 `versionId`（第一页响应值）；若已不再生效，返回 409 `REVISION_CONFLICT`，客户端从第一页刷新。`versionId` 只作一致性条件，不赋予历史版本访问能力。

纯文本返回，保留段落、标题和表格文本，不返回未净化 HTML、内嵌脚本和公开原文件地址。单块输出有服务端长度限制，超长原始段落在解析时拆为可定位子块，不能无界返回。

### 12. 重试失败处理

`POST /knowledge-bases/{kbId}/documents/{docId}/reprocess`，要求 `Idempotency-Key`。

```json
{ "versionId": "version_2", "expectedRevision": 8 }
```

只允许重试当前最新、状态为 FAILED、`error.retryable=true` 的版本；READY/PENDING/PROCESSING 或已被新版本取代的旧失败版本返回 409 `VERSION_NOT_RETRYABLE`。

返回 202 `MutationAccepted`，`unchanged=false`，`acceptedVersionId` 仍是该文件版本；内部生成新的处理尝试和索引代次，不篡改不可变原文件。解析不支持、加密、空文本等确定性问题要求用户换文件，不提供无效的重试按钮。

### 13. 查询授权候选成员

`GET /enterprise/members?view=knowledge-grant&page=1&pageSize=20&keyword=张`

复用现有成员路由，**新增显式 `view=knowledge-grant` 的管理员专用投影**：返回 `Page<MemberDisplay>`，仅当前企业有效成员，按姓名或岗位搜索，不返回邮箱、账号 ID、邀请 token 等非必要信息。无姓名时服务端生成可用的成员显示名，不把邮箱作为默认兜底暴露。

目前该路由无此投影、分页及搜索契约，不能宣称直接可用。为避免破坏现有组织页面，不传 `view` 的旧请求保持原格式和权限；新投影使用独立 schema 和角色校验。其他未知 `view` 返回 400。若平台决定统一升级所有成员列表，必须先迁移其现有调用方，不能悄悄改变响应形状。

### 14. 查询已授权成员

`GET /knowledge-bases/{kbId}/grants?page=1&pageSize=20&keyword=张`

返回 `Page<KnowledgeGrant>`；`keyword` 按被授权成员显示名/岗位筛选。只列显式授权，不把所有隐式拥有访问权的管理员合成授权记录。员工不能借此浏览同事名单。

授权人离职后 `grantedBy.memberId=null`，保留安全姓名快照用于审计显示；被授权人离职则授权记录同步清理或确保不可生效、不可列为有效授权。

### 15. 批量授予知识库访问权

`POST /knowledge-bases/{kbId}/grants`

```json
{ "memberIds": ["member_1", "member_2"] }
```

输入为 1～100 个不同的有效企业成员 ID。先验证整批成员归属与有效性，再在单一事务中添加；任何一个无效都返回 400 `MEMBER_SELECTION_INVALID`，不回显跨企业成员信息，不部分成功。

返回 200：

```json
{ "addedMemberIds": ["member_1"], "existingMemberIds": ["member_2"] }
```

唯一约束保证重复授权无副作用；并发重复请求也不创建多条记录。本接口不接受 `permission=admin` 等权限升级参数，授予的固定是查看和检索。

### 16. 撤销成员访问权

`DELETE /knowledge-bases/{kbId}/grants/{memberId}`，无请求体。

管理员撤销指定显式授权，返回 204；同企业有效成员原本未授权时也返回 204，便于重试。目标成员不存在或不属于本企业返回统一 404。管理员的企业级隐式访问权不能通过删除显式授权撤销，需通过企业角色管理处理。

撤销提交后，后续列表、预览、来源和检索均重新鉴权；清理权限缓存与搜索缓存。不能仅从前端列表移除就认为完成撤权。

### 17. 检索知识库

`POST /knowledge-bases/search`

```json
{ "query": "智能行李箱的电池保修规则是什么？", "knowledgeBaseIds": ["kb_1"], "topK": 5 }
```

| 字段 | 规则 |
| --- | --- |
| `query` | 必填，去首尾空格后 1～1000 字符 |
| `knowledgeBaseIds` | 可省略；若提供必须为 1～100 个不同 ID，空数组报 400 |
| `topK` | 可省略，默认 5，范围 1～20 的整数 |

不接收订阅、员工、模型、任意相似度阈值或客户端自报授权范围。

- 未传库范围：检索当前身份全部可访问库；不是只检索列表当前页。范围计算在平台 SQL 中进行，不要求客户端穷举所有库。
- 显式传范围：逐一校验；任何一个不存在/未授权，整个请求返回统一 404，不静默忽略。
- 只搜索当前已发布的生效索引代次；失败新版本不会影响旧版本查询。
- 返回 `SearchResponse`，`count === results.length`，命中不保证凑满 `topK`。
- 单次正文总量受 `maxResultTokens` 限制，截断时设置结果的 `truncated=true`；计数使用服务端固定 tokenizer，不与未来注入模型的上下文窗口混为一谈。
- 相似度不是可信概率；V1 不输出“正确率 95%”或让客户端根据未定义分数决定是否引用。

| `status` | 含义 | 其他字段 |
| --- | --- | --- |
| `MATCHED` | 至少一个有效命中 | `count>0`，策略非空 |
| `NO_MATCH` | 已执行检索，但没有满足规则的命中 | `count=0`，策略非空 |
| `NO_ACCESS` | 仅限未指定范围且没有任何可访问知识库 | `count=0,actualStrategy=null` |
| `NOT_READY` | 有可访问库，但没有任何生效可检索文档 | `count=0,actualStrategy=null` |

`partial=true` 表示在实际检索范围内，仍有非删除文档没有生效版本，结果只覆盖可用文档；没有实际执行检索时为 false。新版本处理期间已有旧生效版本的文档不因此视为缺失。NOT_READY 不代替依赖故障错误。

正常目标策略为 `HYBRID`。仅查询向量化服务暂不可用时，允许显式降级到 `LEXICAL`，并返回 `degraded=true,degradationReason=QUERY_EMBEDDING_UNAVAILABLE`；词法检索也失败则返回 503，不伪装成未命中。未执行检索的状态固定 `degraded=false,degradationReason=null`。

命中示例：

```json
{
  "searchId": "search_1",
  "status": "MATCHED",
  "actualStrategy": "HYBRID",
  "degraded": false,
  "degradationReason": null,
  "durationMs": 168,
  "count": 1,
  "partial": false,
  "results": [{
    "sourceId": "source_1",
    "knowledgeBaseId": "kb_1",
    "knowledgeBaseName": "产品知识库",
    "documentId": "doc_1",
    "documentName": "智能行李箱售后规则.pdf",
    "versionId": "version_1",
    "chunkId": "chunk_12",
    "content": "电池保修期为自购买之日起十二个月，具体以有效购买凭证为准。",
    "tokenCount": 31,
    "truncated": false,
    "location": { "pageStart": 3, "pageEnd": 3, "sectionPath": ["售后服务", "电池保修"], "blockStart": 12, "blockEnd": 12 }
  }]
}
```

示例 `tokenCount` 仅示意，实际必须由配置的 tokenizer 计算；示例不构成检索效果证据。

### 18. 查看检索来源

`GET /knowledge-bases/{kbId}/sources/{sourceId}`

返回 `KnowledgeSource`，对当前身份重新校验企业、成员、库授权及文档未删除。`sourceId` 是版本化片段的稳定不透明标识，不是可绕过权限的访问票据；不为每次检索重复存储完整片段正文。

若片段属于仍保留的曾发布版本，可只读查看并返回 `isCurrent=false`，客户端标示“历史版本”；不能把当前最新版正文替换进旧引用。未发布版本永远不可通过来源接口读取。保留期结束、资源删除或撤权返回统一 404。

建议已发布历史解析内容保留 30 天，期限与企业删除策略以评审配置为准；不承诺引用永远可用。旧来源仅用于追溯，不自动成为下一轮当前知识检索输入。

## 8. 平台数据模型与不变量

沿用 NestJS、Prisma、PostgreSQL、pgvector、Redis/BullMQ，不为了首期引入新向量数据库。下面是逻辑模型，字段名按平台 schema 规范实现。

| 对象 | 关键字段 | 约束与用途 |
| --- | --- | --- |
| `KnowledgeBase` | id、enterpriseId、name、description、revision、deletedAt、creator 快照、时间 | 企业拥有内容；不是创建者私有资产 |
| `KnowledgeGrant` | id、enterpriseId、knowledgeBaseId、memberId、grantedBy、时间 | 唯一 `(knowledgeBaseId,memberId)`；成员与库必须同企业 |
| `KnowledgeDocument` | id、enterpriseId、knowledgeBaseId、name、revision、activeVersionId、latestVersionId、deletedAt | active 指针是对外可用性的唯一发布入口 |
| `KnowledgeDocumentVersion` | id、documentId、versionNumber、objectKey、sha256、size、mime、originalFilename、status、stage、配置快照、时间 | 唯一 `(documentId,versionNumber)`；原始文件及内容元数据不可变，处理状态可变 |
| `KnowledgeProcessingJob` | id、versionId、indexGeneration、attempt、stage、lease/fencingToken、status、safeError、时间 | 一个版本一个当前处理代次；数据库记录是恢复依据 |
| `KnowledgeParseBlock` | id、versionId、indexGeneration、sequence、type、text、location | 保留结构，支持预览与可追溯切片 |
| `KnowledgeChunk` | id/sourceId、versionId、indexGeneration、sequence、text、tokenCount、location、tokens | 唯一 `(versionId,indexGeneration,sequence)`；记录词法 token |
| `KnowledgeEmbeddingProfile` | id、provider、modelRevision、dimensions、tokenizer、distance、configFingerprint | 不可变配置；端点密钥只保存安全配置引用，不存入文档 DTO |
| `KnowledgeEmbedding` | chunkId、embeddingProfileId、dimensions、vector | 与对应切片、模型版本严格一致，不混维度、不混配置 |
| `KnowledgePublishedIndex` | versionId、indexGeneration、embeddingProfileId、publishedAt、retireAt | 一次发布只能指向完整代次；历史来源查询依赖发布记录 |
| `KnowledgeOutbox` | eventId、type、payload IDs、availableAt、attempt、publishedAt | 事务提交后可靠派发处理/清理事件 |
| `KnowledgeIdempotency` | scope/key、requestDigest、status、leaseUntil、safeResponse、expiresAt | 唯一幂等作用域；不保存令牌或原文件正文 |
| `KnowledgeAudit/SearchLog` | enterprise/member、操作、对象 ID、结果码、requestId/searchId、耗时 | 默认不记用户问题及命中文本；脱敏、留存受控 |

企业 ID 的冗余字段要通过组合外键、数据库约束或事务校验保持一致，不能只依靠 ORM include 的结果“看起来属于同企业”。离职成员的 grant 外键级联清理；审计中的操作者使用可空引用与姓名快照，不级联删除企业内容。

最低索引：库 `(enterpriseId,deletedAt,updatedAt,id)`；授权 `(memberId,knowledgeBaseId)` 与唯一约束；文档 `(knowledgeBaseId,deletedAt,updatedAt,id)`；版本 `(documentId,versionNumber)`；块/切片 `(versionId,indexGeneration,sequence)`；作业/outbox 按状态和可调度时间索引；向量按配置的距离函数建立匹配索引。具体索引与执行计划必须用实际数据验证。

**发布不变量：**

1. 检索只命中有效库、有效文档、`activeVersionId` 和其已发布索引代次。
2. 新版本构建失败不得删除或污染旧生效切片。
3. 原文件与版本不可变；同一重试用新处理代次隔离中间产物。
4. worker 的过期任务、旧租约和已删除文档不能发布。
5. 权限过滤进入数据库查询；禁止全库召回后仅在前端或最终 topK 之后筛权限。
6. 库/文档删除首先改变可见性，物理清理可重试且不能使内容重新出现。

## 9. 平台各模块搭建方案

### 9.1 企业身份与知识访问策略

建立单一 `KnowledgeAccessPolicy`，复用企业成员上下文，不在每个 controller 各写一份权限判断。

- 提供管理检查、单库读取检查、显式多库检查、可访问库 SQL 条件构建四种能力。
- controller 做请求 schema；service 调策略并编排事务；repository 统一封装带企业、删除和版本条件的查询。
- 列表、详情、文档、预览、检索、来源及旧路由共用策略，不留“只验证同企业即可读取”的旁路。
- V1 优先直接查询有效成员/grant，避免长期权限缓存；如采用缓存，必须有成员和授权修订的强制失效机制。
- 撤权和删除与搜索最终校验定义明确线性化边界：响应提交前做最终有效性检查；必要时对相关授权/资源行加共享锁，撤权写持排他锁。撤权成功确认之后新进入的请求不得再读，已在边界前提交的响应无法撤回。

交付：策略单测、跨企业与对象越权集成测试、成员离职/降权测试、撤权并发测试。

### 9.2 知识库与授权管理

在现有知识库模块内替换资源访问规则，新增 member grant，保留薄 controller 和事务型 service。

- 名称、描述、分页与关键词白名单校验；统计只包含未删除文档及其生效版本。
- 批量授权先验证整批同企业成员，事务内写入唯一关系并记录审计。
- 授权、撤权、库删除与成员离职使用一致锁顺序；若成员身份被硬删除，FK/事务要保证授权不能挂到失效成员。
- 授权管理不赋予管理权限，不复用硅基员工授权表来隐式解释知识权限。

### 9.3 文件接收、原件存储与版本管理

建立 `KnowledgeObjectStorage` 接口，支持写入、读取流、删除、存在性检查；业务层不拼物理路径。

- 可先用平台受控的持久化卷实现，具备私有路径、磁盘容量监控和备份；多实例部署必须共享可持久访问存储。已有私有对象存储时实现相同 adapter，不依赖公开静态目录。
- 原件 key 由平台生成，例如企业/文档/版本 ID 组合，不信任原文件名作为路径。物理 key 不下发客户端。
- 入口先鉴权、预检额度，再边接收边限制大小和计算哈希；同时校验扩展名、MIME、文件特征，不能只信浏览器声明。
- DOCX 解包有条目数、总展开大小和压缩比限制；解析器禁止外部资源访问、宏执行及路径穿越。需要的恶意内容扫描在进入解析 worker 前完成，未通过不能发布。
- 原件写成功后，以事务登记版本、作业、outbox、幂等结果；数据库事务失败的孤立原件由清理器回收。事务成功但响应丢失按幂等键找回结果。
- 额度预留与释放必须原子化，不能并发上传绕过企业限制；删除待清理字节、历史版本及失败版本的计费/额度口径需配置一致。

安全原则参考 OWASP File Upload Cheat Sheet（第 14 章），不把参考清单替代本项目测试。

### 9.4 异步作业与可恢复处理

API 和解析/向量化 worker 分进程部署，共享数据库与私有存储。复用 BullMQ，但作业必须携带 `jobId/versionId/indexGeneration`，不是只携带可变 `documentId`。

```text
接收文件并落库（PENDING / QUEUED）
  -> outbox 派发
  -> worker 认领租约（PROCESSING）
  -> PARSING -> CHUNKING -> EMBEDDING -> PUBLISHING
  -> 原子发布（READY / DONE）
失败 -> FAILED，保留安全错误及最后阶段，旧 active 不变
```

- outbox 与文档接受事务一起写；投递器可重复派发，worker 按数据库作业键幂等执行。
- BullMQ 的 jobId 去重不等于业务幂等；队列记录被移除后仍须靠数据库状态和代次防止重复发布。
- 采用租约心跳和 fencing token，最终发布检查 job 仍是当前代次、租约仍有效、版本仍是 latest、资源未删除。
- 可恢复故障建议最多 3 次指数退避，可配置；429 遵守上游等待时间。格式不支持、加密、空文本不自动重试。
- 重试次数、队列重投和人工重试分开记录，禁止叠加造成无限重试。
- `processedChunks/totalChunks` 表达真实进度；解析前总量未知返回 null，不伪造线性进度百分比。
- 定期扫描过期租约、未派发 outbox、长期 PENDING，启动时恢复，不让应用重启丢失已接受任务。
- 文档删除后内部可进入取消状态；公开列表已不可见，不需要新增客户端取消接口。

### 9.5 文档解析与预览

建立按格式分派的 parser adapter，输出统一 `ParseBlock[]` 和配置指纹，而非一串失去结构的全文。

- PDF 采用与锁定版本匹配的 API，按真实页边界提取；没有文本层返回安全错误 `NO_EXTRACTABLE_TEXT`，V1 不自动承诺 OCR。
- DOCX 保留标题、段落和表格行列文本，不把旧 DOC 交给 DOCX 解析器。
- TXT/Markdown 严格处理支持编码，保留段落/标题/代码块；Markdown 不渲染为未净化 HTML。
- 清理仅去确定噪声；不能无条件删除纯数字行，订单金额、年份、型号都可能是有效知识。
- 对文件页数、展开大小、解析耗时、内存设置资源上限，隔离 worker；限制解析器网络访问。
- 解析块定位绑定版本及代次，预览和检索来源使用同一套定位，避免“预览第 3 页但引用来自另一份文件”。

交付：每种首批格式的正常/异常样本与结构快照；不满足的格式不出现在 `allowedExtensions`。

### 9.6 切片模块

纯函数服务：输入解析块和配置，输出带来源的切片；不负责鉴权、数据库写入或调用模型。

- 先按标题、段落和句子边界分组，再按实际 tokenizer 限长；不先把全文空白压成一行。
- 试验默认：目标 500 tokens、上限 800、重叠约 80；仅作为起点，需以中文业务评测集验证，不称为最优参数。
- 大段落按句子继续拆；表格片段尽量附带表头；代码块及列表保留语义结构。
- 重叠只用于上下文延续，不能无限增加同内容；每片保留块范围、章节、真实页码和配置版本。
- 确定性切片顺序与唯一键使重复运行可核对，不产生重复结果。
- 索引 tokenizer 与 embedding tokenizer 必须明确，不能把“字符数”假定为 token 数；embedding 输入留出标题等前缀预算。

### 9.7 向量化模块

复用现有 embedding adapter 思路，将配置明确为不可变 `EmbeddingProfile`：供应商、端点配置引用、固定模型/修订、维度、tokenizer、输入长度、距离函数、归一化规则。

- 当前代码默认指向 OpenAI-compatible 本地端点和 `bge-m3:latest`、1024 维，这是代码默认，不是确认过的生产部署。
- V1 可先验证 BGE-M3 dense 1024 维路线；上线应固定模型制品摘要/版本，不能依赖可漂移的 `latest`。BGE-M3 的模型卡描述 1024 维，不等于本项目的端点已经正确实现。
- 批量输入校验非空/长度；输出校验数量、顺序映射、维度、数值有限且不是零向量。异常批次不得发布。
- 入库与 query 使用同一兼容 profile，不得供应商失败后静默切到另一种向量空间。
- 设置超时、有限重试、批大小和并发上限；查询优先级/资源池与批量入库隔离，防止上传堵塞在线检索。
- 如调用外部 embedding 服务，向其发送知识正文属于数据外发，需先经企业部署策略允许；本方案不默认获得此许可。
- profile 改变需要新索引代次重建，不能只修改数据库中的 modelName 掩盖旧向量。

### 9.8 索引存储与原子发布

关系元数据、词法字段、解析块和向量优先共用 PostgreSQL；pgvector 为部署前置条件，生产不以 BYTEA 全表内存扫描作为隐式替代。

- 新代次写入临时可识别行，构建过程中不参与检索；词法和向量均完整校验后才可发布。
- 发布事务：检查资源/任务/代次 -> 写发布记录 -> 切换 activeVersion/索引代次 -> READY -> 增加修订与统计。
- 首次入库的 embedding 失败必须 FAILED，不将仅有文本的文档标为 READY。查询阶段的临时词法降级与入库不完整不是一回事。
- 旧版本/代次在保留期内仅提供历史来源，当前检索必须排除；到期由清理任务回收。
- pgvector 距离运算和索引算子类必须与 profile 一致；向量、词法两条路径都在 SQL 内限制企业、授权库、有效文档和已发布代次。
- 小规模先验证带权限条件的精确检索正确性与耗时，再评估 ANN。ANN 的过滤可能减少召回，需要结合部署版本验证迭代扫描/过采样或分区方案，不能以取消权限过滤换取 topK 数量。

### 9.9 检索、排序与来源模块

单一检索用例执行：校验 query -> 确定授权范围 -> 筛可用版本 -> 词法/向量候选召回 -> 融合/去重 -> 总量限制 -> 最终权限和版本校验 -> 响应。

- 词法复用中文分词、数据库候选召回和 BM25 思路；BM25 临时索引不得由并发请求共用可变单例状态。
- 两路候选集大小受服务端上限约束，混合排序可先用 RRF。不要将两类原始分数未经校准直接相加。
- 排序规则、候选数、去重规则和门槛使用服务端版本化 profile；V1 不向普通客户端开放调参。
- 相同片段只返回一次；同文档相邻高度重叠片段合并或抑制，但必须保留真实定位。
- 发布切换、撤权或删除发生在检索中途时，最终检查剔除已不再可用候选，必要时有限重查；无法建立一致有效范围则失败，不能返回过期授权内容。
- 缓存不能只按 query；V1 优先不缓存敏感结果。以后缓存至少包含企业、成员权限版本、检索 profile、内容版本并再次鉴权。
- 只读来源模块验证片段所属版本曾发布且仍保留；`sourceId` 不包含原件路径或签名密钥。
- 文件正文是外部不可信数据，后续模型接入不能把其中指令当系统权限；具体上下文拼装另立方案。

### 9.10 删除、审计与运维

- 删除 tombstone 和清理 outbox 同事务提交；依次回收向量、切片、解析块、历史原件及临时产物，重复执行无副作用。
- 删除优先级高于发布；worker 每个重要写入阶段及最终发布均检查 tombstone/租约，不允许内容复活。
- 审计记录管理操作、授权变化、处理状态、检索结果码/耗时/降级，不默认记录问题、正文和 token；正文调试必须临时、受控、脱敏并有留存期限。
- 监控队列积压/最长等待、解析失败率、向量服务延迟、失败阶段、查询 p95、无命中率、降级率、清理滞后、存储和索引增长。
- 上线必须有原文件、PostgreSQL 的一致备份/恢复演练以及 Redis 持久化策略；不能把 Redis 中唯一一份队列当可靠业务记录。
- 企业存储额度、最大文档数、解析资源预算、查询预算、备份和历史保留期使用配置管理，部署说明明确磁盘位置与访问权限。

### 10.1 旧能力迁移与防绕过

- 旧订阅/部门授权不能自动转成企业成员授权。无法明确归属的授权默认不授予，交由管理员重新授权。
- 旧文档只有能确认企业归属、原件存在、内容来源合法的才转为首个版本；重新处理通过后发布。无法确认的手工片段隔离，不直接扩大可见范围。
- 搜索请求去掉必填订阅是同一路由的破坏性契约变化；发布前列出平台 Web、SDK、客户端等所有调用方并协调升级或隔离发布，不只更新桌面端。
- 旧上传别名如临时保留，必须走同一新策略和版本服务；旧下载、切片写入、全量列表、内部检索入口也要关闭或同样鉴权，不可成为旁路。
- 迁移先做演练和权限差异核对；新库 API 通过 feature flag 开放。回退时可关闭知识功能，不能为了兼容恢复不受成员授权限制的旧检索。
- 本文不要求立即删除现有代码；开发时逐路径验收，不能只新增一套接口而保留可绕过的新旧双通道。

## 12. 联调与验收清单

### 12.1 权限与接口

- 管理员空列表仍可创建；员工空列表不显示创建按钮，直接请求管理接口仍被拒绝。
- 员工只看被授权库；任意猜测其他库/文档/来源 ID 都无法读取；错误不泄漏对象归属。
- 两企业相同文件名、相同 query 和相同幂等键不串数据；企业 A 的成员不能进入企业 B grant。
- 成员离职、管理员降权、授权撤销对列表、预览、检索、来源及幂等回放同时生效。
- 授权包含未来文件；批量授权混入无效成员整批失败；重复授权无重复记录。
- `count` 与实际结果数量一致，204 无响应体，列表 total 不含隐藏数据，schema 与 OpenAPI 一致。

### 12.2 版本与处理可靠性

- 同名普通上传是两份文档；指定文档替换不改其他文档；同 active 哈希返回 unchanged。
- v1 生效、v2 在途/失败时仍检索 v1；v2 成功后切换，任何查询不混入半成品。
- 同时替换、替换与删除、重试与删除、worker 租约过期竞争时无覆盖、无复活。
- 接受事务后队列不可用仍可由 outbox 恢复；重复投递、服务重启、响应丢失不重复创建/发布。
- 上传/解析/向量失败分别有安全错误和有限重试；向量失败不能伪报 READY。
- 大小越界、伪扩展名、恶意压缩结构、空文本、加密 PDF、非法编码有明确拒绝结果。
- 预览翻页遇到版本切换有冲突提示；引用不会悄悄变成另一版本正文。

### 12.3 检索质量与性能

- 准备实际业务问题与预期文档/片段标注，覆盖中文关键词、同义表达、型号、数字、无答案、跨库、权限隔离。
- 对比词法、向量、混合三种策略，记录 Recall@K、来源准确性、无答案误召回及延迟；不能仅凭几次演示选参数。
- ANN 与带过滤精确结果对照；极窄授权范围、多个企业混合数据、删除/更新中均测召回与权限。
- query embedding 故障时明确降级；数据库/词法不可用返回错误，不“正常无命中”。
- 并发中文词法请求不互相污染 BM25 状态；批量入库不压垮查询；输出 token 预算有效。
- 上线前记录真实环境、模型制品、文档量、切片量、并发及 p95 目标并压测。本方案不凭空承诺吞吐或准确率。
