# 电商媒体接口协作合同 v1

> 日期：2026-10-12。状态：配置、runtime 扩展和批准 Skill 安装产物分发已实现并进行本地验证；媒体执行接口仍为合同草案，未上线。
> 首期：图片；视频暂不接入。先完成实现及本地验证，再进行真实模型联调。
> 总纲：[两端开发方案](../development/2026-10-12-电商图片与视频员工两端开发方案.md)。客户端任务：[客户端开发文档](../development/2026-10-12-电商图片员工客户端开发文档.md)。
> 平台任务：[SEP Web 与后端开发文档](../development/2026-10-12-电商图片员工SEP-Web与后端开发文档.md)。接口变更先更新本合同与 shared schema/fixtures，再同步两端任务书。

## 1. 合同归属

SEP 维护权威 HTTP DTO/Zod、权限校验与网关；客户端维护工具/IPC、本地持久化与 UI。**双方以本文件的行为约定为共同基线，字段进入实现前在 SEP `backend/src/shared/` 落成可验证 schema 和不含秘密的 fixtures。** 客户端按同一 fixtures 实现边界解析，不把两仓库内部类型假装成已经存在的共享 npm 包。

接口路径不含部署全局 `/api` 前缀，由现有可信客户端 API 配置统一处理；不硬编码 longdaoai 地址作为客户端网关。HTTP envelope 沿用 SEP 现有约定，下面 JSON 只表示业务数据，不能直接假定所有接口裸返回对象。

本草案不替代现有登录、employment token 续期或任务监控协议。新增字段优先兼容扩展；发生破坏性变化时更新 `protocolVersion`，双方一起调整 fixtures，禁止一端静默改字段。

## 2. runtime 与版本

现有 `GET /client/subscriptions/:subscriptionId/runtime` 使用普通 access token。保留旧 `manifestVersion: 1` 合同；媒体扩展的协商载体已落地为 query：`?mediaProtocolVersion=1`。未传或正整数的其他版本不返回 `runtime.media`，不查询媒体配置；非法值返回 400。客户端仍须正常校验订阅授权。

新增 `runtime.media`，下例为新字段片段，不是整个现有 runtime 响应：

```json
{
  "media": {
    "protocolVersion": 1,
    "executionAvailable": false,
    "defaultProfileId": "product-image-standard",
    "tools": [],
    "profiles": [
      {
        "profileId": "product-image-standard",
        "kind": "image",
        "displayName": "商品图片",
        "configVersion": "cfg_001",
        "operations": ["generate", "edit"],
        "executionMode": "sync-response",
        "capabilities": {
          "supportsReferenceImage": true,
          "maxOutputs": 1,
          "sizes": ["1024x1024"],
          "maxWidth": 1024,
          "maxHeight": 1024
        }
      }
    ]
  }
}
```

上例是配置阶段的 **mock**，不是四个实际图片模型的测试结论。当前 `executionAvailable` 恒为 false、`tools` 为空，即使有 Profile 也不得开始生成。profile 是平台能力标识，不等于上游模型 ID；供应商地址/key/modelId 不下发。规格、操作、数量均按 profile 和企业策略交集校验，媒体不继承 `allowedChatModels`。无有效配置时 `profiles: []`、`defaultProfileId: null`，不影响普通聊天。

权威 schema：`backend/src/shared/media.dto.ts`；可供客户端复制用于解析测试的脱敏 fixtures：`backend/src/shared/fixtures/media-runtime-v1.json`。配置接口已落地：管理员使用 `/admin/media/connection` 与 `/admin/media/profiles`，企业使用 `/enterprise/media-config` 与 `/enterprise/media-config/available-profiles`。企业列表不含上游 modelId；Profile 更新必须传 `expectedConfigVersion`，冲突返回 409。连接的空密钥表示保留旧密钥，真实连接变化会撤销 Profile 验证，重复保存相同连接不撤销。

`executionMode` 首期覆盖 `async-query` 与 `sync-response`。取消和恢复能力字段尚未加入当前配置 schema，必须在媒体执行阶段根据真实适配结果另行扩展；客户端不能从 executionMode 推断恢复保证。同步接口不支持查询/恢复时，将来的恢复能力声明必须为 false；SEP 回执存在不代表能重新取得图。当前视频不可创建，也不会出现在 tools/profiles 中；媒体不可用不影响普通聊天。

媒体员工缺少所需协议、批准 Skill 或必须的编辑能力时，客户端明确阻止该制作操作，不降级到 shell/curl。Skill 安装分发已按下节实现；必需工具/操作依赖的批准发布仍待实现，不能从正文、可变 Capability metadata 或 `allowed-tools` 推导媒体执行授权。

### 2.1 批准 Skill 安装分发（第二批已实现）

协商与媒体协议独立：`GET /client/subscriptions/:subscriptionId/runtime?skillArtifactProtocolVersion=1`。也可以同时传 `mediaProtocolVersion=1`。只有 Skill 协议为 1 时增加 `runtime.skillArtifactProtocolVersion: 1` 与各个 `runtime.skills[].artifact`；未传或其他正整数版本不加这些字段、不读取安装包。非法 query 返回 400，旧 `manifestVersion: 1`、`content`、`versionId` 等不变。

`versionId` 是**当前实际生效的批准 SkillVersion ID**，不是贡献版本 ID；企业批准默认版本、订阅选择、绑定默认及平台回退沿用既有选择顺序。声明 `AVAILABLE` 只表示可下载/安装，不表示模型、工具、脚本或媒体操作获准执行。

字段以 `backend/src/shared/client-skill-artifact.dto.ts` 为准；解析 fixtures 为 `backend/src/shared/fixtures/skill-artifact-v1.json`，明确标为 mock，示意 hash 不对应真实发布包。

| 字段 | 行为 |
| --- | --- |
| `protocolVersion / capabilityId / versionId` | 协议 1、绑定能力 ID、实际批准版本 ID |
| `approvedContentSha256` | 当前 runtime Skill.content 原字符串的 UTF-8 SHA256，不先去空白 |
| `status` | AVAILABLE 或 BLOCKED；BLOCKED 无下载字段 |
| `format / installationDirectory` | single-file 或 zip；目录名为入口 frontmatter.name |
| `entryPath / entrySha256` | 产物中的安全相对入口路径、入口原字节 hash |
| `artifactSha256 / byteLength / fileCount` | 下载字节 hash、下载大小、非目录文件数 |
| `downloadPath` | SEP 相对 API 路径，不含部署 `/api`、秘密或供应商 URL |

下载使用**普通 access token**，不是 employment token：

`GET /client/subscriptions/:subscriptionId/skills/:capabilityId/versions/:versionId/artifact`

每次重新验证当前企业成员/部门 grant、grant 到期、ACTIVE 订阅和 endDate、启用的 SKILL 绑定，以及该版本仍是当前生效的同能力批准版本。个人、草稿、其他企业或旧版本均不可下载；已缓存的 descriptor 不构成永久授权。接口不读取贡献版本，也不对外暴露 storage key/path 或上游凭据。

200 是**二进制裸响应，无 JSON envelope**：单文件 `text/markdown; charset=utf-8`，ZIP `application/zip`；`Content-Disposition` 固定 `SKILL.md` 或 `skill.zip`，`Content-Length` 为原始字节数，`X-SHA256` 为产物 hash，`Cache-Control: private, no-store`，`X-Content-Type-Options: nosniff`。未认证 401，无企业身份 403，订阅/授权/绑定/版本不再可用统一 404；非法参数 400；无法安装 409（响应 `code: SKILL_ARTIFACT_BLOCKED` 与 `reason`）；存储临时故障 503。失败无下载字节。runtime 使用已有 JSON 返回形式。

`BLOCKED.reason`：`INVALID_ENTRY`（非法入口/包/编码/大小），`PACKAGE_REQUIRED`（无包正文出现受限本地资源引用），`PACKAGE_UNAVAILABLE`（已关联包缺失或引用无效），`PACKAGE_CONTENT_MISMATCH`（原包剥 frontmatter、trimStart 后正文与批准正文不一致）。这不会删改批准正文或自动回退成缺资源的单文件。

单文件：已有合法 YAML frontmatter 原字节保留；无 frontmatter 的纯正文生成稳定 name 和取自批准正文摘要的 description，正文不修改。入口最大 500 KiB。不对任意正文做完整语义/文件引用解析；常见 references/scripts/assets 路径、相对 Markdown 链接采取保守阻止，客户端仍负责缺失资源检查。

ZIP：原字节和附件完整保留，不重新打包。下载前校验 SHA256、唯一 SKILL.md、UTF-8/frontmatter、嵌套入口目录名、路径、符号链接、CRC、字节数与解压预算；本地文件头与中央目录的原始名字节、flags/method 必须一致，文件名严格 UTF-8 解码。最大 ZIP 20 MiB、解压 64 MiB、500 条目、入口 500 KiB。旧上传/预览允许的历史包未强制改写，不合法包仅在新安装合同中 BLOCKED。

客户端在下载后同时核验 descriptor、`X-SHA256`、实际 hash/字节数；ZIP 安全解包到 staging，核验入口 hash、frontmatter、目录名和正文对应关系，再原子安装到当前 scope 的不可变版本容器。根入口 ZIP 放入 `installationDirectory`；嵌套入口保留整包布局，向 SDK 提供入口父目录，不丢弃根级附件。ZIP 的批准正文比对沿用剥 frontmatter、trimStart；单文件已有 frontmatter 时比对完整原串，无 frontmatter 生成时比对剥生成头后的原正文。下载期间授权或内容变化返回错误/hash 不匹配时重新获取 runtime，不静默运行旧资源。已有运行资源不覆盖，快照不是永久远程授权。

客户端还须按目标文件系统拒绝大小写/Unicode 等价路径碰撞、文件与目录冲突，以及任何会覆盖已有 staging 文件的解包；服务端 `AVAILABLE` 不替代宿主文件系统安全校验。该跨平台安装行为仍需在客户端仓库验收。

客户端正文提交的 `parentVersionId` 仅用于谱系与来源校验，不继承父版本 ZIP；审核复制提交源记录自身的包字段。无包的批准正文自包含时生成单文件，仍引用受限本地附件时返回 `PACKAGE_REQUIRED`。当前审核通过会切换企业默认版本，但审核状态不保证安装产物可用；携带不一致旧包的历史记录仍可获批，分发时返回 `PACKAGE_CONTENT_MISMATCH`，客户端必须停止安装准备并提示管理员修正。

协商安装协议 v1 的 runtime 需要读取已关联包；包存储临时不可用时整个 runtime 可返回 503，客户端有限退避重试，不将其伪装成无包单文件或永久 BLOCKED。未协商安装协议的旧 runtime 不读取安装包。

包可能有 scripts；安装不执行脚本，`allowed-tools` 不替代宿主白名单。第三方来源/许可和媒体工具依赖尚未形成不可变发布元数据，本批未导入真实电商 Skill，也未把任何模型标为可用。

## 3. 接口清单

以下媒体端点均为待新增，使用 subscription 的 employment token，逐次校验企业/成员/订阅权限。

| 方法与路径 | 行为与最小业务数据 |
| --- | --- |
| `POST /gateway/v1/media/references` | 接收经宿主批准的参考图片字节；返回 `referenceId`、`expiresAt`、MIME、大小和 hash |
| `POST /gateway/v1/media/quotes` | 输入 profile/configVersion、operation、参考 ID、creativeBrief、parameters；返回绑定请求内容的 `quoteId`、有效期和计价状态 |
| `POST /gateway/v1/media/requests` | 接收稳定 clientRequestId 和 quoteId；建幂等回执并转发，不启动云端 worker |
| `GET /gateway/v1/media/requests/by-client-id/:requestId` | 按当前鉴权作用域找原回执，不发起生成 |
| `GET /gateway/v1/media/requests/:receiptId` | 客户端请求驱动地查询原任务；返回回执状态、outputs 与账务状态 |
| `GET /gateway/v1/media/requests/:receiptId/outputs/:outputId/content` | 归属校验后流式转发文件，不接受任意 URL，不建立成品库 |
| `POST /gateway/v1/media/requests/:receiptId/cancel` | 只有上游能力支持才请求取消；不支持时明确返回，不伪造取消成功 |

参考上传建议 multipart，唯一文件字段 `file`，大小/MIME 与配额经服务端限制；具体上游需要二进制还是临时 URL 由 SEP 适配。参考 ID 绑定当前作用域与订阅，不接收 renderer 任意指定磁盘路径。

报价金额与结算沿用平台金额单位和账务精度，禁止使用浮点金额自行计算。报价状态区分 `quoted` / `unavailable`；未配置真实价格不返回零元报价，是否允许生产生成需要明确产品策略。金额字段与钱包合同对齐后补 schema，不由客户端猜币种或倍率。

生成请求业务数据示例：

```json
{
  "clientRequestId": "request_immutable_001",
  "profileId": "product-image-standard",
  "configVersion": "cfg_001",
  "operation": "edit",
  "quoteId": "quote_001",
  "referenceIds": ["reference_001"],
  "creativeBrief": "只更换为明亮厨房背景，保留商品外形、颜色和 Logo",
  "parameters": { "aspectRatio": "1:1", "count": 1 }
}
```

`operation=edit` 要求参考图和允许的编辑能力；`generate` 是否允许参考图由 schema/profile 明确，不静默忽略图片。`parameters` 使用操作对应的严格 schema，不开放任意供应商 payload；真实允许值联调后再启用。

回执业务数据示例：

```json
{
  "receiptId": "receipt_001",
  "clientRequestId": "request_immutable_001",
  "profileId": "product-image-standard",
  "configVersion": "cfg_001",
  "status": "RUNNING",
  "pollAfterMs": 5000,
  "outputs": [],
  "billingStatus": "PENDING"
}
```

5 秒是 mock 建议间隔，不是上游 SLA。服务端可返回退避提示，客户端限制并发并遵守 `Retry-After`。受理返回 202，已经得到终态的请求可返回 200；同 ID 重放返回同一回执，不再次转发。

成功的每个 output 至少包含 `outputId`、类型、MIME、已知大小/尺寸和已知 `expiresAt`；未知值明确可空。客户端用 ID 构造受控 content 请求，不把私有上游 URL/key 带到 renderer。多张按 outputId 保存，部分成功和错误分别表达，不能只返回第一个文件。

同步返回 Base64 的适配器要明确其内容交付策略：只在当前请求流中交付时，丢失响应后不承诺回执能重取；如需请求级短期缓冲，必须显式约定 TTL、大小和清理边界，不暗中引入云端成品库。该策略是实际适配联调项，不能让同步协议伪装成可查询任务。

## 4. 状态映射

回执仅反映上游和本次请求，不记录客户端磁盘保存进度：

| SEP 回执状态 | 客户端行为 |
| --- | --- |
| `SUBMITTING` / `QUEUED` / `RUNNING` | 等待原请求，按能力查询，不重复生成 |
| `SUBMISSION_UNKNOWN` | 提交结果不明，停止自动重发；查回执/对账，必要时人工处理 |
| `SUCCEEDED` / `PARTIAL_SUCCEEDED` | 保存已成功 outputs；本地完成之前不宣称最终交付 |
| `FAILED` / `CANCELLED` | 展示明确终态与账务状态；新生成需新授权 |
| `RESULT_EXPIRED` | 无法取得结果时明确过期，不自动重生成 |

客户端自己的 `SAVING`、`SAVE_FAILED`、`SUCCEEDED` 与 `ACTIVE/INTERRUPTED/AUTH_REQUIRED` 分开持久化。下载失败不把上游 SUCCEEDED 改成 FAILED；暂停本地跟踪不把上游改成 CANCELLED。

同一 `(enterpriseId, clientRequestId)` 只对应一个语义请求，服务端校验 hash。quote 更新但语义请求没变时，不能因瞬时 quoteId、token 或 reference 上传 ID 更新就生成新订单；请求规范化与参考内容 hash 规则由共享 schema/fixtures 固定。输入、规格或创意改变则是新请求，不能复用旧 ID。

## 5. 错误与重试

错误业务码是新增草案，与现有 HTTP envelope 对齐后落 schema；不把上游原始异常直接传给客户端。

| HTTP / 业务码示意 | 客户端处理 |
| --- | --- |
| 401 / `AUTH_REQUIRED` | 复用现有认证续期；恢复查原回执，不新建生成 |
| 403 / `MEDIA_FORBIDDEN` | 暂停该任务远程操作，保留本地记录，不跨账户重试 |
| 409 / `IDEMPOTENCY_CONFLICT` | 阻止重试，提示请求内容冲突 |
| 409 / `QUOTE_EXPIRED` 或 `CONFIG_CHANGED` | 新提交重新报价/审批；已有回执不换模型重做 |
| 422 / `UNSUPPORTED_MEDIA_PARAMETERS` | 展示允许规格，不静默丢弃参数 |
| 429 / `MEDIA_RATE_LIMITED` | 遵守退避；提交已发出过时先查回执 |
| `RESULT_EXPIRED` / `CANCEL_UNSUPPORTED` | 分别提示过期/不支持取消，不伪造成功 |
| 网络断开、超时或 5xx | 提交可能已接单，先查原 ID；查询/保存可以有限退避重试 |

查原 ID 返回 404 也不证明上游没接单，可能仍在提交窗口或无法恢复。同步无查询模式必须进入保守的 UNKNOWN 状态，不以自动重发“修好”。完整错误表与 HTTP 状态在合同落地时锁定。

## 6. 双方共用 fixtures 与联调门槛

SEP 提供并由客户端复用以下脱敏场景数据，二进制用本地静态图片 fixture，不调用收费模型：

1. 无媒体能力、旧客户端不支持协议、图片可用但视频缺失。
2. 可查询异步：受理 -> 运行 -> 两个 output 部分成功 -> 保存。
3. 同步成功，以及同步提交后响应丢失且不可查询。
4. 同 requestId 重放、不同语义请求冲突、提交超时后找到原回执。
5. 报价过期、无报价、预算不足、401/403/429 与配置变更。
6. 结果过期、下载中断、跨企业请求/参考/素材访问。

开始媒体执行 HTTP 联调前，报价金额、同步内容交付、媒体执行响应 envelope 和错误表仍需落成 schema；批准 Skill 下载、runtime 的独立 query 协商和安装描述 fixtures 已完成。它们是两端研发对齐事项，不要求用户撰写技术文档；涉及收费/权利政策时再向用户确认。

开发期间用 mock 完成组件、恢复和契约测试；实现完成后才使用已授权测试服务验证四个图片模型。未真实验证的参数不设为生产默认，视频缺失不阻塞图片交付。本文不含真实 Key，也不证明任何模型已经可用。
