1. 未建立镜像时等待有效 `subscriptionId` 和 `activeRunId`，保持后端订阅授权和 runId 必填约束。
2. 持久化队列里旧的缺标识创建请求，用当前有效快照更新，不再无限重发 null runId。

## 4. 给客户端开发者的明确接口约定

所有路径相对带 `/api` 的根地址；使用客户端普通 access token，**不是 employment token**。

| 方法/路径 | 必需内容 | 返回/说明 |
|---|---|---|
| POST `/client/tasks` | clientTaskId、非空 clientRunId、授权 subscriptionId、title | 顶层对象含 id；同用户同 clientTaskId upsert |
| PATCH `/client/tasks/:id/status` | status | 返回镜像对象 |
| POST `/client/tasks/:id/heartbeat` | 可传 `{}` | 更新 lastHeartbeatAt，返回镜像对象 |
| POST `/client/tasks/:id/events` | 正整数 sequence、type | 可带 occurredAt、stepKey、message、progress；重放去重 |
| GET `/client/tasks` | 普通 access token | 顶层数组，最多最近更新的 100 条，无分页协议 |
| GET `/client/tasks/:id` | 普通 access token | 镜像对象加 events 数组 |

支持状态：`QUEUED / RUNNING / WAITING_APPROVAL / PAUSED / COMPLETED / FAILED / CANCELLED`。

必须注意：

- 创建接口的 DTO **不接收初始 status/createdAt**；客户端发来的这两个扩展字段会被剥离，初始状态按后端默认 QUEUED，创建时间按服务端。协调器创建后 PATCH 状态。
- 当前事件 DTO/数据库**不保存客户端的 `data` 对象**。`toolName/success/attempt` 等不能据此认为已经落库。当前确认保存的是 type、sequence、occurredAt 及声明过的展示字段；要显示工具摘要，下一步可在客户端将白名单信息映射成有长度限制的 message/stepKey，或单独设计结构化字段迁移，避免直接上传敏感参数。
- 当前客户端状态写接口只上传 status，未上报 progress/clientVersion 等字段，所以可能看到「已完成、0%、版本未知」；这不是本地执行进度的真实测量值。后续需要双方补齐展示字段，不应凭空推算进度。
- Web 列表每 15 秒轮询、展开详情每 10 秒轮询；不是 WebSocket 实时任务流。后端保存数据库镜像，不只是内存实时数据。
- 当前读权限按企业隔离，管理员可看本企业，普通成员看自己的；写入还应继续核查企业切换场景，不能仅凭匿名 401 测试宣称越权验证全部通过。
