# Web 与客户端共享员工头像

状态：2026-09-16，SEP 接口与 Web 已实现；客户端需按本协议消费字段。无需下载整套素材包，也无需新增素材库 API。

## 数据源与接口

数据库 `DigitalEmployee.avatar` 是员工与图片的唯一绑定。按员工 ID 绑定，不按名称或订阅别名重新分配；不同企业订阅同一员工使用同一人物。图片继续存放在 `web/public/assets/`，由 Web 静态服务或配置的 CDN 提供。

| 接口 | 头像字段位置 |
| --- | --- |
| `GET /api/client/subscriptions` | 每条记录的 `template.avatarAsset` |
| `GET /api/client/subscriptions/:subscriptionId/runtime` | `employee.avatarAsset` |
| `GET /api/enterprise/my-employees` | 每条记录的 `employee.avatarAsset` |
| `GET /api/subscriptions`、`GET /api/subscriptions/:id` | `employee.avatarAsset` |
| `GET /api/subscriptions/:id/employee-detail` | `avatarAsset` |
| 会话创建、列表、详情接口 | `employee.avatarAsset` |

授权规则不变：头像元数据随已授权员工接口返回，不增加员工访问权限。内置人物图片本身是公开静态资产，不存放任何企业私密内容。

示例（域名及版本为示意）：

```json
{
  "id": "emp_xxx",
  "avatar": "https://平台域名/assets/employees/silicon/frontend-engineer.webp?v=0123456789abcdef",
  "avatarAsset": {
    "id": "silicon:frontend-engineer",
    "version": "0123456789abcdef",
    "portraitUrl": "https://平台域名/assets/employees/silicon/frontend-engineer.webp?v=0123456789abcdef",
    "faceUrl": "https://平台域名/assets/employees/silicon/frontend-engineer-face.webp?v=0123456789abcdef"
  }
}
```

## 客户端显示规则

1. 员工卡片、聊天小头像使用 `faceUrl`；大尺寸人物详情使用 `portraitUrl`，等比显示，不拉伸。
2. 不拼接 API 域名，不自行推导 `-face` 文件名，不按姓名、下标或随机数选头像。API 返回可直接访问的绝对 HTTP(S) URL。
3. 加载失败依次回退到同一 `avatarAsset.portraitUrl`、姓名首字；两种 URL 相同时只尝试一次，不换成另一个人物。
4. 旧服务器没有 `avatarAsset` 时，暂用 `avatar`；无头像时两个字段都为 `null`。旧客户端仍可读取 `avatar`，其含义保持为完整人物主图。
5. 自定义外部头像无已登记构图时，两个 URL 都是原图，`version` 为 `null`，保留外部 URL 的签名及查询参数，不擅自加工。

## 同步与缓存

- 登录、重新进入员工列表、窗口重新获得焦点、恢复网络时重新读取接口，并按 employee ID 更新已有记录。Web 已为主要员工查询启用重新挂载、聚焦和重连刷新。
- 图片缓存使用完整 URL（包括查询参数）；元数据可按 `avatarAsset.id + version` 辅助判断变更。外部图 `version=null` 时以完整 URL 判断。
- 图片内容变化会改变素材内容哈希及 URL 的 `v` 参数，触发新图片下载。不使用 `templateVersion` 判断头像更新；即使员工技能版本锁定，视觉素材仍随平台更新。
- 离线可以显示上次成功缓存的图片，联网刷新后同步。本阶段没有服务端推送，不承诺两个持续打开、未触发刷新的窗口同时即时换图。
- CDN 必须把 `v` 查询参数纳入缓存键。当前是内容版本查询参数，不是保留历史副本的不可变文件服务；不要对无版本路径设置长期 immutable 缓存。

## 部署配置

后端配置 `ASSET_BASE_URL=https://实际提供图片的平台或CDN域名`，只能填写 origin，不带 `/api`、`/assets`、账号密码、查询参数或子路径。未设置时兼容 `FRONTEND_URL`；仅非生产环境默认 `http://localhost:3000`。生产启动时校验配置，防止向客户端发出容器内部地址或无效相对路径。

现有生产及开发 Compose 已分别配置对应网站域名。新 CDN 必须按原目录部署 `/assets/...`。如果客户端运行在另一台设备上，本地联调应将 `ASSET_BASE_URL` 改为那台设备可访问的 Web 地址，不能使用客户端自身的 localhost。

## 新增或替换素材

1. 将验收后的 `<slug>.webp` 主图和 `<slug>-face.webp` 头肩图放入 `web/public/assets/employees/silicon/`。`-full.webp` 是可选完整构图小缩略图，不是本协议的详情图。
2. 在仓库根目录运行 `pnpm assets:sync`，生成 `backend/src/common/employee-avatar-assets.json`。同一 slug 的两张图片共同计算版本，不手写版本号。运行 `pnpm assets:check` 检查清单。
3. 将图片、生成清单一起提交和部署；后端 build 会检查清单过期或缺少头肩图。先发布 Web 图片，再发布引用新清单的后端，防止新图片 URL 短暂 404。
4. 使用现有员工维护页面或接口更新该员工的 `avatar` 绑定。已支持 canonical `/assets/employees/silicon/<slug>.webp`，不存 `v` 参数；外部图片保留完整 HTTP(S) URL。解析器也兼容素材域名下的完整 URL，推荐相对路径以方便以后切换 CDN。
5. 替换为另一个人物时修改员工绑定；更新同一人物的素材时保留 slug，重新生成版本。不要删除仍被员工绑定引用的文件。

后续迁移对象存储只改变图片部署位置及 `ASSET_BASE_URL`。数据库使用 canonical 相对路径时无需批量改员工，也不需要客户端升级图片命名规则。
