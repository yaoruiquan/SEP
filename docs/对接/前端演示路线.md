# 硅基人才平台 — 前端演示路线

> 面向演示与验收：按路线点一遍，即可覆盖 P0–P2 的全部功能。
> 最后更新：2026-07-28

## 启动

```bash
# 依赖服务（PostgreSQL + Redis）
docker-compose up -d

# 后端 :3001（Swagger 在 /api/docs）
cd backend && node dist/main.js
# 或开发模式：pnpm dev:backend

# 前端 :3000
cd web && npx next start -p 3000
# 或开发模式：pnpm dev:web
```

入口：**http://localhost:3000**

## 路线一：访客视角（先不要登录）

打开 http://localhost:3000 → 自动跳转 `/marketplace`。

| 看什么 | 预期 |
|---|---|
| 员工卡片 | 能看到已上架员工（**不登录也有数据**） |
| 右上角 | 「登录 / 免费注册」 |
| 卡片按钮 | 「登录后订阅」，点击跳 `/login?redirect=/marketplace/<id>` |
| 点「详情」 | 员工详情页，展示绑定的硅基能力及其描述 |
| 搜索框 | 输入「文案」，服务端过滤（300ms 防抖） |

**这一页曾经是坏的**：路由上已公开，但读的接口要登录，访客只看到转圈的骨架屏。
现在改走 `/market/employees` 公开接口。

**看不见但重要**：访客拿到的数据里**没有 `systemPrompt`**（员工提示词）。
后端用 select 白名单裁掉了 —— 提示词基本等于这个员工的全部内容，
公开即可被完整复制。`modelId` / `maxSteps` 同样不返回。

## 路线二：企业管理员 `boss@acme.local`

从路线一的「登录后订阅」跳过来登录，**会自动回到刚才看的员工详情页**，
不是甩到工作台（`?redirect=` 生效）。

登录后侧边栏：

```
工作台

组织              ← 仅企业管理员可见
  部门管理
  成员管理

员工
  我的员工
  员工市场
  员工实例         ← 仅企业管理员可见

账务
  用量统计

个人设置 / 退出登录
```

侧边栏顶部显示**企业名**（示例科技有限公司）而非平台名 —— 多租户下一眼确认所在企业。

### 1. 部门管理

现有「技术部 / 前端组」「运营部」。悬停部门行，右侧出现：加子部门 / 重命名 / 删除。

可以验证的两条守卫：

- **环检测**：把「技术部」移到它自己的子部门「前端组」下 → 被拒（400）。
  成环后这些节点会从树里彻底消失（既非根、祖先链又不可达），只能改库修复。
- **删除不级联**：删有子部门或有成员的部门 → 被拒（409），需先清空。

### 2. 成员管理

3 名成员的表格（成员 / 角色 / 部门 / 职位）。

- 「添加成员」→ 填邮箱 + 初始密码即可**代建账号**（MVP 不做邮件邀请，
  邮件服务未接入）。这是第二个人进入企业的唯一途径 —— 注册入口只用于开公司。
- **角色下拉只有「普通成员」「企业管理员」**，没有「部门负责人」。
  该角色本版按普通成员对待，枚举值保留但不开放新分配。
- 试着把自己（boss）改成普通成员 → 被拒。企业必须保留至少一名管理员，
  否则永久失去管理能力（没人能加成员、建部门、订阅，也没人能把自己提回管理员）。

### 3. 员工实例

> 这一页是补上的一处**断链**：之前前端没有任何入口能创建实例，
> 「订阅 → 建实例 → 授权 → 使用」这条链中间只有后端接口、没有 UI。

现有 2 个实例。点「创建实例」：

- 模板下拉**只列生效中的订阅** —— 没订阅建不了实例
  （订阅 = 使用权，实例 = 实际部署一份）
- **同一员工可建多个实例**，按部门各部署一份，互不影响
- 新建实例初始状态是「待激活」，需手动启用

每行右侧图标按钮：

| 按钮 | 行为 |
|---|---|
| 升级（↑） | 仅当模板发了新版才出现；只改版本号，**不迁移配置** |
| 停用 / 启用 | 停用**不删授权记录**，恢复后原授权继续有效 |
| 授权管理（盾牌） | 见下一节 |
| 改名（笔） | 改名 / 换部门 |
| 回收（垃圾桶） | 独立确认弹窗，明示**终态不可撤销** |

### 4. 授权管理（点某实例的盾牌图标）

决定「谁能用这个员工」。

- 上半：已开通的授权列表，过期的标灰，每条可收回
- 下半：切换「给个人 / 给部门」→ 选对象 → 可选到期时间 → 开通

授权对象**二选一**（部门或成员），故用单选切换而非两个下拉 ——
后端用 zod refine 强制，两个都传或都不传返回 400，UI 让用户无从踩到。

当前「技术部文案助手」已授权给整个技术部。

### 5. 我的员工

管理员自己没被单独授权，这里可能是空的 —— **这一页是使用者视角，不是管理视角**。

## 路线三：普通成员 `staff@acme.local`

退出后换此账号登录，对比看差异：

| 对比项 | 管理员 | 普通成员 |
|---|---|---|
| 「组织」组（部门/成员） | 可见 | **不可见** |
| 「员工实例」 | 可见 | **不可见** |
| 「我的员工」 | 可见 | 可见（**核心页面**） |

「我的员工」里能看到「技术部文案助手」，卡片上带「**部门授权**」徽章 ——
他没被单独授权，是因为他在技术部、而技术部被授权了。
徽章区分「直接授权 / 部门授权」，回答「我凭什么能用这个」。

> ⚠️ **前端隐藏菜单只是体验优化，不是安全措施。**
> 角色信息存在浏览器内存里，用户改得动 —— 在控制台改 store 能把菜单显出来，
> 但点下去照样 403。真正的拦截在后端（`assertEnterpriseAdmin`）。
> 不存在「前端藏了所以后端可以松」这回事。

## 路线四：多租户隔离 `boss@globex.local`

换此账号登录：

- 侧边栏企业名变为「另一家公司」
- 部门管理为空
- 员工实例只有「乙企业文案助手」
- **看不到示例科技的任何数据**

这是整个系统的安全基线。跨企业访问返回 **404 而非 403** ——
403 等于承认「该 ID 存在但你无权」，404 连存在性都不泄漏。

企业归属**只认服务端上下文**：请求体里塞 `enterpriseId` 会被忽略
（Zod `parse` 剥掉未声明字段 + 服务层只用 `EnterpriseContextService.resolve()` 的结果）。

## 路线五：平台运营端 `admin@sep.local`

登录后落在 `/admin`。与企业台是**两套体系**：
运营人员不属于任何企业（登录响应里 `enterprise: null`、`roleInEnterprise: null`），
其全局角色是 `ADMIN`；而企业成员的全局角色是 `USER`、企业内角色另算。

| 页面 | 内容 |
|---|---|
| `/admin` | 仪表盘（待审能力数、能力总数、员工数） |
| `/admin/capabilities` | 能力审核（通过 / 驳回、导入 Coze Bot） |
| `/admin/employees` | 员工模板管理（增删改、绑定能力） |
| `/admin/models` | 可用模型（含未配价的保底计费警示徽章） |
| `/admin/settings` | 系统设置（汇率、密钥等） |

> 这一端是方向调整前就有的，本次未改动，仅从 `(admin)` 路由组改名为
> `(platform)`，URL 路径 `/admin/*` 保持不变。

## 已知的「不是 bug」

| 现象 | 原因 |
|---|---|
| 「用量统计」是空的 | 尚未产生真实消费。接口已是企业视角，数据需实际调用模型后才有 |
| 订阅列表里有「新公司科技」 | 测试注册流程时创建的企业，可清理 |
| 侧边栏没有「对话中心」 | 会话/聊天已于 2026-07-27 暂停，代码与后端接口保留，仅移除导航入口 |
| 员工详情页无「开始对话」 | 同上。订阅后的下一步是「建实例」，不是聊天 |
