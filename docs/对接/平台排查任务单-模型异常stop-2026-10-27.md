## 四、平台需要执行的排查任务

### 任务 1：补齐真实路由和上游关联

检索第一节三条 ID，并用请求 1、7、8 作成功对照，随后补齐其余请求。查询入口环境、真实模型版本、供应商、渠道、部署、适配器/配置版本，以及每一次上游调用 ID。检查期间是否发生渠道切换、fallback、自动重试或内部补全。

**交付：** 每个平台请求对应的上游调用清单。一次入口请求若触发多个上游调用，必须分别列出尝试顺序、时间、结束原因和用量，不能仅给最后一次汇总。

### 任务 2：定位 stop 最早在哪一层产生

取出三条重点请求的上游原始响应和平台下发客户端的响应，按帧对照所有非空 `finish_reason`，包含 `choice.index`、时间和帧顺序。

- 核查上游是否本来就返回 `stop`，还是 `length`、`tool_calls`、其他原因被转换为 `stop`。
- 核查流结束、`[DONE]`、usage 帧、超时、EOF 和异常兜底分支是否合成 `stop`。
- 核查非流式转 SSE 是否固定写 `stop`；是否先返回 `tool_calls` / `length`，随后又返回 `stop` 覆盖。
- 核查是否存在工具调用内容却配上 `stop`；不能只检查结束原因、不检查内容。

**交付：** `上游原始原因 → 各适配层原因 → 平台下发原因 → 客户端 rawStopReason` 对照及对应帧。发现改写时指出具体代码分支或配置；确认没有改写时提供两侧证据。

### 任务 3：解释三次 8704 输出用量及有效预算

查询入口请求、平台最终上游请求、供应商原始 usage 和用量归一化规则。

- 给出实际生效的正文/推理/总输出限制及来源：模型默认、套餐、渠道、网关配置或供应商限制。
- 确认 8704 是否供应商原始 completion_tokens，是否包括隐藏推理，是否经过固定值填充、累计或内部多次调用聚合。
- 确认是否触发预算限制、截断、上下文限制或服务端超时；触发后是否仍报告 `stop`。
- 若上游实际收到输出上限或推理配置，说明由哪一层加入。不能归因于客户端发送了其未发送的参数。

**交付：** 三个请求各自的有效预算、原始 usage、归一化结果、是否触发限制及证据。不能仅回复“8704 是模型消耗”，也不能把可见字符数直接换算成丢失 Token。

### 任务 4：核对思考、正文和工具是否在转换时丢失

比较客户端入口与最终上游请求中的 tools、messages，以及上游/下游响应中的 `content`、`reasoning_content` 等思考字段和 `tool_calls`。

- 工具 schema 是否完整；历史 `assistant.tool_calls` 和 `tool.tool_call_id` 是否对应；是否删减或重排历史思考/工具消息。
- 上游是否原本有工具调用，但工具标记解析、跨帧合并、参数 JSON 解析或过滤发生失败。
- 是否存在只读取 `delta` / 只读取 `message` 的协议不兼容；是否有 DSML 等原生工具标记未转成标准字段。
- 请求 9 的思考标签最早在哪一层出现，是否存在思考与正文错分、未闭合标签吞内容或历史污染。
- 平台是否注入与执行工具冲突的系统指令，或修改工具选择和推理模式。

**交付：** 三个请求逐层的正文、思考、工具数量/长度/摘要及首个差异位置。若上游原文也没有工具和最终回答，明确给出该结论，而不是臆测客户端丢失。

## 五、客户端已核对信息：用于平台交叉判断

- Pi 0.83.0 在解析非空 `choice.finish_reason` 时保存 `rawStopReason`；`stop/end → stop`，`length → length`，`tool_calls/function_call → toolUse`。本次三个持久化样本均记录 raw 与 mapped 为 stop，未发现客户端把 length 转成 stop 的证据。若同一流有多个非空原因，后来的值可能覆盖前值，因此必须回查所有帧。
- 客户端请求封装返回原 Response，日志流包装转发原事件，业务适配器读取 SDK 的结束原因。以上是本地代码核对结果，不代替平台原始流与 SDK 回放验证。
- 仅请求 3、9、10 后发生提交格式校验失败，均为 `INVALID_SUBMISSION`，尚未进入实际文件验收。终端两条失败提示是同一检查的两层记录，不是两次独立验收。
- 校验失败后客户端追加修正用户消息，保留原会话和文件，因此后续可继续调用工具。这解释修正后的工具行为，但不解释三次异常 stop 的来源。
- 修正消息要求修正提交格式、保留有效工作、不重做全任务，并说明尚未检查文件；没有要求重新搜索资料。实际工具共 read 1 次、bash 4 次、write 4 次，无浏览器/搜索调用。
- 内置 Office 可执行文件缺失是已发现的客户端本地资源问题，另行处理；不能据此解释网关结束原因是否正确。客户端同步 403/409 也不是模型响应状态，本任务三条重点模型请求均为 200。
