# 媒体规格协商合同 V3

本合同对应 SEP 新版图片/视频执行。供应商支持范围由实际通道决定；本地合同测试不代表已通过真实付费生成验收。

## 协商与请求

使用现有订阅 runtime 接口，分别传 `mediaProtocolVersion=3` 和 `videoProtocolVersion=3`。未传版本的旧行为以及 V1/V2 合同保持兼容。V3 返回 `protocolVersion:3`，不返回业务 `defaults`。

Profile 的 `authorized` 与 `adapter.available` 分别表示授权和适配器就绪状态。`capabilityHints` 包含 `field/values/source/observedAt/confidence`，是建议证据，不是允许值列表。`defaultProfileId` 仅选择路由，不补规格。

沿用真实端点：

| 操作 | 图片 | 视频 |
|---|---|---|
| 报价 | `POST /api/gateway/v1/media/real/quotes` | `POST /api/gateway/v1/media/video-real/quotes` |
| 提交 | `POST /api/gateway/v1/media/real/requests` | `POST /api/gateway/v1/media/video-real/requests` |
| 查询 | 对应端点的 `/requests/:receiptId` | 同左 |
| 幂等查找 | 对应端点的 `/requests/by-client-id/:requestId` | 同左 |
| 下载 | 对应端点的 `/requests/:receiptId/outputs/:outputId/content` | 同左 |

全部使用当前员工订阅的 employment token。通用助手账号不能借用员工令牌；独立账号媒体授权尚未接入本合同。

请求使用 `protocolVersion:3`、正整数 `specRevision`、`requestedSpec`，替代旧版 `parameters`。`referenceIds` 显式提供，`parameterSources` 可选，按字段记录 `user/model/upstream` 或 `{source,decisionRef}`。来源仅用于追溯，不证明用户授权费用。

可复用的 JSON 样本见 [media-v3-contract.json](../../backend/test/fixtures/media-v3-contract.json)，由 SEP 合同测试直接读取。客户端可复制相同 fixture 验证解析兼容；本次未修改相邻客户端仓库。

图片规格：`size/width/height/aspectRatio/count/quality`；视频规格：`durationSeconds/aspectRatio/resolution/width/height/frameRate/audio/outputFormat`。不接受任意 provider JSON、URL、模型、header 或 key。省略保持省略，`audio:false` 保持关闭；空串、零、非法数值拒绝。像素宽高成对提供；与 size、比例、数字 p 分辨率冲突时返回 `SPEC_CONFLICT`。

## 报价与执行

当前图片报价合同需要明确尺寸、数量和质量；视频需要时长及分辨率。缺字段返回 `MISSING_SPEC`，不提交收费生成。宽高可等价表示为 size；适配器不能表达的字段返回 `ADAPTER_FIELD_UNMAPPED`。生成数量、参考数量、可读取文件格式仍受适配器实现和资源边界约束，错误不能冒充供应商能力限制。

报价返回冻结的 `effectiveSpec`、`semanticHashVersion:3` 与 `billingDimensions`。提交在原报价请求上增加 `quoteId/clientRequestId`。规格、引用、需求版本、配置或连接变化需要重新报价；同一幂等键不同语义冲突。未知提交后只能查原请求，不自动发起新付费生成。

`actualSpec` 由产物测量获得，不使用请求值填充未知信息。规格验收与账务独立：安全原件可以保留下载，规格不符不表示免费；以原请求可信 usage 结算，证据缺失保持对账中。

图片 V3 的供应商 4xx（包括安全分类的规格不支持）不单凭状态码证明未执行；无可信提交前拒绝证据时回执保留 `SUBMISSION_UNKNOWN` 与 `RECONCILING`，不得自动重试生成或释放预留。命名图片尺寸与显式宽高不能证明等价时，在报价前返回 `ADAPTER_FIELD_UNMAPPED`。

## 错误与兼容

规格错误通过 `error.code` 区分 `INVALID_PARAMETER`、`SPEC_CONFLICT`、`MISSING_SPEC`、`MEDIA_FORBIDDEN`、`ADAPTER_UNAVAILABLE`、`ADAPTER_FIELD_UNMAPPED`、`PRICE_UNAVAILABLE`、`UPSTREAM_SPEC_UNSUPPORTED`、`SUBMISSION_UNKNOWN`、`OUTPUT_SPEC_MISMATCH`、`UPGRADE_REQUIRED`。HTTP 状态和旧错误码继续保留。

媒体 HTTP 错误可携带安全的 `field/reason/source/stage/retryable/submissionState/billingState`。未确认提交状态不能声明未扣费；可恢复不代表可自动重发。全局过滤器不回显原始上游 body、URL、请求值、任意扩展或密钥。

V1/V2 仍使用原 DTO、原语义哈希和历史合同。新任务显式使用 V3；历史 JSON 不重算、不补新版默认、不切模型重放。不需要新增数据库表或重写历史迁移，版本化快照存放现有 JSON 字段。

Sub2API 当前报价接口的尺寸/质量/分辨率范围仍可能拒绝新值；SEP 返回价格合同原因，不能将其解释为供应商规格能力，也不承诺任意规格可端到端使用。真实通道联调、客户端启用与生产发布须分别验收。
