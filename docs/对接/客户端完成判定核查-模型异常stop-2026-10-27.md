### 当前怎么约束

针对声明了交付文件的文档编排节点，实际流程是：

1. 提示词要求模型先生成文件，确认符合要求，最后提交 JSON 文件清单。
2. 模型结束这一轮回复后，客户端检查提交 JSON、节点 ID、文件 ID 和路径。
3. 提交格式正确，再检查文件是否真实存在、非零字节、能够按规定格式解析。
4. 上述检查通过，才确认节点完成；失败则在原会话追加提示词，让模型修正。

所以，`stop` 的含义是“这一轮回复结束”，不是“文档已经写完”。只返回“已结束”这三个字，不能通过当前文档编排节点的提交校验。

## 3. 如何修复

1. **先补文件内容验收。** DOCX 至少提取正文并拒绝空内容；再按交付要求检查必要章节、表格等。复杂质量要求可以增加独立审核，不能只信模型自己的“完成”说明。
2. **把提交做成明确工具。** 模型调用 `submit_deliverables`，由客户端检查并返回通过或具体失败项；客户端验收通过才更新完成状态。普通回复结束时，继续保留未完成状态。工具提交仍需配合内容验收。
3. **区分异常类型并限制无效重试。** 空回复、输出截断、提交错误、文件缺失分别处理；连续没有进展时暂停并说明原因，保留已有文件和会话。
4. **界面明确区分回复结束和成果交付。** 未通过验收时显示“尚未交付／正在修复／需要处理”；“已完成”只对应验收通过。当前未取得用户所见“已结束”的具体界面事件，不能断言是哪一处状态显示错误。
