### ✅ P0-2: 工具调用 `undefined.id` 修复

**问题描述**:
- 前端工具卡片显示 `undefined`
- 根因:后端 `capabilityByToolName.get(tc.toolName)` 返回 `undefined` 时,代码未检查就访问 `cap!.id`

**修复内容**:
```typescript
// backend/src/modules/conversation/conversation-stream.service.ts:152-180

for (const tc of pendingToolCalls) {
  const cap = capabilityByToolName.get(tc.toolName);

  // 🔴 新增:检查工具是否存在
  if (!cap) {
    this.logger.error(`Tool "${tc.toolName}" not found in bindings for session ${sessionId}`);
    toolResults.push({
      type: 'tool-result',
      toolCallId: tc.toolCallId,
      toolName: tc.toolName,
      result: `工具 "${tc.toolName}" 未找到或未绑定`,
    });
    yield {
      event: 'tool_end',
      data: { name: tc.toolName, success: false, durationMs: 0 },
    };
    continue;  // 跳过该工具,不中断整个流程
  }

  // ... 继续执行工具
}
```

**效果**:
- ✅ 不再访问 `undefined.id`,避免运行时错误
- ✅ 向前端发送明确的失败事件,显示「工具未找到」
- ✅ 不中断整个对话流程,其他工具仍可正常执行

export function useLogout() {

### 2. P0-4: 原始 JSON 泄漏给用户 ⭐⭐⭐

**问题**:
数据库 `role=TOOL` 的消息 content 存储的是:
```json
[{"type":"tool-result","toolCallId":"toolu_xxx", ...}]
```

用户看到原始 JSON 数组,而非人类可读文本。

**修复方案**:
```typescript
// conversation-stream.service.ts:183-185

// 🔴 修复前
await this.prisma.message.create({
  data: { sessionId, role: 'TOOL', content: JSON.stringify(toolResults) },
});

// ✅ 修复后
const toolResultText = toolResults.map(r => {
  const result = r.result;
  if (typeof result === 'string') {
    return `工具: ${r.toolName}\n结果: ${result}`;
  }
  return `工具: ${r.toolName}\n结果: ${JSON.stringify(result)}`;
}).join('\n\n');

await this.prisma.message.create({
  data: { sessionId, role: 'TOOL', content: toolResultText },
});
```
