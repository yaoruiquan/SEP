# SEP 前后端端到端测试计划

> 计划日期：2026-07-24
> 测试范围：`web` 前端与 `backend` API 的浏览器端到端流程
> 约束：只允许新增测试文档；不修改任何源代码、依赖、配置或数据库结构

## 1. 测试目标

验证用户能否通过浏览器完成从访问前端、注册/登录、个人资料、能力浏览、数字员工使用、订阅和对话的核心流程；同时确认前后端错误提示、鉴权、路由跳转、刷新恢复和关键空状态可用。

## 2. 测试环境

| 项目 | 预期值 |
|---|---|
| 前端 | `http://127.0.0.1:3000` |
| 后端 API | `http://127.0.0.1:3001` |
| 前端代理 | `/api/*` 转发至后端 |
| API 文档 | `http://127.0.0.1:3001/api/docs` |
| 数据依赖 | PostgreSQL、Redis 已运行 |
| 外部模型 | 若对话流程触发模型，记录 sub2api 可达性和实际错误，不伪造通过 |

## 3. 测试数据策略

使用唯一的临时测试邮箱和随机密码。注册、创建会话、订阅等有副作用的操作只在本地开发环境执行，并在报告中记录是否成功；不删除或修改项目已有业务数据。

## 4. 测试用例

### A. 前端启动与页面

1. 打开首页，确认页面加载、无白屏、无未处理异常。
2. 访问 `/login`、`/register`，确认表单和导航可用。
3. 访问受保护页面，确认未登录时跳转或显示登录要求。
4. 检查浏览器控制台是否存在阻断级错误。

### B. 认证

1. 空表单提交，确认前端校验。
2. 注册唯一用户，确认成功提示和登录状态。
3. 重复邮箱注册，确认错误提示。
4. 登录错误密码，确认失败提示。
5. 正确登录，确认进入用户工作区。
6. 刷新页面，确认登录状态按项目约定恢复。
7. 退出登录，确认受保护页面不可继续访问。

### C. 用户资料

1. 查看当前用户信息。
2. 修改姓名或头像字段，确认成功反馈和刷新后保留。
3. 错误密码修改，确认失败且不改变登录状态。

### D. 能力与数字员工

1. 查看能力列表及空状态。
2. 查看数字员工列表及详情。
3. 非管理员访问管理操作，确认被拒绝。
4. 管理员创建、编辑、发布数字员工（若已有管理员测试凭据）。
5. 绑定/解绑能力，确认状态和错误提示。

### E. 订阅与会话

1. 查看订阅列表及未订阅空状态。
2. 创建会话并确认显示在会话列表。
3. 重命名会话、刷新页面，确认标题持久化。
4. 发送消息，确认 SSE 文本/工具事件或结构化错误可见。
5. 查看历史消息，确认刷新后仍存在。
6. 删除会话，确认列表和详情状态正确。

### F. 兼容性与安全

1. 未登录直接访问核心 API 对应页面。
2. 检查 access token 不落入 localStorage。
3. 检查 refresh token 不显示在页面脚本可读内容中。
4. 检查重复点击、空输入、超长输入和网络失败的 UI 行为。

## 5. 判定标准

- 通过：页面、请求、状态反馈和持久化结果符合预期，无阻断错误。
- 失败：出现白屏、路由死循环、未捕获异常、鉴权绕过、数据丢失或核心流程无法继续。
- 阻塞：缺少必要凭据、外部服务或运行环境导致无法执行；不得将阻塞记为通过。

实际执行结果写入同目录的 `2026-07-24-e2e-test-report.md`，逐条记录步骤、结果、证据和未执行原因。
