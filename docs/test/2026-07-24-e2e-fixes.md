### P0：员工详情页客户端崩溃 ✅

**问题描述**：访问 `/marketplace/[id]` 时页面崩溃，报错 `Cannot read properties of undefined (reading 'length')`

**根本原因**：
- 代码位置：`web/src/app/(user)/marketplace/[id]/page.tsx:109`
- 代码直接访问 `cap.industry.length`，但 `industry` 字段可能为 `undefined`

**修复方案**：
```typescript
// 修复前
{cap.industry.length > 0 && (
  <p className="mt-1 text-xs text-fg-subtle">
    行业：{cap.industry.join('、')}
  </p>
)}

// 修复后
{cap.industry && cap.industry.length > 0 && (
  <p className="mt-1 text-xs text-fg-subtle">
    行业：{cap.industry.join('、')}
  </p>
)}
```

**文件**：`web/src/app/(user)/marketplace/[id]/page.tsx`

### P1：管理员待审核状态过滤错误 ✅

**问题描述**：
- 仪表盘显示"待审能力 4"
- 能力审核页"待审核"标签显示 4 条记录
- 切换到"全部"标签，这 4 条记录状态全部显示"已通过"

**根本原因**：
1. 后端 `GET /capabilities` 端点没有 `status` 查询参数
2. 前端调用 `useAllCapabilities('PENDING')` 传入 `status=PENDING`，但后端忽略了该参数
3. 后端 Service 层硬编码只返回 `status: APPROVED` 的数据

**修复方案**：

**后端 Controller** (`backend/src/modules/capability/capability.controller.ts`):
```typescript
// 添加 status 查询参数
@ApiQuery({ name: 'status', required: false, enum: ['PENDING', 'APPROVED', 'REJECTED'] })
async findAll(
  @Query('type') type?: string,
  @Query('industry') industry?: string,
  @Query('position') position?: string,
  @Query('status') status?: string,  // 新增
  @Query('page') page = 1,
  @Query('limit') limit = 20,
) {
  return this.capabilityService.findAll({ type, industry, position, status, page: +page, limit: +limit });
}
```

**后端 Service** (`backend/src/modules/capability/capability.service.ts`):
```typescript
// 修复前：硬编码 APPROVED
async findAll(opts: { type?, industry?, position?, page, limit }) {
  const where: any = { status: APPROVED };  // ❌ 硬编码
  // ...
}

// 修复后：支持动态 status 过滤
async findAll(opts: { type?, industry?, position?, status?, page, limit }) {
  const where: any = {};
  
  // 只有未明确指定 status 时才默认为 APPROVED
  if (status) {
    where.status = status.toUpperCase();
  } else {
    where.status = APPROVED;
  }
  // ...
}
```

**文件**：
- `backend/src/modules/capability/capability.controller.ts`
- `backend/src/modules/capability/capability.service.ts`

### P1：移动端布局未响应式适配 ✅

**问题描述**：375px 视口下侧栏仍固定 240px，主内容区域仅约 135px，导航未收起为汉堡菜单

**根本原因**：
- 代码位置：`web/src/components/shell/user-shell.tsx`
- 侧边栏使用 `w-60` 固定宽度，没有响应式断点
- 缺少移动端汉堡菜单实现

**修复方案**：
1. 添加移动端汉堡菜单按钮（使用 `Menu` 和 `X` 图标）
2. 添加侧边栏开关状态 `sidebarOpen`
3. 添加遮罩层（点击关闭侧边栏）
4. 侧边栏使用 `fixed` 定位 + `translate-x` 动画
5. 使用 `lg:` 断点在大屏幕上恢复为静态布局

**关键代码**：
```typescript
const [sidebarOpen, setSidebarOpen] = useState(false);

// 汉堡菜单按钮（仅移动端显示）
<button className="fixed left-4 top-4 z-50 ... lg:hidden">
  {sidebarOpen ? <X /> : <Menu />}
</button>

// 遮罩层（仅移动端显示）
{sidebarOpen && (
  <div className="fixed inset-0 z-30 bg-black/50 lg:hidden" />
)}

// 侧边栏响应式
<aside className={`
  fixed lg:static ... 
  transition-transform lg:translate-x-0
  ${sidebarOpen ? 'translate-x-0' : '-translate-x-full'}
`}>
```

**文件**：`web/src/components/shell/user-shell.tsx`
