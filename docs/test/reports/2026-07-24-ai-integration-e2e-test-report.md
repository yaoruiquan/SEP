> 测试日期：2026-07-24

## 1. 验收结论

本轮共覆盖 28 个验收项：**通过 16 项、部分通过 3 项、不通过 4 项、阻塞 2 项、未执行 3 项**。

结论为：**AI 能力集成端到端验收不通过，当前版本不满足 AI 对话核心能力的发布标准。**

注册、登录、员工订阅、管理员员工管理、模型选择器、能力列表与路由权限等基础功能可用；但最关键的普通 AI 回复、Token 统计和工具调用闭环均未通过。普通消息等待超过 135 秒仍没有助手文本；工具调用出现未处理异常、异常能力名和原始 JSON 泄漏，且没有最终助手回复。另发现账号切换后短时间展示上一账号工作台缓存数据的高风险问题。

建议判定：

- 基础管理与演示页面：**有条件通过**。
- AI 对话与能力执行：**不通过**。
- Coze 真实集成：**环境阻塞，不能判定通过**。
- 整体生产发布：**不建议**。

## 4. 核心失败详情

### 4.1 P1：账号切换后出现跨账号工作台缓存

复现过程：

1. 注册并登录新账号。
2. 退出后登录 `user@sep.local`。
3. 侧栏已显示演示用户身份，但工作台主体仍显示上一账号的欢迎信息、订阅数、会话数和消息数。
4. 等待约 2.6 秒仍未自动恢复；手动刷新页面后才恢复为当前账号数据。

影响：

- 属于用户隔离和隐私展示风险。
- 即使后端权限没有越权，前端展示上一用户缓存数据也不应发生。
- 账号切换、退出登录和登录成功后，需要清除或按用户隔离所有用户相关查询缓存。

建议优先级：**P1 高**。如页面可能显示敏感会话摘要或个人数据，应按 P0 安全问题处理。

### 4.2 P0/P1：普通 AI 回复严重超时

测试会话：`cmrynrb47000s7qbjaign1nm1`  
数字员工：小海  
测试消息：`你好,介绍一下你自己`

实际结果：

- 用户消息立即显示。
- 页面进入“停止生成”状态。
- 超过 135 秒没有任何可见助手文本。
- 测试期间浏览器控制台未出现可直接解释该问题的应用错误。
- 最终只能手动停止生成。
- 页面没有 Token 消耗信息。

数据库结果：该用户消息已持久化，但没有对应的正常助手文本消息。这说明“请求已提交”不等价于“AI 回复链路可用”。

建议优先级：**P0（若 AI 对话是发布核心功能）**。

### 4.3 P0：工具调用流程异常且错误处理不合格

测试消息：`搜索一下 2026 年全球跨境电商市场规模预测`

页面实际表现：

- 出现两个标记为完成的“调用能力”卡片，但能力名称显示成笼统的“能力调用”。
- 随后出现失败卡片，能力名称分别显示为 `____` 和 `tool`。
- 页面直接展示：`Execution error: Cannot read properties of undefined (reading 'id')`。
- 页面展示：`No output generated. Check the stream for errors.`。
- 原始工具结果 JSON 直接出现在聊天消息区域。
- 没有产生最终助手总结回复。
- 页面没有显示 Token 消耗。

只读数据库证据：

- 会话状态为 `ACTIVE`。
- 共 4 条消息：2 条 `USER`、1 条空内容 `ASSISTANT`、1 条包含原始错误 JSON 的 `TOOL`。
- `tool_executions` 表中该会话记录数为 0。

`OPENCODE_API_BASE_URL` 为空时，联网搜索能力真实执行失败可以视为环境限制；但前端仍应正确显示能力名称、友好错误、失败状态，并完整结束本轮流式响应。当前的 `undefined.id`、异常工具名、原始 JSON 泄漏和空助手消息不能归类为“符合预期的未配置提示”。

建议优先级：**P0**。

### 4.4 P2：会话创建界面与测试指南不一致

指南要求创建会话时填写“市场调研测试”，但实际创建界面没有会话名称输入框。数据库中测试会话的 `title` 为空。

影响：用户无法按指南创建可识别的会话名称，多个会话的管理体验和历史定位能力受限。

### 4.5 P2：员工创建状态流程与测试指南不一致

创建员工表单没有状态字段，创建后员工默认为“草稿”；只能在编辑表单中再修改为“已发布”。最终发布、编辑和能力绑定均能持久化成功，但流程与指南要求不一致。

需要明确产品预期：

- 如果“创建即草稿”是安全设计，应更新测试指南。
- 如果管理员应能创建时选择状态，则需要补齐表单和接口行为。

## 8. 发布建议与回归要求

### 8.1 发布建议

- **生产发布：不通过。** AI 回复、Token 统计、工具调用和用户缓存隔离均存在关键问题。
- **内部基础功能演示：有条件通过。** 可演示注册、登录、订阅和管理员管理；不要将 AI 对话和真实 Coze/OpenCode 能力标记为已完成。
- **Coze 集成：不能判定。** 必须在配置有效 `COZE_PAT` 和真实 Bot 后重新测试。

### 8.2 必须回归的项目

1. 账号 A 退出后登录账号 B，B 的页面不得出现 A 的欢迎信息、统计或会话数据。
2. 普通 AI 消息应在可接受时间内开始流式输出，并正常结束生成状态。
3. `inputTokens`、`outputTokens`、`totalTokens` 应持久化且页面显示均大于 0。
4. OpenCode 未配置时，应显示可理解的“服务未配置/不可用”错误，而不是 `undefined.id`。
5. 工具卡片必须显示真实能力名称、参数、明确成功/失败状态和经过处理的输出。
6. 工具调用失败后不应生成空助手消息，也不应把内部原始 JSON 直接展示给用户。
7. 配置 OpenCode 服务后，重新验证“用户消息 → 工具调用 → 工具结果 → 最终助手回复”的完整闭环。
8. 配置 Coze PAT 和真实 Bot 后，完成导入、绑定及对话调用回归。
9. 明确会话名称和员工创建状态的产品规范，并同步 UI 或测试指南。

## 9. 最终判定

**本次 AI 能力集成端到端测试：不通过。**

阻断原因不是单纯的外部服务缺失：即使考虑 `OPENCODE_API_BASE_URL` 未配置，当前系统仍存在普通模型回复超时、Token 缺失、工具流程未正常收尾、内部异常直接暴露和跨账号缓存展示等应用层问题。修复后需按第 8.2 节进行完整回归，再决定是否具备发布条件。
