# 硅基人才平台 — 模块开发顺序指南

> **版本**: v1.0 · **日期**: 2026-07-23  
> **原则**: 按依赖关系、风险优先级、价值交付顺序

---

## 0. 开发顺序设计原则

### 原则 1：依赖优先
被依赖的模块先开发（例如：认证模块 → 用户模块 → 业务模块）

### 原则 2：风险优先
技术不确定性高的模块先验证（例如：Agent Runtime + ModelRelayClient 集成）

### 原则 3：价值优先
能尽早展示核心价值的模块优先（例如：对话窗口比管理后台优先）

### 原则 4：最小闭环
每个阶段交付一个可运行的最小闭环（例如：能完成一次对话 = 闭环）

---

## 1. 开发顺序总览

```
第 0 层：基础设施（地基）
  → 第 1 层：核心风险验证（Agent Runtime）
    → 第 2 层：用户体系（认证 + 用户）
      → 第 3 层：能力管理（硅基能力上传 + 审核）
        → 第 4 层：碳基员工管理（创建 + 绑定能力）
          → 第 5 层：对话服务（MVP 核心闭环）
            → 第 6 层：订阅 + 算力（商业化）
              → 第 7 层：数据资产 + 运营（增值功能）
```

## 第 1 层：核心风险验证（最高优先级）

### 1.1 Vercel AI SDK + ModelRelayClient 集成验证

**目标**：验证技术可行性（风险最大的部分）

**任务**：
1. 创建测试端点 `/api/test/agent-runtime`
2. 实现 `createOpenAICompatible` 对接 ModelRelayClient
3. 实现简单 tool calling（一个 echo tool）
4. 验证流式输出（SSE）

**核心代码**：
```typescript
// apps/platform-api/src/test/agent-runtime.test.ts
const modelRelay = createOpenAICompatible({
  name: 'model-relay',
  baseURL: process.env.MODEL_RELAY_BASE_URL,
  apiKey: process.env.MODEL_RELAY_KEY
});

const tools = {
  echo: tool({
    description: 'Echo tool for testing',
    parameters: z.object({ message: z.string() }),
    execute: async ({ message }) => ({ result: message })
  })
};

const result = await streamText({
  model: modelRelay('gpt-4o-mini'),
  messages: [{ role: 'user', content: 'Call echo tool with "hello"' }],
  tools,
  maxSteps: 5
});
```

**验收标准**：
- ✅ ModelRelayClient 调用成功（返回 LLM 响应）
- ✅ Tool calling 成功（LLM 调用 echo tool）
- ✅ 流式输出正常（SSE 流返回）
- ✅ 错误处理完整（超时、模型不可用、tool 执行失败）

**关键决策点**：如果这一步失败，整个 Agent Runtime 方案需要重新评估。

### 1.2 OpenCode Skill 集成验证

**目标**：验证 OpenCode 作为硅基能力的可行性

**任务**：
1. 安装 OpenCode CLI
2. 创建测试 Skill（简单文案生成）
3. 实现 `OpenCodeSkillAdapter`
4. 在 Vercel AI SDK 中注册为 tool

**核心代码**：
```typescript
class OpenCodeSkillAdapter implements Capability {
  async execute(params: { prompt: string }) {
    const result = await spawnOpenCode({
      skill: this.skillName,
      prompt: params.prompt,
      model: 'via-model-relay',  // 指向 ModelRelayClient
      format: 'json'
    });
    return { success: true, data: result };
  }
}

// 注册为 tool
const tools = {
  copywriting: tool({
    description: 'Generate product copywriting',
    parameters: z.object({ product: z.string() }),
    execute: async ({ product }) => {
      return await openCodeSkillAdapter.execute({ prompt: product });
    }
  })
};
```

**验收标准**：
- ✅ OpenCode CLI 能被 Node.js spawn 调用
- ✅ OpenCode 能通过 ModelRelayClient 调用 LLM
- ✅ Skill 执行结果能返回给 Vercel AI SDK
- ✅ 错误处理（Skill 执行失败、超时）

## 前后端开发模式

### 核心原则：分层并行开发

**策略**：
- **第 0-1 层**：后端先行（验证技术风险）+ 前端搭建框架
- **第 2-7 层**：前后端并行（API 文档先行 + Mock API）

---

### 阶段 1：后端先行（第 0-1 层）

**后端任务**：
- 搭建基础设施（Monorepo、Prisma、Docker Compose）
- Agent Runtime 技术验证（Vercel AI SDK + ModelRelayClient）
- OpenCode Skill 集成验证

**前端任务**：
- 搭建 Next.js 框架
- 设计 UI 组件库（对话窗口、卡片组件、表单）
- 不对接 API，先做静态页面

**为什么后端先行**：
- Agent Runtime 是最大技术风险，必须先验证
- 前端可以独立进行 UI 设计，不等后端

**交付物**：
- ✅ 开发环境一键启动
- ✅ Agent Runtime 技术演示可运行
- ✅ 前端框架 + 静态 UI 组件库

---

### 阶段 2：并行开发（第 2-7 层）

#### 并行开发流程

```
第 1 步：后端定义 API 接口文档（OpenAPI/Swagger）
    ↓
第 2 步：前后端并行开发
    ├─ 后端：实现真实 API
    └─ 前端：使用 Mock API 开发
    ↓
第 3 步：对接联调
    ├─ 移除 Mock API
    ├─ 对接真实 API
    └─ 验收测试
    ↓
第 4 步：进入下一层
```

---

**要求**：每层开始前，后端必须先输出 API 接口文档

**工具**：

- Swagger UI（可视化文档）

#### Mock API（前端不等后端）

**方案 A：Next.js API Routes（推荐）**

```typescript
// app/api/auth/login/route.ts
```

## 开发顺序与并行关系总结

### 串行关系（必须按顺序）

```
第 0 层（基础设施）
  ↓ 必须完成
第 1 层（风险验证）
  ↓ 必须完成
第 2 层（用户体系）
  ↓ 依赖认证
第 3 层（硅基能力）
  ↓ 依赖认证
第 4 层（碳基员工）
  ↓ 依赖能力库
第 5 层（对话服务）
  ↓ 依赖碳基员工
第 6 层（订阅 + 算力）
  ↓ 依赖对话服务
第 7 层（数据资产 + 运营）
```

**层与层之间是串行**（必须按顺序），**层内前后端是并行**。

---

### 并行关系（可同时进行）

#### 层内并行（同一层）

```
第 2 层：
  后端开发认证 API  ║  前端开发登录页面
                     ║
                   对接联调
```

#### 模块并行（同一层不同模块）

```
第 3 层：
  能力上传模块  ║  能力审核模块
  （贡献者端）  ║  （运营端）
```

#### 前端多项目并行

```
platform-web    ║  admin-web      ║  contributor-web
（用户端）      ║  （运营端）     ║  （贡献者端）
```
