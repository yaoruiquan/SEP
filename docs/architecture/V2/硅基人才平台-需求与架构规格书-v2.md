## 0. Executive Summary

硅基人才平台是一个**面向 B/C 端的 AI 能力订阅平台**，让企业和个人用户像"雇佣员工"一样订阅碳基员工（例如"电商运营专员"），通过 ChatGPT 风格的对话窗口使用碳基员工提供的硅基能力（Agent/RPA/Skill/AI应用）完成业务任务。

**核心价值**：
- 企业无需懂技术，开箱即用 AI 能力
- 统一算力入口，无需自己申请各家 LLM Key
- 能力可复用，降低开发成本
- 数据沉淀为企业资产

**第一阶段聚焦**：电商行业

## 1. 核心概念

### 1.1 碳基员工（Digital Employee）

**定义**：平台售卖的"岗位包"，例如"电商运营专员"、"客服专员"。

**特征**：
- 由平台运营方创建和上架
- 包含多个硅基能力（Agent/RPA/Skill/AI应用）
- 按行业和岗位分类（例如：电商 → 运营岗）
- 用户订阅后，通过对话方式使用

**类比**：招聘网站上的"岗位 JD"（职位描述），明确这个岗位会做什么事

---

### 1.2 硅基能力（Silicon Capability）

**定义**：第三方开发者上传的 AI 能力，包括 4 种类型：

| 类型 | 说明 | 示例 |
|------|------|------|
| **Agent** | 基于 Coze/Dify/N8N 等平台开发的智能体 | 竞品分析助手、选品助手 |
| **RPA** | 实在智能/影刀 等 RPA 工作流 | 商品上架流程、数据采集流程 |
| **Skill** | 提示词模板 + LLM 生成 | 爆款文案生成、标题优化 |
| **AI 应用** | 独立的 Web 应用 | 商品主图生成器、换装应用 |

**特征**：
- 由能力贡献者（内部员工/外部 ISV）上传
- 可被多个碳基员工复用（例如"爆款文案生成"可用于运营专员、内容创作助手）
- 对外暴露统一接口，隐藏底层实现差异

## 2. 用户角色与功能

### 2.1 企业/个人用户（B/C 端）

**核心流程**：
1. 注册/登录平台
2. 浏览碳基员工市场（按行业/岗位筛选）
3. 查看碳基员工详情（包含的硅基能力清单）
4. 订阅碳基员工（付费，本版暂不讨论计费细节）
5. 进入对话窗口，使用碳基员工

**核心页面**：
- 碳基员工市场（浏览、筛选、订阅）
- 我的碳基员工（已订阅列表）
- 对话窗口（ChatGPT 风格，与碳基员工交互）
- 算力管理（充值、消费记录、余额预警）
- 数据资产（对话历史、生成内容）

---

### 2.2 能力贡献者（内部员工 / 外部 ISV）

**核心流程**：
1. 注册/登录平台
2. 上传硅基能力：
   - Agent：提供 Coze Bot ID / Dify 配置 / N8N workflow
   - RPA：上传压缩包 + 参数说明
   - Skill：编写提示词模板
   - AI 应用：提供 Web URL 或 API endpoint
3. 填写元数据（名称、类型、行业、岗位、描述、输入输出 schema）
4. 提交审核
5. 审核通过后进入能力库
6. 查看收益（能力被调用次数、收入分成）

**核心页面**：
- 能力上传（分类型的上传表单）
- 我的能力（已上传列表、状态、收益）
- 使用统计（哪些碳基员工使用了我的能力）

---

### 2.3 平台运营方

**核心流程**：
1. 审核硅基能力（能力贡献者上传后）
2. 创建碳基员工：
   - 填写基本信息（名称、行业、岗位、简介）
   - 从能力库选择硅基能力进行绑定
   - 编写碳基员工的 System Prompt（Agent 人设）
   - 设置定价、标签
   - 上架
3. 管理企业/用户（租户管理、订阅管理）
4. 管理算力平台（上游渠道接入、余额监控）
5. 数据分析（使用统计、收益报表）

**核心页面**：
- 能力审核（待审核列表、审核详情）
- 碳基员工管理（创建、编辑、上架/下架）
- 企业管理（租户列表、订阅记录）
- 算力平台（渠道配置、余额监控、消费统计）
- 数据看板（使用量、收益、Top 能力）

### 3.3 第二层：碳基员工层（Agent 编排）

**核心逻辑**：

```typescript
class DigitalEmployee {
  id: string;
  name: string;              // "电商运营专员"
  industry: string;          // "电商"
  position: string;          // "运营"
  systemPrompt: string;      // Agent 人设
  capabilities: Capability[]; // 绑定的硅基能力列表
  
  async chat(userMessage: string, sessionId: string) {
    // 使用 Vercel AI SDK 的 Tool Calling 能力
    const result = await streamText({
      model: openai('gpt-4o'),
      system: this.systemPrompt,
      messages: await getSessionHistory(sessionId),
      tools: this.buildTools(),  // 将硅基能力转为 tools
      maxSteps: 10,
      onStepFinish: async (step) => {
        // 持久化每个 step（tool_calls + 结果）
        await saveStep(sessionId, step);
      }
    });
    
    return result.toDataStreamResponse();
  }
  
  // 将硅基能力转换为 Vercel AI SDK 的 tools 格式
  buildTools() {
    return this.capabilities.map(cap => ({
      [cap.name]: tool({
        description: cap.description,
        parameters: zodFromSchema(cap.inputSchema),
        execute: async (args) => {
          // ★ 调用统一接口
          return await cap.execute(args);
        }
      })
    }));
  }
}
```

**System Prompt 示例**：

```
你是电商运营专员，擅长竞品分析、商品上架、文案生成、主图制作。

你拥有以下能力工具：
- 竞品分析助手：分析市场竞品数据
- 选品助手：根据市场趋势推荐商品
- 商品上架流程：自动上架商品到店铺
- 爆款文案生成：生成小红书/抖音风格文案
- 商品主图生成器：生成商品主图

当用户提出需求时，你需要：
1. 理解用户意图
2. 自动选择合适的工具
3. 按顺序执行（如：先分析竞品 → 再生成文案 → 再生成主图 → 最后上架）
4. 遇到缺少信息时，主动追问用户
5. 任务完成后，总结执行结果

保持专业、高效、友好的沟通风格。
```

### 3.4 第三层：硅基能力抽象层（★核心创新）

**设计目标**：
- 统一接口：不管底层是 Agent/RPA/Skill/AI应用，对碳基员工层暴露相同接口
- 适配器模式：每种类型有自己的 Adapter，负责协议转换
- 能力复用：一个硅基能力可被多个碳基员工调用

**统一接口定义**：

```typescript
interface Capability {
  // 元数据
  id: string;
  name: string;                    // "竞品分析助手"
  type: 'agent' | 'rpa' | 'skill' | 'ai-app';
  description: string;             // LLM 可理解的描述
  industry: string[];              // 适用行业
  position: string[];              // 适用岗位
  
  // Schema（用于参数验证 + LLM tool calling）
  inputSchema: JSONSchema;
  outputSchema: JSONSchema;
  
  // ★ 统一执行接口
  execute(params: Record<string, any>): Promise<CapabilityResult>;
}

interface CapabilityResult {
  success: boolean;
  data: any;
  error?: string;
  metadata?: {
    duration: number;    // 执行耗时（ms）
    tokensUsed?: number; // Token 消耗（如适用）
  };
}
```

**适配器实现（4种类型）**：

#### 3.4.1 Agent Adapter

```typescript
class AgentAdapter implements Capability {
  type = 'agent';
  platform: 'coze' | 'dify' | 'n8n';
  config: {
    botId?: string;      // Coze Bot ID
    apiKey?: string;     // Dify API Key
    workflowUrl?: string; // N8N Webhook URL
  };
  
  async execute(params: Record<string, any>): Promise<CapabilityResult> {
    if (this.platform === 'coze') {
      const result = await cozeAPI.chat({
        bot_id: this.config.botId,
        user: params.user_id,
        query: params.message,
        stream: false
      });
      return {
        success: true,
        data: result.messages[0].content
      };
    }
    
    // TODO: 支持 Dify、N8N
  }
}
```

#### 3.4.2 RPA Adapter

```typescript
class RPAAdapter implements Capability {
  type = 'rpa';
  platform: '实在' | '影刀';
  executionMode: 'cloud' | 'download' | 'client';
  
  async execute(params: Record<string, any>): Promise<CapabilityResult> {
    if (this.executionMode === 'download') {
      // 返回下载链接
      return {
        success: true,
        data: {
          downloadUrl: await getPresignedUrl(this.workflowId),
          configDoc: this.configDoc,
          message: '请下载 RPA 包并导入到实在智能平台'
        }
      };
    }
    
    if (this.executionMode === 'cloud') {
      // 云端执行（需要 RPA 运行时）
      const result = await rpaCloudService.execute({
        workflowId: this.workflowId,
        params: params
      });
      return { success: true, data: result };
    }
    
    // TODO: client 模式（客户端执行）
  }
}
```

#### 3.4.3 Skill Adapter

```typescript
class SkillAdapter implements Capability {
  type = 'skill';
  template: string;  // 提示词模板
  modelConfig: {
    model: string;
    temperature: number;
    maxTokens: number;
  };
  
  async execute(params: Record<string, any>): Promise<CapabilityResult> {
    // 填充模板
    const prompt = fillTemplate(this.template, params);
    
    // 调用 LLM（通过平台算力层）
    const result = await computePlatform.complete({
      model: this.modelConfig.model,
      prompt: prompt,
      temperature: this.modelConfig.temperature,
      maxTokens: this.modelConfig.maxTokens
    });
    
    return {
      success: true,
      data: result.content,
      metadata: {
        tokensUsed: result.usage.totalTokens,
        duration: result.duration
      }
    };
  }
}
```

#### 3.4.4 AI App Adapter

```typescript
class AIAppAdapter implements Capability {
  type = 'ai-app';
  integrationMode: 'api' | 'iframe' | 'redirect';
  apiUrl?: string;
  webUrl?: string;
  
  async execute(params: Record<string, any>): Promise<CapabilityResult> {
    if (this.integrationMode === 'api') {
      // HTTP API 调用
      const result = await axios.post(this.apiUrl, params);
      return { success: true, data: result.data };
    }
    
    if (this.integrationMode === 'iframe') {
      // 返回 iframe URL
      return {
        success: true,
        data: {
          iframeUrl: this.webUrl,
          params: params
        }
      };
    }
    
    // redirect: 返回跳转链接
    return {
      success: true,
      data: {
        redirectUrl: `${this.webUrl}?${new URLSearchParams(params)}`
      }
    };
  }
}
```

## 4. 硅基能力实现路径（已确认）

### 4.1 两条技术路径

| 路径 | 覆盖类型 | 实现方式 | 优势 |
|------|---------|---------|------|
| **路径 A：第三方集成** | Agent（Coze/Dify/N8N）<br>AI 应用 | 调用外部 API | 快速接入现有生态 |
| **路径 B：自研 Agent** | Agent（OpenCode）<br>Skill（SKILL.md） | OpenCode Runtime<br>模型走 SEP ModelRelayClient | MIT 开源，商用无风险<br>模型自主可控 |

### 4.2 混合绑定设计

**核心原则**：一个碳基员工可以混合绑定多种路径的硅基能力

**示例**：
```
碳基员工：电商运营专员
├── [OpenCode Agent] 竞品分析助手
├── [Coze Agent] 选品助手  
├── [OpenCode Skill] 爆款文案生成
├── [API] 主图生成器（AI应用）
└── [下载] 商品上架流程（RPA，用户手动执行）
```

**用户对话流程**：
```
用户: "帮我上新一款手机壳"

碳基员工 Agent Runtime（统一编排）:
  → 调用 OpenCode Agent "竞品分析助手"
  → 调用 OpenCode Skill "爆款文案生成"
  → 调用 Coze Agent "选品助手"
  → 调用 AI 应用 "主图生成器"
  → 返回 RPA 下载链接（用户手动执行上架）
```

### 4.3 RPA 处理方式

- **第一阶段**：下载模式（用户手动导入实在/影刀平台）
- **长期规划**：客户端执行（桌面应用，会议纪要已明确）

### 4.4 推理循环控制

- **采用 LLM 自由决策**（tool-calling loop）
- 碳基员工 Agent 自动选择调用顺序和组合
- 基于 Vercel AI SDK 或 OpenCode 的原生能力

## 5. 数据模型（高层设计）

### 5.1 核心实体

```
碳基员工 (DigitalEmployee)
├── 基本信息: id, name, industry, position, description
├── Agent 配置: systemPrompt, modelId, maxSteps
├── 状态: draft / published / archived
└── 关联: 绑定的硅基能力列表（多对多）

硅基能力 (Capability)
├── 基本信息: id, name, type, description
├── 分类: industry[], position[]
├── Schema: inputSchema, outputSchema
├── 配置: 根据 type 不同而不同
│   ├── Agent: platform, botId, apiKey
│   ├── RPA: platform, workflowPackageUrl, configDoc
│   ├── Skill: template, modelConfig
│   └── AIApp: integrationMode, apiUrl/webUrl
├── 状态: pending / approved / rejected
└── 统计: usageCount, rating

绑定关系 (EmployeeCapabilityBinding)
├── employeeId
├── capabilityId
└── order: number  // 推荐调用顺序（可选）

订阅记录 (Subscription)
├── userId / tenantId
├── employeeId
├── status: active / paused / expired
├── startDate / endDate
└── config: 用户配置的参数（店铺账号等）

会话 (ConversationSession)
├── userId
├── employeeId
├── messages: Message[]
└── status: active / archived

消息 (Message)
├── sessionId
├── role: user / assistant / tool
├── content
├── toolCalls: ToolCall[]  // tool_call 记录
└── createdAt

工具调用记录 (ToolExecution)
├── sessionId
├── capabilityId
├── input
├── output
├── duration
├── tokensUsed
└── status: success / failed
```

## 7. 关键设计决策（已确认）

### 7.1 数据模型设计原则

**A. 租户设计**
- ✅ 第一阶段：不设计多租户（B/C端都直接关联 User）
- 🔄 第二阶段：如需企业多人共享订阅，再引入 `Tenant` 表

**B. 能力配置存储**
- ✅ **采用方案 C：分表 + metadata JSON**

```prisma
model Capability {
  id          String   @id @default(cuid())
  type        String   // 'agent' | 'rpa' | 'skill' | 'ai-app'
  
  // 共同字段
  name        String
  description String
  inputSchema Json
  outputSchema Json
  
  // 类型特定配置（分表，类型安全）
  agentConfig  AgentConfig?
  rpaConfig    RPAConfig?
  skillConfig  SkillConfig?
  aiAppConfig  AIAppConfig?
  
  // 灵活扩展字段（未来不确定的配置）
  metadata    Json?
}

model AgentConfig {
  id           String @id @default(cuid())
  capabilityId String @unique
  platform     String  // 'coze' | 'dify' | 'n8n'
  botId        String?
  apiKey       String?
  workflowUrl  String?
  
  capability   Capability @relation(fields: [capabilityId], references: [id])
}

// RPAConfig, SkillConfig, AIAppConfig 类似
```

**优势**：
- ✅ 核心字段类型安全（TypeScript 自动推断）
- ✅ 查询性能好（可建索引，不需要解析 JSON）
- ✅ 灵活扩展（metadata JSON 兜底）
- ✅ 长期维护友好（重构时 TypeScript 编译器提示修改点）

**C. 表设计模式**
- ✅ **分表模式**（避免"横向表 vs 纵向表"的二元对立）
  - 核心实体用主表（Capability 存共同字段）
  - 类型特定字段用关联表（AgentConfig / RPAConfig 分表）
  - 灵活扩展用 JSON（metadata 字段）

**D. 字段规范（遵循会议要求）**
- ✅ 主键统一用 `cuid()`，不用自增 ID
- ✅ 尽量减少表关联（用冗余字段）
- ✅ 枚举配置化（不写死在代码里）

## 8. 前端交互设计（已确认）

### 8.1 碳基员工选择与会话管理

**A. 碳基员工选择方式**
- ✅ 对话窗口顶部有下拉框，随时切换碳基员工

- 会话列表显示在左侧边栏

### 8.2 能力调用展示

**采用可折叠模式**

```
🤖 电商运营专员:
好的，我来帮您完成新品上架。
```

- 默认简洁（避免信息过载）

### 8.4 多轮对话

- ✅ 支持多轮对话、中途追问、迭代修正
- ✅ 碳基员工记住上下文
- ✅ 依赖 Agent Runtime 原生能力（Vercel AI SDK / OpenCode）
