## 3. 设计系统（方案 B — 白底商务风）

### 3.1 色板

品牌主色为**靛蓝（Indigo）**——这是实现层（`globals.css` / `tailwind.config.ts`）一直在用、整套暗色玻璃系统也建立其上的颜色。**正式定案：保留靛蓝为基调，废弃本文档早期的橙红 `#eb3f00`（该色从未落地）。**

为消除"单一冷色相显得单调、默认靛蓝显得不够专业"的问题，本版本做三处升级：① 主色靛蓝调更深沉（`#4f46e5` 而非默认的 `#6366f1`）；② 引入**第二强调色：青（Teal）**，专做数据强调；③ 中性色从偏暖灰统一到冷静的 **Slate** 系。三色分工：

- **靛蓝（Primary）**——品牌主色。只给"最想让用户点的动作"：主 CTA、当前选中项、链接、品牌标识。
- **青（Secondary / Accent）**——数据强调色。只用于关键指标数字、图表序列、数据高亮，制造色相层次。**不承担状态语义**（成功/警告/危险仍是各自的绿/琥珀/红）。
- **Slate 中性**——承担全部分层（背景/表面/边框/文字），让两种彩色"稀缺而突出"。

```css
/* ── 品牌主色 · Indigo（更深沉，去模板感）── */
--brand:            #4f46e5;   /* indigo-600 主色：CTA、链接、选中 */
--brand-hover:      #4338ca;   /* indigo-700 悬停/按下 */
--brand-subtle:     #eef2ff;   /* indigo-50  主色浅底：选中态、标签底 */
--brand-ring:       #4f46e533; /* focus ring（20% 透明） */

/* ── 第二强调色 · Teal（数据强调，非状态语义）── */
--secondary:        #0d9488;   /* teal-600  关键指标、图表、数据高亮 */
--secondary-hover:  #0f766e;   /* teal-700  */
--secondary-subtle: #f0fdfa;   /* teal-50   数据卡浅底 */
--secondary-ring:   #0d948833;

/* ── 中性色 · Slate（冷静、统一，承担分层）── */
--background:       #ffffff;   /* 页面背景 */
--sidebar:          #f8fafc;   /* slate-50  侧边栏 */
--card:             #ffffff;   /* 卡片 */
--muted:            #f1f5f9;   /* slate-100 次级背景、hover */
--border:           #e2e8f0;   /* slate-200 边框、分隔线 */

/* ── 文字 · Slate ── */
--fg:               #0f172a;   /* slate-900 主文字 */
--fg-muted:         #64748b;   /* slate-500 次要文字 */
--fg-subtle:        #94a3b8;   /* slate-400 占位、时间戳（仅大字/装饰） */

/* ── 语义状态色（保持交通灯直觉，与青强调严格区分）── */
--success:          #16a34a;   /* green-600  通过、成功、在线 */
--warning:          #d97706;   /* amber-600  待审核 */
--danger:           #dc2626;   /* red-600    拒绝、删除、错误 */
--info:             #2563eb;   /* blue-600   提示 */
```

**完整色阶**（开发阶段一并修正：当前 `tailwind.config.ts` 的 `primary.50–900` 误用了 Tailwind 默认 **blue** 色阶，导致 `primary-600` 等相对 `primary.DEFAULT` 偏色，须换成真实 indigo）：

| 阶 | Indigo（primary） | Teal（secondary） | Slate（neutral） |
|----|------------------|-------------------|------------------|
| 50 | `#eef2ff` | `#f0fdfa` | `#f8fafc` |
| 100 | `#e0e7ff` | `#ccfbf1` | `#f1f5f9` |
| 200 | `#c7d2fe` | `#99f6e4` | `#e2e8f0` |
| 300 | `#a5b4fc` | `#5eead4` | `#cbd5e1` |
| 400 | `#818cf8` | `#2dd4bf` | `#94a3b8` |
| 500 | `#6366f1` | `#14b8a6` | `#64748b` |
| 600 | `#4f46e5` | `#0d9488` | `#475569` |
| 700 | `#4338ca` | `#0f766e` | `#334155` |
| 800 | `#3730a3` | `#115e59` | `#1e293b` |
| 900 | `#312e81` | `#134e4a` | `#0f172a` |

**用色纪律**（"专业感"的来源 = 克制 + 分工明确）：

1. **靛蓝只给唯一主 CTA**：每屏最多一个靛蓝实心按钮（主操作）；次要动作用中性描边/幽灵按钮。链接、选中态用靛蓝。
2. **青只做数据强调**：仪表盘关键数字、图表主序列、"活跃数据"标记。**绝不**用青表达"成功/通过"——那是 `--success` 绿的职责，二者必须可区分。
3. **状态色保持交通灯直觉**：绿=成功/在线、琥珀=待处理、红=危险/错误、蓝=信息。不引入第四种状态语义。
4. **分层交给中性**：背景/表面/边框/文字全走 Slate，靠明度与边框分层，不靠彩色。彩色越稀缺越显高级。
5. **背景克制**：aurora 光斑、三色渐变文字/边框收敛（见 §3.5），不再大面积铺陈——这是当前"廉价模板感"的主因。

### 3.2 字体与排版

```css
--font-sans: "Inter", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
--font-mono: "JetBrains Mono", "SF Mono", Menlo, monospace;  /* 代码块 */
```

| 层级 | 字号 / 行高 / 字重 |
|------|-------------------|
| 页面标题 H1 | 24px / 32px / 600 |
| 区块标题 H2 | 18px / 28px / 600 |
| 卡片标题 | 15px / 22px / 600 |
| 正文 | 14px / 22px / 400 |
| 次要/时间 | 12px / 18px / 400 |

### 3.3 间距 / 圆角 / 阴影

```css
--radius:        10px;   /* 卡片、输入框 */
--radius-sm:     6px;    /* 标签、小按钮 */
--radius-full:   9999px; /* 头像、状态点 */

/* 阴影克制，白底靠边框分层，仅悬浮元素用阴影 */
--shadow-sm:  0 1px 2px rgba(0,0,0,0.04);
--shadow-md:  0 4px 12px rgba(0,0,0,0.08);   /* 弹窗、下拉 */
```

栅格间距统一用 Tailwind 的 4 的倍数（`gap-4` `p-6` 等）。

### 3.4 Tailwind 主题映射

`globals.css` 的 CSS 变量接到 `tailwind.config.ts` 的语义 token，组件**只用语义 class**（`bg-primary` `text-fg-muted` `border-border`），换色只改变量、不动调用点。双色系统对应两个 token 键：

| Tailwind token | 映射变量 | 用途 |
|----------------|---------|------|
| `primary` / `primary-hover` / `primary-subtle` | `--brand*` | 主 CTA、链接、选中 |
| `secondary` / `secondary-hover` / `secondary-subtle` | `--secondary*` | 数据强调（指标、图表、高亮） |
| `foreground` / `fg-muted` / `fg-subtle` | `--fg*` | 文字三级 |
| `background` / `sidebar` / `card` / `muted` / `border` | 同名变量 | 表面与分层 |
| `success` / `warning` / `danger` / `info` | 同名变量 | 状态语义 |

约定：

1. **不透明令牌写成 `rgb(var(--x-rgb) / <alpha-value>)`**——Tailwind v3 对 `var()` 形式的颜色会**静默丢弃 alpha 修饰符**（`bg-primary/10` 一条声明都编译不出）。半透明令牌（`border`/`sidebar`/`fg*`）保持 `var()`。
2. **`primary.50–900` 必须是真实 indigo 色阶**（见 §3.1 表），不得沿用 Tailwind 默认 blue——否则 `primary-600` 相对 `primary.DEFAULT` 偏色。`secondary.50–900` 同理用真实 teal。
3. **`error` 与 `danger` 只留一个**（当前重复定义）；`status` / `capability` 命名空间各只声明一次。
4. **不得出现无定义的 token**：`brand-500`/`ring-brand-ring` 这类调用点若 config 无对应键即静默失效（当前 7 处死 class）。补键或把调用点改回 `primary-*`/`secondary-*`，二选一。

### 3.5 暗色模式与背景纪律

暗色不是另一套配色，而是同一套语义 token 在 `.theme-glass` 作用域下的**重新取值**——页面套上 `theme-glass` 类即整体变暗，调用点零改动。双色系统在暗色下同样成立，但**填充与文字链接必须分开取值**（暗底上"白字压品牌色"和"品牌色文字压画布"是两个不同的对比度问题，不能用一个值）：

| Token | 浅色 | 暗色填充（白字压上去） | 暗色文字链接（压在画布上） |
|-------|------|----------------------|--------------------------|
| primary（indigo） | `#4f46e5` | `#6366f1` indigo-500（白字 4.47:1，大文本/控件达 AA） | `#818cf8` indigo-400（on canvas 高对比） |
| secondary（teal） | `#0d9488` | `#14b8a6` teal-500（白字达 AA） | `#2dd4bf` teal-400（数据数字/图表 on canvas） |
| background / card | `#ffffff` | 深玻璃底 `#0f0f2d` / 实心 `#1a2137` | — |
| foreground | `#0f172a` | `rgba(255,255,255,.95)` | — |

> 这套填充/文字分档是 `globals.css` 现有的、已逐色实测 WCAG 的做法（见 `.theme-glass` 段注释），落地时**沿用并扩展一个 teal 分支即可，不得回退到单值**。

**硬编码浅色类是暗色模式的头号杀手**：任何 `bg-white`、`text-gray-900`、`border-gray-200` 都不随主题切换，会在暗色下变成"白底白字/黑底黑字"。治本是**全部改语义 token**；`globals.css` 里那块靠 `.theme-glass` 逐个覆盖硬编码类的 SCOPED OVERRIDES 补丁（约 120 行）应在调用点改完后**整块删除**——补丁存在本身就是"暗色靠打补丁维持"的警示。

**背景纪律**（直接对治"廉价模板感"）：

1. **aurora 光斑收敛**：当前 violet/blue/cyan/pink 多色斑 + 三色渐变（`#818cf8 → #6366f1 → #8b5cf6`）大面积铺在侧边栏、卡片、文字上，是"花哨但不专业"的主因。改为：要么移除，要么降为**极淡的单色靛蓝 tint**（低透明度、单一色相），只在登录/落地页保留一处点睛。
2. **渐变文字/边框克制**：`gradient-text-brand`、三色 `gradient-border` 仅限品牌标识或空态插画，**不进管理台正文**。
3. **管理台靠留白与边框分层，不靠彩色背景**——彩色越稀缺，CTA 与关键数据越突出。

## 4. 布局与路由结构

### 4.1 目录

```
web/src/app/
├── (auth)/                    # 无侧边栏，居中卡片
│   ├── login/page.tsx
│   └── register/page.tsx
├── (user)/                    # 用户端外壳：左侧导航 + 顶栏
│   ├── layout.tsx             # UserShell（侧边栏 + 用户菜单）
│   ├── dashboard/page.tsx     # 仪表盘（首页，登录后落地）
│   ├── marketplace/
│   │   ├── page.tsx           # 员工广场列表
│   │   └── [employeeId]/page.tsx  # 员工详情 + 订阅
│   ├── chat/
│   │   ├── page.tsx           # 对话中心（空态：选个员工开始）
│   │   └── [sessionId]/page.tsx   # 具体会话
│   ├── subscriptions/page.tsx # 我的订阅
│   └── settings/page.tsx      # 个人设置
├── (admin)/
│   ├── layout.tsx             # AdminShell（仅 ADMIN 可进）
│   ├── dashboard/page.tsx     # 数据看板
│   ├── employees/
│   │   ├── page.tsx
│   │   └── [id]/page.tsx      # 员工编辑 + 绑定能力
│   ├── capabilities/page.tsx  # 能力审核队列
│   └── users/page.tsx         # 用户管理
└── layout.tsx                 # 根 layout：Providers（Query + Theme）
```

### 4.2 两种外壳

- **UserShell**：左侧固定导航（Logo + 5 个入口 + 底部用户菜单），主区自适应。侧边栏 `#f7f7f6`。
- **AdminShell**：同结构不同导航项，顶部加"运营后台"标识，进入前校验 `role === 'ADMIN'`，否则重定向 `/dashboard`。

### 4.3 鉴权与路由守卫

- access token 存 Zustand（内存），刷新页面时先 `GET /auth/refresh` 用 httpOnly cookie 换新 token 再渲染受保护页。
- 一个 `<AuthGate>` 客户端组件包住 `(user)` `(admin)`：token 拿不到 → 跳 `/login`；`(admin)` 额外查 role。
- API client 统一在请求头带 `Authorization: Bearer <token>`；收到 401 自动尝试一次 refresh，失败则登出跳登录。

## 5. 用户仪表盘 / 看板（本期重点）

> 用户需求："让用户一眼看清自己的情况"。仪表盘是登录后的落地页，回答三个问题：**我订了谁、我聊了多少、接下来点哪。**

### 5.1 布局（自上而下）

```
┌────────────────────────────────────────────────────────┐
│  你好，{name} 👋        [＋ 去员工广场]  ← 主色 CTA       │
├──────────┬──────────┬──────────┬────────────────────────┤
│ 活跃订阅 │ 累计会话 │ 本月消息 │  快捷入口（最近会话跳转）│  ← 4 个指标卡
│   3      │   28     │   142    │                        │
├──────────┴──────────┴──────────┴────────────────────────┤
│  我的员工（订阅卡片横排）                                 │
│  [头像 名称 状态点  → 开始对话]  [ + 发现更多 ]           │
├────────────────────────────────┬────────────────────────┤
│  最近会话（可点击继续）          │  平台动态 / 新上架员工   │
│  · 与 X 的对话  2小时前          │  · 新员工 Y 已上架       │
│  · 与 Z 的对话  昨天             │  · ...                  │
└────────────────────────────────┴────────────────────────┘
```

### 5.2 指标卡（4 个）

| 卡片 | 含义 | 数据来源 |
|------|------|---------|
| 活跃订阅 | `status===ACTIVE` 的订阅数 | `GET /subscriptions` 前端统计 |
| 累计会话 | 会话总数 | `GET /conversations` 计数 |
| 本月消息 | 当月消息条数 | 需后端 dashboard 接口（见 §9 缺口） |
| 快捷入口 | "继续最近会话" 跳转按钮 | 最近一条 session |

> 本月消息暂时可用"会话数"占位，待后端 `GET /users/me/stats` 就位再接真实值。

### 5.3 我的员工

横向卡片：头像、名称、一句话简介、订阅状态点（绿=ACTIVE / 灰=PAUSED / 红=EXPIRED）、主色"开始对话"按钮（直接进 `/chat` 并新建会话）。末尾一张虚线"+ 发现更多"卡跳 `/marketplace`。

### 5.4 空态

无订阅时，整页替换为居中引导：一句文案 + 主色大按钮"逛逛员工广场"。演示时哪怕新账号也不空。

## 6. 用户端页面清单

### 6.1 登录 / 注册 `(auth)`

居中卡片，左侧品牌插画/Logo（可选），右侧表单。复用 `RegisterDtoSchema` / `LoginDtoSchema` 做 `zodResolver`。

- 注册：email + password + name → `POST /auth/register`（后端会 set httpOnly cookie 并返回 token+user）。
- 登录：`POST /auth/login` → 存 token 到 Zustand → 跳 `/dashboard`。
- 表单错误内联提示；提交按钮 loading 态。

### 6.2 员工广场 `/marketplace`

- 顶部筛选：行业 industry、岗位 position、类型；搜索框。
- 卡片网格：头像、名称、简介、订阅数/标签。分页（`page`/`limit`）。
- 数据：`GET /digital-employees`（仅展示 PUBLISHED）。
- 详情 `/marketplace/[employeeId]`：`GET /digital-employees/:id`，展示能力构成、示例，底部主色"订阅"按钮 → `POST /subscriptions { employeeId }`；已订阅则显示"开始对话"。

### 6.3 对话中心 `/chat`（核心，ChatGPT 布局）

```
┌──────────────┬─────────────────────────────────────┐
│ 会话历史侧栏 │  当前会话标题 · 员工名                │
│ ＋ 新对话     │─────────────────────────────────────│
│ · 会话 A      │  消息流（用户右 / 员工左，md 渲染）   │
│ · 会话 B ←选中│  ├─ 工具调用折叠块（ToolExecution）   │
│ · ...         │─────────────────────────────────────│
│               │  输入框 [发送]  ← 流式回复           │
└──────────────┴─────────────────────────────────────┘
```

- 会话列表：`GET /conversations`；新建：`POST /conversations { employeeId }`（无订阅返回 403 → 提示去订阅）。
- 发消息：`POST /conversations/:id/messages`，**SSE 流式**。前端用 `fetch` + `ReadableStream` 读增量，逐字渲染。
- 消息内容 react-markdown + highlight.js；工具调用（ToolExecution）渲染为可展开卡片，显示能力名/入参/结果。
- 会话操作：重命名 `PATCH /conversations/:id`、删除 `DELETE /conversations/:id`。

### 6.4 我的订阅 `/subscriptions`

- 列表/卡片：员工、状态、订阅时间、配置。
- 操作：调配置 `PATCH /subscriptions/:id/config`、取消 `DELETE /subscriptions/:id`。
- 数据：`GET /subscriptions`。

### 6.5 个人设置 `/settings`

- 资料：`GET /auth/me` 展示，`PATCH /users/me` 改 name/avatar。
- 改密：`PATCH /users/me/password`。
- 退出：`POST /auth/logout`（清 cookie）→ 清 Zustand → 跳登录。

## 7. 管理端页面清单 `(admin)`

> 进入前校验 `role === 'ADMIN'`。

### 7.1 数据看板 `/admin/dashboard`

平台级指标卡（总用户、总员工、待审能力、总会话）+ 趋势/排行（本期可先用静态/简单聚合）。依赖后端 admin stats 接口（见 §9）。

### 7.2 员工管理 `/admin/employees`

- TanStack Table 列表：`GET /digital-employees`（含未发布）。
- 新建/编辑：`POST /digital-employees`、`PATCH /digital-employees/:id`。
- 详情 `/admin/employees/[id]`：绑定能力 `POST /digital-employees/:id/capabilities`、解绑 `DELETE /digital-employees/:id/capabilities/:capabilityId`；发布状态切换（PATCH）。
- 删除：`DELETE /digital-employees/:id`。

### 7.3 能力审核 `/admin/capabilities`

- 审核队列：`GET /capabilities`（按 status 过滤待审）。
- 通过 `POST /capabilities/:id/approve`、拒绝 `POST /capabilities/:id/reject { reason }`。
- 详情抽屉：查看四类能力的配置（agent/rpa/skill/ai-app）。

### 7.4 用户管理 `/admin/users`

- 列表 + 搜索 + 分页（TanStack Table）。
- **依赖后端 `GET /admin/users` 接口——当前缺失（见 §9）。**

## 8. 组件架构与状态

### 8.1 目录（对齐 CLAUDE.md：按 feature 就近）

```
web/src/
├── components/ui/          # Shadcn 生成的原子组件
├── components/             # 全局复用（AppSidebar, StatCard, EmptyState, PageHeader）
├── features/
│   ├── dashboard/          # StatCard, MyEmployeesRow, RecentSessions
│   ├── chat/               # ChatWindow, MessageBubble, ToolCallBlock, InputBar, SessionList
│   ├── marketplace/        # EmployeeCard, EmployeeFilter, SubscribeButton
│   ├── subscription/       # SubscriptionCard, ConfigDialog
│   └── admin/              # EmployeeTable, CapabilityReviewList, UserTable
└── lib/
    ├── api/                # apiClient（fetch 封装 + 401 refresh）、各资源的 query/mutation hooks
    ├── store/              # authStore（token/user）, uiStore（sidebar/active session）
    └── utils/
```

### 8.2 状态划分

| 类型 | 工具 | 存什么 |
|------|------|--------|
| 服务端数据 | TanStack Query | 用户、员工、会话、订阅、能力（缓存 + 失效重取） |
| 全局 UI | Zustand `uiStore` | 侧栏折叠、当前会话 id、弹窗开关 |
| 鉴权 | Zustand `authStore` | 内存 access token、当前 user；**绝不落 localStorage** |

### 8.3 Query key 约定

```
['users','me']   ['employees',{filters}]   ['employee',id]
['conversations']   ['conversation',id]   ['subscriptions']
['capabilities',{status}]
```

Mutation 成功后 `invalidateQueries` 对应 key。

## 10. 实施优先级

1. **地基**：`web/` 脚手架（Next 15 + Tailwind + Shadcn init）、Providers、apiClient、authStore、AuthGate、UserShell/AdminShell。
2. **鉴权闭环**：登录/注册 → refresh 落地 → 受保护路由。
3. **仪表盘**：指标卡 + 我的员工 + 最近会话（老板第一眼看到的页面）。
4. **对话中心**：会话列表 + SSE 流式聊天（平台核心价值）。
5. **员工广场 + 订阅**：浏览 → 订阅 → 回到对话打通闭环。
6. **我的订阅 + 个人设置**。
7. **管理端**：员工管理 → 能力审核 → 用户管理（依赖 §9 接口）。

> 演示路径以 1→5 为主线，保证"注册→订阅→聊天"整条闭环先能跑。
