## 1. Agent Runtime 选型

### 1.1 决策结果

**✅ 选定：Vercel AI SDK**（综合评分 92/100）

---

### 1.2 调研背景

碳基员工 = Agent Runtime，核心需求：
1. Tool calling（自动调度多个硅基能力）
2. 多轮对话（会话状态管理）
3. 可编程调用（后端 API 能调用，非交互模式）
4. 模型无关（能接入 SEP ModelRelayClient）
5. 商用授权（无转售限制）

候选框架：
- Vercel AI SDK
- OpenCode
- LangGraph.js
- Bee Agent Framework
- Mastra
- Dust.tt

---

### 1.3 选型理由

#### A. 完美匹配架构需求

- ✅ 轻量级，不强加会话管理（我们已有 ConversationSession/Message 模型）
- ✅ 专注 LLM 交互和工具调用
- ✅ 灵活的工具注册机制

#### B. 模型接入零障碍

```typescript
const modelRelay = createOpenAICompatible({
  name: 'model-relay',
  baseURL: process.env.MODEL_RELAY_BASE_URL,
  apiKey: process.env.MODEL_RELAY_KEY
});
```

- `createOpenAICompatible` 直接对接 ModelRelayClient
- 支持自定义 headers、request body 转换
- Provider Registry 统一管理多模型

#### C. 工具生态最灵活

```typescript
const tools = {
  cozeAgent: tool({ /* Coze API */ }),
  openCodeSkill: tool({ /* OpenCode CLI */ }),
  httpApi: tool({ /* HTTP 调用 */ }),
  rpaScript: tool({ /* RPA 执行 */ })
};
```

- 可注册任意类型工具
- 支持 `maxSteps` 控制最大循环次数
- `onStepEnd` 监听每轮工具调用结果

#### D. 商用无风险

- **MIT License**，允许商业使用和转售
- Vercel 官方长期维护
- 生产案例丰富（v0.dev、Vercel AI Playground）

#### E. 开发体验最佳

- 文档完善（9758 个代码示例）
- TypeScript 原生支持
- React hooks（`useChat`）开箱即用
- 实施周期短（3-4 周）

---

### 1.4 其他框架对比

| 框架 | 评分 | 主要劣势 | 适用场景 |
|------|------|---------|---------|
| **Vercel AI SDK** | **92/100** | - | **本项目** |
| Bee Agent | 78/100 | 文档少、社区小 | 企业级可观测性需求 |
| LangGraph.js | 72/100 | 学习曲线陡峭、过度复杂 | 复杂多步骤编排 |
| OpenCode | 68/100 | 工具生态窄、定位不符 | 代码编辑类任务 |
| Mastra | 65/100 | 企业功能付费、授权风险 | 功能全面但有付费墙 |
| Dust.tt | 55/100 | 更像产品而非框架 | - |

**OpenCode 不推荐作为碳基员工底层的原因**：
- 工具生态偏窄（主要面向代码编辑场景）
- 缺少通用业务工具注册机制
- 自定义 model provider 能力不明确

**OpenCode 的正确定位**：作为**硅基能力**（路径 B：自研 Agent + Skill），不是碳基员工底层。

---

### 1.5 架构分层

```
碳基员工层（Agent Runtime）
  → 使用 Vercel AI SDK
  → 负责：对话编排、tool calling、流式输出、多轮对话
  
硅基能力层（Tools）
  ├── [路径 A] Coze Agent → 调用 Coze API
  ├── [路径 A] AI 应用 → HTTP API 调用
  ├── [路径 B] OpenCode Agent/Skill → spawn opencode CLI
  └── [路径 A] RPA → 下载包（第一阶段）
```

---

### 1.6 核心代码示例

```typescript
import { streamText, tool } from 'ai';
import { createOpenAICompatible } from '@ai-sdk/openai-compatible';
import { z } from 'zod';

// 1. 对接 ModelRelayClient
const modelRelay = createOpenAICompatible({
  name: 'model-relay',
  baseURL: process.env.MODEL_RELAY_BASE_URL,
  apiKey: process.env.MODEL_RELAY_KEY
});

// 2. 注册硅基能力为 tools
const tools = {
  cozeAgent: tool({
    description: '竞品分析助手',
    parameters: z.object({ product: z.string() }),
    execute: async ({ product }) => {
      // 调用 Coze API
      return await cozeAPI.chat({ bot_id, message: product });
    }
  }),
  
  openCodeSkill: tool({
    description: '爆款文案生成',
    parameters: z.object({ 
      product: z.string(),
      sellingPoints: z.string() 
    }),
    execute: async ({ product, sellingPoints }) => {
      // spawn opencode CLI
      return await spawnOpenCode({ 
        skill: 'copywriting', 
        prompt: `商品：${product}，卖点：${sellingPoints}` 
      });
    }
  }),
  
  httpApi: tool({
    description: '主图生成器',
    parameters: z.object({ imageUrl: z.string() }),
    execute: async ({ imageUrl }) => {
      // HTTP API 调用
      return await axios.post('https://api.example.com/generate', { imageUrl });
    }
  })
};

// 3. 碳基员工对话编排
class DigitalEmployeeRuntime {
  async chat(userMessage: string, sessionId: string) {
    const result = await streamText({
      model: modelRelay('gpt-4o'),
      system: this.employee.systemPrompt,
      messages: await this.getSessionHistory(sessionId),
      tools,
      maxSteps: 10,
      onStepFinish: async ({ step }) => {
        // 持久化每个 tool call
        await this.saveToolExecution(sessionId, step);
      }
    });
    
    return result.toDataStreamResponse();
  }
}
```

## 2. 后端框架选型

### 2.1 决策结果

**✅ 选定：NestJS**

---

### 2.2 需求分析

- TypeScript（与 Vercel AI SDK 统一）
- RESTful API / GraphQL
- WebSocket/SSE 支持（流式对话）
- 认证授权（JWT）
- 数据库 ORM（Prisma）
- 模块化架构（认证、对话、能力、算力等模块）

---

### 2.3 候选方案

| 框架 | 优势 | 劣势 |
|------|------|------|
| **NestJS** | 模块化、企业级、生态完善 | 相对重 |
| Express + TS | 轻量、灵活 | 无内置架构 |
| Fastify | 性能最优 | 社区较小 |
| tRPC + Next.js | 类型安全 | 仅适用 TS 前端 |

---

### 2.4 选型理由

1. **项目规模预期大**
   - B/C 端、运营端、贡献者端（三套前端）
   - 多模块（认证、对话、能力、算力、订阅、数据资产）

2. **长期维护友好**
   - 架构清晰（Controller → Service → Repository）
   - 新人容易上手（类似 Spring Boot）

3. **Vercel AI SDK 集成无障碍**
   - 都是 TypeScript
   - NestJS 的 Module 可以封装 Agent Runtime

4. **生态成熟**
   - `@nestjs/passport`（认证）
   - `@nestjs/jwt`（JWT）
   - `@nestjs/websockets`（WebSocket）
   - Prisma 集成成熟

## 3. 前端框架选型

### 3.1 决策结果

**✅ 选定：React + Next.js**

---

### 3.2 需求分析

- TypeScript
- 对话窗口（ChatGPT 风格）
- SSE 流式渲染（Vercel AI SDK 提供 `useChat` hook）
- 三套前端（B/C 端、运营端、贡献者端）
- SEO 友好（能力市场需要搜索引擎收录）

---

### 3.3 候选方案

| 框架 | 优势 | 劣势 |
|------|------|------|
| **React + Next.js** | SSR、Vercel AI SDK 官方支持 | 学习曲线 |
| React + Vite | 轻量、快速 | 无 SSR |
| Vue + Nuxt | 开发体验好 | 无 Vercel AI SDK 支持 |

---

### 3.4 选型理由

1. **Vercel AI SDK 官方支持**
   ```typescript
   import { useChat } from 'ai/react';
   
   function ChatWindow() {
     const { messages, input, handleSubmit } = useChat({
       api: '/api/conversation/chat'
     });
     
     return (
       <form onSubmit={handleSubmit}>
         {messages.map(m => <div key={m.id}>{m.content}</div>)}
         <input value={input} />
       </form>
     );
   }
   ```

2. **能力市场需要 SEO**
   - Next.js SSR/SSG（搜索引擎友好）
   - 动态路由（`/employees/[id]`）

3. **技术栈统一**
   - TypeScript 全栈（后端 NestJS + 前端 Next.js）

4. **三套前端可共享组件**
   - Monorepo 结构
   - `packages/ui` 共享组件库

## 4. 部署方案选型

### 4.1 决策结果

**✅ 选定：分阶段策略**

- **Phase 1（MVP）**：Docker Compose
- **Phase 2（扩展）**：Kubernetes

---

### 4.2 需求分析

- 容器化
- PostgreSQL + Redis
- 算力平台（已有 new-api 中转站）
- 开发环境 + 生产环境

---

### 4.3 候选方案

| 方案 | 优势 | 劣势 | 适用场景 |
|------|------|------|---------|
| **Docker Compose** | 简单、快速 | 不支持自动扩容 | 开发 + MVP |
| Kubernetes | 高可用、自动扩容 | 学习曲线陡峭 | 大规模生产 |
| Serverless | 无需运维 | 成本高 | 极小规模 |

---

### 4.4 选型理由

#### Phase 1：Docker Compose（MVP 阶段）

**优势**：
- ✅ 简单、快速（会议要求 3 个月产出）
- ✅ SEP 已有 Docker Compose 经验，复用基础设施
- ✅ 开发环境友好
- ✅ 单机够用（<1000 用户）

**劣势**：
- ❌ 不支持自动扩容
- ❌ 单点故障

**docker-compose.yml 示例**：

```yaml
version: '3.8'

services:
  postgres:
    image: postgres:16
    environment:
      POSTGRES_USER: sep
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_DB: sep_platform
    volumes:
      - postgres_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

  platform-api:
    build: ./apps/platform-api
    environment:
      DATABASE_URL: postgresql://sep:${DB_PASSWORD}@postgres:5432/sep_platform
      REDIS_URL: redis://redis:6379
      MODEL_RELAY_BASE_URL: http://model-relay:3000
    depends_on:
      - postgres
      - redis
    ports:
      - "3001:3001"

  platform-web:
    build: ./apps/platform-web
    environment:
      NEXT_PUBLIC_API_URL: http://platform-api:3001
    ports:
      - "4173:3000"

  model-relay:
    image: justsong/new-api:latest
    environment:
      # 算力平台配置
    ports:
      - "3000:3000"

volumes:
  postgres_data:
```

---

#### Phase 2：Kubernetes（扩展阶段）

**触发条件**（满足任一即迁移）：
- 用户量 > 1000
- 需要高可用（99.9% SLA）
- 需要自动扩容

**Kubernetes 架构**：

```yaml
# 核心服务
- Deployment: platform-api（3 副本）
- Deployment: platform-web（2 副本）
- StatefulSet: postgres（主从复制）
- Deployment: redis（哨兵模式）
- HPA: 自动扩容（CPU > 70%）
```

---

### 4.5 迁移路径

**从 Docker Compose 到 Kubernetes**：

1. **代码无变化**（都是容器化）
2. **配置迁移**：
   - `docker-compose.yml` → Kubernetes YAML
   - 环境变量 → ConfigMap / Secret
3. **数据迁移**：
   - PostgreSQL 数据导出/导入
   - Redis 数据同步
4. **流量切换**：
   - 蓝绿部署
   - 灰度发布

**预计迁移时间**：2-3 周
