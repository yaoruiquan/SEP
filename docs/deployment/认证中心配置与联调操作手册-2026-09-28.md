## 1. 先看结论：配置应该放在哪里

SEP 目前采用两层配置模型：

```text
运营端「系统设置 → 认证与安全」中的数据库配置
        > 后端环境变量 .env / Docker Secret
        > 代码中的默认值
```

也就是说，同一个配置如果同时存在于数据库和环境变量中，**数据库配置优先生效**。

### 1.1 适合放在运营端的配置

这些是业务运营可以调整、且已经接入运行时读取的配置：

- SMTP 邮件服务：邮件开关、SMTP 地址、端口、SSL、用户名、密码、发件人；
- 微信网站应用登录：启用开关、AppID、AppSecret、回调地址；
- QQ 互联网站应用登录：启用开关、AppID、AppKey、回调地址；
- 登录失败锁定策略；
- 登录、密码找回、邮箱验证、OAuth 回调的限流策略；
- OAuth 授权事务有效期。

这些配置保存后，认证相关服务会在下一次请求时读取最新的生效值，通常不需要重启后端。

### 1.2 必须放在 `.env`、Docker Secret 或 Secret Manager 的配置

以下配置不应开放给普通运营人员修改：

- `DATABASE_URL`、`REDIS_URL`：基础设施连接；
- `JWT_SECRET`：系统加密和兼容模块密钥；
- `ACCESS_JWT_SECRET`：Access Token 签名密钥；
- `REFRESH_TOKEN_PEPPER`：Refresh Token 哈希 pepper；
- `CORS_ORIGIN`：跨域安全边界；
- `WEB_BASE_URL`、`ASSET_BASE_URL`：公开站点和资源地址；
- `PORT`、`NODE_ENV`、Docker 网络和容器地址；
- `API_ORIGIN`：前端 Next.js 代理到后端的地址；
- `SUB2API_API_KEY`、生产数据库密码、Redis 密码等基础设施密钥。

原因是这些值会影响应用启动、基础设施连接、全局安全边界或密钥体系，修改后往往需要重启，而且不适合由日常运营人员操作。

### 1.3 敏感配置的显示规则

以下值会加密写入数据库，管理端不会回显明文：

```text
SUB2API_API_KEY
ALIPAY_PRIVATE_KEY
MAIL_PASSWORD
WECHAT_APP_SECRET
QQ_APP_KEY
```

管理端只会显示「已配置/未配置」。如果已经配置过敏感值，输入框留空后保存，表示**保持原值**；不要因为页面没有显示明文而重复填写或误以为丢失。

## 2. 当前本地服务状态和地址

截至 2026-09-28，本地前后端已经重启并通过基础检查：

| 服务 | 地址 | 作用 |
|---|---|---|
| 前端 | `http://localhost:3000` | Next.js 页面、运营端和同源 `/api` 代理 |
| 后端 | `http://localhost:3001` | NestJS API |
| 后端健康检查 | `http://localhost:3001/api/health` | 返回 `status: ok` |
| 运营端配置中心 | `http://localhost:3000/admin/settings` | 管理认证中心配置 |
| 登录页 | `http://localhost:3000/login` | 邮箱密码、微信、QQ 登录入口 |
| 忘记密码 | `http://localhost:3000/forgot-password` | 发起密码重置邮件 |
| 重置密码 | `http://localhost:3000/reset-password?token=...` | 使用邮件令牌重置密码 |
| OAuth 回调前端页 | `http://localhost:3000/oauth/callback` | 后端完成第三方回调后跳转的结果页 |

### 2.1 启动或重启本地服务

在项目根目录执行：

```bash
cd /Users/yao/LLM/SEP
pnpm dev:backend
pnpm dev:web
```

建议分别在两个终端运行。启动前如果修改了 Prisma schema，先执行：

```bash
pnpm --dir backend db:generate
```

检查后端：

```bash
curl -fsS http://localhost:3001/api/health
```

预期返回中包含：

```json
{"status":"ok","service":"sep-backend"}
```

检查前端：

```bash
curl -fsSI http://localhost:3000/login | head
```

预期为 `HTTP/1.1 200 OK`。

### 2.2 前端代理配置注意事项

浏览器中的认证请求统一使用同源地址 `/api`，前端 Next.js 通过 `web/next.config.mjs` 的 rewrite 转发到后端。前端代理目标由 `API_ORIGIN` 控制：

```bash
# web/.env.local
API_ORIGIN=http://localhost:3001
```

当前认证主链路不直接读取 `NEXT_PUBLIC_API_URL`，而是使用 `/api`，这样 Refresh Token 的 httpOnly Cookie 保持同源。项目中少数历史业务模块仍可能读取 `NEXT_PUBLIC_API_URL`，本地若要兼容它们，可以同时保留：

```env
API_ORIGIN=http://localhost:3001
NEXT_PUBLIC_API_URL=http://localhost:3001/api
```

生产环境应让前端和后端通过同一正式 HTTPS 域名访问，避免把 Refresh Token Cookie 变成跨站 Cookie。

## 3. 第一次配置前的准备工作

### 3.1 管理员账号

登录一个具有 `ADMIN` 角色的运营端账号，然后打开：

```text
系统设置 → 配置中心 → 认证与安全
```

如果没有管理员账号，不要把管理员密码写入文档、脚本或 Git；使用现有初始化/seed 流程创建或重置管理员账号。

### 3.2 数据库、Redis 必须正常

认证中心依赖：

- PostgreSQL：用户、认证凭据、OAuth 身份、会话和认证事件；
- Redis：认证限流和跨实例共享的限流计数；
- 后端服务：签发 Access Token、轮换 Refresh Token、发送邮件和处理 OAuth 回调。

开发环境可以先检查：

```bash
curl -fsS http://localhost:3001/api/health
```

生产环境还要检查容器日志、PostgreSQL 连接、Redis 连接和反向代理 HTTPS 状态。

### 3.3 生产密钥生成

生产环境不要使用示例值或开发环境值。生成三个相互独立的值：

```bash
openssl rand -hex 32   # JWT_SECRET
openssl rand -hex 32   # ACCESS_JWT_SECRET
openssl rand -hex 32   # REFRESH_TOKEN_PEPPER
```

要求：

- `ACCESS_JWT_SECRET` 至少 32 个字符；
- `REFRESH_TOKEN_PEPPER` 至少 32 个字符；
- `ACCESS_JWT_SECRET` 和 `REFRESH_TOKEN_PEPPER` 必须不同；
- `JWT_SECRET` 必须长期稳定，因为运营端保存的敏感配置密文由它派生的密钥加密；
- 不要把密钥写入 Git、截图、聊天记录或前端代码。

## 4. 运营端配置中心的操作方法

### 4.1 保存规则

1. 登录运营端；
2. 打开 `http://localhost:3000/admin/settings`；
3. 选择「配置中心」；
4. 点击「认证与安全」；
5. 修改一个分组中的字段；
6. 点击该分组的保存按钮；
7. 重新加载页面，确认来源和配置状态；
8. 对 SMTP 点击连接测试/发送测试邮件；
9. 对微信、QQ 点击「检查配置」。

页面会展示配置来源：

| 来源 | 含义 |
|---|---|
| 数据库覆盖 | 当前值来自运营端保存的 `SystemSetting`，优先级最高 |
| 环境变量 | 数据库没有覆盖，使用后端 `.env` 或容器环境 |
| 系统默认 | 数据库和环境变量都没有配置，使用代码默认值 |
| 未配置 | 没有可用值 |

### 4.2 如何恢复环境变量值

如果某个配置已经被运营端保存到数据库，之后想恢复使用 `.env`：

1. 打开对应字段；
2. 将非敏感字段清空；
3. 保存；
4. 页面应显示来源变为「环境变量」或「系统默认」。

敏感字段建议不要通过反复清空来试错。密码、AppSecret、AppKey 一旦保存，页面不会显示明文；要更换时直接输入新值并保存。

## 5. SMTP 邮件服务配置（优先完成）

邮箱服务是忘记密码、邮箱验证、安全通知和企业邀请的基础，建议在配置微信/QQ 前先完成。

### 5.1 需要准备的 SMTP 信息

从邮件服务商后台获取：

- SMTP 主机；
- SMTP 端口；
- SSL/STARTTLS 方式；
- SMTP 用户名；
- SMTP 密码或授权码；
- 已验证的发件邮箱。

常见连接方式：

| 方式 | `MAIL_PORT` | `MAIL_SECURE` |
|---|---:|---|
| SMTPS/SSL | `465` | `true` |
| STARTTLS | `587` | `false` |

最终以邮件服务商控制台给出的参数为准。不要把邮箱网页登录密码直接当成 SMTP 密码；很多服务商要求单独生成授权码。

### 5.2 在运营端填写

在「认证与安全 → 邮件与密码找回」填写：

| 页面字段 | 配置键 | 示例（仅示例，不要照抄） |
|---|---|---|
| 启用邮件服务 | `MAIL_ENABLED` | `true` |
| SMTP 服务器 | `MAIL_HOST` | `smtp.example.com` |
| SMTP 端口 | `MAIL_PORT` | `587` |
| SMTP SSL | `MAIL_SECURE` | `false` |
| SMTP 用户名 | `MAIL_USER` | `mailer@example.com` |
| SMTP 密码/授权码 | `MAIL_PASSWORD` | 真实授权码，不要写入文档 |
| 发件邮箱 | `MAIL_FROM` | `mailer@example.com` |
| 发件人名称 | `MAIL_FROM_NAME` | `硅基人才平台` |

保存后按以下顺序测试：

1. 点击「测试 SMTP 连接」；
2. 确认握手成功；
3. 输入自己的测试收件地址；
4. 点击「发送测试邮件」；
5. 检查收件箱、垃圾邮件和邮件标题；
6. 确认邮件中的站点链接是正确的本地或正式域名；
7. 再进行忘记密码联调。

### 5.3 生产环境使用 `.env` 的写法

如果不希望由运营端保存 SMTP，可以在后端环境中配置：

```env
MAIL_ENABLED=true
MAIL_HOST=smtp.example.com
MAIL_PORT=587
MAIL_SECURE=false
MAIL_USER=mailer@example.com
MAIL_PASSWORD=请填真实SMTP密码或授权码
MAIL_FROM=mailer@example.com
MAIL_FROM_NAME=硅基人才平台
```

生产环境强制要求真实 SMTP：

```env
MAIL_ENABLED=true
```

如果邮件配置不完整，开发模式可能退回控制台邮件提供器；这不代表真实邮件已经发送成功，必须以 SMTP 握手和测试投递成功为准。

## 6. 忘记密码和邮箱验证联调

### 6.1 忘记密码流程

接口和页面流程如下：

```text
登录页
  → 忘记密码
  → 输入注册邮箱
  → POST /api/auth/password/forgot
  → 收到邮件
  → 打开 /reset-password?token=...
  → POST /api/auth/password/reset
  → 使用新密码重新登录
```

验收步骤：

- [ ] 使用一个真实存在的注册邮箱发起找回；
- [ ] 页面返回统一成功提示，不泄露邮箱是否存在；
- [ ] 邮件实际送达；
- [ ] 链接域名正确，不能指向 `localhost`；
- [ ] 令牌能成功重置密码；
- [ ] 重置成功后旧密码不能登录；
- [ ] 令牌只能使用一次；
- [ ] 过期令牌被拒绝；
- [ ] 重置密码后旧会话按产品策略失效；
- [ ] 对不存在的邮箱不会发送可枚举账号状态的提示。

### 6.2 邮箱验证流程

邮箱验证主要用于：

- 注册后的邮箱确认；
- 登录后重新发送验证邮件；
- 修改登录邮箱后的确认。

验收步骤：

- [ ] 能收到验证邮件；
- [ ] 验证链接域名正确；
- [ ] 首次点击成功；
- [ ] 重复点击不会重复改变状态；
- [ ] 过期或无效令牌有明确错误提示；
- [ ] 验证邮件发送受用户/IP 限流保护。

### 6.3 密码重置限流建议

初始配置可以使用页面默认值：

| 配置键 | 默认值 | 含义 |
|---|---:|---|
| `AUTH_RATE_PASSWORD_RESET_EMAIL_LIMIT` | `3` | 单个邮箱在窗口内最多请求次数 |
| `AUTH_RATE_PASSWORD_RESET_EMAIL_WINDOW_SECONDS` | `3600` | 邮箱限流窗口，秒 |
| `AUTH_RATE_PASSWORD_RESET_IP_LIMIT` | `20` | 单个 IP 在窗口内最多请求次数 |
| `AUTH_RATE_PASSWORD_RESET_IP_WINDOW_SECONDS` | `3600` | IP 限流窗口，秒 |

如果测试时反复点击导致限流，等待窗口结束或在 Redis 中清理对应测试计数，不要为了测试直接关闭限流。

## 7. 微信网站扫码登录配置

### 7.1 代码使用的登录类型

当前实现使用微信开放平台的**网站应用扫码登录**，授权起始地址为微信网站扫码登录接口，回调进入：

```text
/api/auth/oauth/wechat/callback
```

微信登录不是微信公众号网页授权，也不是小程序登录。申请应用时要选择和网站扫码登录匹配的应用类型。

官方入口（如平台栏目调整，以官方入口当前页面为准）：

- 微信开放平台：<https://open.weixin.qq.com/>
- 网站应用微信登录开发指南：<https://developers.weixin.qq.com/doc/oplatform/Website_App/WeChat_Login/Wechat_Login.html>
- 微信网站应用审核规范：<https://developers.weixin.qq.com/doc/oplatform/Website_App/operation.html>
- 微信网站应用业务域名配置：<https://developers.weixin.qq.com/doc/oplatform/Website_App/guide/domain.html>

微信官方接入材料的核心要求是：使用已审核通过的网站应用，并取得对应的 AppID/AppSecret；平台后台配置的是授权域名，而代码发起授权时提交的是完整 `redirect_uri`。两者域名必须一致。具体审核入口和当前资质要求以微信开放平台实际页面为准。

### 7.2 正式环境准备

需要准备：

- 已审核/可使用的网站应用；
- `AppID`；
- `AppSecret`；
- 正式网站域名；
- HTTPS 证书；
- 可以从公网访问的后端回调地址。

建议正式域名统一使用：

```text
https://你的域名/api/auth/oauth/wechat/callback
```

微信开放平台后台的回调域名、站点域名或授权配置，必须按照平台页面要求填写。代码向微信提交的是**完整回调 URI**，所以平台配置和系统配置必须保持同一域名、协议、路径和端口规则。

### 7.3 在运营端填写

在「认证与安全 → 微信与 QQ 登录 → 微信登录」填写：

| 页面字段 | 配置键 | 填写内容 |
|---|---|---|
| 启用微信登录 | `WECHAT_OAUTH_ENABLED` | 先填 `false`，完成检查后再改 `true` |
| 微信 AppID | `WECHAT_APP_ID` | 开放平台网站应用 AppID |
| 微信 AppSecret | `WECHAT_APP_SECRET` | 开放平台网站应用 AppSecret，敏感值 |
| 微信回调地址 | `WECHAT_REDIRECT_URI` | `https://你的域名/api/auth/oauth/wechat/callback` |

推荐顺序：

1. 先填 AppID、AppSecret、回调地址；
2. 保存；
3. 点击「检查配置」；
4. 确认启用状态、AppID、密钥、回调地址均通过；
5. 再把启用开关改为 `true` 并保存；
6. 从登录页点击「微信登录」；
7. 扫码并授权；
8. 检查是否回到 `/oauth/callback?provider=wechat&status=success`；
9. 检查用户是否创建或登录成功。

配置检查只检查本地生效配置的完整性和回调地址格式，不会替你完成微信平台审核，也不会模拟真实扫码授权。

### 7.4 微信联调验收

- [ ] 未配置时，登录页点击微信登录会得到可理解的配置错误；
- [ ] 配置完整后可以跳转微信授权页；
- [ ] 用户取消授权能回到前端，并显示取消而不是 500；
- [ ] 首次授权能创建本地用户；
- [ ] 再次授权能识别同一个微信身份；
- [ ] 回调 `state` 缺失、篡改、重复使用、过期时被拒绝；
- [ ] 不会把 AppSecret、授权码、Access Token 打到浏览器或普通日志；
- [ ] 回调地址使用正式 HTTPS 域名；
- [ ] 生产反向代理转发 `/api/auth/oauth/wechat/callback` 到后端成功。

### 7.5 本地开发的现实限制

本地 `http://localhost` 适合单元测试和代码验证，但不应把它当作正式微信网站应用联调方案。微信官方公开指南对 localhost 是否可登记、测试环境是否可直接使用没有在本手册中作承诺；实际联调时建议使用已配置的 HTTPS 测试域名，并把：

- 前端站点地址；
- `WEB_BASE_URL`；
- 微信授权域名；
- 微信完整回调地址；
- 反向代理路由；

统一到同一个测试域名体系。项目自身的生产校验要求 OAuth 回调使用 HTTPS。

不要把临时隧道地址直接当作生产回调地址；如用于短期测试，测试结束后应立即撤销或更换。

## 8. QQ 网站登录配置

### 8.1 代码使用的登录类型

当前实现使用 QQ 互联 OAuth 2.0 网站应用登录，回调进入：

```text
/api/auth/oauth/qq/callback
```

官方入口（如平台栏目调整，以平台官网当前页面为准）：

- QQ 互联：<https://connect.qq.com/>
- 成为开发者：<https://wiki.connect.qq.com/成为开发者>
- OAuth 2.0 准备工作：<https://wiki.connect.qq.com/准备工作_oauth2-0>
- 回调地址常见问题：<https://wiki.connect.qq.com/回调地址常见问题及修改方法>
- 网站审核规范：<https://wiki.connect.qq.com/网站审核规范>

QQ 官方文档使用 App ID（appid）和 App Key（appkey）命名。QQ 网站应用需要登记实际处理授权 `code` 的回调 URL；官方回调地址说明明确要求使用外网可访问域名，不能使用 localhost 或端口号。是否满足网站备案、审核等条件，以 QQ 互联当前后台要求为准。

### 8.2 与微信最容易混淆的字段

QQ 使用的是：

```text
QQ_APP_ID
QQ_APP_KEY
```

不是 `QQ_APP_SECRET`。当前代码会将 `QQ_APP_KEY` 作为 OAuth 的 `client_secret` 使用，并加密保存。

### 8.3 在运营端填写

在「认证与安全 → 微信与 QQ 登录 → QQ 登录」填写：

| 页面字段 | 配置键 | 填写内容 |
|---|---|---|
| 启用 QQ 登录 | `QQ_OAUTH_ENABLED` | 先填 `false`，完成检查后再改 `true` |
| QQ AppID | `QQ_APP_ID` | QQ 互联网站应用 App ID |
| QQ AppKey | `QQ_APP_KEY` | QQ 互联网站应用 App Key，敏感值 |
| QQ 回调地址 | `QQ_REDIRECT_URI` | `https://你的域名/api/auth/oauth/qq/callback` |

推荐顺序与微信相同：保存 → 检查配置 → 开启 → 从登录页点击 QQ 登录 → 授权 → 验证回调和账号绑定。

### 8.4 QQ 联调验收

- [ ] QQ 互联后台应用类型和网站登录能力正确；
- [ ] App ID、App Key 与运营端值对应；

- [ ] 能跳转 QQ 授权页；
- [ ] 取消授权能回到前端；

## 9. 登录风控与限流配置

入口：

```text
运营端 → 系统设置 → 配置中心 → 认证与安全 → 登录风控与限流
```

### 9.1 账号锁定

| 配置键 | 默认值 | 建议理解 |
|---|---:|---|
| `AUTH_MAX_FAILED_ATTEMPTS` | `5` | 连续登录失败达到该次数后锁定账号 |
| `AUTH_LOCK_MINUTES` | `15` | 锁定时长，分钟 |

正式运行初期建议先保持默认值，观察误伤率后再调整。

### 9.2 登录限流

| 配置键 | 默认值 | 作用 |
|---|---:|---|
| `AUTH_RATE_LOGIN_IP_LIMIT` | `20` | 单 IP 登录请求次数 |
| `AUTH_RATE_LOGIN_IP_WINDOW_SECONDS` | `60` | 单 IP 登录限流窗口 |
| `AUTH_RATE_LOGIN_ACCOUNT_LIMIT` | `10` | 单账号登录请求次数 |
| `AUTH_RATE_LOGIN_ACCOUNT_WINDOW_SECONDS` | `300` | 单账号登录限流窗口 |

### 9.3 邮箱验证限流

| 配置键 | 默认值 | 作用 |
|---|---:|---|
| `AUTH_RATE_EMAIL_VERIFICATION_USER_LIMIT` | `5` | 单用户请求验证邮件次数 |
| `AUTH_RATE_EMAIL_VERIFICATION_USER_WINDOW_SECONDS` | `3600` | 用户限流窗口 |
| `AUTH_RATE_EMAIL_VERIFICATION_IP_LIMIT` | `20` | 单 IP 请求验证邮件次数 |
| `AUTH_RATE_EMAIL_VERIFICATION_IP_WINDOW_SECONDS` | `3600` | IP 限流窗口 |

### 9.4 OAuth 回调限流和事务有效期

| 配置键 | 默认值 | 作用 |
|---|---:|---|
| `AUTH_RATE_OAUTH_CALLBACK_IP_LIMIT` | `30` | 单 IP OAuth 回调次数 |
| `AUTH_RATE_OAUTH_CALLBACK_IP_WINDOW_SECONDS` | `300` | OAuth 回调限流窗口 |
| `OAUTH_TRANSACTION_TTL_SECONDS` | `300` | OAuth `state` 事务有效期 |

这些限流依赖 Redis。Redis 不可用时服务会降级记录告警并放行请求，因此生产环境必须监控 Redis 可用性，不能只依赖应用层限流。

## 11. Refresh Token 和多设备会话验收

认证中心的浏览器会话设计为：

- Access Token：只存前端内存/Zustand，不写 `localStorage`；
- Refresh Token：后端设置为 httpOnly Cookie；
- 刷新页面：前端调用 `POST /api/auth/refresh` 恢复 Access Token；
- 刷新成功：Refresh Token 轮换，旧令牌被消费；
- 检测到旧 Refresh Token 重放：撤销对应 Session Family。

验收清单：

- [ ] 登录响应设置 httpOnly Refresh Cookie；
- [ ] 浏览器开发者工具中看不到 Refresh Token 的 JavaScript 可读值；
- [ ] 刷新页面后仍能恢复登录态；
- [ ] 手动重复提交旧 Refresh Token 会失败；
- [ ] 旧 Token 重放不会继续创建新会话；
- [ ] 「退出当前设备」只撤销当前会话；
- [ ] 「退出全部设备」撤销该账号所有会话；
- [ ] 多浏览器/多设备会话列表可查看；
- [ ] Redis 多实例环境下限流和会话行为一致；
- [ ] 生产 Cookie 使用 `__Host-sep_refresh`、`Secure` 和正确的 Path/Domain 策略。

## 13. 常见问题排查

### 13.1 页面显示「已配置」，但我看不到密钥

这是正常行为。敏感字段不会回显明文。可以通过「已配置」状态、SMTP 测试或 OAuth 配置检查确认，不要要求接口返回密钥。

### 13. 保存后仍然使用旧值

按以下顺序排查：

1. 重新加载配置中心；
2. 查看来源是否为「数据库覆盖」；
3. 确认保存接口返回成功；
4. 确认当前运营账号拥有 `ADMIN` 角色；
5. 查看后端日志是否有配置解密失败；
6. 检查是否把配置保存到了另一个数据库/环境；
7. 对邮件重新执行 SMTP 连接测试；
8. 对微信/QQ重新执行配置检查。

### 13.3 SMTP 连接失败

重点检查：

- 主机名和端口；
- `465` 是否设置 `MAIL_SECURE=true`；
- `587` 是否设置 `MAIL_SECURE=false` 并由服务商支持 STARTTLS；
- 用户名是否为完整邮箱；
- 使用的是 SMTP 授权码而非网页登录密码；
- 发件邮箱是否和账号/服务商要求一致；
- 服务器出站防火墙是否允许 SMTP；
- 云厂商是否限制 25 端口；
- 运营端保存后是否重新测试；
- 生产容器是否加载了正确的环境变量。

### 13.4 忘记密码邮件链接指向 localhost

密码邮件链接由后端的 `WEB_BASE_URL` 生成。检查生产后端环境：

```env
WEB_BASE_URL=https://你的正式域名
```

修改环境变量后重启后端。不要只修改前端 `.env.local`。

### 13.5 微信/QQ 点击后提示未配置

检查：

- 对应启用开关是否为 `true`；
- AppID 是否填入；
- 敏感密钥是否已经保存；
- 回调地址是否填写；
- 当前生效来源是否是预期环境；
- 运营端「检查配置」是否全部通过；
- 如果保存过错误的数据库覆盖，是否需要清空恢复环境变量。

### 13.6 第三方平台提示回调地址不匹配

逐字符比较：

- `http`/`https`；
- 域名大小写和实际域名；
- 端口；
- `/api` 前缀；
- 路径中的 `wechat`/`qq`；
- 是否多了尾部 `/`；
- 配置是否保存到了当前运行环境；
- 反向代理是否真的把该路径转发到后端。

当前正确代码路径为：

```text
微信：/api/auth/oauth/wechat/callback
QQ：  /api/auth/oauth/qq/callback
```

### 13.7 OAuth 回调后跳回前端但显示 error

查看后端日志和认证事件，优先检查：

- `state` 已过期或重复使用；
- 回调的 provider 与 state 不一致；
- 授权码已被消费；
- 第三方 AppSecret/AppKey 错误；
- 服务器无法访问微信/QQ接口；
- 第三方返回的身份标识为空；
- 生产 `WEB_BASE_URL` 错误；
- Redis/数据库连接异常。

不要在日志中打印授权码、AppSecret、AppKey、Access Token 或完整带 token 的 URL。

### 13.8 重启后端后数据库里的敏感配置无法解密

`SystemSetting` 的敏感配置密文依赖 `JWT_SECRET` 派生的加密密钥。确认：

- 重启前后 `JWT_SECRET` 没有改变；
- 当前进程连接的是同一个数据库；
- 没有把开发环境数据库配置误带到测试/生产；
- 未手工修改 `SystemSetting.value`。

如果必须轮换 `JWT_SECRET`，需要提前制定密文迁移方案，不要直接替换后重启。

## 15. 本次配置完成的判定标准

「认证中心代码开发完成」与「正式上线完成」是两个不同节点：

### 代码开发完成

- 运营端已经可以管理运行时认证配置；
- SMTP、忘记密码、邮箱验证接口和页面已实现；
- 微信/QQ OAuth 回调链路已实现；
- Refresh Token 轮换和重放检测已实现；
- 后端生产环境校验已实现；
- 自动化测试、类型检查和构建通过。

### 正式联调完成

- 你填入了真实 SMTP 参数并收到测试邮件；
- 你完成了真实密码找回和邮箱验证；
- 你完成了正式或测试域名下的真实微信授权；
- 你完成了真实 QQ 授权；
- 你验证了取消授权、失败回调、重复回调和限流；
- 你验证了多设备会话、退出全部设备和 Refresh Token 重放；
- 你在目标生产部署环境中完成了上述测试。

因此，**配置完成后进行真实联调测试并通过验收，才算认证中心对当前上线环境真正完成**。如果微信/QQ尚未获得可用的网站应用能力，可以先保持开关关闭；这不影响邮箱密码登录和忘记密码先上线，但第三方登录功能本身还不能标记为正式完成。
