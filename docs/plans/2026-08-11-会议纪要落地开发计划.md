**两个原任务为何作废：**

1. **任务 2.1（embedding 改走 sub2api）→ 作废，且方向本来就是错的。**
   `embedding.service.ts` 现在读的是自己的一套 env（`EMBEDDING_PROVIDER` / `EMBEDDING_BASE_URL` /
   `EMBEDDING_MODEL` / `EMBEDDING_DIMENSION`），全文不含 `SUB2API_*`。这符合决策：
   **sub2api 不代理 `/v1/embeddings`，知识库的向量模型与中转通道彻底分开**，
   用自部署 TEI 或第三方 embedding API。文件头注释已写明「独立于 sub2api，支持 TEI 容器部署」。
   → 决策 5.3.2 已闭环，不需要再问。

2. **任务 2.2（换 pgvector）→ 作废。** 没走 pgvector 也没走 Pinecone，
   而是第三条路：向量以 `bytea` 存在 `text_chunks` 里，检索时按企业整批载入内存做余弦。
   好处是零外部依赖、零扩展安装、数据不出境（正好回应会议 8.2 的数据安全顾虑）；
   代价是单企业向量量级受内存约束（当前设计 600MB 上限、5 企业 LRU）。
   演示体量下完全够用，**上量后再评估是否上 pgvector**。
   → 决策 5.3.1 已闭环（实质选了「都不选」）。

**唯一剩下的问题：生产环境仍在降级运行**

- 生产 `.env` / `deploy/production/docker-compose.yml` **完全没有 `EMBEDDING_*` 变量**（已 grep 确认）
- `deploy/production/docker-compose.yml` 只有 `sep-migrate` / `sep-backend` / `sep-web` 三个服务，**没有 TEI 容器**
- 于是 `embedding.isAvailable()` 探活失败 → `resolveStrategy()` 返回 `lexical`

**即：知识库当前是 BM25 关键词检索，不是语义检索。** 比上午认知的 SQL LIKE 好一档
（BM25 有真实相关性排序），但措辞和文档差得远的提问依然可能检索不到。

**因此任务 2.3 是知识库唯一的剩余工作量**，且它不再是「补几个 env」，而是「先部署一个 embedding 服务」。

#### 任务 1.1　数据建模（0.5 天）

新增 Prisma model，与 sub2api 的算力账户彻底分离：

```prisma
/// 平台订单。只管【员工订阅费】，不碰 Token 计费。
/// Token 消耗走 ComputeAccount / ComputeTransaction（sub2api 侧结算）。
model Order {
  id String @id @default(cuid())

  orderNo String @unique          // 对外单号，供支付宝 out_trade_no

  enterpriseId String
  enterprise   Enterprise @relation(fields: [enterpriseId], references: [id], onDelete: Cascade)

  createdBy String                // 下单人（企业管理员 User.id）

  status      OrderStatus @default(PENDING)
  totalAmount Decimal     @db.Decimal(12, 2)   // 元，不用 Float

  // 支付信息
  payChannel   PayChannel?
  payTradeNo   String?     // 支付宝 trade_no
  paidAt       DateTime?
  closedAt     DateTime?   // 超时关闭 / 用户取消

  items OrderItem[]

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([enterpriseId, createdAt(sort: Desc)])
  @@map("orders")
}

/// 订单明细。一行 = 招聘一位硅基员工。
/// 价格在下单时快照，模板后续调价不影响已下单据。
model OrderItem {
  id String @id @default(cuid())

  orderId String
  order   Order  @relation(fields: [orderId], references: [id], onDelete: Cascade)

  employeeId String
  employee   DigitalEmployee @relation(fields: [employeeId], references: [id])

  // 下单时快照
  employeeName String
  unitPrice    Decimal @db.Decimal(12, 2)
  periodMonths Int     @default(12)   // 雇佣周期
  quantity     Int     @default(1)    // 席位数

  /// 该明细赠送的初始算力额度（元），支付成功后注入 ComputeAccount
  includedComputeCNY Decimal @default(0) @db.Decimal(12, 2)

  @@index([orderId])
  @@map("order_items")
}

/// 购物车。按企业维度，多个管理员共享同一购物车。
model CartItem {
  id String @id @default(cuid())

  enterpriseId String
  enterprise   Enterprise @relation(fields: [enterpriseId], references: [id], onDelete: Cascade)

  employeeId String
  employee   DigitalEmployee @relation(fields: [employeeId], references: [id], onDelete: Cascade)

  periodMonths Int @default(12)
  quantity     Int @default(1)

  addedBy String

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@unique([enterpriseId, employeeId])
  @@index([enterpriseId])
  @@map("cart_items")
}

/// 支付回调流水。幂等去重 + 审计留痕，永不删除。
model PaymentNotify {
  id String @id @default(cuid())

  channel    PayChannel
  outTradeNo String        // 我们的 orderNo
  tradeNo    String        // 渠道流水号
  rawBody    String @db.Text
  verified   Boolean       // 验签结果
  processed  Boolean @default(false)

  createdAt DateTime @default(now())

  @@unique([channel, tradeNo])
  @@index([outTradeNo])
  @@map("payment_notifies")
}

enum OrderStatus {
  PENDING    // 待支付
  PAID       // 已支付
  CLOSED     // 已关闭（超时/取消）
  REFUNDED   // 已退款
}

enum PayChannel {
  ALIPAY
  WECHAT
  MANUAL     // 线下转账，运营手动确认
}
```

同时给 `DigitalEmployee` 补定价字段（会议 3.2 的订阅模型）：

```prisma
model DigitalEmployee {
  // ... 现有字段
  price Float?   // 保留，兼容存量数据

  /// 年费（元）。会议示例：5000 元/年
  annualPriceCNY Decimal? @db.Decimal(12, 2)
  /// 订阅赠送的初始算力额度（元）。会议示例：1000 点 = 1000 元算力
  includedComputeCNY Decimal @default(0) @db.Decimal(12, 2)
}
```

> **注意**：钱一律用 `Decimal`，不要用 `Float`。现有 `ComputeAccount.balance` 是 `Float`，
> 前端 `billing/page.tsx` 还在做 `/100` 的微单位换算 —— 这块有历史债，本次不动，
> 但**新的订单金额链路必须走 Decimal**，避免再欠债。

**产出**：迁移 `20260811xxxxxx_add_order_and_cart`

原描述「补几个 env」低估了：生产**根本没有 embedding 服务在跑**，得先把它拉起来。

**Step 1 — 选一个 embedding 来源**（需你拍板，二选一）：

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **A. 自部署 TEI**（推荐） | 生产 compose 加一个 `ghcr.io/huggingface/text-embeddings-inference` 容器，跑 `BAAI/bge-small-zh-v1.5` | 零调用成本、数据不出机器、中文效果好、代码默认 provider 就是它 | 占 ~1-2GB 内存，需确认服务器余量 |

> 代码两条路都已支持，切换只是改 env，不用动代码。
> 推荐 A：既省钱又正好符合老板对数据安全的要求，讲故事也顺。

**Step 2 — 生产配置**：
- 方案 A：`deploy/production/docker-compose.yml` 加 `sep-embedding` 服务，`sep-backend` 补：
