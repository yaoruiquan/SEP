# 知识库正式上线生产化开发方案

> **历史实施方案，部署章节已被替代。** 当前正式架构是 Ollama `bge-m3:latest`（1024 维）+ PostgreSQL pgvector/HNSW；生产部署只使用[当前 Embedding 部署指南](../deployment/embedding-service.md)。本文保留旧实现决策与当时验收记录，不再作为环境变量或数据库架构依据。

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将企业知识库从“代码链路已存在、生产闭环未打通”升级为可安全上线的文档上传、异步处理、授权检索、会话 RAG、观测与运维闭环。

**Architecture（现状更新）:** NestJS + Prisma + Redis/BullMQ 负责业务与异步处理，Ollama `bge-m3:latest` 生成 1024 维向量，PostgreSQL pgvector/HNSW 执行向量检索；旧版 Bytes 列只保留迁移兼容。所有知识库读写都通过企业上下文和明确的管理员/成员权限判断，检索结果在授权范围内生成。

**Tech Stack:** NestJS 10, Prisma 6, PostgreSQL 16/18, Redis 7/8, BullMQ, Next.js 15, TanStack Query, Jest, Vitest.

## 1. 现状与上线结论

### 1.1 当前已存在的能力

- 知识库 CRUD、文档上传、文档解析、段落分块、Embedding、BM25、向量检索、混合 RRF 检索。
- BullMQ 文档处理队列和 PROCESSING 卡死恢复。
- 企业员工订阅与知识库授权关系。
- 会话流中存在知识检索和知识来源持久化字段。
- 企业端有文档状态、检索测试、检索分析和授权管理界面。

### 1.2 当前不能直接上线的原因

1. 企业端 `POST /knowledge-bases/:id/documents` 命中旧 MVP 接口，只保存元数据并直接标记 `READY`，不会解析、分块或向量化；真正的队列接口是另一个 `/documents/upload` 路径。
2. 生产 compose 没有 `EMBEDDING_*` 配置，也没有 Embedding 容器；代码默认访问容器内 `localhost:8080`。
3. `openai` provider 固定拼接 `/v1/embeddings`，基础地址如果已经带 `/v1` 会形成 `/v1/v1/embeddings`。
4. `VectorService` 的企业级缓存没有保存知识库归属，缓存命中后没有按当前授权知识库过滤。
5. 文档、文本片段和部分检索接口只校验 JWT，不校验企业归属、订阅归属和角色。
6. 真实会话检索没有写 `KnowledgeSearchLog`，分析页不能代表线上真实使用。
7. 手动文本片段没有 tokens/embedding 生成；编辑和删除也没有统一触发向量缓存失效。
8. 本地磁盘文件和数据库生命周期没有统一，删除知识库或旧接口删除文档会留下孤儿文件。

### 1.3 上线策略

- **P0 修复完成前禁止全量开放知识库检索。**
- P0 完成后先用内部企业和少量真实文档灰度。
- 灰度通过隔离、重启、故障降级和检索质量验收后，再开放给全部授权企业成员。

## 2. 目标契约

### 2.1 文档状态契约

```text
PENDING -> PROCESSING -> READY
                    \-> FAILED
```

- `PENDING`：数据库记录已创建，队列任务尚未完成。
- `PROCESSING`：Worker 正在解析或生成向量。
- `READY`：文本片段已生成；如果启用向量模式，所有片段必须有向量；如果明确启用 lexical-only 模式，必须在状态接口和 UI 标明降级原因。
- `FAILED`：处理失败，`lastError` 必须可见，支持安全重试。

### 2.2 Embedding 契约

生产部署必须显式配置以下变量，禁止依赖代码默认值。当前生产使用独立 Ollama 的 OpenAI-compatible 接口：

```dotenv
EMBEDDING_PROVIDER=openai
EMBEDDING_BASE_URL=http://sep-ollama:11434/v1
EMBEDDING_MODEL=bge-m3:latest
EMBEDDING_DIMENSION=1024
EMBEDDING_API_KEY=ollama-local
EMBEDDING_BATCH_SIZE=32
EMBEDDING_TIMEOUT_MS=120000
```

OpenAI provider 的 base URL 可以带 `/v1`，代码会规范化并只追加一次 `/embeddings`。容器内禁止使用 `localhost` 访问其他服务；模型或维度变化后必须对历史知识库执行 reindex。

### 2.3 权限契约

- 知识库管理写操作：企业管理员；是否允许部门管理员由后续明确角色矩阵后再开放。
- 知识库查看、文档查看、文本片段查看：企业成员且属于当前企业；是否能查看未授权知识库由产品选择，默认仅管理员可管理，普通成员只能通过员工订阅间接检索。
- 文档上传、删除、重处理、文本片段写操作：企业管理员。
- 会话检索：当前用户必须属于传入订阅关系所在企业；知识库范围由该订阅和当前部门上下文共同计算。
- `search/by-knowledge-base`：仅内部管理/测试使用，必须增加管理员或内部服务认证；不能作为普通 JWT 用户接口。

### 2.4 统一接口契约

保留一套主路径，前端和后端测试统一使用：

```text
POST   /knowledge-bases/:knowledgeBaseId/documents/upload
GET    /knowledge-bases/:knowledgeBaseId/documents
GET    /knowledge-bases/:knowledgeBaseId/documents/:documentId
GET    /knowledge-bases/:knowledgeBaseId/documents/:documentId/download
POST   /knowledge-bases/:knowledgeBaseId/documents/:documentId/reprocess
DELETE /knowledge-bases/:knowledgeBaseId/documents/:documentId
```

旧的 `/knowledge-bases/:id/documents` multipart 接口必须删除或返回明确迁移错误，不能继续把文档标记成假 READY。

## 4. 验收门槛

### P0 必须全部通过

- 前端上传进入唯一的异步处理接口。
- 文档跨企业访问、下载、删除全部被拒绝。
- 普通用户不能调用不检查授权的检索接口。
- 同企业不同授权范围不会因缓存返回错误知识。
- 生产 Embedding 健康检查 200，单条和批量返回维度正确。
- 真实上传后 `chunks > 0` 且向量非空。
- 会话检索只使用当前订阅/部门允许的知识库。

### P1 必须在灰度前通过

- 真实会话检索日志可在分析页看到。
- 失败文档可重试，重启后 PROCESSING 可恢复。
- 删除文档/知识库不会持续积累上传文件。
- 手动文本片段可被词法和向量检索命中。
- `pg_trgm` 或等价词法召回能力在生产数据库可验证。

### 质量与性能目标

- 20 个并发文档上传无 500、无永久 PROCESSING、无 OOM。
- 小规模知识库检索 P95 目标 500ms 内；超出时记录慢查询。
- Embedding 服务不可用时，UI 明确显示降级，不伪装为“已向量化”。
