# SEP 视觉素材与头像库规划

**日期**：2026-09-15  
**状态**：素材规划，待分阶段实施  
**适用范围**：硅基人才市场、硅基员工、碳基员工、技能库/技能详情、营销首页 Hero，以及复用这些数据的聊天、任务和企业管理页面。

## 1. 先说结论

项目里的图片不应该全部按“照片”处理。当前产品有三种不同的视觉任务：

1. **人员身份图**：让用户认出是哪位硅基员工或哪位碳基员工。
2. **技能表达图**：帮助用户快速理解技能主题或类别，不承担人物身份识别。
3. **品牌/场景图**：用于营销首页 Hero，表达“碳基团队与硅基员工协作”的产品叙事。

推荐的第一期素材量如下：

| 资产组 | 第一期开工量 | 用途 | 是否按人员/技能一一生成 |
|---|---:|---|---|
| 硅基员工半身照 | **64 张** | 人才市场、员工详情、我的硅基员工、聊天、任务、订单等 | 按当前员工分配，含 8 张备用 |
| 碳基员工默认大头照 | **24 张** | 未上传头像的成员、演示租户、空状态 | 不按真实成员生成，成员可自行上传覆盖 |
| 技能库分类视觉 | **11 张** | 7 个业务分类视觉 + 4 个能力类型图 | 不按每个技能生成 |
| 技能详情精选场景图 | **8 张** | 访问量最高的技能详情/市场展示 | 只给高频技能，后续按数据扩展 |
| Hero 场景图 | **2 张成品** | 桌面端宽幅 + 移动端竖幅 | 同一叙事的两个构图，不是两套品牌 |

因此第一期建议准备 **109 张最终素材**。其中真正需要生成大量人物图的是 64 张硅基员工半身照；技能库和 Hero 不应简单复制“再生成一批头像”的思路。

## 2. 当前项目事实

### 2.1 硅基员工已经有统一头像入口

- 数据模型是 `DigitalEmployee.avatar`，另有历史性的 `avatarStyle`。
- 种子数据包含 **50 个导入员工**（`backend/prisma/seed/03-import-50-employees.ts`）和 **6 个精选电商员工**（`backend/prisma/seed/02-catalog.ts`），当前规划基线是约 **56 个硅基员工**。
- 导入脚本当前使用 `ui-avatars.com` 随机头像，无法体现岗位，也不符合新版拟人化方向。
- 人才市场卡片、详情抽屉、详情页、我的硅基员工、聊天气泡、员工切换器、任务节点、购物车、结算和技能库分组都读取同一个 `avatar` URL。
- 现在的 `Avatar` 组件默认圆形裁切；市场详情页还有一处姓名首字母渐变占位，需要改成真实半身图优先。

关键代码位置：

- `backend/prisma/schema.prisma`：`DigitalEmployee.avatar`、`avatarStyle`
- `web/src/components/ui/avatar.tsx`：统一头像渲染
- `web/src/app/(market)/marketplace/_components/employee-card.tsx`：人才市场卡片
- `web/src/app/(market)/marketplace/_components/employee-drawer.tsx`：市场详情抽屉
- `web/src/app/(market)/marketplace/[id]/page.tsx`：市场详情页 Hero 身份区
- `web/src/app/(enterprise)/my-employees/EmployeeCard.tsx`：我的硅基员工
- `web/src/features/chat/message-bubble.tsx`、`employee-switcher.tsx`：聊天头像
- `web/src/features/task/components/employee-badge.tsx`：任务节点头像

### 2.2 碳基员工没有独立的人事照片模型

- 真人成员来自 `EnterpriseMember -> User`，照片入口是 `User.avatar`。
- 团队成员页、企业顶栏、用量统计、知识库授权等页面会使用这个字段。
- 成员数量由企业邀请和注册决定，不能在素材阶段按“现有成员数”永久生成一套照片。
- 当前无头像时显示姓名首字母，因此默认头像库应是“可选占位”，不能把一张 AI 脸自动当作某位真实员工。

### 2.3 技能目前没有图片字段

- `Capability` 只有名称、描述、类型、行业、岗位、统计和 `metadata`，没有 `coverImageUrl` 或 `iconUrl`。
- 企业端 `/capabilities` 实际重定向到技能库，技能列表按硅基员工分组，行内只有名称、版本、调用次数和待办状态。
- 技能详情主要是版本时间线、改动、执行记录和洞察，没有图像区域。
- 运营端新建技能页展示的是平台图标（Coze、Dify、n8n、OpenCode 等），这类图标应继续使用品牌 SVG/图标，不应替换成生成照片。

关键代码位置：

- `backend/prisma/schema.prisma`：`Capability`
- `web/src/features/capability-iteration/capability-iteration-list.tsx`：技能库列表
- `web/src/app/(enterprise)/capabilities/[capabilityId]/page.tsx`：技能详情
- `web/src/app/(platform)/admin/capabilities/new/page.tsx`：能力类型/平台图标

### 2.4 Hero 目前是 CSS/JSX 工作台示意

- `web/src/app/(marketing)/_components/hero.tsx` 当前使用 `DashboardMockup`，不是实际图片。
- 这种做法适合演示数据结构，但不能提供用户希望的“拟人化场景”和品牌记忆点。
- Hero 图不应使用硅基员工头像拼贴，也不应把头像库当作背景装饰；它需要独立表达团队协作场景。

## 3. 各板块的图片类型和数量

### 3.1 硅基人才市场：半身照，64 张

**推荐构图**：胸像/肩部以上，人物从胸口或肩部开始，脸部清晰，正面或轻微三分之二侧脸，背景干净且有轻微岗位色差。不要放电脑、平板、计算器、文件夹等道具，避免缩小后变成杂物。

**数量**：

- 56 张对应当前两批种子员工，每位硅基员工一张主头像。
- 8 张备用，用于后续新增员工、替换质量不稳定的图和演示账号。
- 不建议现在直接生成 100 张。100 张会产生大量没有对应岗位的闲置素材，增加管理、压缩、审核和风格一致性成本。

**规格**：

- 生成母版：`1024x1024` 或 `1254x1254`。
- 线上主图：`512x512 WebP`，保留 `256x256 WebP` 小尺寸版本。
- 人物脸部占画布约 45%–55%，肩部不贴边，给圆形和圆角矩形两种裁切留安全区。
- 统一 4 组低饱和背景即可，不要每张随机背景。

**页面使用方式**：

- 市场卡片：72–88px 圆角矩形/圆形头像，半身仍能看出服装和岗位气质。
- 市场详情抽屉：80–96px 头像，旁边放岗位、行业、服务企业数。
- 市场详情页：96–128px 半身头像；删除当前只显示姓名首字母的渐变块。
- 我的硅基员工、聊天、任务、订单：继续复用同一 URL，以 CSS 控制裁切尺寸，不再单独生成聊天头像。

**岗位差异**：差异应来自发型、服装、年龄层、表情和配色，而不是给每个人添加道具。建议按员工岗位分组做 prompt，保持整体 3D 拟人化风格。

### 3.2 碳基员工/团队成员：大头照，24 张默认库

**推荐构图**：头肩近景或大头照，脸部占画布 60%–70%，背景纯色或轻微渐变，适合 32–56px 圆形裁切。真人成员的头像应当更像“个人资料头像”，不需要岗位服装和品牌化布景。

**数量**：

- 24 张默认头像，建议覆盖不同性别表达、年龄层、发型、眼镜和肤色/面部特征。
- 默认库只解决“成员没有上传头像”的演示和空状态，不为每个成员预生成一张“假真人照片”。
- 用户上传自己的头像后，`User.avatar` 直接覆盖默认值；管理员不应把默认脸误认为真实身份。

**规格**：

- 母版：`512x512` 或 `768x768`。
- 线上：`256x256 WebP`，成员列表实际显示 32–40px，无需使用硅基员工的半身构图。
- 给每张默认头像一个稳定 seed/id，按 `userId` 哈希分配，避免刷新页面后换脸。

**页面使用方式**：

- 团队成员列表、部门成员面板、企业顶栏、用量榜单：大头照小尺寸显示。
- 个人资料页：支持上传、替换和恢复默认头像。
- 不在人才市场和硅基员工卡片中混用碳基员工头像，避免两类主体失去叙事区分。

### 3.3 技能库：分类视觉 11 张，不做“每个技能一张人像”

这里需要明确反驳一个容易产生的方向：**技能不是员工，给每个技能生成一张人物照片会让用户误以为技能是另一个可雇佣主体，也会造成几十张风格不一的装饰图。** 技能库的主任务是查找、比较、调整版本和查看使用情况，信息密度比照片更重要。

**第一期素材**：

- 7 张业务分类视觉，对应 `EmployeeCategory`：技术、产品设计、营销增长、电商、销售客户、运营组织、财务法务。
- 4 张能力类型图标/小插画，对应 `AGENT`、`RPA`、`SKILL`、`AI_APP`。
- 8 张精选技能详情场景图，只给高频或市场重点技能使用；当前种子中约 62 个独立 SKILL 文件，不建议全部配图。

**推荐形式**：

- 技能库分组头：继续使用硅基员工半身头像，旁边增加很小的分类色块或图标，不要再加大图。
- 技能行：使用 24–32px 类型图标/分类图案，不显示照片。
- 技能详情页：顶部可放 3:2 横向场景图，下面立刻进入版本和执行数据；图片高度建议不超过 180–220px。
- 平台品牌（Coze、Dify、n8n、OpenCode）使用官方或项目内 SVG，不用生成图。

**数据建议**：

- 最终建议在 `Capability` 增加明确字段：`iconUrl`、`coverImageUrl`、`imageAlt`。
- 短期若不想改 Prisma，可先在 `metadata.visual` 下存同样的结构，但这只是过渡，不能让前端散落读取任意 JSON 路径。
- 分类视觉用代码映射；技能详情图按 `capabilityId` 或稳定 slug 映射，不能按列表顺序绑定。

### 3.4 Hero：2 张成品，场景图而不是头像拼贴

**主题**：一个真实的企业工作场景中，碳基团队成员与几位硅基员工协作。画面要让人先看到“人在工作、数字员工在协作”，再看到产品界面。

**第一期数量**：

- 桌面端 1 张：`1536x1024`，主体集中在中右区域，左侧保留标题和 CTA 的留白。
- 移动端 1 张：`1024x1536`，主体更居中，避免桌面端裁切时人物被截断。
- 可以先生成 3–4 个候选构图，最终只保留 2 张成品；候选不进入产品资源库。

**约束**：

- 不在图片内生成中文、英文、Logo、按钮或可读 UI 文本，文字由 HTML 渲染。
- 不使用过暗、过虚、纯氛围化背景；用户要能看清人物和协作关系。
- 不把 56 张硅基头像缩小堆在 Hero 里；最多出现 2–3 位代表性硅基员工。
- 保留当前 `DashboardMockup` 作为 Hero 下方的产品解释模块，图片负责情绪和叙事，CSS UI 负责可读功能信息。

## 4. 一套素材如何被多个页面复用

### 硅基员工

一位硅基员工只维护一张 canonical 半身图，所有下列位置都读取 `DigitalEmployee.avatar`：

- 硅基人才市场卡片、详情抽屉、详情页
- 我的硅基员工卡片和员工详情
- 聊天消息气泡、员工切换器、新建会话
- 任务编排节点、团队准备度、任务历史
- 购物车、结算、支付结果、订阅申请
- 技能库按员工分组的头像

不要为这些位置分别生成“卡片头像、聊天头像、任务头像”。尺寸和形状由组件控制，资源只保留一份主图和必要的 WebP 派生尺寸。

### 碳基员工

所有成员相关页面读取 `User.avatar`：

- 团队成员、部门成员
- 企业顶栏和个人资料
- 用量分析的成员排行
- 知识库授权成员列表

默认头像库只在 `User.avatar` 为空时作为稳定 fallback，不写回成真实用户头像，除非产品明确允许用户选择后保存。

## 5. 建议的资源目录和命名

```text
web/public/assets/
├── employees/
│   ├── silicon/            # 硅基员工半身照，按 employee slug 命名
│   └── carbon-defaults/    # 碳基员工默认大头照，carbon-01.webp ...
├── capabilities/
│   ├── categories/         # 7 个业务分类视觉
│   ├── types/              # 4 个能力类型图标/插画
│   └── featured/           # 8 个精选技能详情场景图
└── marketing/
    └── hero/               # desktop.webp、mobile.webp
```

原始生成图放在受控的素材源目录，线上只引用压缩后的 WebP。建议保留一个 manifest：

```ts
type VisualAsset = {
  src: string;
  alt: string;
  focalPoint?: { x: number; y: number };
};
```

这样可以为半身图记录焦点位置，避免圆形头像裁切到头发或肩膀，而不需要为每个组件复制图片。

## 6. 分阶段实施顺序

### Phase 1：统一硅基员工头像（P0）

1. 将当前 56 个硅基员工映射到 64 张半身素材。
2. 把 `ui-avatars.com` 和 DiceBear 风格头像降级为迁移 fallback，不再作为新员工默认主视觉。
3. 统一 `Avatar` 的 `object-position`、圆形/圆角矩形两种展示模式。
4. 修复市场详情页仍使用姓名首字母渐变块的路径。
5. 验证市场、员工详情、聊天、任务和结算页的加载、裁切和空状态。

### Phase 2：碳基员工默认头像（P1）

1. 生成 24 张默认大头照并建立稳定分配表。
2. 个人资料页支持上传/替换，上传后覆盖默认值。
3. 成员列表、部门列表、用量排行统一使用同一个头像组件。
4. 明确 UI 文案：这是“默认头像”，不是系统识别出的真人照片。

### Phase 3：技能视觉层（P1）

1. 先增加 `Capability` 的 `iconUrl`、`coverImageUrl`、`imageAlt` 语义字段或统一过渡适配层。
2. 上线 7 个分类视觉和 4 个能力类型图标。
3. 只为 8 个高频技能详情补场景图，观察点击率和详情停留后再扩容。
4. 保持技能库列表的信息密度，不能因为图片把版本、待办和调用次数挤到折行。

### Phase 4：营销 Hero（P1）

1. 生成桌面端和移动端两张同主题 Hero 图，选定后压缩为 WebP。
2. 将图片接入 `web/src/app/(marketing)/_components/hero.tsx`，保留可读的 HTML 标题和 CTA。
3. 用真实浏览器检查桌面、平板和手机裁切，重点观察标题留白、人物脸部和下一节内容露出。

## 7. 质量验收标准

- 头像在 32px、56px、96px 三个尺寸都能识别人脸，不能出现脸部被裁掉或道具抢主体。
- 市场卡片和员工详情使用同一人物，不因页面切换变脸。
- 男女、年龄、发型和服装有差异，但光照、材质、背景控制在同一套品牌风格内。
- 碳基默认头像不会覆盖用户自己上传的照片，也不会按刷新随机变化。
- 技能图片不承载名称、版本、价格或状态等必须文字化的信息。
- Hero 图片无乱码文字、无水印、无品牌误植，并在桌面/移动端不遮挡标题和 CTA。
- 原图不直接作为线上资源：头像线上 512px/256px WebP，技能详情图和 Hero 也要做压缩和缓存策略。
- 所有外部 URL 都应迁移到项目对象存储或静态资源目录，避免第三方头像服务失效导致整站变空头像。

## 8. 本次决策边界

- **同意**：人才市场和硅基员工使用半身照；碳基员工使用大头照；Hero 使用独立场景图。
- **建议采纳**：技能库使用分类视觉和类型图标，精选技能详情才使用场景图。
- **不建议**：为每个技能、每个聊天气泡、每个任务节点分别生成图片；这会增加成本，却不会增加识别和操作效率。
- **暂不做**：直接生成 100 张无绑定关系的头像。先完成 64 张硅基员工素材和 24 张碳基默认头像，等真实岗位和使用数据稳定后再扩库。
