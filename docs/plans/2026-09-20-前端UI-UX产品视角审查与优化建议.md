## 0. 一页结论

功能完成度已经很高（企业组织层、市场、对话、计量、运营端都在跑），但从产品视角看，
**"能跑"和"能卖/能演示"之间还差一层"完成感"**。问题集中在四个系统性根因，
而不是零散的页面 bug：

| # | 根因 | 表现（举例） | 影响 |
|---|------|-------------|------|
| 1 | **设计系统执行断裂**：语义 token 只覆盖了约八成调用点，其余是硬编码 Tailwind 类；还有一批引用了**根本不存在的 class** | `brand-*` 类在 6+ 处被使用但 tailwind 配置里没有 `brand` 键 → 进度条填充不可见、统计卡图标圈无样式；`animate-in/out` 用了 21 处但 `tailwindcss-animate` 没装 | 视觉细节随机失灵，且修一处不漏一处 |
| 2 | **反馈体系缺失**：toast / 空态 / 加载态 / 错误态四件事都没有统一落地 | 运营端 6 个文件约 30 处 `sonner` toast 调用，但 sonner 的 `<Toaster/>` **从未挂载** → 保存成功/失败完全无提示；`EmptyState`/`ErrorState` 组件写好了（共 359 行）**零引用**，各页空态各自 improvis（审计页空态只有一个裸表头 "(0)"） | 用户操作后"不知道发生了什么"，是演示时最掉价的体验 |
| 3 | **品牌与视觉语言三套并存**：设计文档的橙红 `#eb3f00`、实现的靛蓝 `#6366f1`、登录页 logo 的粉橙，互不相认 | 登录页左栏粉橙 logo + 靛蓝 CTA；文档承诺的 Inter 字体从未加载；标题字号 5 种写法 | 看一眼就知道"不是同一个产品" |
| 4 | **暗色模式与移动端是半成品**：机制在、执行不到位 | 暗色下仪表盘指标数字几乎不可见、成员卡片白底白字；37/73 页面零断点，聊天侧栏 `w-72` 固定宽在手机上不可用 | 老板演示时随手切暗色/缩窗口就会翻车 |

**优先级总览**（详见 §11 路线图）：

- **P0（演示阻断，本周）**：sonner toast 失效、`/api/notifications/preferences` 404、知识库死按钮、仪表盘假趋势/`−100%`、暗色白底卡片、删除确认不统一。
- **P1（设计系统收敛，两周）**：品牌色定案 + 死 class 清零、状态映射单一来源、表格/空态/加载态收敛、padding 约定、Button 暗色盲修。
- **P2（逐页打磨，一个月）**：每页空/载/错三态、面包屑映射、会话列表标题策略、模型 id 显示名、popover 移动端溢出、a11y 一批。
- **P3（长期治理）**：术语/i18n、动效治理、暗色模式定位决策、死代码清理。

## 2. 品牌与视觉语言：三套系统并存

### 2.1 现状

| 来源 | 品牌色 | 状态 |
|------|--------|------|
| V2 设计文档 §3.1 | `#eb3f00` 饱和橙红，含 hover/subtle/ring 四档 + "用色纪律" | **未实现** |
| `web/tailwind.config.ts` | `primary.DEFAULT = #6366f1`（靛蓝） | 实际在用的主色 |
| 登录页左栏 logo | 粉/橙渐变 | 与以上两者都不一致 |

进一步的断裂：

- `tailwind.config.ts` 里 `primary.DEFAULT` 是 `#6366f1`，但 `primary.50–900` 是
  **Tailwind 默认 blue 色阶**——任何用 `primary-600`（hover/按下态）的地方都会偏色。
- 配置里**没有 `brand` 键**，但 `brand-*` 类在以下位置被真实使用，全部静默失效：
  - `components/ui/tabs.tsx:33,48`（focus ring 缺失）
  - `components/ui/stat-card.tsx:74,75`（统计卡图标圆圈无样式）
  - `components/ui/progress.tsx:20,24`（**进度条填充不可见**）
  - `app/(enterprise)/dashboard/page.tsx:174,318,452`
- 字体：文档 §3.2 要求 `Inter + PingFang SC` 与 `JetBrains Mono`；实现中
  `layout.tsx` **没有加载任何 webfont**（无 `next/font`），实际渲染为系统字体；
  字阶（H1 24/32/600 …）也未落地——实测页面标题有 5 种字号写法。
- 用色纪律：文档要求"主色只用在最想让用户点的那一个动作上"；实现中靛蓝大面积铺在
  侧边栏渐变、aurora 背景斑、卡片渐变上（`layout.tsx`），主色不再"稀缺"，CTA 反而不突出。
- `error` 与 `danger` 两个 token 重复定义；`status` / `capability` 命名空间在配置里声明了两次。

### 2.2 建议

1. **品牌色定案**（产品决策，二选一）：
   - A. 回归文档的 `#eb3f00`：改 `primary` 全色阶 + logo 保持，文档不动；
   - B. 正式采用靛蓝：把 V2 文档 §3.1 改写为靛蓝色阶，并补"用色纪律"章节。
   无论选哪个，**文档与实现必须只剩一套**，否则每次新页面都会再分裂一次。
2. 在 `tailwind.config.ts` 补 `brand` 键（或把 `brand-*` 调用点改回 `primary-*`），
   并补全 `primary.50–900` 为品牌色自己的色阶，消灭 §2.1 的死 class 与偏色 hover。
3. 用 `next/font` 加载 Inter（latin）+ 回退 PingFang SC；代码块统一 JetBrains Mono。
4. 落地字阶：把 5 种标题写法收敛到文档的 5 级（H1 24 / H2 18 / 卡题 15 / 正文 14 / 次要 12），
   做成 `components/page/page-header.tsx` 的唯一出口。
5. 恢复"用色纪律"：背景/渐变用中性色或极低饱和品牌 tint，主色留给每页唯一主 CTA。

## 3. 信息架构与导航

### 3.1 四套外壳 + 嵌套子侧栏

现有 4 个 shell：`(marketing)` 落地页、`(enterprise)` EnterpriseShell、
`(platform)` PlatformShell、`(auth)`，外加 settings 页内**第三层**子侧栏。
v3 方案 §8.2 的规划是三块功能域（market / enterprise / platform），
实现里 market 被并进 enterprise shell 的顶栏入口（"硅基人才市场"按钮），
这个合并本身是合理的（同一人的连续动作），但带来两个问题：

1. **企业台侧边栏 13 个入口、6 个分组**（组织/员工/工作/组织能力/服务 + 底部设置），
   分组标题（"组织""员工""工作"）信息量低，扫读成本高。建议按 v3 §8.2.1 的角色表
   做**按角色收敛**：普通成员默认只看到 市场/我的员工/对话/知识库 4 项，
   其余折叠进"管理"分组——现在所有角色看到同一份满配导航。
2. **settings 双层侧栏**：EnterpriseShell 侧栏 + settings 页内 `w-56` 子侧栏，
   lg 宽度下仅导航就占 472px（见 §9 响应式）。建议 settings 子导航改为页内 tab 或锚点。

### 3.2 面包屑泄漏原始 slug

`(enterprise)` 面包屑直接渲染路由段：`/settings/profile` 显示为
"工作台 › 个人设置 › **profile**"。需要一张 slug→中文名映射表
（profile/security/notifications/…），放进 `lib/utils.ts` 或 locales。
同类问题：聊天页头部直接显示原始模型 id `gemini-3.5-flash-high`（见 §4.2）。

### 3.3 角色与可见性（对照 v3 §8.2.1）

v3 已定"同一套页面 + 按角色控制可见性"，并明确**订阅 vs 申请**的按钮三态。
实现现状：市场订阅按钮未按角色切换文案（普通成员点了才报 403 的风险仍在）；
导航项未按 `roleInEnterprise` 过滤。这是 P2 的产品正确性问题，不只是视觉问题。

## 5. 设计系统执行度

### 5.1 令牌桥与暗色机制

- 浅色：`:root` CSS 变量 → Tailwind 语义 token（`globals.css` 顶部）。
- 暗色：`html.theme-glass` 类（玻璃拟态）+ 一段 token 桥（globals.css:487–540）把
  `--background/--card/…` 重指到玻璃变量。机制本身可用（截图 33–36 证明大部分页面能暗）。
- 但 `globals.css:1477–1603` 有一块 **SCOPED OVERRIDES**：约 120 行补丁，
  在 `.theme-glass` 作用域里逐个覆盖页面里**硬编码的浅色类**
  （`bg-white`、`text-gray-900`、`border-gray-200` …）。
  这是"暗色模式靠打补丁维持"的信号：每新写一个硬编码类，暗色就漏一处。
  治本是把这些调用点改成语义 token（`bg-card`、`text-foreground`），补丁块即可删除。
- `.theme-glass-light`（globals.css:1103–1254，150 行）**定义了但 provider 从不应用**——死代码。
- `theme-provider.tsx` 的 `useTheme()` 在 SSR 期 throw，导致 3 处调用点包 try/catch 绕过；
  应改为 SSR 安全的默认值而非抛错。
- markdown `pre` 硬编码 `#1a1a1a` 底 + highlight.js 只引了浅色主题 → 暗色下代码块刺眼。
- 无 `::selection` 样式；focus-visible ring 只写在 `.theme-glass` 下，`.glass-scope` 漏。

### 5.2 组件库：写了不用 / 用了不存在

| 资产 | 状态 |
|------|------|
| `ui/empty-state.tsx`（181 行 + 5 张 SVG 插画） | **零引用** |
| `ui/error-state.tsx`（178 行） | **零引用** |
| `ui/loading.tsx` | 基本死 |
| `components/page/section-card`、`stat-strip`、`filter-bar` | 死 |
| `components/page/PageHero` | 73 页中仅 4 页用 |
| `components/charts/lazy-*.tsx` | 死 |
| `features/*/animated-card.tsx` | 死 |
| 两个同名 `Skeleton`（`bg-gray-200` vs `bg-neutral-200`） | 冲突 |
| 两个 `KpiCard` | 冲突 |
| `ui/badge.tsx` default variant | 空字符串（等于没样式） |
| `ui/button.tsx:17-21` secondary/outline/ghost | 建在 `neutral-*`/`bg-white` 上 → **暗色盲** |

加载态现状是**四套并存**：自定义 `ui/loading`、两个 Skeleton、裸 `animate-pulse` div、
以及什么都不放（白屏等数据）。收敛为一套 `<PageSkeleton>` + `<InlineSkeleton>`。

### 5.3 动效

- `PageTransition`（framer-motion）只挂在 `(enterprise)/layout.tsx:18`，其余路由组切换无过渡——
  有/无过渡随机出现比全无更糟。
- 21 处 `animate-in/animate-out` 依赖 `tailwindcss-animate`，**该包未安装** → 全部无效。
- framer 动画与 PageTransition 均未尊重 `prefers-reduced-motion`。

## 6. 真实缺陷清单（P0/P1，非风格问题）

### 6.1 sonner toast 从未挂载 → 运营端反馈全丢

- 6 个文件、**30 处** `toast.success/error/…` 调用（`admin/employees` new/edit/bindings/list、
  `avatar-styles`、`features/admin/avatar-library-forms.tsx`）import 自 `sonner`。
- `components/providers.tsx:40` 挂载的是**自定义** `components/ui/toast` 的 `<Toaster/>`；
  sonner 的 `<Toaster/>` 全仓库无挂载点 → 这 30 处调用**静默无输出**。
- 另有 `hooks/use-toast.ts` 也包了一层 sonner，但**无人 import**（死钩子）。
- 企业端 43 个文件用的是自定义 toast（工作正常）→ 形成"企业端有反馈、运营端没反馈"的割裂。
- **修复方向**（二选一，P0）：在 providers 挂 sonner `<Toaster/>` 并把自定义 toast 内部转接 sonner；
  或把 6 个文件的 import 改到 `components/ui/toast`。长期只留一套。

### 6.2 `/api/notifications/preferences` 404

- 前端 `features/notifications/use-notifications.ts:131,143` 调 `GET/PUT /notifications/preferences`；
- 后端 `notifications.controller.ts` 只有 `GET /notifications` 与 `GET /notifications/unread-count`。
- 每次进企业台都会打两次 404（截图网络面板确认 ×2）。属前后端契约 bug：
  要么后端补 preferences 路由，要么前端移除偏好设置 UI。

## 7. 一致性：状态映射、表格、间距、图表

### 7.1 状态映射 9 套并存

- `lib/utils.ts:24` 与 `:37` 两套 SubscriptionStatus 映射；
  `my-employees/[id]/page.tsx:52` 第三套；
- `admin/employees/page.tsx:29` 与 `[id]/page.tsx:18` 是**逐字节相同**的 STATUS_META 复制；
- `admin/capabilities/page.tsx:68` 又一套不同 scheme；
- 同一 PENDING 状态在不同页面叫"待审批"/"待审核"（术语治理见 §12）；
- capability 类型 AGENT 有 3 种配色，其中一种是不支持暗色的硬编码 hex（`lib/utils.ts:10-18`）。

建议：`lib/status-meta.ts` 单一来源，按 domain（subscription / capability / task / review）
各一张表，导出 `{label, badgeVariant, dotColor}`；页面只 import 不复制。

### 7.2 表格：19 张手搓、8 种 `<th>` 方言

无 `ui/table.tsx`、无 react-table（V2 文档 §2 承诺 TanStack Table v8，未落地）。
8 种表头写法（`<th className="...">` 各异）、缺失 `overflow-x-auto`（admin/employees、members）、
`min-w-[520px]` 硬撑（my-employees/[id]:872,931）。
建议：补 `ui/table.tsx`（shadcn 标准件）+ 一个 `<DataTable>` 封装（排序/空态/加载行/横向滚动内置），
19 处逐步迁移；不引 react-table 也可以，但**表头/行高/对齐/滚动容器必须一个出口**。

### 7.3 内边距：shell 与页面双重叠加

- `enterprise-shell.tsx:354` 已加 `px-4 py-5 sm:px-6 lg:px-7`；
  members/notifications/subscriptions/settings-profile/usage/wallet 又各加 `p-6` → 双层 padding。
- PlatformShell 不加 padding，页面四种写法（§4.10）。
建议：**shell 唯一负责 padding**，页面根节点零 padding；写进 CLAUDE.md 前端约定。

### 7.4 图表：主题契约是假的

- `lib/chart-theme.ts` 文件头注释声称"3 个页面共用"，实际只有 `admin/page.tsx:19` 一处 import。
- `usage/page.tsx:169` 网格线用 `#e5e7eb`——正是该文件注释里警告不要用的值；
  且未设 tooltip 样式 → 暗色下**白色 tooltip 块**（截图 36）。
- dashboard 混用自有 hex + `var()` 轴色；analytics 用另一套 `var(--color-*)` 命名空间。
建议：chart-theme 补全（grid/axis/tooltip/legend 四组 token，含暗色值），三个图表页全部接入；
tooltip 必须走 token。

## 10. 首屏与性能感知

- 实测的"卡住"均为 `next dev` 首次编译（§1），**不是产品缺陷**；但产品侧有两个真问题：
  1. **首屏无骨架/降级**：受保护页在 AuthGate + 首个 query 返回前是白屏或裸 loading 文案，
     慢网络下观感=坏。建议 shell 内首屏渲染 `<PageSkeleton>`，query 用 `placeholderData`。
  2. 全客户端渲染（无 SSR/流式）：市场这类公开页首屏也要等 JS。
     若市场要对外，建议 `(market)` 开 SSR/静态化（访客态本就不依赖登录）。
- `nextjs-toploader` 颜色硬编码 `#3b82f6`（蓝），与品牌色不一致（§2）。
- recharts / framer-motion 未见 route 级懒加载（`components/charts/lazy-*.tsx` 是死的）。
