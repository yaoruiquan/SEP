# 模型配置与会话系统优化方案

## 一、现状调研

### 1.1 当前架构

**后端模型管理**
- ✅ 已有完整的模型管理模块 (`backend/src/modules/model/`)
- ✅ 支持从 sub2api 上游同步模型列表
- ✅ 支持启用/禁用模型
- ✅ 支持模型排序和自定义显示名
- ✅ 数据库表：`PlatformModel` 存储模型白名单

**前端模型管理**
- ✅ 已有运营端模型管理界面 (`web/src/app/(platform)/admin/models/`)
- ✅ 支持同步、启用/禁用模型
- ✅ 显示模型计费状态（是否配价）

**员工模型配置**
- ✅ 员工模板（DigitalEmployee）有 `modelId` 字段
- ✅ 创建员工时可以指定模型
- ✅ 运行时使用 `employee.modelId || SUB2API_DEFAULT_MODEL`

**配置存储**
- ✅ 环境变量：`SUB2API_BASE_URL`, `SUB2API_API_KEY`, `SUB2API_DEFAULT_MODEL`
- ✅ 数据库：`SystemSetting` 表可以覆盖环境变量
- ⚠️ 当前 `.env` 文件缺少这些配置

### 1.2 当前问题

#### 问题 1：环境变量缺失导致会话失败
**错误信息**：
```
Model "claude-opus-5" is not supported by any configured account in this group
```

**根本原因**：
- `backend/.env` 中没有配置 `SUB2API_BASE_URL` 和 `SUB2API_API_KEY`
- 系统无法连接到上游 AI 服务

**影响**：
- 会话功能完全不可用
- 员工无法执行任何对话任务

#### 问题 2：模型配置界面简陋
**现有功能**：
- 只能启用/禁用模型
- 只能修改显示名称

**缺失功能**：
- 无法配置模型参数（temperature, max_tokens 等）
- 无法设置模型别名映射
- 无法配置模型使用限制（频率、并发）
- 无法设置模型成本和计费规则
- 没有模型测试功能

#### 问题 3：用户端缺少模型选择功能
**当前流程**：
1. 用户订阅员工 → 员工使用固定模型（模板的 `modelId`）
2. 用户无法在对话时切换模型
3. 用户无法看到可用的模型列表

**用户痛点**：
- 不同任务适合不同模型（简单任务用便宜模型，复杂任务用强模型）
- 无法根据成本/性能权衡选择模型
- 无法体验新模型

#### 问题 4：员工创建时模型配置体验差
**当前流程**：
1. 管理员在运营端同步模型
2. 管理员启用模型
3. 管理员在创建员工时手动输入 `modelId`

**问题**：
- 手动输入容易出错（拼写、大小写）
- 没有模型选择下拉框
- 没有模型说明和建议
- 不知道哪些模型适合当前员工类型

## 三、技术方案

### 3.1 修复会话失败（立即执行）

#### 步骤 1：配置环境变量
```bash
# backend/.env
SUB2API_BASE_URL="https://longdaoai.cn/v1"
SUB2API_API_KEY="sk-xxx"  # 需要实际的 API Key
SUB2API_DEFAULT_MODEL="gpt-4o-mini"
```

#### 步骤 2：测试连接
```bash
# 测试上游 API 是否可用
curl https://longdaoai.cn/v1/models \
  -H "Authorization: Bearer sk-xxx"
```

#### 步骤 3：同步模型
1. 登录运营端 → 可用模型
2. 点击"同步上游模型"
3. 启用需要的模型（如 gpt-4o-mini, gpt-4o, claude-3.5-sonnet 等）

### 3.2 完善模型管理界面

#### 功能清单
| 功能 | 优先级 | 实现难度 | 说明 |
|------|--------|----------|------|
| 模型测试 | P0 | 低 | 发送测试消息验证模型可用性 |
| 模型详情展示 | P0 | 低 | 显示上下文长度、支持的功能等 |
| 批量启用/禁用 | P1 | 低 | 勾选多个模型批量操作 |

#### UI 改进
**当前界面**：
- 简单的表格
- 只有开关和模型名

**优化后界面**：
- 分组展示（按厂商：OpenAI, Anthropic, Google 等）
- 卡片式布局，每个模型一张卡片
- 显示模型关键信息：
  - 上下文长度（如：128K tokens）
  - 定价（如：¥0.001/1K tokens）
  - 性能指标（如：速度快、质量高）
  - 适用场景（如：编程、写作、分析）

  - 绿色：已启用且有定价
  - 黄色：已启用但未配价（保底计费）
  - 灰色：已禁用
  - 红色：已失效（上游不再提供）

### 3.3 用户端模型选择

#### 实现位置
**方案 A：会话级别**（推荐）
- 在对话界面顶部添加模型选择下拉框
- 用户可以随时切换模型
- 切换后的消息使用新模型

**方案 B：实例级别**
- 在"我的员工"页面为每个实例设置默认模型
- 覆盖员工模板的模型设置
- 该实例的所有会话都使用设置的模型

**最佳实践：两者结合**
- 实例有默认模型（继承自模板或自定义）
- 会话中可以临时切换（不影响实例默认值）

#### 数据流
```typescript
// 1. 获取可用模型列表

Message {

  tokens: { input: 100, output: 200 },
  cost: 0.003  // 按该模型的定价计算
}
```

### 3.4 优化员工创建流程

#### 当前问题
```typescript
// 管理员手动输入 modelId
<input
  name="modelId"
  placeholder="gpt-4o-mini"
  defaultValue="gpt-4o-mini"
/>
```

#### 优化后
```typescript
<Select
  name="modelId"
  options={enabledModels}  // 从 GET /models 获取
  placeholder="选择模型"
  defaultValue="gpt-4o-mini"
  renderOption={(model) => (
    <div>
      <div className="font-medium">{model.label}</div>
      <div className="text-xs text-muted">
        {model.contextLength} · {model.pricing}
      </div>
    </div>
  )}
/>
```

**智能推荐**：
- 根据员工类型推荐模型
  - 客服类 → gpt-4o-mini（快速响应）
  - 编程类 → claude-3.5-sonnet（代码质量高）
  - 分析类 → gpt-4o（理解能力强）
  - 写作类 → claude-3-opus（创意好）

## 四、数据库变更

### 4.1 新增字段

#### PlatformModel 表（已有，需要扩展）
```prisma
model PlatformModel {
  id          String   @id @default(cuid())
  modelId     String   @unique  // 模型 ID（如 gpt-4o-mini）
  label       String              // 显示名称
  enabled     Boolean  @default(false)
  isStale     Boolean  @default(false)
  sortOrder   Int      @default(0)
  lastSeenAt  DateTime
  
  // 新增字段
  contextLength    Int?      // 上下文长度（tokens）
  maxOutputTokens  Int?      // 最大输出长度
  supportedFeatures Json?    // 支持的功能（function_calling, vision, etc.）
  pricingInputPer1K  Decimal?  // 输入价格（元/1K tokens）
  pricingOutputPer1K Decimal?  // 输出价格（元/1K tokens）
  description      String?   // 模型说明
  vendor           String?   // 厂商（OpenAI, Anthropic, Google）
  category         String?   // 分类（chat, code, vision）
  
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}
```

#### Conversation 表（已有，需要扩展）
```prisma
model Conversation {
  id           String   @id @default(cuid())
  employeeId   String
  userId       String
  title        String?
  
  // 新增字段
  modelId      String?  // 会话默认模型（覆盖实例模型）
  
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
}
```

#### Message 表（已有，需要扩展）
```prisma
model Message {
  id             String   @id @default(cuid())
  conversationId String
  role           String   // user, assistant, system
  content        String
  
  // 新增字段
  modelId        String?  // 实际使用的模型
  tokensInput    Int?     // 输入 tokens
  tokensOutput   Int?     // 输出 tokens
  cost           Decimal? // 成本（元）
  latencyMs      Int?     // 响应延迟（毫秒）
  
  createdAt      DateTime @default(now())
}
```
