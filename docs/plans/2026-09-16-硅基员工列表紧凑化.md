# 硅基员工列表紧凑化

## 已确认方向

按用户提供的参考图调整列表密度与信息顺序，保留当前已确认的人物身份，不新增虚假部署/在线状态，不恢复下载和管理授权入口。

## 执行顺序

1. 在 `web/public/assets/README.md` 整理素材用途、变体、来源、新增流程和接入状态。既有文件不移动，避免已有 URL 失效。
2. 保留现有链接、授权文案、赠送余额和缺数据行为的回归测试。
3. 卡片按人物姓名、两行简介、四行真实使用摘要、赠送余额、技能标签、紧凑操作排列。使用同一人物的正方形头肩变体。
4. 网格按内容区宽度切换三/二/一列，避免仅在 1536px 以上才三列。搜索覆盖名称、岗位、简介、能力；分类与数量使用真实 functionalCategory。
5. 清除营销/分类素材的跨用途横幅引用。员工专用横幅生成若受凭据阻塞，保留紧凑标题，不用无关素材替代。
6. 验证分类计数、搜索、排序、链接、余额显示以及桌面和移动端溢出与头像比例。

## 验证边界

本轮不修改扣费、权限和执行统计逻辑；仅给列表返回已有员工分类字段。其他页面只调整误用图片和对应标题区，不重排其业务模块。

## 执行结果

- 素材 README 与 manifest 已更新，237 个 WebP 文件及每位人物的派生图已检查齐全；保持原有文件路径。
- 列表改为按内容区宽度切换列数。1440px 桌面实测三列，卡片宽 368px，头像为 104×104；390px 页面无横向溢出。
- 卡片采用头肩方图，保留版本和真实授权来源；四行使用摘要、余额、能力标签、短按钮按参考图顺序排列。
- 分类使用后端已有 functionalCategory。名称/岗位/描述/能力关键词搜索、排序、空结果清除已验证。
- 工作台、部门、技能库和员工页已移除跨用途配图。当前使用紧凑文字页头；专用员工横幅因 relay CLI 无法读取当前凭据未生成，未使用其他类别素材替代。
- 验证：前端相关 37 项测试、后端授权服务 21 项测试通过，前后端类型检查、后端定向 ESLint、Next.js 生产构建通过。浏览器使用模拟接口和真实本地图片；未改真实业务数据。
