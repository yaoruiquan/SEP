## 二、方案设计

### 核心概念

**员工模板**（DigitalEmployee）
- 定义：一个"工作角色"（如市场调研员）
- 属性：名称、描述、行业、岗位
- **不直接包含能力，而是通过绑定关联**

**能力**（Capability）
- 定义：可复用的功能单元（如"网页搜索"、"数据分析"）
- 类型：Agent / Skill / RPA / AI_APP
- **一个能力可以被多个员工绑定**

**绑定关系**（EmployeeCapabilityBinding）
- 定义：员工 ↔ 能力的多对多关系
- 额外信息：配置参数、优先级、是否启用
- **灵活可扩展**

## 三、数据库设计

### 1. 新建绑定表

```prisma
model EmployeeCapabilityBinding {
  id           String           @id @default(cuid())
  employeeId   String
  employee     DigitalEmployee  @relation("EmployeeBindings", fields: [employeeId], references: [id], onDelete: Cascade)
  capabilityId String
  capability   Capability       @relation("CapabilityBindings", fields: [capabilityId], references: [id], onDelete: Cascade)
  
  // 绑定配置
  priority     Int              @default(0)      // 优先级（0-100）
  enabled      Boolean          @default(true)   // 是否启用
  config       Json?                             // 能力配置（JSON）
  // config 结构示例：
  // {
  //   "maxRetries": 3,
  //   "timeout": 30000,
  //   "customParams": { ... }
  // }
  
  createdAt    DateTime         @default(now())
  updatedAt    DateTime         @updatedAt
  
  @@unique([employeeId, capabilityId])
  @@index([employeeId])
  @@index([capabilityId])
  @@map("employee_capability_bindings")
}
```

## 四、后端实现

### 1. AdminService 新增方法

`backend/src/modules/admin/admin.service.ts`:

```typescript
/**
 * 获取员工的能力绑定列表
 */
async getEmployeeBindings(employeeId: string) {
  return this.prisma.employeeCapabilityBinding.findMany({
    where: { employeeId },
    include: {
      capability: {
        select: {
          id: true,
          name: true,
          type: true,
          description: true,
          status: true,
        },
      },
    },
    orderBy: { priority: 'desc' },
  });
}

/**
 * 批量绑定能力到员工
 */
async bindCapabilities(employeeId: string, capabilityIds: string[], operatorId: string) {
  const employee = await this.prisma.digitalEmployee.findUnique({
    where: { id: employeeId },
  });
  if (!employee) throw new NotFoundException('员工不存在');

  // 删除现有绑定
  await this.prisma.employeeCapabilityBinding.deleteMany({
    where: { employeeId },
  });

  // 创建新绑定
  const bindings = capabilityIds.map((capabilityId, index) => ({
    employeeId,
    capabilityId,
    priority: capabilityIds.length - index, // 按顺序设置优先级
    enabled: true,
  }));

  await this.prisma.employeeCapabilityBinding.createMany({
    data: bindings,
  });

  return { success: true, count: bindings.length };
}

/**
 * 更新单个绑定的配置
 */
async updateBinding(bindingId: string, data: {
  priority?: number;
  enabled?: boolean;
  config?: any;
}) {
  return this.prisma.employeeCapabilityBinding.update({
    where: { id: bindingId },
    data,
  });
}

/**
 * 删除绑定
 */
async removeBinding(bindingId: string) {
  await this.prisma.employeeCapabilityBinding.delete({
    where: { id: bindingId },
  });
  return { success: true };
}

/**
 * 获取可用能力列表（用于绑定选择）
 */
async getAvailableCapabilities() {
  return this.prisma.capability.findMany({
    where: { status: 'ACTIVE' }, // 假设有 status 字段
    select: {
      id: true,
      name: true,
      type: true,
      description: true,
    },
    orderBy: { name: 'asc' },
  });
}
```

@Get('employees/:id/bindings')

@Post('employees/:id/bindings')
@ApiOperation({ summary: '批量绑定能力到员工' })
bindCapabilities(

  @Body() dto: { capabilityIds: string[] },
  @Request() req: any,
) {
  return this.adminService.bindCapabilities(employeeId, dto.capabilityIds, req.user.id);
}

@Patch('bindings/:id')
@ApiOperation({ summary: '更新绑定配置' })
updateBinding(
  @Param('id') id: string,
  @Body() dto: { priority?: number; enabled?: boolean; config?: any },
) {
  return this.adminService.updateBinding(id, dto);
}

@Delete('bindings/:id')
@ApiOperation({ summary: '删除绑定' })
removeBinding(@Param('id') id: string) {
  return this.adminService.removeBinding(id);
}

@Get('capabilities')
@ApiOperation({ summary: '获取可用能力列表' })
getAvailableCapabilities() {
  return this.adminService.getAvailableCapabilities();
}

  <Label>绑定能力（多选）*</Label>

  // 创建员工

## 八、风险和注意事项

### 风险
1. **能力表可能不存在** - 需要先确认 Capability 表的结构
2. **迁移可能失败** - 如果外键关联的表不存在
3. **前端复杂度** - 拖拽排序需要额外库（如 dnd-kit）

### 注意事项
1. 删除员工时需要 CASCADE 删除绑定
2. 删除能力时需要检查是否被绑定（或 CASCADE）
3. 绑定的 `config` 字段是 JSON，需要验证格式
4. 优先级范围建议 0-100，前端需要限制
