# Web 端媒体能力与授权配置优化开发文档

日期：2026-10-24

状态：本轮授权配置、能力展示、服务端预览及客户端配套修复已实现；验证记录见第 7 节。新增供应商规格和资源扩容不在本轮范围内。

## 1. 目标与实施边界

让管理员看清模型状态和企业授权配置。Web 不按当前 Profile 能力收窄企业授权，也不维护会阻止新规格的前端白名单；管理员填写的授权范围原则上都可以保存。Web 只做类型、结构和输入体验校验，不把“当前模型暂时不支持”变成保存失败。真正使用时由后台按当前模型、adapter、企业授权和协议统一预检，并在报价或产生费用前用提示词和结构化错误说明不可执行原因。

本文将浏览器页面任务标为 W，将 SEP 后台任务标为 B。后台是 Web 与 Electron 的共同依赖，不属于浏览器前端。移除 Web 限制不等于真实接口自动支持任意规格；执行能力仍由后台 adapter 和供应商路径决定。未知能力不得由 Web 猜测，也不得因此阻止企业保存授权；后台在报价/扣费前返回字段化预检结果。

边界：移除按当前 Profile 规格、目录结果或静态枚举阻止保存/提交的 Web 重复校验。保留登录与角色权限、企业数据隔离、资金/审批/幂等、结构完整性、文件类型与字节/像素安全校验。策略数值不再设置业务含义上的最大值；仅保留安全整数、序列化和数据库可表达范围，避免溢出或损坏数据。浏览器校验只改善输入体验；后台共享 DTO、授权和真实执行校验为最终依据。

配套：[客户端开发文档](../../../sep-client/docs/plans/2026-10-24-客户端媒体能力与执行限制优化开发文档.md)、[完整调研与证据](../../../sep-client/docs/plans/2026-10-24-媒体能力限制与跨层契约一致性优化.md)。

授权字段只是管理员意图的记录，不等于模型支持承诺。例如企业可以保存很大的宽高/输出数授权，当前 runtime 仍只能下发 Profile 和 adapter 能兑现的规格。Web 不因两者数值不同阻止保存；用户实际使用时，后台在报价、扣费和提交前判断当前请求，并把原因写入提示词和结构化错误。未知能力不猜测、不静默改参。

## 4. Web 开发任务

### W01 / P1：补充只读能力详情和验证来源

修改公共模型面板，展示现有 Profile DTO 能提供的字段。能力详情是管理员参考信息，不作为前端规格白名单。后续后台若提供更多字段，再随版本契约展示；不能从 modelId 推测缺失信息。

1. 展示当前 DTO 已有字段；没有的质量、合法组合、输入/输出限制显示“未提供”，不生成默认能力，也不因此禁用授权保存。
2. 展示 configVersion、能力来源、校验范围。区分目录可见、本地适配、可报价、真实生成验证；没有验证记录时不得显示真实生成已验证。
3. 自动管理 Profile 保持规格只读，保留紧急停用。仅在后续单独设计后台人工覆盖机制后才增加对应编辑入口，本轮不绕过 `auto-` 保护。
4. 能力详情和错误不展示 API key、内部下载地址或原始上游响应；平台管理员现有连接表单仍可查看、修改已配置的 Base URL，沿用公共组件、现有脱敏与权限机制。

验收：不同 Profile 展示各自能力；未知字段不会伪装成不支持或已验证；检测不发起生成；Profile 详情不会拦截企业策略保存；停用、错误重试和连接保存不回退。

### W02 / P1：企业策略与实际能力交集预览

修改企业媒体页、视频面板及相关 hooks；共享服务端预览由 B03 提供。预览用于说明实际执行范围，不是保存策略的前置条件。Web 不因规格交集为空而阻止管理员保存授权。

预览分为“当前后台可用能力”“企业授权范围”“本协议下有效能力”三部分，显示每个 Profile 被过滤的原因。预览失败、能力未知或交集为空时仍允许管理员保存草稿；服务端有效能力不代表具体请求已通过实时授权、报价、资金和审批检查。Web 不复制 runtime 过滤算法。

采用服务端权威预览；如需草稿即时预览，只复用不依赖数据库、服务类或密钥的共享纯函数，不让 Web 导入后台 service。保存后以服务端结果为准，不能各写一份近似算法。

必须识别：授权范围当前没有匹配的尺寸/比例/时长/操作/分辨率、默认 Profile 无效、模型停用、配置未适配、连接未配置。缺少价格或组合信息时标记“未知”，不推断为支持或不支持；预览只提示，不阻止策略保存。

具体回归：启用仅支持 16:9 的视频 Profile，策略仍仅允许 9:16。页面应解释“已授权，但当前没有满足策略的规格”，提供修改草稿的明确操作；只有管理员执行并保存才改变授权。禁止静默增加比例、放宽时长或选择另一模型。

空授权、全部停用、授权与当前能力没有交集都可能是管理员有意配置，允许保存。保留默认 Profile 必须属于授权列表等结构约束；不增加“必须有可执行模型”的门槛。

验收：相同企业、配置快照、目标协议和 real/mock 模式下，预览的服务端有效能力与 runtime 一致；预览为空时仍可保存；无管理员权限只能查看；企业切换不串用预览；后台撤销后刷新正确显示不可用。未知能力只标记状态，不增加策略保存门槛。

### W03 / P1：配置控件取消业务限制

配置控件不按当前 Profile 的能力收窄企业授权。Web 不再写 `max`、固定尺寸列表或固定视频组合；数值只要求为可序列化的正整数，数组只要求结构正确。视频比例、分辨率、时长等授权集合保留历史值并允许按策略编辑，不因为当前模型没有该值就隐藏或拒绝保存。共享 DTO 可以保留安全整数范围，但不得再加入“当前模型上限”一类业务上限。

Web 不单独维护生成规格枚举。协议已能表达的字段直接交给后台；协议暂时不能表达的值由后台版本协商处理，Web 不偷偷替换、截断或改成另一个值。旧策略中的未知值保持可见、可移除，不静默替换。当前能力提示只在使用页面展示，不参与保存判断。

能力存在条件组合时，使用页面的提示词要说明“这些字段不是任意组合都能执行”；Web 不把独立字段并集伪装成保证可执行，也不因此阻止管理员保存授权。

验收：Web 不以 Profile 能力或旧规格枚举阻止策略保存；旧策略能读取和调整；不存在当前模型组合的授权仍能保存；切换模型不会静默改写授权；输入只因类型、结构或安全序列化失败而提示。实际使用时再由后台提示当前通道限制。

### W04 / P1：错误提示和刷新闭环

复用现有 React Query 与企业作用域键。完善模型同步、停用、策略保存后能力详情和预览的失效范围。平台 Profile 更新/校验处理 `expectedConfigVersion` 冲突；企业策略更新按现有事务冲突响应处理，提供重新加载并保留用户草稿供比较。

当前企业策略更新 DTO 不含 `expectedConfigVersion`，不能把 Profile 版本检查当成企业策略的乐观锁；本轮不据此新增策略版本提交门槛，也不承诺检测所有先后覆盖的旧草稿。

依赖 B04 的结构化错误，区分字段冲突、授权不足、连接异常、配置过期、协议不支持和请求能力不满足。现有 generic error 作为兼容兜底；不根据自然语言错误猜测并自动改策略。能力不足错误应发生在报价/扣费前，并保留用户输入供修正。

验收：同企业多标签页修改后可刷新；缓存不会跨企业复用；旧响应仍能显示基础状态；请求失败不导致页面假显示保存成功。

## 5. SEP 后台共享开发任务

以下是后台任务，集中在本文登记以避免双重实施；客户端文档通过 B 编号依赖它们。后台改动须在 SEP 仓库单独审查。

### B01 / P1：图片能力契约与真实执行一致

主要代码：

- `backend/src/modules/media-gateway/image-model-contract.ts`
- `backend/src/modules/media-config/media-config.service.ts`
- `backend/src/modules/media-config/media-model-sync.service.ts`
- `backend/src/shared/media.dto.ts`
- `backend/src/shared/media-real.dto.ts`
- `backend/src/modules/media-gateway/sub2api-image.adapter.ts`
- `backend/src/modules/media-gateway/media-real.service.ts`

当前支持模型共用三尺寸模板，真实请求 size 也只有三值；这是真实后台执行边界，不是浏览器白名单。B01 负责确保 runtime、报价和请求由同一后台能力判断；不因 Web 放开策略字段而自动开放任意尺寸。新增真实尺寸须有供应商/adapter 证据并完成闭环。

同一次变更贯穿配置校验、自动同步、企业过滤、报价/hash、请求、adapter、receipt 与实际输出校验。加入提示词、参考图和输出的真实限制描述；有效输出上限先与当前存储/下载实现对齐，再通过 B04 发布。资源扩容归客户端 C07 及对应后台后续任务，不是本轮能力对齐的前提。不要直接把历史持久化 schema 收窄。自动同步不得覆盖人工授权或把未知模型自动放行。

验收：Web 授权上限不再复制图片 Profile 上限；backend 对实际请求仍按当前 Profile/adapter 能力在报价前校验；已支持规格闭环不回退。没有明确目标和真实通道证据时，不以“移除 Web 限制”为由声称支持新尺寸。

### B02 / P1：视频能力、发送与对账同步扩展

主要代码：`backend/src/modules/media-config/media-video-config.service.ts`、`backend/src/shared/media-video-config.dto.ts`、`backend/src/shared/media-video-real.dto.ts`、`backend/src/modules/media-gateway/sub2api-video.adapter.ts`、`backend/src/modules/media-gateway/media-video-real.service.ts`。

当前真实路径冻结 minimax-h3、4 秒、16:9、720p、24fps、带音轨、MP4；adapter 请求字段与 usage 对账也依赖该规格。不能只放宽能力清单或表单。

Web 不按时长、画幅、分辨率等独立枚举推断合法组合。后台 runtime 和报价/执行负责最终判断并在扣费前说明当前 adapter 不支持的组合；后台能力矩阵必须来自 adapter 可兑现范围。新增组合须贯通请求、输出验证和 usage 对账，不能通过只放宽 Web 控件开放。

验收：不匹配的企业策略可保存并能预览为空；具体请求在报价/扣费前按 backend 能力拒绝并返回字段化原因；旧路径不回退。没有明确目标和真实通道证据时，不要求虚构新增组合。

### B03 / P1：复用运行时过滤逻辑提供策略预览

复用 image/video config service 现有 runtime 过滤，抽取必要的纯计算逻辑，并通过现有 controller 分层提供管理员可用的预览接口或响应。接口形态由实现时最小改动决定，无需新建独立能力服务。

输入草稿必须按共享 schema、企业作用域和权限校验。结果包含每 Profile 的服务端有效规格、排除原因和 Profile `configVersion`，并明确目标协议、real/mock 模式及所依据的策略草稿/已保存策略。仅依据 Profile 版本不能识别企业策略变化，不能据此缓存整个预览或声明策略未变。预览不返回未授权内部信息，不持久化配置，不发起上传/生成/报价扣费。

图片与视频更新目前分别保存并保留另一方策略；继续保证并发更新不互相覆盖。预览与员工 runtime 在相同企业、策略、Profile、协议及执行模式下比较。Web 不计入未知客户端的本地处理能力；客户端在服务端有效能力基础上继续求交集。

### B04 / P1：版本协商和业务错误

已有版本协商入口：`backend/src/modules/client/client.controller.ts`、`backend/src/modules/client/client.service.ts`；已存在媒体/视频 runtime V1/V2。扩展它们，不另造平行协商系统。

对 strict schema，新增可选字段也可能破坏旧客户端。新字段/枚举使用明确版本和对应投影，旧协议保持可表达范围。Web 共享 DTO 和解析随后台契约一起升级，Electron 按其支持版本消费。

统一脱敏错误 code、field、stage、恢复动作；保留权限、计费、幂等和文件校验。B01/B02 决定真实输入/输出能力，B04 负责协议投影与错误，不重复决定另一套上限。

### 5.5 跨端共同约定

| 事项 | 统一口径 |
| --- | --- |
| 能力层级 | 后台产出协议内可表达的服务端有效能力；客户端再与自身安全处理能力求交集；具体请求仍需报价、资金、审批和提交复验 |
| 版本含义 | `configVersion` 当前属于 Profile；企业策略变化必须重新读取/校验，不能假定同步变更该版本 |
| 早提示 | 客户端使用动态能力说明规格、选择默认值；不另造按旧规格拒绝请求的业务白名单。后台复验具体请求，客户端保留文件真实性、资源安全及交付可兑现性检查 |
| 资源范围 | P1 对齐已能兑现的限制并提前解释；P2 才扩容、细分资源并发或实现多需求映射 |
| 交付修复 | C01 负责交接取消域及复用现有恢复路径的回归；C06 负责超时/未知提交和恢复流程完善 |
| 开放顺序 | 后台先部署兼容契约和执行支持，客户端具备消费能力后，才向支持版本及显式授权的企业开放新规格；Web 展示既有信息可独立交付 |

两份文档的交接以本表及任务编号为准，不将展示完成、协议接通或单侧测试通过视为新规格全链路完成。

## 6. 顺序、迁移与回滚

1. W01 现有字段展示可独立实施；新增能力字段依赖 B01/B02/B04。W02 先接现有可确定的说明，权威交集预览依赖 B03/B04，不为抢先上线复制一份前端过滤算法。

5. Web 展示可独立回滚；后台契约回滚须保留新任务读取能力。不得把回滚代码等同于可以删除新规格历史记录。
