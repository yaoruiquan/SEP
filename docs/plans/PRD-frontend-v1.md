# 硅基员工平台 前端产品需求文档 (PRD)

> **版本**: v1.0  
> **日期**: 2026-07-31  
> **作者**: Claude Code  
> **状态**: 草稿

## 1. 文档说明

### 1.1 背景

硅基员工平台是一个以企业组织为核心的 AI 员工管理平台。本文档定义前端产品需求，明确两个门户的功能规格、用户流程和交互要求。

### 1.2 范围

本文档覆盖两个前端门户：
- **企业端 (Enterprise Portal)** — 企业管理员、部门负责人、普通成员使用
- **运营端 (Platform Portal)** — 平台运营人员使用

**不包含**：开发者端（暂缓）、移动端

### 1.3 设计原则确认

基于需求讨论，确认以下关键设计决策：
- **导航**: 侧边栏 + 顶部面包屑（类似 Dify）
- **员工市场**: 独立入口 + 卡片网格 + 抽屉详情
- **招聘流程**: Modal 弹窗步骤条（5步）
- **我的员工**: 卡片网格 + 实时状态（WebSocket）
- **任务中心**: 集中式 + 员工详情联动 + 流式展示
- **权限管理**: 简化表格勾选 + 审批融入
- **审核中心**: 统一待办列表 + 左右分屏
- **数据可视化**: 中等复杂度（recharts 折线图/饼图/柱状图）
- **响应式**: 桌面优先（≥1280px）
- **实时性**: WebSocket 推送员工状态和任务进度

## 2. 产品定位

硅基员工平台的核心价值主张：

> **让企业像管理人类员工一样管理 AI 员工——招聘、入职、配置、授权、考核、离职全流程闭环。**

### 2.1 核心差异

| 维度 | 传统 AI 工具平台 | 硅基员工平台 |
|------|-----------------|-------------|
| 心智模型 | 工具箱、能力列表 | 员工组织、人才市场 |
| 使用主体 | 个人用户 | 企业组织（部门/成员/权限） |
| 交互形态 | 聊天对话为主 | 管理后台 + 任务派发 |
| 生命周期 | 开通/关闭 | 招聘 → 入职 → 配置 → 授权 → 考核 → 停用 |
| 数据边界 | 用户级 | 企业级隔离（知识库/权限/算力） |

### 2.2 关键概念区分

| 概念 | 定义 | 归属 |
|------|------|------|
| **硅基能力 (Capability)** | 原子化工具单元，类型为 `AGENT` / `RPA` / `SKILL` / `AI_APP` | 平台维护 |
| **硅基员工模板 (Employee Template)** | 市场中的标准员工定义，绑定一组能力 | 平台维护 |
| **企业员工实例 (Employee Instance)** | 企业招聘后生成的专属员工，有企业内名称/部门/权限/知识库 | 企业所有 |
| **任务 (Task)** | 员工工作的基本记录单元 | 企业所有 |

> **要点**：能力是"技能"，员工是"能力的打包 + 人格化包装"。企业招聘的是员工，不是能力。

## 3. 用户角色

| 角色 | 权限范围 | 主要使用场景 | 本期支持 |
|------|---------|-------------|---------|
| **企业管理员** | 企业全局 | 招聘员工、组织管理、权限配置、查看全局数据、算力充值 | ✅ |
| **部门负责人** | 本部门 | 部门员工管理、审批跨部门申请、查看部门数据 | ✅ |
| **普通成员** | 被授权资源 | 提交任务、查看本人任务结果 | ✅ |
| **平台运营人员** | 平台全局 | 企业管理、员工审核上架、能力审核、平台数据看板 | ✅ |
| **硅基员工开发者** | 自有能力 | 上传能力、版本管理 | ❌ 暂缓 |

## 4. 功能范围

### 4.1 本期包含 (MVP)

**企业端 (8 个模块)**
1. 工作台 — 核心指标 + 趋势图表 + 待处理事项
2. 人才市场 — 浏览/搜索/筛选员工，试用与招聘
3. 我的员工 — 已招聘员工管理，实时状态
4. 任务中心 — 任务派发、状态监控、结果查看
5. 组织管理 — 部门、成员、岗位
6. 权限管理 — 授权矩阵 + 跨部门审批
7. 知识库 — 知识库创建、文件上传、授权
8. 算力账户 — 余额、消耗趋势、明细、充值

**运营端 (5 个模块)**
1. 数据看板 — 平台级指标、Top 榜单、异常监控
2. 企业管理 — 企业列表、详情、充值/扣减、冻结
3. 员工管理 — 员工模板创建、能力绑定、上架管理
4. 能力管理 — 能力创建（4 种类型）、列表管理
5. 审核中心 — 员工/能力审核统一待办

**跨模块能力**
- 招聘入职完整流程（5 步向导）
- 员工状态 WebSocket 实时推送
- 任务执行过程流式展示（Trace 面板）

### 4.2 本期不包含

| 不做的功能 | 原因 |
|-----------|------|
| 开发者端门户 | 本期能力由运营人员代为创建 |
| 移动端适配 | 管理后台场景，桌面优先 |
| 聊天对话界面 | Web 端只做管理，对话在客户端 |
| 多员工协同编排 | 核心闭环稳定后再做 |
| 复杂套餐/计费规则 | 先做简单算力点数扣减 |
| 跨企业协作 | 第一阶段聚焦单企业闭环 |

### 5.1 工作台 (Dashboard)

**路由**: `/enterprise/dashboard`  
**角色**: 所有角色

#### 5.1.1 功能描述

企业成员登录后的首页，快速了解企业硅基员工运行状况和个人待办事项。

#### 5.1.2 布局结构

```
┌─ 欢迎语 + 快捷操作 ───────────────────────┐
│ 早上好，张三 👋                            │
│ [+ 招聘员工] [发起任务] [查看报表]         │
├─ 第一行：4 个核心指标卡片 ─────────────────┤
│ [在线员工 12/15 ↑20%] [今日任务 48 ↓5%]   │
│ [算力消耗 85.2K →0%] [活跃成员 23 ↑15%]   │
├─ 第二行：两个图表 ─────────────────────────┤
│ [算力消耗趋势折线图 60%] [员工任务分布饼图 40%] │
├─ 第三行：两个列表 ─────────────────────────┤
│ [待处理事项 50%]  [最近任务 50%]           │
└───────────────────────────────────────────┘
```

#### 5.1.3 核心指标卡片

| 指标 | 数据来源 | 趋势对比 | 点击跳转 |
|------|---------|---------|---------|
| 在线员工 | WebSocket 实时 | 对比昨日同时刻 | `/enterprise/employees` |
| 今日任务 | 当日 0 点至今 | 对比昨日全天 | `/enterprise/tasks` |
| 算力消耗 | 当日累计 tokens | 对比昨日全天 | `/enterprise/compute` |
| 活跃成员 | 当日发起过任务的成员数 | 对比昨日 | `/enterprise/organization` |

#### 5.1.4 算力消耗趋势图

- **类型**: 折线图（recharts `LineChart`）
- **数据**: 最近 30 天每日消耗
- **交互**: Hover 显示具体数值，可切换时间范围（7 天/30 天/90 天）

#### 5.1.5 员工任务分布饼图

- **类型**: 饼图（recharts `PieChart`）
- **数据**: 今日任务按员工分组统计
- **交互**: 点击扇区高亮对应员工

#### 5.1.6 待处理事项列表

显示需要当前用户处理的事项：
- 跨部门申请待审批（部门负责人/管理员可见）
- 员工待配置（招聘后未完成初始化）
- 算力余额不足预警
- 任务失败需重试

每条点击跳转到对应操作页面。

#### 5.1.7 最近任务列表

显示本人发起的最近 5 条任务，状态实时更新（WebSocket）。

### 5.3 招聘入职流程

**触发**: 人才市场点击 [立即招聘]  
**形式**: Modal 弹窗 (宽度 800px)

#### 5.3.1 步骤进度条

```
●━━━○━━━○━━━○━━━○
1    2    3    4    5
基本  运行  知识  模型  权限
信息  环境  配置  选择  分配
```

当前步骤为实心圆●，已完成为实心带连线●━━━，未完成为空心○。

#### 5.3.2 Step 1: 基本信息

**字段**:
- 企业内名称（必填，文本框，最多 20 字）
- 所属部门（必选，下拉单选）
- 员工编号（选填，自动生成或手动填写）

**校验**:
- 名称不能与现有员工重复
- 必须选择部门

**按钮**: [取消] [下一步 →]

#### 5.3.3 Step 2: 运行环境

**选项**（单选 Radio）:
```
○ 统一客户端 (推荐)
   适用于大部分场景，无需额外配置

○ 独立 Agent 平台
   支持 Coze、扣子等第三方平台

○ 企业现有系统对接
   通过 API 集成到企业内部系统
```

**按钮**: [← 上一步] [下一步 →]

#### 5.3.4 Step 3: 知识库配置

**授权知识库**:
- 多选 Checkbox，列出企业已有的知识库
- 勾选后该员工可读取对应知识库内容

**上传补充资料**:
- 拖拽上传区域（支持 PDF/Word/TXT/Markdown）
- 自动创建「员工专属知识库」

**按钮**: [← 上一步] [下一步 →]

#### 5.3.5 Step 4: 模型选择

**默认模型**（单选下拉）:
- GPT-4 (推荐)
- Claude 3.5 Sonnet
- 通义千问 Plus
- 其他...

**算力预算**（滑块）:
- 范围: 500 - 5000 tokens/天
- 实时显示预估费用

**按钮**: [← 上一步] [下一步 →]

#### 5.3.6 Step 5: 权限分配

**授权使用成员**:
- 按部门勾选（展开树形）
- 按个人勾选
- 支持 "全员可用" 快捷选项

**数据权限**（可选配置）:
- ☑ 读取客户信息
- ☐ 修改订单
- ☐ 导出数据

**按钮**: [← 上一步] [完成招聘]

#### 5.3.7 完成后行为

- Toast 提示 "招聘成功！销售助理小李已加入企业"
- Modal 关闭
- 自动跳转到 `/enterprise/employees`
- 新员工卡片高亮显示（3 秒动画）
- 首次引导气泡：「点击 [⚙配置] 可调整详细参数」

## 7. 关键用户流程

### 7.1 企业首次使用完整流程

**目标**: 从注册到首次使用硅基员工完成任务

**步骤**:
1. 注册企业账号（邮箱 + 密码）
2. 创建企业信息（企业名称、行业、规模）
3. 创建第一个部门（如"销售部"）
4. 添加碳基员工（邀请成员或跳过）
5. 进入人才市场浏览员工
6. 选择一个员工查看详情
7. 点击 [免费试用 7 天] 或 [立即招聘]
8. 完成招聘入职 5 步向导
9. 在"我的员工"看到新招聘的员工
10. 点击 [发起任务] 提交第一个任务
11. 查看任务执行过程（流式展示）
12. 查看任务结果

**成功标准**: 用户能在 10 分钟内完成从注册到获得第一个任务结果。

### 7.2 跨部门员工使用申请流程

**场景**: 市场部成员需要临时使用销售部的"销售助理小李"

**步骤**:
1. 市场部成员登录，在"我的员工"页面看到"销售助理小李"（灰色，显示"无权限"）
2. 点击卡片 → 提示"该员工属于销售部，您需要申请使用权限"
3. 点击 [申请使用]
4. Modal 填写:
   - 申请理由（必填）
   - 使用期限（单选: 1 天/3 天/7 天/自定义）
   - 需要的数据权限（多选）
5. 提交申请
6. 销售部负责人收到通知（工作台"待处理事项" + 站内信）
7. 负责人在"权限管理"页面看到申请
8. 点击 [批准] → 填写审批意见（选填）→ 确认
9. 市场部成员收到通知"申请已批准"
10. "销售助理小李"卡片变为可用状态
11. 到期后自动回收权限，卡片恢复灰色

**分支**: 如果拒绝，市场部成员收到拒绝通知和原因。

---

### 7.3 运营人员审核员工上架流程

**场景**: 运营人员审核新提交的硅基员工

**步骤**:
1. 运营人员登录，顶部显示"审核中心 (5)" 角标
2. 点击"审核中心"菜单
3. 左侧列表显示待审核员工，按提交时间倒序
4. 点击第一条"销售助理小李"
5. 右侧分屏显示员工详情（介绍、能力、定价等）
6. 查看绑定能力列表，确认都已审核通过
7. 滚动到底部查看审核检查清单
8. 点击绑定的能力名称 → 抽屉显示能力详情（快速核查）
9. 如果没有问题，点击 [通过]
10. Modal 二次确认 → 点击 [确认通过]
11. Toast 提示"审核通过，员工已上架"
12. 该员工从待审列表移除
13. 员工立即出现在人才市场，企业可见

**分支**: 
- 如果发现问题（如能力边界不清晰），点击 [拒绝] → 选择或填写拒绝原因 → 确认
- 提交人收到拒绝通知，可编辑后重新提交

### 7.4 员工实时任务执行与监控流程

**场景**: 成员提交任务并实时查看执行过程

## 8. 非功能性需求

### 8.1 性能要求

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| 首屏加载时间 | < 2s | Lighthouse |
| 页面切换响应 | < 300ms | 用户感知 |
| 实时数据延迟 | < 500ms | WebSocket ping |
| 列表分页大小 | 20 条/页 | 标准配置 |
| 大列表虚拟滚动 | > 1000 条启用 | 日志、任务历史 |

### 8.2 兼容性要求

**浏览器支持**:
- Chrome >= 90
- Edge >= 90
- Safari >= 14
- Firefox >= 88

**不支持**: IE 11 及以下

**屏幕分辨率**:
- 最小支持: 1280 × 720
- 推荐: 1920 × 1080
- 不支持移动端

### 8.3 实时性要求

**WebSocket 推送场景**:
| 数据 | 推送频率 | 延迟要求 |
|------|---------|---------|
| 员工在线状态 | 状态变化时 | < 500ms |
| 任务执行进度 | 每 1s 或进度变化 | < 500ms |
| 任务执行步骤 | 步骤变化时 | < 300ms |
| 流式输出内容 | 每个 token | < 200ms |
| 待审核数量角标 | 新增待审时 | < 1s |

**轮询场景**（WebSocket 不可用时降级）:
- 员工状态: 每 30s
- 任务列表: 每 10s

### 8.4 安全要求

**认证**:
- JWT Token 存储在 LocalStorage（企业端）或 Cookie（考虑切换方案）
- Token 过期时间: 7 天
- 过期后自动跳转登录页

**权限**:
- 前端路由守卫：未登录 → 登录页
- API 调用失败 (401) → 登录页
- 权限不足 (403) → 提示"无权限访问"

**数据脱敏**:
- 企业 ID 在 URL 中混淆（使用 nanoid 替代数字 ID）
- 敏感操作（充值/扣减/冻结）需要二次确认
- 审计日志记录所有敏感操作

### 8.5 可访问性要求

**基本要求**:
- 所有交互元素支持键盘访问（Tab 导航）
- 焦点状态清晰可见（蓝色描边）
- 表单错误提示与输入框关联（aria-describedby）
- 图片提供 alt 文本
- 按钮提供 aria-label（图标按钮）

**颜色对比度**: 符合 WCAG 2.1 AA 级别（4.5:1）

### 8.6 数据缓存策略

**TanStack Query 配置**:
| 数据类型 | staleTime | cacheTime | 自动重新请求 |
|---------|-----------|-----------|------------|
| 员工列表 | 5 分钟 | 10 分钟 | 窗口聚焦时 |
| 任务列表 | 1 分钟 | 5 分钟 | 窗口聚焦时 |
| 员工详情 | 10 分钟 | 30 分钟 | 手动刷新 |
| 工作台数据 | 30 秒 | 2 分钟 | 每次进入 |
| 知识库列表 | 5 分钟 | 15 分钟 | 窗口聚焦时 |
| 组织架构 | 30 分钟 | 60 分钟 | 手动刷新 |

**失效策略**:
- 创建/更新/删除操作后，立即失效相关 query
- 使用 `queryClient.invalidateQueries()` 触发重新请求

### 8.7 错误处理

**全局错误边界**:
- 捕获 React 组件渲染错误
- 显示友好错误页面（不是白屏）
- 提供 [刷新页面] [返回首页] 操作

**API 错误处理**:
| HTTP 状态码 | 处理方式 |
|------------|---------|
| 400 | Toast 显示错误消息 |
| 401 | 跳转登录页 |
| 403 | Toast "权限不足" |
| 404 | Toast "资源不存在" |
| 500 | Toast "服务器错误，请稍后重试" |
| Network Error | Toast "网络连接失败" + 重试按钮 |

**表单验证错误**:
- 实时验证（onBlur）
- 错误消息显示在输入框下方（红色文字）
- 提交时滚动到第一个错误字段

## 9. UI/UX 原则（简述）

详细设计规范见 `UIUX-frontend-v1.md`，此处仅列出核心原则：

1. **参考 Dify 风格** — 简洁、现代、专业，重交互体验
2. **信息层级清晰** — 主次分明，重要信息突出
3. **减少操作步骤** — 常用操作一键直达
4. **实时反馈** — 所有操作立即给予视觉反馈
5. **状态可见** — 员工状态、任务进度、系统状态随时可见
6. **容错性** — 关键操作二次确认，支持撤销
7. **响应式加载** — 骨架屏代替 Loading Spinner
8. **渐进增强** — WebSocket 不可用时降级到轮询

## 附录 B: 核心数据流

### B.1 员工状态实时更新

```
后端 WebSocket Server
  ↓ (员工状态变化时推送)
前端 WebSocket Client (useWebSocket hook)
  ↓ (接收消息)
更新 TanStack Query Cache (queryClient.setQueryData)
  ↓ (触发重新渲染)
员工卡片组件显示最新状态
```

### B.2 任务执行流式展示

```
用户点击 [查看实时输出]
  ↓
打开 Modal，建立 WebSocket 连接 (wss://.../tasks/:id/stream)
  ↓
后端推送执行步骤和流式输出
  ↓
前端逐 token 更新 Trace 面板内容
  ↓
任务完成，WebSocket 连接关闭
  ↓
刷新任务列表（invalidateQueries）
```

### B.3 权限变更即时生效

```
用户勾选权限矩阵中的 Checkbox
  ↓
前端乐观更新 UI（立即显示勾选状态）
  ↓
调用 API: PATCH /permissions
  ↓
后端更新数据库
  ↓
后端通过 WebSocket 推送权限变更事件
  ↓
前端失效相关 query (员工列表、任务中心权限筛选)
  ↓
Toast 提示 "已授权张三使用销售助理小李"
```
