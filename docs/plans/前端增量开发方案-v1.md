## 2. 开发阶段规划

### 阶段划分原则

1. **增量迭代** — 基于现有代码扩展，不推翻重来
2. **独立验证** — 每个阶段完成后可独立测试
3. **优先闭环** — 优先完成核心流程的端到端闭环
4. **降低风险** — 先做基础组件和页面框架，再做复杂交互

## 5. 风险与应对

### 5.1 WebSocket 后端未就绪

**风险**：阶段 3 需要 WebSocket 支持，但后端可能未实现。

**应对**：
1. 前端先用 Mock 数据 + setTimeout 模拟推送
2. 定义好 WebSocket 消息格式（与后端对齐）
3. 后端就绪后，只需替换连接地址，消息处理逻辑不变

### 5.2 API 字段变更

**风险**：开发过程中后端 API 字段可能调整。

**应对**：
1. 使用 Zod Schema 校验所有 API 响应
2. 字段变更时，Zod 校验失败会立即发现
3. 集中在 `web/src/features/*/schemas.ts` 中维护 Schema

### 5.3 UI/UX 规范落地困难

**风险**：设计规范太细致，开发难以完全遵守。

**应对**：
1. 阶段 1 建立 Design Token 和基础组件后，后续只需复用

## 7. 开发注意事项

### 7.1 代码规范

- **组件命名**：PascalCase，功能清晰（`TaskTraceModal` 而非 `Modal2`）
- **文件命名**：kebab-case（`task-trace-modal.tsx`）
- **Hook 命名**：use 前缀（`useWebSocket`, `useTasks`）
- **样式**：只用 Tailwind，不写 CSS 文件
- **类型**：所有组件 Props 必须有 TypeScript 类型定义

### 7.2 性能优化

- **列表渲染**：使用 `key={item.id}`，不用 `index`
- **大列表**：>1000 条使用 `@tanstack/react-virtual`
- **图片**：使用 `next/image`，不用 `<img>`
- **防抖节流**：搜索框使用 `useDebouncedValue`（300ms）

### 7.3 无障碍

- **键盘操作**：所有交互元素支持 Tab / Enter / Esc
- **Focus 状态**：使用 `focus-visible:` 显示清晰边框
- **图标按钮**：必须有 `aria-label`
- **表单**：`<label>` 关联 `<input>`
