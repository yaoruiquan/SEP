# 碳基员工邮件邀请开发文档

**Goal:** 管理员填写邮箱后直接发送邀请邮件，明确反馈发送结果，支持重发，手动复制作为备用操作。

**Architecture:** 复用 NestJS MailService / Nodemailer 和现有企业邀请模型。数据库记录邀请生命周期与最近一次邮件发送结果，发送发生在邀请事务提交后；前端继续使用 TanStack Query，接受邀请沿用现有注册、登录及 OAuth 流程。

**Tech Stack:** NestJS、Prisma / PostgreSQL、Nodemailer、Next.js、React、TanStack Query、Zod、Vitest、Jest、Playwright。无需新增依赖。

## 1. 现状与范围

- `InvitationService.create()` 已尝试发信，但异常被忽略，响应未说明发送结果。
- 邮件未启用或配置不全时使用 Console provider，管理员无法得知实际没有发信。
- 前端创建后无条件要求复制，列表只显示接受状态，缺少重发。
- 邮件和复制链接分别使用后端配置域名、浏览器域名，存在不一致。
- 保留邮箱绑定、管理员权限、多租户隔离、SHA-256 摘要存储和一次性使用。
- 不改变认证凭据存储、注册验证码规则或企业归属限制。

方案选择：同步发送并返回明确结果。仅改文案无法解决发送失败和重发问题；本次不增加异步队列和长期保存明文 token 的机制。

## 2. 产品行为

1. 管理员填写邮箱、角色、部门和岗位，点击“发送邀请”。
2. 后端创建邀请并尝试发送邮件；邀请创建成功和邮件发送结果分开处理。
3. `SENT`：展示“邀请邮件已发送”，注明邮件服务器已接收，未收到时可检查垃圾邮件；复制链接为备用操作。
4. `FAILED`：展示“邀请已创建，邮件发送失败”，提供重发入口和当前链接；不要求管理员重新填写成员信息。
5. `NOT_CONFIGURED`：展示邮件服务尚未就绪，提示联系平台管理员，并提供当前链接。
6. 列表分别展示邀请状态和邮件状态。历史记录显示“发送记录未知”，不推断已经发信。
7. `PENDING` / `EXPIRED` / `REVOKED` 可重新发送，`ACCEPTED` 不可重发。
8. 重发更新原邀请，保留角色、部门、岗位，生成新 token，有效期重置为 7 天，旧 token 立即失效。
9. 同企业同邮箱最近一次尝试后 60 秒内拒绝创建/重发，前端操作等待后恢复，后端是最终约束。
10. 邮件状态 `SENT` 只表示 SMTP 接收，不等同于邮箱投递成功或收件人阅读。

## 3. 数据结构

在 `EnterpriseInvitation` 增加：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `emailStatus` | `InvitationEmailStatus`，默认 `UNKNOWN` | 最近一次发送结果 |
| `emailLastAttemptAt` | `DateTime?` | 发送尝试开始时间，用于冷却限制 |
| `emailSentAt` | `DateTime?` | 最近一次 SMTP 接收时间，重发开始时清空 |
| `emailError` | `String?` | 固定、安全的用户提示，不存 SMTP 原始错误 |
| `updatedAt` | `DateTime` | 邀请更新时间 |

`InvitationEmailStatus`：`UNKNOWN`（历史无记录）、`SENDING`（发送中）、`SENT`（SMTP 接收）、`FAILED`（发送失败）、`NOT_CONFIGURED`（邮件服务不可用）。

迁移仅增加列和枚举，历史状态保持 `UNKNOWN`；不回填虚构发送时间，不删除数据。使用 Prisma 生成新迁移，不修改历史迁移。若已有开发库存在历史迁移漂移，使用本机独立临时数据库生成及验证迁移，不重置现有数据库。

## 4. 接口契约

### 创建

`POST /enterprise/invitations`，现有请求字段保持兼容。

响应保留一次性 `token`，增加服务端生成的 `invitationUrl` 和上述邮件状态字段。旧 `POST /enterprise/members` 继续委托同一服务并返回兼容响应。

### 列表

`GET /enterprise/invitations` 增加邮件状态字段。列表不返回 `token`、`tokenHash` 或完整邀请链接。

### 重发

`POST /enterprise/invitations/:id/resend`，仅企业管理员，无请求体。响应与创建一致。

- 跨企业或不存在：404。
- 已接受、竞争更新或冷却未结束：409，固定中文提示。
- 创建/重发事务失败：不发信，不留下部分更新。
- 发信失败：邀请仍有效，返回 `FAILED`；不存在原始异常或凭据泄漏。

所有接口保持 JwtAuthGuard、Swagger 描述和共享 Zod 验证规范。

## 5. 后端实现与并发约束

- 创建：在 Serializable 事务中检查同企业同邮箱最近邀请及冷却、撤回旧 PENDING、创建新邀请，初始发送状态 `SENDING`。
- 重发：同样在 Serializable 事务中读取、鉴权、检查状态/冷却，条件更新当前 token 摘要，保留同一邀请 ID。
- 重发历史邀请前检查邮箱是否已加入企业，并撤回同邮箱其它 PENDING 邀请；创建时的成员检查也放入事务，避免与接受邀请竞争。
- Prisma 序列化冲突转 Nest `ConflictException`，不得吞异常或直接暴露数据库错误。
- 邮件在事务外同步发送，连接/握手/读写超时有界；不把外部 SMTP 放进数据库事务。
- 邮件模块专用邀请发送方法返回 `SENT` / `NOT_CONFIGURED`，SMTP 异常由邀请服务转为 `FAILED`。
- 邮件服务未启用/配置缺失时不得把 Console provider 标记为 `SENT`。
- 发送完成条件更新 `id + tokenHash + emailStatus=SENDING`，防止旧发送覆盖新一次结果。若进程中断，`SENDING` 保留为真实未知中的状态，60 秒后可人工重发，不自动重复发信。
- 密码运行时更换必须触发 SMTP provider 更新；指纹只存密码摘要，不输出凭据。
- `invitationUrl` 统一由服务端 `WEB_BASE_URL` 通过 URL API 生成，生产 HTTPS；本地默认 `http://localhost:3000`。拒绝非法协议/带认证信息的基地址。
- 邮件包含企业名、加入链接、有效期和忽略非本人操作提示，HTML 中所有动态内容转义。
- 普通密码注册、已登录接受和 OAuth 接受的最终条件更新必须包含当前 token 摘要、PENDING 和未过期条件，阻止重发前已读取的旧 token 被并发接受。
- 撤回和 token 校验中的过期收敛也使用摘要、当前状态和有效期条件，避免旧请求覆盖重发后或已接受的状态。

## 6. 前端实现

- `CreatedInvitation` 增加服务端 URL、邮件字段；使用共享邀请 Zod schema 校验表单，不复制邮箱/角色规则。
- 创建/重发 mutation 失效邀请列表缓存。发送时按钮禁用并显示 loading，失败不关闭填写对话框。
- 结果弹窗按发送状态显示标题和原因；当前链接只保存在组件内存，关闭后不再展示。
- 邮件成功时备用链接折叠，失败/未配置时直接展示；剪贴板失败给出提示。
- 列表增加邮件状态、时间/原因与带 tooltip 的重发图标，保留撤回。
- 重发确认弹窗注明邮箱、7 天有效期及旧链接失效。冷却期间操作禁用，冷却结束恢复；所有变更操作进行中阻止重复提交。
- 表格允许横向滚动，弹窗限制移动端宽度和高度，长邮箱/URL 不遮挡按钮。
- 精简旧的“生成后手动转达”文案；不修改受邀注册和认证交互。
