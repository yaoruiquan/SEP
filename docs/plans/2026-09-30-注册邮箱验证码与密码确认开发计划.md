# 注册邮箱验证码与密码确认开发计划

**目标：** 为邮箱密码注册增加注册前邮箱验证码，并为自助注册和受邀注册增加确认密码。

**方案：** 新增公开验证码发送接口；验证码由 Redis 短期保存服务端密钥摘要，通过后才允许创建账号。自助开企业和受邀加入两种本地密码注册均要求验证码，并在创建用户时标记邮箱已验证；邮箱确认密码只做前端校验，不传给后端。第三方 OAuth 注册流程保持不变。

**技术栈：** NestJS、Zod、Redis/ioredis、Nodemailer、Next.js App Router、React Hook Form、TanStack Query、Jest、Vitest。

## 接口契约

- `POST /auth/registration/email-code`：请求 `{ "email": "user@example.com" }`；返回统一提示 `{ "message": "如果该邮箱可用于注册，验证码将发送至该邮箱" }`。
- `POST /auth/register`：除现有字段外必须提供 `emailCode`，格式为 6 位数字。
- `POST /auth/register-by-invitation`：除现有字段外必须提供 `emailCode`，格式为 6 位数字。
- 确认密码字段只在 Web 表单本地校验，不属于上述 API payload。

## 范围与安全约束

- 验证码为 6 位数字，10 分钟有效，验证成功即删除；最多允许 5 次错误尝试。
- 按归一化邮箱每小时最多发送 3 次，按 IP 每小时最多发送 10 次；接口另有请求级限流。
- 邮箱与 IP 限流次数/时间窗口在运营端现有「认证与安全」设置中可视化调整，默认分别为 3 次/小时和 10 次/小时。
- 已注册邮箱与可注册邮箱的发送 API 返回相同提示，避免通过该接口枚举账号。
- SMTP 发送失败时清除挑战并返回明确错误；Redis 不可用时注册验证失败关闭，不绕过验证码。
- 验证码只存 HMAC 摘要，摘要密钥复用认证服务已有 JWT secret；Redis key 使用邮箱 SHA-256 摘要。
- 已通过注册验证码的本地注册账号直接记录 `emailVerifiedAt`，不再重复发送注册验证链接。现有登录后重发验证链接能力保留，供其他账号路径使用。
- 邀请链接与邮箱验证码均须有效；已有账号仍按现有流程登录后接受邀请。
- 不新增依赖、不改 Prisma schema、不手写数据库迁移。
