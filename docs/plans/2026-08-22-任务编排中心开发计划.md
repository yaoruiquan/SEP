# Task Orchestration Center Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将企业端任务中心从“会话列表”升级为面向目标的任务编排工作区，自动从已订阅硅基员工及其绑定能力中生成执行计划，并在执行时可视化展示员工、技能、步骤状态、进度和中间结果。

**Architecture:** 本次先做可验证的前端垂直切片，不新增 Prisma 任务表。候选员工通过现有订阅和数字员工详情接口获得，规划器根据任务文本、员工岗位和绑定能力描述进行可解释的关键词匹配，生成可确认的步骤 DAG；确认后按步骤复用现有 Conversation/SSE/Capability 执行链，并将运行状态保存在当前页面状态中。后续再把同一份计划/运行事件抽取为后端 `Task`、`TaskStep`、`TaskRun` 和 `TaskEvent` 持久化模型。

**Tech Stack:** Next.js 15 App Router, React, TanStack Query, existing `api` client, existing Conversation SSE stream, Tailwind/shadcn-style components, Vitest.

---

## Product decisions

- 默认流程为：描述任务 → 自动生成计划 → 用户确认 → 执行。
- 不再要求用户先选择单个硅基员工；高级设置允许限制候选范围。
- 计划步骤必须显示：员工、技能、步骤说明、依赖关系、预计状态。
- 执行页必须显示：当前员工、当前技能、步骤时间线、进度、事件和中间输出。
- 任务中心的历史会话继续兼容展示，但明确标记为“历史执行”，不再冒充完整编排任务。
- 本次不修改 Prisma schema；页面刷新后运行中的本地编排状态不保证恢复，文档中记录为后续风险。
