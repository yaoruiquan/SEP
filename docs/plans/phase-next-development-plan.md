## 三、下一阶段开发任务

### **P0 — 对话中心（演示核心，最高优先级）**

> **目标**：季度会议前完成"订阅→授权→对话→调用技能"完整演示流程

#### 3.1 对话界面（web）
- [ ] **对话窗口基础布局**
  - 左侧：硅基员工列表（已授权的实例）
  - 右侧：消息流 + 输入框
  - 响应式布局，不同窗口大小下不出现错位

- [ ] **消息渲染**
  - 支持文本、代码块（highlight.js）、Markdown
  - 用户消息 vs 员工回复样式区分
  - 时间戳、状态标识（发送中/已送达/失败）

- [ ] **多模态输入**
  - 文本输入框（支持多行、@mention）
  - 文件上传（图片、文档、视频）
  - 对象存储集成（阿里云 OSS / 腾讯云 COS）

- [ ] **@员工 / @技能**
  - 在对话中 @ 指定硅基员工
  - 支持同时调用多个员工协作
  - 技能列表浮层选择

- [ ] **会话管理**
  - 新建会话 / 历史会话列表
  - 会话重命名 / 删除
  - 会话持久化到后端

#### 3.2 对话后端（backend）
- [ ] **Conversation 模块**
  - `POST /conversations` — 创建会话
  - `GET /conversations` — 用户会话列表
  - `POST /conversations/:id/messages` — 发送消息
  - `GET /conversations/:id/messages` — 消息历史

- [ ] **SSE 流式响应**
  - `GET /conversations/:id/stream` — SSE 端点
  - Vercel AI SDK `streamText` 集成
  - 支持多轮对话上下文

- [ ] **技能调用编排**
  - 解析 @员工 / @技能 指令
  - 路由到对应 Capability（agent / rpa / skill / ai-app）
  - 返回结果聚合（多员工协作场景）

- [ ] **对话数据持久化**
  - 消息存储（用户消息 + 员工回复）
  - 算力消耗记录（每条消息的 token 用量）
  - 关联到 ComputeTransaction

### **P2 — 算力管理精细化**

> **目标**：企业管理员可控制成本、监控用量、防止滥用

#### 3.5 算力配额系统
- [ ] **部门/人员配额设置**
  - 企业管理员为部门设置月度配额
  - 部门管理员为成员分配配额
  - 配额每月自动重置（未用完的额度归零）

- [ ] **配额监控与告警**
  - 实时余额显示（企业总余额、部门余额、个人余额）
  - 配额不足告警（邮件/站内通知）
  - 超额限制（达到配额后禁止调用）

- [ ] **用量追踪与分析**
  - 按部门/成员统计算力消耗
  - 按技能统计调用频次和成本
  - 生成用量报表（日/周/月）

#### 3.6 数据洞察（AI 驱动）
- [ ] **用量价值分析**
  - 识别高价值调用 vs 无效调用
  - 员工能力评估（相同任务的算力消耗对比）
  - 技能 ROI 分析

### **P3 — 组织效能与协作**

> **目标**：个人能力组织化、知识沉淀、协作增效

#### 3.7 知识库优化
- [ ] **多模态知识库**
  - 支持文本、图片、PDF、视频
  - 向量化 + BM25 混合检索（已有基础）
  - 企业级知识库隔离

- [ ] **知识库权限管理**
  - 企业知识库 vs 部门知识库 vs 个人知识库
  - 知识共享与权限控制

#### 3.8 技能贡献者体系
- [ ] **贡献者入口**
  - 员工可创建技能/智能体
  - 技能提交审核流程
  - 技能上架到企业内部市场

- [ ] **技能迭代与同步**

## 五、技术债务与风险

### 5.1 技术债务
- **知识库并发瓶颈** — 当前 pgvector 方案在高并发下性能未验证
- **对象存储未集成** — 文件上传功能依赖外部存储服务
- **客户端缺失** — 演示阶段暂用 Web 端，客户端需后续开发

### 5.2 风险与应对
| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 演示前对话功能未完成 | 无法展示核心价值 | P0 任务每日跟进，提前3天冻结需求 |
| sub2api 性能不稳定 | 对话延迟高、用户体验差 | 准备备用模型中转方案 |
| 知识库并发崩溃 | 内部测试阶段服务不可用 | 第四周必须完成并发优化 + 压测 |
| 技能调用失败率高 | 硅基员工不可用 | 增加重试机制 + 降级方案 |

## 六、会议核心共识

### 6.1 产品定位
- **不是工具集，是组织效能平台** — 个人效率提升是手段，组织能力沉淀是目标
- **数据与知识在线化** — 统一平台收集使用数据，为 AI 治理奠定基础
- **能力可复制** — 90 分员工的能力应该让所有人达到 90 分

### 6.2 设计原则
- **简单、高效、易用** — 前期不追求复杂功能，聚焦核心流程
- **开箱即用** — 降低企业 AI 落地门槛
- **数据驱动决策** — 用算力消耗数据评估员工能力、技能价值

### 6.3 商业模式
- **订阅制 + 算力包** — 硅基员工按年订阅，赠送基础算力，超出部分单独购买
- **技能付费** — 默认技能免费，高级技能包单独定价
- **收益分配** — 技能创造的价值按 50%-40%-10% 分配给部门、团队、集团
