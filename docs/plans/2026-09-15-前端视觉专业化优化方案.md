# SEP 前端视觉专业化优化方案

**日期**：2026-09-15
**状态**：方案，待分阶段实施
**适用范围**：`web/` 全部路由组 —— 企业端 `(enterprise)` 37 页、运营端 `(platform)` 18 页、市场 `(market)`、官网 `(marketing)`。
**配套文档**：`docs/plans/2026-09-15-视觉素材与头像库规划.md`（图片资产由该文档负责，本文只定义组件的接入契约）。

---

## 1. 结论：不是缺组件，是视觉语言分裂

现有前端的信息架构（左侧分组导航 + 顶栏 + 卡片内容区）与目标风格属于同一类，**不需要重做布局**。观感不专业来自三个系统级问题，而不是某一页做得难看：

1. **品牌色分裂成三套**。同一套后台，切一次主题，主色从靛蓝变粉；切到市场又变橙。
2. **玻璃拟态被当成默认材质**。`Card` 的默认变体是 `glass`，全站 148 处调用点、52 个文件继承它，只有 22 处显式写了 `variant="solid"`；数据密集的表格和列表叠模糊底，观感发脏、滚动掉帧。
3. **页面没有统一的头部与筛选层**。企业端与运营端共 44 个 `<h1>` 分散在 51 个文件里，字号有 4 档、颜色有 4 种；搜索框、筛选 pill、统计条每页重新实现一遍。

另外还有一层隐性问题：**设计令牌已经存在且质量不低，但没有被执行**。`tailwind.config.ts` 定义了完整的语义色、玻璃阶、圆角阶、阴影阶，`globals.css` 有 1654 行令牌；页面却仍在写 `text-gray-900`、`bg-neutral-600`、`rounded-[22px]`、`#3b82f6`。所以本方案的重点不是"再造一套设计系统"，而是**收敛既有令牌、补齐缺失的四类页面级组件、并建立可校验的约束**。

### 有效设计基准（从参考图反推，与现有令牌兼容）

| 类别 | 取值 | 现有对应令牌 |
|---|---|---|
| 品牌主色 | `#6366f1` / hover `#4f46e5` | 需统一，见 §3.1 |
| 品牌辅助 | 紫 `#a855f7`、粉 `#ec4899` | 仅用于渐变装饰 |
| 页面画布 | `#f5f6fa` 级浅灰蓝 | `--gbg-canvas: #f0f2f5`（接近，微调） |
| 卡片表面 | 纯白 + 1px 淡边 + 柔和投影 | `--surface-solid-raised` |
| 正文阶梯 | 主/次/弱 三级 | `--gtext-primary/secondary/muted` |
| 圆角 | 卡片 16、控件 10、徽章 pill | `--gradius-lg/md/pill` |
| 语义色 | 成功绿、警告橙、危险红、信息蓝 | `--gsuccess/gwarning/gdanger/ginfo` |

## 2. 问题诊断（附实测数据）

### 2.1 品牌色分裂

| 位置 | 当前值 | 影响面 |
|---|---|---|
| `globals.css:7` 根令牌 | `#eb3f00` 橙 | 登录页、市场、旧浅色组件 |
| `globals.css:434` `.theme-glass` | `#4f46e5` 靛蓝 | 深色后台 |
| `globals.css:1162` `.theme-glass-light` | `#db2777` 粉 | 浅色后台 |

企业端默认走浅色主题（`theme-provider.tsx` 默认 `light`），因此**当前企业后台的主色实际是粉**，而顶栏"人才市场"按钮硬编码了 `#6366F1 → #A855F7 → #EC4899` 三段渐变（`enterprise-shell.tsx:342`），三种色彩语言同时出现在一个屏里。

### 2.2 标题与页面结构不一致

实测 37 个企业页的 `<h1>`：

- 字号：`text-2xl` 35 处、`text-xl` 7 处、`text-3xl` 6 处、`text-4xl` 2 处
- 字重：`font-bold` 33 处、`font-semibold` 19 处
- 文字色：`text-gtext-primary` 20 处、`text-foreground` 8 处、`text-neutral-900` 1 处、`text-gray-900` 1 处

外层间距同样散乱：`space-y-6 p-6`、`space-y-5 pb-8`、`space-y-8` 三种写法混用（注意 `enterprise-shell.tsx:357` 已经提供了 `p-6`，页面再写一遍会变成 48px 双倍内边距）。

### 2.3 玻璃材质与实心表面混用

`Card` 默认 `glass`（`card.tsx:20`），但平台端已有 17 处显式 `variant="solid"`——说明团队已经发现表格页不该用玻璃，却没有把结论回写到默认值。

`globals.css:560` 的 `.glass-card` fallback 是 `rgba(20, 26, 43, 0.92)`（深色），浅色主题下靠 `.theme-glass-light` 覆盖成白色。这意味着**任何遗漏主题作用域的页面都会渲染成深色卡片**，是一类潜在的显示事故。

### 2.4 任意值与硬编码色

`rounded-[22px]` 2 处、`rounded-[24px]` 6 处、`rounded-[28px]` 1 处，与令牌阶 `--gradius-lg: 16px` / `xl: 24px` 并存但不等价。硬编码色集中在 dashboard 图表（`#3b82f6`、`#14b8a6`）、usage（`#0ea5e9`）与顶栏渐变——图表色可接受，UI 色不可接受。

### 2.5 缺失的页面级构件

参考图里贡献观感最大的四类构件，当前**都没有统一实现**：页面 Hero/标题区、统计条、筛选条、带"查看详情"的区块卡。37 个企业页各自手写头部，因此永远无法对齐。

## 3. 目标设计语言

一句话定义：**浅色画布 + 纯白卡片 + 单主色靛蓝 + 柔和高斯投影 + 少量渐变只用于装饰与 Hero**。

玻璃拟态从"默认材质"降级为"特定场景材质"，仅保留在：深色模式、官网营销区、登录页、Modal/抽屉、以及少数强调卡。

### 3.1 色彩收敛规则

- 仅保留**一个**品牌主色源：`#6366f1`（hover `#4f46e5`，浅底文字 `#4f46e5`，深底文字 `#818cf8`）。
- `.theme-glass`（深色）与 `.theme-glass-light`（浅色）的 `--gbrand*` 必须指向同一色相族，只允许在明度上区分。
- 根令牌 `--brand` 从 `#eb3f00` 改为品牌靛蓝；橙色仅作为 `--warning` 语义色保留。
- 渐变（`--ggradient-*`）只能出现在：Hero 背景、装饰插画底、图表填充。**禁止用于正文标题与按钮文字**。
- 现有 `gradient-text-*` / `bg-clip-text` 用法共 7 个文件 10 处，需逐处复核，仅保留官网 Hero。

### 3.2 圆角与阴影

| 用途 | 圆角令牌 | 值 |
|---|---|---|
| 页面级大容器 / Hero | `rounded-glass-xl` | 24px |
| 标准卡片 | `rounded-glass-lg` | 16px |
| 按钮 / 输入 / 小控件 | `rounded-glass-md` | 12px |
| 徽章 / 头像 / 开关 | `rounded-glass-pill` | 9999px |

阴影只用两档：`shadow-glass-sm`（静态卡片）、`shadow-glass-md`（hover / 浮层）。投影必须带蓝紫底色（现有 `--glass-shadow-*` 已符合），禁止纯黑投影。

### 3.3 排版阶梯

| 层级 | 规格 | 用途 |
|---|---|---|
| 页面标题 | 28px / 600 | Hero 内主标题 |
| 区块标题 | 18px / 600 | 卡片组标题 |
| 卡片标题 | 15px / 600 | 卡片内标题 |
| 正文 | 14px / 400 | 描述、表格内容 |
| 辅助 | 13px / 400 | 元信息、时间戳 |
| 标签 | 12px / 500 | 徽章、分类 pill |

> 中文界面不使用 `uppercase` 与 `tracking-wider`（现有 `enterprise-shell.tsx` 的分组标题用了 `uppercase tracking-wider`，对中文无效果，只增加视觉噪音）。

## 4. 组件补齐计划

新增 4 个页面级组件，放在 `web/src/components/shell/`（与 `shell-topbar.tsx` 同级）或 `web/src/components/page/`。每个组件必须消费 §3 的令牌，禁止硬编码色值。

### 4.1 `PageHero`

页面顶部渐变横幅，提供标题、副标题、右侧插画槽与操作区。

```
props: title, description?, eyebrow?, actions?, illustration?, gradient?
```

- 高度约 120–160px，圆角 `glass-xl`，背景为品牌色 8% 透明渐变到底色。
- 插画槽接收素材库产出的图片路径（见 §6），缺省时不渲染，退化为纯文字 Hero。
- 必须支持 `prefers-reduced-motion`（背景若带动画需可关闭）。

### 4.2 `StatStrip`

一行内联统计，共参考图的「20 个技能 / 6 个已调整 / 579 次调用」形态。

```
props: items: Array<{ icon, value, label, tone? }>
```

- 每个 item 左侧 32px 圆角方块图标（底色为语义色 12%），右侧上下排布数值与标签。
- 数值用 20px/600，标签用 12px 次级色。
- 移动端横向滚动，不换行堆叠。

### 4.3 `FilterBar`

搜索 + 筛选 + 排序 + 视图切换的统一入口。

```
props: searchValue, onSearchChange, filters?, sort?, viewMode?, onViewModeChange?
```

- 搜索框占满剩余宽度，圆角 pill 或 12px，高度 40px。
- 筛选项渲染为可滚动 pill 组，选中态用品牌色 12% 底 + 品牌色文字（复用 `NavItem` 的 active 逻辑，去掉发光）。
- 替代各页自写的 `CategoryTabs`、`RangeTabs` 等重复实现。

### 4.4 `SectionCard`

带标题与右上角行动链接的内容卡。

```
props: title, description?, action?: { label, href, onClick? }, children, padded?
```

- 白底 + 1px 淡边 + `shadow-glass-sm`，圆角 `glass-lg`。
- 标题行左侧标题（15px/600）+ 可选副标题，右侧「查看详情 →」链接。
- 表格类内容使用 `padded={false}`，让表头贴边。

## 5. 分阶段实施

### Phase 0：令牌与卡片默认值收敛（P0，约 1 天）

1. 三个 brand 值统一到 `#6366f1` 族，同步 `--brand-rgb` / `--gbrand-rgb` / `--gbrand-text-rgb`。
2. `card.tsx` 默认变体 `glass` → `solid`，同时保留 `variant="glass"` 供显式使用。
3. `Card` 的 `rounded` 默认从 6px 改为 `--gradius-lg`（16px），避免各页写 `rounded-[22px]`。
4. 移除 `enterprise-shell.tsx:342` 顶栏按钮的三段渐变与 `ring-2`/`shadow-lg`/`hover:scale-105`，改为品牌色淡底 pill。
5. 移除 `nav-item.tsx:47` 的 `shadow-[0_0_10px]` 发光。

**验收**：`/design-preview` 页色卡全部刷新且层级单调；企业端浅色与深色下主色一致；平台端表格无模糊底。

### Phase 1：页面级组件与样板页（P0，约 2–3 天）

1. 实现 `PageHero`、`StatStrip`、`FilterBar`、`SectionCard`。
2. 在四个页面落地：`dashboard`、`my-employees`、`capabilities`、`departments`。
3. 统一页面外层：由 shell 提供 `p-6`，页面只写 `space-y-6`，禁止双重内边距。
4. 统一 `<h1>` 为组件内渲染，页面不再手写标题样式。

**验收**：四个页面并排截图，标题字号、间距、卡片圆角、阴影一致；`space-y-*` 与 `p-6` 不再同时出现在页面根节点。

### Phase 2：全量铺开（P1，约 3–5 天）

1. 按页面清单逐个替换为四个组件，优先高频页：`subscriptions`、`usage`、`knowledge`、`members`、`wallet`、`compute-quota`。
2. 运营端 `(platform)` 18 页同批对齐（表格类优先 `SectionCard padded={false}`）。
3. 市场 `(market)` 与官网 `(marketing)` 保持玻璃语言，仅同步品牌色与圆角。
4. 清理硬编码：`text-gray-900`、`text-neutral-900`、`bg-neutral-*` 替换为语义令牌。

### Phase 3：素材接入（P1，依赖素材库文档）

1. 实现统一 `Avatar` 扩展：`shape="circle" | "rounded"`、`objectPosition`、尺寸阶梯、`src` 为空时回落到默认头像库。
2. 接入 `web/public/assets/` 的目录结构，读取 manifest。
3. Hero 插画接入 `PageHero` 的 `illustration` 槽。

### Phase 4：可校验约束（P2）

1. 增加 stylelint 或自定义 ESLint 规则：禁止在 `web/src/app/**` 中写 `rounded-[Npx]` 与六位 hex 色值。
2. 在 CI 中跑一条检查脚本，输出"未被令牌覆盖的硬编码色"清单。
3. 更新 `/design-preview` 成为组件的唯一验收入口。

## 6. 与素材库文档的接口

素材库文档（`2026-09-15-视觉素材与头像库规划.md`）定义了资源目录与四类素材。前端侧的对接约定如下：

| 素材类型 | 资源路径 | 消费组件 | 约定 |
|---|---|---|---|
| 硅基员工半身图 | `web/public/assets/employees/silicon/` | `Avatar` | 组件负责裁切；资源只保留一份主图，焦点位置由 manifest 提供 |
| 碳基默认头像 | `web/public/assets/employees/carbon-defaults/` | `Avatar` | 仅在 `src` 为空时作为 fallback，按稳定 ID 分配，不随刷新变化 |
| 技能分类视觉 | `web/public/assets/capabilities/categories/` | `StatStrip` / 列表项图标 | 不承载文字信息 |
| 技能类型图标 | `web/public/assets/capabilities/types/` | `Badge` / 类型标签 | 与 `capability` 语义色对应 |
| 营销 Hero | `web/public/assets/marketing/hero/` | `PageHero.illustration` | 桌面/移动两张，`PageHero` 负责裁切与不遮挡标题 |

前端在 Phase 3 之前不依赖素材产出：`PageHero` 的插画槽与 `Avatar` 的 `src` 都必须支持空值，缺图时退化为纯色或首字母，不出现破图。

## 7. 验收标准

**视觉一致性**
- 企业端浅色/深色下主色色相一致，仅明度不同。
- 全站卡片圆角只有 16px 与 24px 两档；按钮/输入 12px；徽章 pill。
- 页面标题字号只有 28px（Hero）与 18px（区块）两档。
- 不存在纯黑投影；不存在未定义的 `text-gray-*` / `bg-neutral-*`。

**材质正确性**
- 表格、长列表、统计卡为实心白底，无 `backdrop-filter`。
- 玻璃材质只出现在深色模式、营销、登录、Modal/抽屉与显式强调卡。
- 滚动页面时无明显掉帧（长列表页在 60fps 基线内）。

**结构与可维护性**
- 页面根节点不再同时出现 `p-6` 与卡片级 `p-*` 双重内边距。
- 37 个企业页与 18 个运营页全部使用同一套页面级组件。
- `/design-preview` 能覆盖全部新增组件的状态（默认/hover/加载/空态）。

**可及性**
- 主色文字与画布对比度 ≥ 4.5:1（沿用现有注释中的实测口径）。
- 深色模式下主按钮白字对比度 ≥ 4.5:1。
- 所有交互元素有 `focus-visible` 环，颜色用 `--gbrand-ring`。

## 8. 决策边界

- **同意**：统一品牌色、卡片默认转实心、补齐四个页面级组件、统一页面标题与间距。
- **建议采纳**：玻璃材质降级为场景化材质；用脚本在 CI 层拦截硬编码色。
- **不建议**：重写布局与信息架构；引入新的 UI 组件库替换现有 Shadcn 基础；为每个页面单独设计视觉。
- **暂不做**：动效体系重构、图表视觉重构、字体替换。这些在令牌统一后收益会自然出现，提前做只会增加回归面。
