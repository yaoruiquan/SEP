# SEP 企业端前端视觉专业化实施方案

**日期**：2026-09-16  
**状态**：Phase 0/1 已实现，待视觉验收  
**适用范围**：企业端工作台、部门管理、技能库、硅基员工，以及共用的企业壳层。  
**参考基线**：用户提供的 4 张企业管理端截图。  
**素材依赖**：[视觉素材与头像库规划](./2026-09-15-视觉素材与头像库规划.md)

## 1. 设计判断

参考图体现的是一套成熟的企业工作台，而不是营销页面：

- 左侧固定导航承担产品结构，宽度约 248px，当前页面用浅 indigo 底和左侧色条标记。
- 顶部工具栏高度约 64px，包含面包屑、全局搜索、市场入口、购物车、通知、主题切换和用户菜单。
- 主内容使用浅灰蓝画布，内容区最大宽度约 1440px；页面左右留白稳定，不贴屏。
- 每个业务页先有一个 144–184px 的宽幅标题区，右侧使用真实插画或场景图，左侧保留标题、说明和主动作。
- 标题区下面是统计条或筛选条，再进入白色实心内容面板；数据列表优先保证扫描和对齐。
- 卡片不是装饰容器。只有需要分组、抬升或承载动作时才使用卡片；表格和长列表不能叠加大面积毛玻璃。
- 颜色使用“靛蓝主色 + 语义色点缀”：蓝/紫表达品牌和信息，绿表达已生效，橙表达提醒，红只表达风险。
- 插画不承载名称、价格、状态和按钮文字；所有关键信息继续由 HTML 文本提供。

本轮目标是把现有页面收敛到这套工作台语言，同时保留当前路由、API、权限和交互行为。

## 2. 当前项目与参考图的差距

| 区域 | 当前代码 | 参考图目标 | 改造动作 |
|---|---|---|---|
| 企业壳层 | `EnterpriseShell` 已有左栏和顶栏，但顶栏高度、控件密度和浅色表面不统一 | 248px 左栏 + 64px 顶栏 + 统一工具区 | 收敛宽度、间距、活动态、顶栏控件和用户菜单 |

| 页面头部 | 多数页面只有普通 `<h1>`，技能库没有宽幅标题区 | 144–184px Hero，左文案右插画 | 增加 `PageHero`，接入已生成图片 |

| 部门页 | 左树右面板结构正确，但标题区和树/成员卡仍是旧样式 | 左树层级清楚，右侧内容具有明确标题和操作 | 保留交互，替换表面、间距、成员头像和空态 |
| 员工页 | 卡片信息完整，但顶部缺少视觉入口，筛选密度不统一 | Hero + 搜索筛选 + 3 列员工卡 | 接入员工 Hero 图，统一卡片信息阶梯 |

## 3. 设计令牌

### 3.1 颜色

```text
主色填充：#6366f1
主色 hover：#4f46e5
主色文字：#4338ca
页面画布：#f0f2f5
卡片表面：#ffffff
卡片抬升：#fafbfc
成功：#16a34a
提醒：#d97706
危险：#dc2626
信息：#2563eb
```

规则：

1. 企业端浅色和深色主题使用同一 indigo 色相，仅调整明度。
2. 渐变只出现在页面 Hero 插画底、营销区域和少量强调背景，不能用于普通按钮文字或表格表头。
3. 语义色用于状态，不作为大面积页面背景。
4. 所有文字颜色使用语义令牌；新增页面禁止写六位色值。

### 3.2 尺寸

| 对象 | 桌面端 | 移动端 |
|---|---:|---:|
| 左侧导航 | 248px | 抽屉，覆盖内容 |
| 顶栏 | 64px | 56px |
| 内容外层最大宽度 | 1440px | 100% |
| 页面左右内边距 | 28–32px | 16px |
| 页面 Hero | 144–184px | 180–240px，图片下移 |
| 标准卡片圆角 | 16px | 14px |
| 控件圆角 | 10–12px | 10–12px |
| 统计数字 | 24–30px | 22–26px |
| 正文 | 14px | 14px |
| 辅助信息 | 12–13px | 12px |

### 3.3 材质

- 页面背景：浅灰蓝画布，可保留极低透明度的 indigo 光晕。
- 标准内容面板：`surface-solid`，白底、淡边、`shadow-glass-sm`。
- Hero：`glass-hero` 或白色半透明底，仅用于页面头部；必须有图片或明确的色块层次。
- 长列表和表格：实心表面，不使用 `backdrop-filter`。
- 阴影：只用 `shadow-glass-sm` 和 `shadow-glass-md`，不使用纯黑大阴影。

## 4. 页面级组件契约

组件放在 `web/src/components/page/`，页面不重复手写同类结构。

### `PageFrame`

负责页面最大宽度、左右内边距和纵向节奏。默认输出 `mx-auto w-full max-w-[1440px] space-y-6`；壳层已经提供页面内边距，页面禁止再次添加 `p-6`。

### `PageHero`

```ts
type PageHeroProps = {
  title: string;
  description?: string;
  eyebrow?: string;
  actions?: React.ReactNode;
  illustration?: { src: string; alt: string };
  tone?: 'indigo' | 'blue' | 'violet' | 'teal';
};
```

桌面端左文案、右插画；移动端上下排列。标题 28px/600，说明最多 2 行，图片使用 `object-contain`，不得遮挡标题和按钮。缺图时退化为纯色标题区。

### `StatStrip`

```ts
type StatStripItem = {
  label: string;
  value: string | number;
  icon?: React.ReactNode;
  tone?: 'brand' | 'success' | 'warning' | 'info';
};
```

桌面端横向排列，移动端横向滚动；图标 32px、数字 20–24px、标签 12px。统计条只表达汇总，不放操作按钮。

### `FilterBar`

```ts
type FilterBarProps = {
  search?: React.ReactNode;
  filters?: React.ReactNode;
  sort?: React.ReactNode;
  actions?: React.ReactNode;
};
```

搜索框最小宽度 240px；筛选项采用轻量 segmented/pill；移动端工具栏允许横向滚动，但搜索框不能被压缩到不可用。

### `SectionCard`

用于有明确标题和内容边界的区块。表格类区块使用 `padded={false}`，卡片内部不再嵌套卡片。

```ts
type SectionCardProps = {
  title: string;
  description?: string;
  action?: React.ReactNode;
  padded?: boolean;
  children: React.ReactNode;
};
```

## 5. 样板页面落地顺序

### Phase 0：基础令牌和共享壳层

1. 企业端默认使用浅色工作台画布，统一 `--gbrand*` 与 `--surface-solid*`。
2. `Card` 默认使用 `solid`，保留 `variant="glass"` 作为显式营销/强调材质。
3. `EnterpriseShell`：导航宽度固定 248px，顶栏 64px；删除市场入口的多色渐变和发光边框，改为 indigo 轻底按钮。
4. 活动导航使用 3px 左侧色条 + 8% indigo 底色；分组标题使用正常中文大小写，不使用 `uppercase tracking-wider`。
5. 壳层内容区统一 `max-width: 1440px` 和 `28–32px` 内边距。

### Phase 1：四个样板页

#### `/dashboard`

- 顶部使用工作台 Hero 图，标题区左侧保留问候和一句工作状态。
- Hero 下方放 4 个指标：硅基员工、本月对话、碳基成员、本月算力。
- 下方使用 `2fr + 1fr`：模型使用分析、快捷入口/系统公告。
- 空数据时显示有引导的空态，不出现只有 0 的大卡片。

#### `/departments`

- 顶部使用部门管理 Hero 图和“新建顶级部门”动作。
- 主体保持左树右详情，左侧 320px 上限，右侧使用 `SectionCard`。
- 部门节点显示层级、人数和轻量操作；成员卡使用真实碳基默认头像 fallback。
- 移动端先显示部门选择器，再显示成员/模型策略面板。

#### `/capabilities`

- 顶部使用技能库 Hero 图。
- Hero 下方使用 `StatStrip`：技能数、已调整、待处理、调用次数。
- 搜索和筛选合并成一条 `FilterBar`；列表保持高密度，图片只出现在分类/技能详情，不挤压版本和待办列。
- 技能详情场景图只在详情页顶部显示，不进入长列表每一行。

#### `/my-employees`

- 顶部使用硅基员工 Hero 图。
- 搜索、最近使用/按名称排序统一为 `FilterBar`。
- 员工卡保持 3 列网格；头像使用半身图，信息区固定层级：名称、状态、岗位、用量、操作。
- 无数据、错误、搜索无结果都使用同一套反馈组件。

### Phase 2：扩展到高频业务页

按 `subscriptions → compute-quota → usage → knowledge → members → wallet → tasks` 顺序复用页面级组件。每次只改一个页面组，改完运行构建和截图检查。

### Phase 3：资源和细节接入

- 碳基默认头像：读取 `/assets/visual-assets.json`，仅在 `User.avatar` 为空时按稳定 ID 选择。
- 技能分类/类型图：仅在分类标识或类型标签旁展示，不能替代文字。
- 技能详情图：读取 manifest 的 `featured` 映射，找不到时退回无图布局。
- Hero：桌面端使用 `desktop.webp`，移动端使用 `mobile.webp`，保留 HTML 标题和 CTA。

## 7. 验收标准

### 结构

- 四个样板页都使用 `PageFrame`；页面根节点不同时出现 `p-6` 和壳层页面内边距。
- 页面标题区统一为 `PageHero`；标题、说明和主动作在桌面端第一屏可见。
- 顶栏单行显示，桌面端高度不超过 64px；移动端不出现横向溢出。

### 视觉

- 浅色模式主色统一为 indigo，绿色/橙色/红色只表达语义状态。
- 表格、长列表、统计条使用实心白色表面；玻璃效果只出现在 Hero、抽屉、弹窗和营销区。
- 卡片圆角只使用 14–16px；Hero 使用 24px；按钮/输入使用 10–12px。
- 参考图中的留白、对齐和信息密度在 1440px、1280px、390px 三个视口下稳定。

### 交互与可访问性

- 所有按钮有 hover、active、focus-visible 状态；图标按钮有 `aria-label` 或 `title`。
- 图片有描述性 `alt`；装饰图使用 `aria-hidden`。
- 头像加载失败回落首字母，默认头像不覆盖用户上传头像。
- `prefers-reduced-motion` 下禁用非必要位移动画。

### 性能

- 长列表不使用大面积 `backdrop-filter`。
- Hero 和详情图使用 WebP，并通过 `loading="lazy"` 或 Next Image 控制加载。
- 页面构建、TypeScript、lint（若配置）必须通过。
