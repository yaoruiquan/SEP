## 一、核心术语定案

### 1.1 状态术语

| 英文枚举值 | ❌ 不一致写法 | ✅ 统一术语 | 使用场景 |
|-----------|--------------|-----------|---------|
| `PENDING` | 待审批 / 待审核 | **待审核** | 运营端：能力审核、员工审核、技能审核 |
| `PENDING` | 待审批 / 待审核 | **待审批** | 企业端：成员申请、订阅申请 |

**决策**：
- **运营端审核队列统一用「待审核」**（admin/employees、admin/capabilities、admin/skills）
- **企业端审批流统一用「待审批」**（成员申请企业通过、普通成员申请订阅）
- 原则：**运营端 = 平台审核内容质量；企业端 = 企业内部审批流程**

### 1.2 订阅 vs 雇佣

| 层面 | 术语 | 使用场景 |
|-----|------|---------|
| **用户可见** | 雇佣 | 市场页按钮「立即招聘」、雇佣管理、授权说明「企业雇佣该员工」 |
| **技术层** | 订阅 / Subscription | 代码实体名、API 路由、数据库表名、后端日志 |
| **过渡期** | 订阅申请 | 普通成员提交申请的内部状态（逐步改为「申请使用」） |

**决策**：
- **面向用户的所有文案统一叙事为「雇佣」**（体现硅基/碳基拟人化）
- **技术实现层保持 Subscription**（避免大面积重构风险）
- **SEO/元数据可保留「订阅」**（layout.tsx description，搜索引擎友好）

### 2.2 高频硬编码场景（需优先治理）

| 场景 | 示例 | 优先级 | 迁移策略 |
|-----|------|-------|---------|
| 表格列名 | "名称" "状态" "操作" | P1 | 加入 `locales/zh-CN.ts` 的 `table` 命名空间 |
| 按钮文案 | "提交" "取消" "确定" | P1 | 加入 `common.actions` |
| 空态文案 | "暂无数据" "没有匹配的员工" | P1 | 加入 `common.empty` |
| 表单标签 | "员工名称" "价格" | P2 | 各业务域的 `form.labels` |
| Toast 提示 | "保存成功" "操作失败" | P2 | `common.feedback` |
| 搜索占位符 | "搜索员工名称、岗位…" | P2 | `common.search` |

## 三、迁移策略（不追求全量 i18n）

### 3.1 原则
1. **不做全量 i18n**——当前只有中文，一个 `as const` 常量文件已足够
2. **术语表优先**——新文案必须查表，确保一致性
3. **高频词优先**——按钮/状态/空态 > 说明文字 > 长文案
4. **组件 chrome 优先**——UI 控件文案 > 用户生成内容

### 3.2 扩展 `locales/zh-CN.ts` 结构（建议）

```typescript
export const common = {
  actions: {
    submit: '提交',
    cancel: '取消',
    confirm: '确定',
    save: '保存',
    delete: '删除',
    edit: '编辑',
    search: '搜索',
    filter: '筛选',
    reset: '重置',
  },
  status: {
    pending: '待处理',
    active: '进行中',
    completed: '已完成',
    failed: '失败',
  },
  empty: {
    noData: '暂无数据',
    noResult: '没有匹配的结果',
    tryAgain: '试试放宽筛选条件或换个关键词',
  },
  feedback: {
    saveSuccess: '保存成功',
    saveFailed: '保存失败',
    deleteConfirm: '确定删除吗？此操作不可撤销。',
  },

  columns: {
    name: '名称',
    status: '状态',
    createdAt: '创建时间',
    updatedAt: '更新时间',

  },

```

### 3.3 迁移工作流

**新功能开发**：
1. 写文案前先查 `locales/zh-CN.ts`
2. 有对应 key → 直接引用
3. 无对应 key → 先加入 locales，再引用

**存量代码修复**（逐步进行）：
1. 按页面优先级排序（dashboard > 市场 > 设置 > ...）
2. 每次修改某页面时，顺手把硬编码改为 locales 引用
3. 不强求一次性全改完

## 四、Lint 规则（代码评审 checklist）

### 4.1 禁止项
- ❌ 同一状态出现多种译名（PENDING 不能既是"待审批"又是"待审核"）
- ❌ 用户可见文案使用"订阅"（应统一为"雇佣"叙事）
- ❌ 运营端用"待审批"（应为"待审核"）
- ❌ 企业端审批流用"待审核"（应为"待审批"）

### 4.2 建议项
- ⚠️ 新增按钮/表格列名/空态文案时，优先引用 locales
- ⚠️ 长文案（>20 字）可暂时硬编码，但需加 TODO 注释
- ⚠️ 组件内部的 `aria-label` 可硬编码（a11y 优先）
